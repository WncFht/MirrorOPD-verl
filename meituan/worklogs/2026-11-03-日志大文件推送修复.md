# 日志大文件推送修复

## 目标与验收

接收日志后，普通 Git 中的单个 `.wandb` 增长到 125432556 字节，GitHub 拒绝推送。采用 Git LFS 存储 `.wandb`，验证已有同步入口可以继续推送，且不可变上传快照仍包含原始日志。成功条件是远程接受普通快进推送、原始日志逐文件摘要不变、上传队列能还原 LFS 对象。若对象上传被拒绝或快照无法还原，则保留原提交和队列，不能宣称完成。LFS 跟踪范围和首次上传超时可根据验证结果调整。

## 实施与结果

日志仓库为 `/Users/fanghaotian/src/wandb-logs`。迁移范围限定为 `refs/heads/main` 中尚未被 `refs/remotes/origin/main` 包含的提交；远程基线为 `2ddb9983261c2256708122266185c599c32851a4`，原本地提交为 `c86081b47334c583ee57b091c3ea54bcd211fa7d`，转换后为 `14bfcf12c2fb9a7f18261b8364a9c1b146940a11`。原提交保存在 `backup/pre-lfs-20261103`，旧上传任务引用继续保留。迁移工具会同时移动指向原提交的分支，迁移结束后已将备份分支重新指向原提交。

`git lfs install --local` 安装本仓库过滤器与推送钩子。迁移把当前 56 份 `.wandb` 转为 LFS 指针，总对象大小约 1 GiB，未改远程已发布历史。`make sync-log-push GIT_PUSH_TIMEOUT=900` 在约 46 秒内成功完成，使用普通快进推送。`git lfs checkout` 将本地工作区的指针还原为原始日志。

LFS 转换改变 run 的 Git tree ID，现有队列按既有规则登记了 56 个新快照；旧任务与引用保留。此次没有执行 W&B 云端上传，后续上传仍先核对云端 history。

上传器原先直接解包 `git archive`，会读到 LFS 指针。现在在临时准备目录内调用 `git lfs smudge` 还原对象，完成后才发布缓存；对象缺失时任务失败，不发布指针缓存。旧普通 Git 快照和 SDK 修改缓存的规则保持兼容。

`python3 -m unittest tests.special_sanity.test_log_sync_queue tests.special_sanity.test_meituan_log_publish`：45 项测试通过，包含真实本地 LFS 对象还原、工作区后续修改不影响已提交快照、缺失对象时不发布缓存。修改的两个 Python 文件通过 ruff 和 ruff-format。
