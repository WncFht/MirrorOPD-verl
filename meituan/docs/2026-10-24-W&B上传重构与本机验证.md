# W&B 上传重构与本机验证

## 结果与边界

2026-10-23 在本机 Linux 上使用独立上传环境 `wandb==0.31.0`，完整同步一份 16,361,752 字节、2,380 条指标定义、600 条 history 的真实离线 run，用时 18.66 秒。SDK 生成完成标记，云端状态为 finished；回读得到 600 行、step 0–599。与本地原始记录比较的 66,696 个有限数值、字符串或布尔标量全部存在且一致，数值比较使用相对和绝对容差 `1e-8`。

这个结果来自本机网络，不等于 Mac 的网络表现。旧引擎的对比设置了 60 秒上限，没有获得完整运行时间，因此不报告固定加速倍数。测试没有修改训练指标定义，也没有升级训练或本地解码环境。

## 重构范围

`transfer.py` 继续负责人工传输包的扫描、打包、分卷和解包；接收端的本地提交、队列与上传移至 `log_sync.py`。`sync_observe.py` 改为按块读取输出并支持子进程总时限，避免没有换行的进度提示长期不可见。`sync_status.py` 统一展示本地 Git 状态、诊断报告和队列任务。

默认 `sync-log-unpack` 合并日志、本地提交、登记队列并尝试 Git 推送。W&B 上传由 `sync-log-upload` 单独执行，旧日志可用 `sync-log-enqueue` 补入队列，Git 推送可用 `sync-log-push` 单独重试。`WANDB_SYNC=1` 保留在接收后立刻上传的组合入口。

任务身份由 run 路径、现有 Git tree ID 和固定的云端目标组成，没有另行增加文件摘要扫描。队列和上传副本位于日志仓库 `.git/mirroropd-upload/`，SDK 对配置和同步标记的改写不会污染原始日志。同一快照成功后跳过；失败保留缓存；新快照可替代尚未开始或失败的旧任务，正在运行的旧任务先完成。

默认并发两个不同 run，每批最多 900 秒，一轮只尝试每个就绪任务一次。失败保留任务并设置冷却；达到三次尝试后需要显式 `RETRY=1`。worker 锁传给 SDK 子进程，避免父进程异常退出后又启动竞争上传器。

## 成功判定与不完整文件

真实测试发现，SDK 可以在打印同步错误后返回退出码 0。因此队列按每个快照的 `.wandb.synced` 标记确认完成，批次退出码不能代替单个 run 的结果。SDK 报告 incomplete record 且缺少标记时，任务记录为 incomplete，等待更新的源快照，不重复上传同一份不可变化的半条记录。

工具不会裁剪原始 `.wandb`、补造退出记录，也不会对静态归档使用 `--live`。部分数据可能已经出现在云端，但只有完整快照才记为 succeeded。此处保证的是该次本地 SDK 同步结果；状态查询不实时检查云端是否后来被删除或改动。

## 可复现检查

在上传机器安装独立 SDK，然后按操作文档接收、上传和查看状态：

```bash
make sync-log-setup
make sync-log-unpack LOG_ARCHIVE=/下载目录/日志包.tar.gz
make sync-log-upload
make sync-log-status
```

70 项相关测试通过，Ruff 格式、lint、Shell 语法与 diff 检查通过。本机测试使用假的 W&B CLI 和本地 Git bare 仓库验证失败分支，不依赖训练或外网。覆盖原始日志不变、成功跳过、新快照入队、旧失败任务保留、部分批次成功、超时、中断恢复、SDK 零退出码但缺少标记、旧 SDK 拒绝、队列锁、云端目标隔离，以及 Git 推送失败后独立重试。源代码 bundle 与旧 tar 归档测试也继续执行。
