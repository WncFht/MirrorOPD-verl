# 源码历史清理与迁移

更新：2026-10-27。清理覆盖 MirrorOPD 项目在上游基线之后的完整提交历史，移除原始实验明细；上游基线及其祖先保持不变。该操作改变项目提交号，旧 checkout 与清理后的分支不能直接快进合并。

## 数据与源码的边界

Git 保留代码、配置、研究报告、展示图和有界的结果摘要。文档目录中的训练日志、JSONL、压缩 JSON、原始 Parquet、逐 state/token 记录、rollout 明细和下载的论文源文件保留在本机原路径，不随源码 Git 或 bundle 交付。已有的大型 JSON/CSV 汇总也移出历史。

文件限额为 2 MiB；实验 `data/` 中的 JSON/CSV 汇总限额为 1 MiB。现有的小型离线依赖 ZIP、上游测试 fixture 和依赖锁文件保留。完整实验数据在原目录保留，按需人工传输；报告中的原始证据链接在没有这些数据的机器上需要先恢复本地数据。文档检查允许缺少已明确加入 `.gitignore` 的原始证据，但仍检查源码、报告和未声明忽略的链接。

提交前检查暂存内容：

```bash
python3 meituan/code_archive.py check-source --staged
```

检查当前分支的完整可达历史：

```bash
python3 meituan/code_archive.py check-source --history
```

检查已登记到 pre-commit 配置。`make archive-pack` 还会检查当前提交和完整可达历史，即使使用 `git add -f` 或先提交大文件再删除，也不能将其打进源码包。检查失败后应将原始数据从待提交内容中移出，或修正尚未交付的相关提交；提高分卷大小不能减少包的总量。

## 发布清理后的分支

本次只准备本地历史，不自动推送。旧历史、未提交修改及新旧提交映射保存在仓库同级的 `MirrorOPD-history-backup-20261027-154703/`。映射表不作为 Git replacement ref 安装，避免旧历史继续留在活动引用中。

由同步负责人从已清理的本机 checkout 发布 `main`。以下命令只允许覆盖事先记录的远端版本；若远端已继续前进，命令会拒绝，应先核对新增提交，不能改成无条件强推：

```bash
source /mnt/tidalfs-bdsz01/dataset/llm_dataset/zkn_data/fht_data/.ssh/activate.bash
git push --force-with-lease=refs/heads/main:e5d64a70a333232ca97139798ff5a297ffa18c4a \
  git@github.com:WncFht/MirrorOPD-verl.git main:main
```

本机临时给 `origin` 增加了排除 `main` 的 fetch 规则，防止编辑器自动 fetch 将尚未清理的远端历史拉回。只在上面的发布成功后，移除该规则并恢复远端跟踪；它不影响推送，也不影响新克隆的仓库：

```bash
git config --unset-all remote.origin.fetch '^\^refs/heads/main$'
git fetch origin
```

首次发布前不要把旧远端 `main` 合并回新分支；这会重新引入已清理的提交。旧研究记录中的 commit ID 表示运行当时的代码版本，保留其历史含义，可在备份映射中查找对应的新提交。

## Mac 与开发机迁移

Mac 保留旧 checkout，在新目录克隆已经发布的分支，再恢复本地 Hope 配置、资产路径及所需原始研究数据：

```bash
git clone --branch main git@github.com:WncFht/MirrorOPD-verl.git MirrorOPD-verl-clean
```

未提交源码修改从旧目录逐项迁入并检查，不合并旧分支。旧目录先保留，便于恢复本地配置与数据。

开发机继续人工上传、下载。发送端从清理后的 checkout 生成全量包，并使用新的接收端名称：

```bash
make archive-pack FULL=1 TARGET=dev-clean-20261027
```

上传生成的全部分卷和 `transfer_snap/archive_bootstrap.py`。接收端导入一个新的目标目录，保留原有 Git checkout：

```bash
python3 /上传目录/archive_bootstrap.py unpack \
  /上传目录/生成的.bundle.part.000 \
  /目标父目录/MirrorOPD-verl-clean
```

若未生成分卷，传入实际 `.bundle` 文件。接收成功后在发送端确认：

```bash
make archive-ack TARGET=dev-clean-20261027
```

以后继续使用该 `TARGET` 做增量同步。不要复制旧 checkout 中的 `refs/archive/peers/*`；这些引用仍表示旧提交号。旧的 19 分卷包也不再用于清理后历史的同步。
