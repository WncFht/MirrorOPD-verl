# 维护检查与执行边界

使用项目现有 Make：`docs-format` 显式整理维护正文；`docs-check` 依次验证规范格式、Markdown、链接与锚点、源码符号、技能和 Notes。任一失败返回非零，后续检查可继续提供诊断，不把失败标成成功。

`maintenance-check` 在文档检查通过后运行维护工具行为测试。不自动安装依赖、刷新实验、启动 GPU、下载模型或运行队列。依赖安装仅由明确的 `docs-setup` 入口执行。

提交前检查导出 Git index 到临时目录，保留真实暂存内容；不 stash、不格式化、不改 index。格式整理在提交前单独执行，避免部分暂存时隐藏与恢复冲突。未暂存修复不能掩盖 index 内的错误。

仓外证据限于明确声明的相邻日志、理论、模型与运行证据目录；存在时核对路径，未提供时统计为不可核验引用。缺少源码、当前文档、图片或锚点仍阻断。格式与结构通过不证明科学结论或产品行为正确。

Notes 默认只维护必要决定，空树合法，不创建空封存清单。已封存记录检查内容摘要，提交检查再对照本地 HEAD 的旧清单。远端合并保护是否启用由托管平台决定，不能以配置文件存在代替实际验证。

检查详情和维护入口见[维护流程](../../docs/infra/maintenance/README.md)。
