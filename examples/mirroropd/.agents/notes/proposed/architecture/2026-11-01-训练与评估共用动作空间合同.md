# Agent Note: 训练与评估共用动作空间合同

Status: proposed

选择：提取纯数据的模型配对合同与分布定义，编译为现有 head 路径的索引、归一化和动作分组计划。训练继续由 LossContext 处理梯度与全局分母，只读评分继续使用 value-only 路径；V1、RolloutService、SharedTeacherScorer 和 TQ 保持执行所有权。接口、数值反例及迁移顺序由[架构方案](../../../../docs/infra/architecture/evaluation/动作空间与模型兼容.md)维护。

## 理由与代价

当前源码已经区分 raw head RKL、EOS 合并训练目标和 teacher 额外支持修正。扩大模型白名单或在调用点裁到 min(Vs,Vt) 会把数学对象的改变藏在兼容修补中。共享语义编译能让训练和验证选择同一概率空间，同时保留历史 raw 诊断。

真实备选是继续维护各入口的 slice／EOS 规则，或重建通用训练／评估框架。前者短期改动小，但每个新模型都增加语义分叉；后者引入新的调度与状态所有者，重复已经验收的执行层。推荐的代价是一次显式的结果字段与身份版本迁移，以及每种支持模式的数值验收。

## 不变量与验收

- 已批准的 R1 共同支持 C151936 指共同输出行，不能自动改成 151665 个有效 token ID。条件 RKL 同时报告双方排除质量。
- EOS 合并前后、MDPO 目标构造次序及输入／输出 ID 映射显式声明。分组与条件化的首版组合要求完整保留动作类。
- 原生 identity 快路径维持旧 value/VJP、位置对应和全局分母；只读评分不计算 VJP。新增映射保留 root/head FSDP hooks。
- Bootstrap 与 current 的引擎支持规则一致，并在产物身份中记录。旧未屏蔽生成回答单列保存，不改写为新协议。
- 新 Llama adapter 需真实权重、FSDP 更新与导出回读；真正不同分词边界另立序列层协议。

CPU/FP64 反例已验证额外支持、排除梯度、EOS 分解和 ID 置换。生成一致性修补已通过 CPU 测试，四卡验收进行中；通用语义合同和条件训练尚未实施，因此本记录保持 proposed。

本提案补充[统一验证的任务计划与产物边界](2026-10-31-统一验证的任务计划与产物边界.md)，不替代其中的 Parquet、调度与最终 checkpoint 决定。只有实际新模型需要时才增加 bias、softcap 或跨分词能力，不预先引入通用 GPU 服务和长期 logit 缓存。
