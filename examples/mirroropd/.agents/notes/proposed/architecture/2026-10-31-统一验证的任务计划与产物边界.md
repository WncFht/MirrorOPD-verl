# Agent Note: 统一验证的任务计划与产物边界

Status: proposed

选择：在原生 verl 外层增加一个小型评估协调层，使用不可变任务计划和持久轨迹身份，复用既有生成生命周期、FSDP 评分、指标与 checkpoint。避免按 bench／bank／history 分别写 pipeline，也不引入通用工作流服务。

科学预算和用户已确定的串行路线由[四域协议](../../../../docs/experiments/teacher-transfer/protocols/online-four-domain.md)维护。当前代码事实与测试缺口见[代码走读](../../../../docs/archive/engineering/evaluation/2026-11-01-分阶段代码走读与验收.md)；接口草案与运行合同分别见[配置与调度](../../../../docs/archive/engineering/evaluation/2026-10-31-配置与调度草案.md)、[执行存储与可观测性](../../../../docs/archive/engineering/evaluation/2026-11-01-执行与存储设计依据.md)。本记录保留选择理由、真实替代方案和重新讨论条件，方案尚未全部实现。Parquet 基础存储、history 引用、RKL 聚合和 source/history 独立频率已接入原生回调，CPU 与四卡两轮 GPU 基础验收通过；完整协调器、公共评估和最终导出已通过短程集成验收，完整 50 outer 科研运行仍待完成。后续模型扩展的语义边界由[动作空间合同实现记录](../../implemented/architecture/2026-11-01-训练与评估共用动作空间合同.md)单独维护；它补充本文，不替代评估调度与持久化决定。

## 3. 已确认选择与剩余探索

用户已确认下表 S01–S04 及 LR1e-6／reuse32。抽样方案先实验再冻结；资源数值仍需实测。设计记录仍为 proposed，表示代码尚未全部实现，不表示这些用户选择仍待确认。

| 决策                | 方案                                                    | 当前推荐                                                                                                            |
| ------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| S01 Accuracy 题量   | A 面板；B 初末全集；C 所有节点全集                      | **用户已选 C**。0/25/50 均为 1648 题、6703 条回答；bank RKL 单独抽样，去污染保护全集                                |
| S02 训练 loss 平均  | A 有效 token 均值；B 题内均值后按题；C 固定 cap 分母    | **用户已选 A**，沿用现有 token-mean 和分布式 sum/count                                                              |
| S03 RKL 报告平均    | A 按 token；B 题内 token 均值后按题；C 固定 cap         | **用户已选 B**。history 外层 batch 等权，公共外层 domain 等权；保存每题 sum/count                                   |
| S04 checkpoint 保留 | A 最终 model-only；B 滚动恢复点；C 多个模型节点         | **用户已选 A**，不存 optimizer；对应 D14–D16，不再要求可靠中途续训                                                  |
| S05 资源数值        | A 沿旧默认；B 按 32K 与各模型校准；C 运行中自由调 n/cap | **B**。调资源不改变 n/cap；参考配置不是已测最佳值。正式矩阵使用记录完备的 profile，结果驱动的预算变化不属于性能调参 |

已采用的协议主线是串行共享池、常规 n、训练/source7K、公共 32K、每域 128 条 RKL bank、batch128／reuse32／50outer、固定 bank 与 current 分开报告。当前评估频率按已讨论的 source/history 每 outer、公共 bank 早期点加每 5outer、bench0/25/50 编排；实机成本验证可在开跑正式矩阵前形成修订方案，不能在同一 run 中按成绩选择读出点。

## 4. 验收与决策重开

实施前必须完成旧默认路径的回归缺口、typed config dry-run、银行完整性和版本校验。实施后验证同一输入换窗口／chunk／资源 profile 的误差、同一边界任务不重复、最终模型导出故障注入和真实四卡 32K 执行。预备／生成／验证的 cold setup 与 warm 窗口分开计时。

本提案不宣称全局最优：它在现有四卡、RKL 优先和少 checkpoint 约束下，优先选择较少所有者、明确数据身份与可复用模块。只有新增实际需求或实测瓶颈，才重新考虑后台评估集群、通用 DAG、跨卡恢复、长期 logit 缓存、对象存储或多教师同次评分；相关支持需新增能力检查与验收，不能仅靠配置字符串启用。
