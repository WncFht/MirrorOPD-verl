# 评测预算语义、KL 精度与相对位置十分桶

更新：2026-10-24。进一步的误差模型推导、真实初始权重 probe 与接口重构见[后续走读](../../theory/numerical-effects/2026-10-24-KL精度误差模型与诊断接口走读.md)。本文核对当前评测实现，记录与 E16/E17 后期 KL 量级对应的合成数值实验，并说明已接入的 Full-KL 相对位置统计。实际 E16/E17 记录仍见[后期收敛分析](../../experiments/reuse-budget/reuse-comparison/2026-10-24-E16E17位置指标与后期收敛.md)。

## 1. Prefix mean 与随机子集预算指标

对一道题，生成 $N$ 个回答，正确性为 $x_1,\ldots,x_N\in\{0,1\}$，正确数为 $c$。跨题时先对每题计算指标，再等权平均。

### 1.1 当前 pass@k 正确地使用全部 N 个回答

在 $N$ 个回答中均匀、无放回抽取大小为 $k$ 的子集，至少有一个正确回答的概率为：

$$
\widehat{\mathrm{pass@}k}=1-\frac{\binom{N-c}{k}}{\binom Nk}.
$$

若 $N-c<k$，结果为 1。当前 [pass_at_k](../../../../../verl/utils/metric/evaluation.py) 直接计算该公式，不实际随机抽若干子集来近似。等价的精确公式使用所有已生成回答，通常比额外 Monte Carlo 抽样更合适。已有测试枚举所有小规模子集，核对公式。

### 1.2 随机子集的平均正确率不随 k 改变

若 $S$ 是均匀大小为 $k$ 的无放回子集，则每个回答被选中的概率为 $k/N$：

$$
\begin{aligned}
\mathbb E_S\left[\frac1k\sum_{i\in S}x_i\right]
&=\frac1k\sum_{i=1}^N x_i\,\Pr(i\in S)\\
&=\frac1k\sum_{i=1}^N x_i\frac{k}{N}
=\frac cN.
\end{aligned}
$$

因此，若 mean@N 表示正确率，那么随机子集 mean@k 的期望就是 mean@N，不应乘 $k/N$。期望**正确个数**才是 $k(c/N)$；如果原始量是总正确数 $c$，则写成 $c\,k/N$。

随机子集均值虽然期望相同，其波动随 k 改变。在 $N>1$、$p=c/N$ 时，有限总体子集均值的方差为：

$$
\operatorname{Var}_S(\overline x_S)=\frac{N-k}{k(N-1)}p(1-p).
$$

所以研究采样预算时，可以看均值估计的方差或区间宽度，但不需要把同一个期望重复画成多条不同 k 的收益曲线。

### 1.3 prefix_mean@k 是固定前 k 个回答的均值

当前实现按固定 sample index 排序，计算 $k^{-1}\sum_{i=1}^k x_i$，再跨题平均。它不是均匀随机子集期望，作用是展示固定样本序列上估计随样本数变化的波动。如果生成是可交换的独立同分布采样，它对真实单次成功率的期望也相同；一次具体采样中，前 k 个与全部 N 个的均值可以不同。

例如 $N=16,c=8,k=4$：

| 量                            |                                                    数值 |
| ----------------------------- | ------------------------------------------------------: |
| 全部回答平均正确率            |                                                     50% |
| 随机 4 个回答的平均正确率期望 |                                                     50% |
| 随机 4 个回答的正确个数期望   |                                                       2 |
| pass@4                        |                               $1-70/1820\approx96.15\%$ |
| prefix_mean@4                 | 由前 4 个回答实际结果决定，可为 0%、25%、50%、75%、100% |

当前算法符合字段定义，没有把 prefix_mean 当作标准 pass@k。该字段对比较模型主效果的价值有限；主比较使用 acc/mean、pass@k，以及需要投票时的 majority@k。现有评测字段保持原定义，没有为了简化面板改变历史含义。

## 2. 当前 Token KL 的量级

E16 末期每 token KL 约 $1.5\times10^{-3}$；E17 同批末次更新前约 $4.1\times10^{-4}$ nats。以二分类、教师概率 $p=(0.5,0.5)$ 为直观示例，学生为 $q=(0.5+\delta,0.5-\delta)$。在小偏差下：

$$
D_{\mathrm{KL}}(q\Vert p)\approx2\delta^2.
$$

KL=0.0004 对应 $\delta\approx0.0141$，即 51.41% 与 48.59% 对 50% 与 50%；KL=0.0015 对应约 52.74% 与 47.26%。这只是直觉示例，不代表真实词表里每个词元都差 1.4 或 2.7 个百分点。少量尾部候选可能仍有很大的相对误差，平均 KL 不能描述误差集中在哪些位置。

该量级很小但并不等于所有更新都已无效。E17 后期同一批的最后相邻观测仍平均下降约 2.5%，约为 $10^{-5}$ nats/token 的变化量。全批均值也可能掩盖某些已经接近数值误差的小 KL 位置。

## 3. FP32/BF16 的作用分别在哪里

### 3.1 E16/E17 的实际配置与当前执行路径

| 环节                       | 配置／源码语义                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------- |
| Student 常驻训练参数       | `model_dtype=fp32`，FSDP2，AdamW                                                   |
| Transformer 前向及计算参数 | 默认 mixed precision 使用 BF16                                                     |
| Teacher 权重／hidden       | BF16                                                                               |
| Full-KL 输出头投影         | BF16 hidden/head 输入，但 CUDA `torch.mm(..., out_dtype=float32)` 输出 FP32 logits |
| log-softmax、概率、KL 求和 | FP32；未将完整 KL 运算放在 BF16 中                                                 |
| 自定义 head VJP            | `dz` 转回 hidden dtype；梯度矩阵乘积累加器为 FP32，返回梯度转换回对应输入 dtype    |
| FSDP 梯度归约              | FP32 reduce dtype；优化器更新原始 FP32 参数                                        |

依据为运行快照 config、[full_vocab.py](../../../../../verl/trainer/distillation/full_vocab.py) 的 `project/PrecomputedKL` 和 [FSDP engine](../../../../../verl/workers/engine/fsdp/transformer_impl.py)。FSDP 的计算参数 dtype 与优化器使用的原参数 dtype 是不同概念，官方文档也明确区分。[^fsdp]

因此不能把 BF16 在 1 附近的间隔 0.0078125，当成 KL 的绝对下限。浮点间隔随量级变化；在 0.0004 附近，FP32 的相邻数间隔约 $2.91\times10^{-11}$，BF16 约 $1.91\times10^{-6}$。但最终 loss 标量的表示间隔也不是整个计算误差界，log-softmax、相减、求和和模型前向都会引入误差。

同样，LR=1e-6 不意味着更新必然被 BF16 参数舍入吞掉：这里优化器更新 FP32 原参数，微小更新可以累积，再在前向时转换。BF16 前向仍会产生量化效应，返回梯度也包含低精度舍入，不能据此宣称它完全无影响。

### 3.2 已执行的合成数值实验

在空闲 GPU0 上构造 8 个位置、词表 151936 的有峰值分布，教师平均熵约 0.561 nats。调节 logits 扰动，使 FP64 条件 KL 均值达到指定量级，再在**同一份 logits**上比较不同 dtype。没有加载真实末期 checkpoint；这些是数值实验，不是模型的精度消融。

| FP64 参照均值 | FP32 logits＋FP32 KL 均值 | 8 个位置的最大绝对误差 |
| ------------: | ------------------------: | ---------------------: |
|   0.001500000 |               0.001499916 |    $2.46\times10^{-7}$ |
|   0.000400000 |               0.000400038 |    $1.65\times10^{-7}$ |
|   0.000010000 |               0.000009962 |    $1.75\times10^{-7}$ |
|   0.000001000 |               0.000000996 |    $3.24\times10^{-7}$ |

在约 $10^{-6}$ 的平均量级，已经有个别位置算出小负 KL；$10^{-7}$ 时误差占比更大。这不是普适精度阈值，只是这组输入下，FP32 相减与求和误差开始显著的观察。不能通过把负数 clamp 到零就声称精度问题消失。

在 0.0004 参照下，若先将 logits 舍入为 BF16 再转回 FP32 计算，均值变成 0.000393696；如果连 log-softmax／KL 都用 BF16，结果为 0.000834227，偏差明显。给两份 logits 同时加 16 不会改变理想 softmax，但 BF16 舍入后的误差会变化，进一步说明误差依赖中间量尺度，而非固定的 KL 下限。**当前 precompute 路径避免了直接把投影输出及 KL 计算放在 BF16 的做法。**

另做一次 BF16 hidden/head 输入、FP32 输出的真实 `project()` 小规模验证，以同一份已经量化的输入做 FP64 GEMM 作为参照：KL 均值为 0.000443445，当前路径为 0.000443549，最大逐位置绝对误差约 $6.18\times10^{-7}$。它隔离了给定 BF16 输入后的投影／KL 算术误差，没有评估整个 Transformer 前向量化的影响。

### 3.3 现在能下的判断

当前 $4\times10^{-4}$ 到 $1.5\times10^{-3}$ 的平均 KL **没有证据表明已被 FP32 KL 计算误差主导**；观测到的后期更新幅度也高于上述合成验证的计算误差。BF16 模型前向与梯度量化是否限制最终可达对齐，仍缺末期 checkpoint 及代表性长轨迹的匹配输入消融。

严格核验应分两步：固定相同 hidden/head，比较 FP32 与 FP64 的 head/KL；再固定 checkpoint 与输入，比较 BF16 和 FP32 Transformer 前向得到的分布、KL 及梯度。前者检查损失计算，后者检查模型量化误差。PyTorch 文档指出低精度 GEMM 的归约策略和算子后端也会影响数值；原 run 没有记录全部相关后端开关，不能补写为已确定值。[^numerical]

## 4. 已接入相对位置十分桶

对每条回答长度 $L$，response 内零基 token 位置为 $r$，使用词元中点 $u=(r+0.5)/L$，桶编号为 $\lfloor10u\rfloor$。Prompt 不参与；只统计原 loss mask 有效的 token，但 masked gap 不会被删掉后重新编号。完整 sequence mask 也按 responses 的实际起点映射。

每次 Full-KL 更新输出 10 组、每组 3 个字段：

```text
distill/full_kl_position/p00_10/sum
distill/full_kl_position/p00_10/token_count
distill/full_kl_position/p00_10/mean
...
distill/full_kl_position/p90_100/sum
distill/full_kl_position/p90_100/token_count
distill/full_kl_position/p90_100/mean
```

这里 `p00_10` 表示相对位置 0–10%，不表示 KL 数值的百分位。主轴为 `step/update`，已有 outer 与 epoch_index 可用于区分新批首轮与多次复用。十分桶采用每条实际回答的长度，截断回答的最后一桶仍表示已生成部分的末段。

设前 3 桶分别有 KL 总和 $S_1,S_2,S_3$，有效 token 数 $N_1,N_2,N_3$，前 30% 的平均值为：

$$
\overline K_{0:30\%}=\frac{S_1+S_2+S_3}{N_1+N_2+N_3}
=\frac{N_1\overline K_1+N_2\overline K_2+N_3\overline K_3}{N_1+N_2+N_3}.
$$

只有各桶 token 数完全相等时，才能直接平均 3 个 mean。短回答取整、loss mask 和跨样本长度差异都会使数量不同。跨 GPU、microbatch 先合并 sum/count 再算 mean；空桶保留 sum=0、count=0，mean 为未定义，日志出口按已有规则转为缺失值。

新增统计复用已有 KL 行向量，只额外保留 O(有效 token 数) 的 detached 标量和 10 个桶的摘要，不增加词表级 logits 缓存，也不增加 teacher/student forward。优化目标及梯度保持原样。支持 dense、recompute、streaming、cached、precompute、precompute_fused；Liger 只提供聚合 loss，因此保持原功能且不输出这组位置指标。当前接入针对 Full-KL；sampled PG 的 surrogate loss 不被冒称为完整 KL。
