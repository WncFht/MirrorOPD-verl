# 公共训练参数与默认配方

本页维护公共参数含义与领域默认配方。编号方法和启动步骤见[实验入口](../infra/training/launch.md)；各研究的科学设置由所属报告维护。部署命令和通用环境见[运行与架构](../infra/training/runtime.md)。下文最短入口均假设已显式设置获分配的 `CUDA_VISIBLE_DEVICES`、资源池与原生环境，并从仓库根目录执行。Hope 统一通过 `make opd-submit` 提交。

## 单教师数学 full-data 配方

统一入口的 `custom --method sampled`默认使用 V1 同步 trainer、FSDP2 student 和共池冻结 FSDP2 teacher。数学设置参考 One-Shot-OPD 当前可执行配方：DeepSeek-R1-Distill-Qwen-1.5B student、JustRL-DeepSeek-1.5B teacher、完整 DAPO 数据、sampled-token `k1 + PG`、batch 与 mini-batch 均为 64、每批一次更新、AdamW 学习率 1e-6。该默认路径在 loss 中构造 current-policy advantage，未启用 frozen 信号；current/frozen 对照由[优势与 IS 消融入口](../archive/engineering/2026-10-21-优势与更新计数原方案.md)提供。默认配方不能称为原研究实现的完整等价复现。

默认资源与长度：

| 项目                                        | 默认值                                                                      |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| 共享资源池                                  | 8 张 GPU；rollout、teacher 评分、actor 更新分阶段使用                       |
| Student rollout                             | TP=1，共 8 个推理副本，验证复用                                             |
| Student 执行模式                            | 默认编译＋CUDA Graph；`ROLLOUT_ENFORCE_EAGER=True` 可回退 eager             |
| Teacher                                     | FSDP2 DP8，无 optimizer，整批评分后卸载到 CPU                               |
| Prompt / 训练 response                      | 4096 / 7168 token                                                           |
| 验证 response                               | 31744 token                                                                 |
| Student 最大 context / teacher forward 预算 | 35841 / 每卡 32768 token；teacher 预算必须容纳完整训练序列                  |
| 验证集                                      | MATH-500、AMC23、AIME24、AIME25、AIME26；合计 630 题                        |
| 验证采样                                    | 每题 16 次，temperature=0.7、top-p=0.9                                      |
| 验证提交窗口 / 推理并发                     | 数学全量提交（`VAL_BATCH_SIZE=null`）；每个 student 推理副本最多 128 条序列 |
| 推理显存比例 / 调度 token 预算              | 数学 0.65 / 8192；均为每引擎配置                                            |
| Actor 动态 micro-token 预算                 | 每卡 32768，按完整 prompt＋response 拆分并累积梯度                          |
| 采样概率输出                                | 训练保留；验证省略未用于评分的概率输出                                      |
| 训练预算                                    | 1 epoch；全量 17917 条数据未过滤时约 279 steps                              |
| 验证 / 保存间隔                             | 20 / 50 global steps，并在最后一步触发                                      |

默认训练 1 epoch。当前 17917 条 DAPO 的 prompt 均未超过 4096，过滤后仍是 17917 条；V1 trainer 按 `floor(17917 / 64) = 279` 计算步数，最后不足一个 batch 的 61 条不参与这个 epoch。每步全局采样 64 道题，每题生成 1 条回答；`ppo_mini_batch_size=64`、`ppo_epochs=1`，每步做一次全局参数更新。64 是整个 student 资源池的 batch；8 个 student 训练 rank 平均各处理 8 条，内部动态 token batching 与梯度累积按实际序列长度安排。

验证发生在 step 20、40、……、260 和最终 step 279，共 14 次；`val_before_train=False`，训练前不额外验证。每次完整覆盖 MATH-500 的 500 题、AMC23 的 40 题、AIME24/25/26 各 30 题，合计 630 题，每题采样 16 次，共生成约 1.01 万条回答。`VAL_BATCH_SIZE=null`默认一次提交全部 630 道题。正整数值可恢复窗口提交；实际同时运行的请求数受每个推理副本`max_num_seqs=128`约束，八卡合计上限 1024。提交窗口与引擎活跃并发是不同参数。每条验证回答最多 31744 token。checkpoint 保存于 step 50、100、150、200、250、279。

Student Graph 的 capture sizes 根据 `ROLLOUT_MAX_NUM_SEQS` 派生为 2 的幂并包含最后的并发上限；数学默认是 `[1,2,4,8,16,32,64,128]`。仍可通过末尾 Hydra 参数覆盖现有 `actor_rollout_ref.rollout.cudagraph_capture_sizes` 字段。训练 batch64 和更新预算保持不变；早期测量使用 eager、验证窗口 16，复算时以对应运行的冻结配置为准。

默认值的本机验证依据见[完整验证实测](../infra/performance/2026-10-22-训练与验证性能实测.md#1-完整验证与参数对照)；batch128/256 的学习配置边界与验证窗口建议见[批量与 rollout 调优](../infra/performance/2026-10-22-批量大小与GPU利用率调优.md)。全量验证已完成 H800 四卡初始 checkpoint 测量；新默认在目标八卡上的完整训练/验证周期仍须独立验收。

共享/独立池的角色、卸载要求与覆盖参数见[运行与架构](../infra/training/runtime.md#共享与独立池配置)。选择部署方式时保持本页的学习与评测预算不变。

脚本将常用环境变量集中在前半部分，按模型与数据、GPU、训练与验证预算分组；原生 Hydra 参数按 data、actor、rollout、validation、distillation、algorithm、trainer 分成数组，最后统一组装。通常改顶部默认值或使用环境变量即可；新增原生配置放入对应数组。

模型默认从仓库相邻的 `model/` 读取，数据默认从相邻 `data/` 读取；可用 `MODEL_ROOT`、`DATA_ROOT` 或各文件变量覆盖。目录、准备与检查入口见[资产准备](../infra/training/资产准备.md)。数据文件分别是 `math/DAPO/train.parquet`、`math/MATH-500/test.parquet`、`math/AMC23/test.parquet`、`math/AIME24/test.parquet`、`math/AIME25/test.parquet` 和 `math/AIME26/test.parquet`。

从仓库根目录、在已分配的 GPU 与原生环境中运行数学入口：

```bash
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh custom --method sampled
```

GPU 分配、shared/standalone 切换、配置预览见[启动与配置](../infra/training/runtime.md#启动与配置)；Python、运行目录、日志、恢复与人工部署约定见[通用运行合同](../infra/training/runtime.md#通用运行合同)。

### Actor 执行配置

以下是公共数学配方继承的执行默认，学习预算与计算拆分分别维护。参数作用及候选测试见[调优文档](../infra/performance/2026-10-22-批量大小与GPU利用率调优.md#73-actor-重算micro-与梯度同步联合筛选)。

| 调优项                                                    | 公共数学配方的解析值 | 实现与边界                                                                                                                          |
| --------------------------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `GRADIENT_CHECKPOINTING`                                  | True                 | 调用 HF `gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})`；没有逐算子 selective-AC 的配方入口 |
| `PPO_MAX_TOKEN_LEN_PER_GPU`                               | 32768                | Actor 动态 micro token 预算；与训练 global mini64 分开                                                                              |
| `actor.fsdp_config.fsdp_size`                             | -1                   | 默认使用整个 actor world size 分片                                                                                                  |
| `actor.fsdp_config.use_no_sync_for_gradient_accumulation` | False                | 实现允许只在最后一个 micro-batch 同步梯度；当前配方关闭                                                                             |

## 独立验证长度

新增 `actor_rollout_ref.rollout.val_kwargs.max_tokens`，默认 `null`，保留原有训练/验证共用 response budget 的行为。非空时，验证请求和最终 response、mask、log-prob、router replay 输出使用同一预算；V1 的 TQ 保存未 padding 的实际输出，旧 DataProto 路径按验证预算 padding。

当前支持 vLLM/SGLang 的 `single_turn_agent`；本配方使用 vLLM。配置或数据行选择其他 agent 时会拒绝独立验证预算，避免多轮 agent 静默沿用训练上限；会覆盖请求长度的其他后端也会被配置检查拒绝。应显式配置足以容纳 prompt 与验证预算的 `rollout.max_model_len`；底层服务仍受模型 context 和显存约束。该设置不改变 teacher 的训练评分长度。

ResOPD 的公开版本 `3bdf019d` 只设置一个 `MAX_RESPONSE_LENGTH`，没有这条独立验证长度配置；本配方不依赖它的启动脚本。[^resopd]

## 推理执行配置

本表统一维护领域默认与可选 profile。参数均由公共脚本按领域派生；实际任务以合成配置为准。四卡/八卡只改变副本数量，不按卡数放大单引擎参数。

| Profile                            | `VAL_BATCH_SIZE` | `ROLLOUT_MAX_NUM_SEQS` | `ROLLOUT_GPU_MEMORY_UTILIZATION` | `ROLLOUT_TOKEN_BUDGET` |
| ---------------------------------- | ---------------- | ---------------------: | -------------------------------: | ---------------------: |
| R1-Distill-Qwen-1.5B 数学默认      | `null`，全量提交 |                    128 |                             0.65 |                   8192 |
| Qwen3-1.7B 模型预设（E31/E32/E42） | `null`           |                     64 |                             0.65 |                   8192 |
| Qwen3-1.7B 的 E43 预设             | `null`           |                     64 |                             0.80 |                   8192 |
| Qwen3-1.7B-Base 模型预设           | `null`           |                     64 |                             0.80 |                   8192 |
| 数学低显存覆盖                     | `null`           |                     96 |                              0.5 |                   8192 |
| 旧数学执行配置，显式覆盖           | 128              |                     64 |                              0.5 |                   8192 |
| Coding/IF 引擎默认                 | 32               |                     32 |                              0.5 |                   8192 |

数学 profile 保持同一题目集合、每题采样数和回答上限；修改这些评测预算另算实验因素。IF 默认关闭训练期间验证，其引擎默认值不表示会执行验证。并发和显存覆盖命令见[运行方式](../infra/training/runtime.md#验证执行配置与四卡八卡启动)，测量依据见[完整验证对照](../infra/performance/2026-10-22-训练与验证性能实测.md#1-完整验证与参数对照)。

Qwen3-1.7B 的通用设置适用于 E31/E32/E42，E43单独采用64/0.80；Base 的设置适用于 E27/E28/E29/E30/E38/E39/E40/E41/E54，并用于各自的 `-valid-student`。Base 的训练生成与训练中验证共用每卡并发 64、显存比例 0.80 的引擎；当前长程实验的[完整验证资源实测](../infra/performance/inference/validation-resources.md#observed)记录了显存、GPU 利用率和收尾等待。教师独立验证采用单独的教师并发和显存默认，Base 的 0.80 不传给 `-valid-teacher`。环境变量可覆盖模型默认，末尾 Hydra 参数具有最高优先级。这里登记启动配置，配置值不等于已经确认的最优参数；性能复核状态及各模型实测依据见[推理性能与参数选择](../infra/performance/2026-10-27-学生模型推理性能与参数选择.md)。

表外的更高并发与显存组合属于[容量扩展候选](../infra/performance/2026-10-22-批量大小与GPU利用率调优.md#已验证配置与后续扩展)，不自动作为默认 profile。

E41 与 E43 的当前执行预算统一为 100 outer、reuse16、训练 response cap 7168、每 10 outer 验证、每 50 outer 保存；E41 关闭初始验证，E43 开启初始验证。两组均采用每卡并发 64、显存比例 0.80。E41 保留终止动作对齐；E43 采用原生终止协议。E43 的 7168 只覆盖该预设，E31/E32/E42 仍使用 4096。模型、协议和运行记录见[E41 独立分析](../experiments/teacher-transfer/failure-reproduction.md#qwen4)与[E43 独立分析](../experiments/teacher-transfer/failure-reproduction.md#e43)。E41 图中的初始点复用 E39 已测的共享 Base 评测，来源与冻结验证配置核对见 E41 正文；训练内初始验证的关闭设置保持原样。

## OPD／MDPO 训练精度对照

E50/E51 是 E44/E45 的 FP16 对照；E52/E53 是 BF16 GEMM＋FP32 中间表示对照。四组保留 256 outer、reuse16、save128 和 VAL_N=16。`--precision bf16|fp16|bf16_fp32|fp32` 可在同一公开入口选择 actor/anchor 执行策略；fp32 是较慢的 packed math attention 参考。Teacher 与 rollout 精度保持独立，详细语义、命令及验收范围见[共享训练精度](../infra/numerics/precision/2026-10-27-共享训练精度与实验入口.md)。

## E54:30B MoE 教师

E54 使用 Qwen3-1.7B-Base ← Qwen3-30B-A3B-Instruct-2507，沿用 E41 的 Full-r16、100 outer、训练 response cap 7,168、每 10 outer 验证、每 50 outer 保存，无初始验证。Student 推理采用每卡 64 / 0.80；teacher 在共享八卡上以 FSDP2 评分。后续运行默认增加 AIME24、AIME26，完整设置见[教师对照实验](../experiments/teacher-transfer/failure-reproduction.md#qwen4)，数据和历史可比范围见[数学验证协议](验证设置.md)。
