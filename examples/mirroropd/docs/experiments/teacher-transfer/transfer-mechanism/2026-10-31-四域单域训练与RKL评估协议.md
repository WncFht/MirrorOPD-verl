# 四域单域训练与 RKL 评估协议

执行决定：后续训练与 RKL 验证均采用共享 GPU 池分阶段串行执行。允许当前 outer 内复用 teacher hidden，禁止预计算并长期缓存全题池；loss 平均方式仍待调研，分布指标维持 RKL-only。

状态：2026-10-31，训练主循环与来源留出／历史 RKL 已接入原生 verl，JustRL → R1-1.5B 已通过四卡、两轮 64 次更新验收；完整四域协议尚未全部落地。本文是后续四域实验设置的唯一主入口；题目清单、优化器配置及执行验收的待定项见第 9 节。既有实验仍按[固定状态 0–320 展示协议](protocol.md)解释，不把本协议写回历史结果。

本阶段的分布指标只采用反向 KL（RKL）。FKL、TV、JS 及分布熵不进入本轮指标输出；accuracy、代码测试通过率、IF 约束通过率作为低频辅助读出的建议见第 9 节，频率待确认。公共 benchmark 在本轮首先是外部题目分布，保存其答案和评分元数据供后续使用。耗时、有效 token、梯度范数等执行记录仍保留。

## 1. 研究问题与分支关系

研究固定 teacher 能否被规定初始化的 student 拟合，以及训练来源改变后，同来源新题和其他领域上的残差如何变化。

同一 student／模式的各分支从完全相同的 initial student 权重开始，teacher 在整个分支内冻结。改变训练领域时固定师生对和公共评估题；分别训练 Math、Code、Science、IF 四条分支，不把四域混为一个训练流，也不把四域顺序续训成一条链。后续更换 teacher 时另计分支。

Thinking 与 non-thinking 独立成线，分别生成轨迹。相同线内输入模板、token 含义、EOS 和支持集条件须验收；2507 专用模板等不兼容条件单列。本文不新增模型名单，也不把所有既有 teacher 自动加入四域矩阵。

## 2. 训练数据与预算

| 项目                     | 已确认设置                                            |
| ------------------------ | ----------------------------------------------------- |
| Math                     | DAPO-Math-17K，本地清洗候选池                         |
| Code                     | agentica-org/DeepCoder-Preview-Dataset 的训练 configs |
| Science                  | MegaScience/TextbookReasoning，去除Math／CS           |
| IF                       | nvidia/Nemotron-Cascade-2-RL-data 的 IF-RL 子集       |
| 每 outer 新题            | 128 道，跨 outer 无放回                               |
| 每题训练回答             | 1 条                                                  |
| Outer 总数               | 50                                                    |
| Reuse                    | 同批 128 条回答完整复用 32 次                         |
| 每分支独立训练题         | 6,400 道                                              |
| 每分支 optimizer updates | 1,600 次                                              |
| 训练 response cap        | 7,168 token，包含 thinking 及最终回答                 |

每个 outer 开始，由该分支当时的 current student 生成 128 条回答；批内 32 次更新保持题目与回答前缀不变，每次更新重算当前 student 分布。它是按批刷新、批内复用的训练，不能称每次更新均严格 on-policy。

一次 optimizer update 覆盖全局 128 条回答。microbatch 与梯度累积用于实现该全局 batch；不能切成多个独立 optimizer step 后仍称相同 reuse 预算。四个训练域合计每师生对 4 分支、25,600 个训练题实例、6,400 次更新。

训练不按 teacher 准确率、初始 RKL 或训练效果挑题。全词表 teacher 分布是蒸馏信号；数据集原有答案或 CoT 不作为额外训练目标，也不放进 teacher 的特权输入。

### 3.1 当前训练来源留出

DAPO 分支只设 128 道 DAPO 来源留出；DeepCoder、TextbookReasoning 和 IF-RL 分支同理。它们均不参与该研究的梯度训练。不再设置每分支四域合计 2,048 题的来源留出，不另设锁定确认集。

同一训练来源、student 和模式的各 teacher 分支共享这 128 道题及 initial student 前缀。它们在训练开始前生成一次，后续只重新评分。当前不刷新留出上的 current student rollout，因此曲线表示固定状态上的同来源泛化。

### 3.2 公共 benchmark

| 领域    | 候选题库                                                   | 本轮固定题数 |
| ------- | ---------------------------------------------------------- | ------------ |
| Math    | 既有 MATH500、AMC23、AIME24/25/26 合计 630 题              | 128          |
| Code    | DeepCoder 配套 LCB v5 test279 题，2024-08-01 至 2025-02-01 | 128          |
| Science | GPQA-Diamond198 题                                         | 128          |
| IF      | IFEval541 题                                               | 128          |

四域题目对所有训练域保持一致。模型／模式不同可以有不同轨迹，但题目 ID 与输入协议身份必须记录。initial student 轨迹可在相同 student／模式的 teacher 分支间共享；teacher 轨迹在相同 teacher／模板／模式的训练域分支间共享。

两个轨迹银行合计 1,024 条回答。两者都计算同一方向的 RKL，即 student 对 teacher 的条件分布差距；teacher rollout 只改变前缀来源，不把指标改成 FKL。不同 teacher 的 teacher 轨迹银行不同，跨 teacher 主排序使用共享 initial student 前缀的结果。

公共验证 response cap 已确认为 32,768；训练与本来源留出仍为 7,168，history 保留真实训练轨迹。Accuracy 的常规 n 已确认：MATH500=1、AMC23=16、各年 AIME=16、LCB=10、GPQA=4、IFEval=1。Accuracy 题量仍与 RKL 每域 128 题分开决定，不能将 bank 每题 1 条等同于 accuracy n1。当前只按实际保留的整条回答计算 RKL，记录有效长度和 cap。前 7,168／完整 16,384 的双时域读出暂缓，优先区分题目集合与轨迹来源。各模型都遵守相同评估域／模式的 cap，不随模型训练在哪个领域而变化。当前不增加 IFBench、HumanEval+、MBPP+、MMLU-Pro 或 BBH。512 题是自定义子集，不冒充完整 benchmark 结果；具体题目尚未抽取。

公共银行由初始化 bench 评估产出：initial student 与 teacher 分别按各 benchmark 的 accuracy 采样协议生成回答，再对预先指定的每域 128 题保留固定 sample index（建议 0）的原始 token。Accuracy 使用其全部回答；RKL 不要求对所有 accuracy 样本评分。样本选择不看正确率、长度、RKL 或返回先后。对两个银行的初始 RKL 都使用 initial student→teacher；teacher 生成轨迹不意味着改成 teacher 与自己比较。后续固定银行评分与 current bench 生成各自调度。来源留出 128 题仍单独准备。论文依据、n／cap 候选和实现分工见[正确率与银行生成调研](../../../literature/teacher-transfer/2026-10-31-四域正确率评测与RKL银行生成协议调研.md)。

### 3.3 真实训练轨迹

保存每批全部 128 条实际进入训练的回答 token，不用同题的 initial student 回答替换。每次更新直接记录当前批 RKL loss，不新增 inner0／1／4／8／16／32 的额外评分。loss 是该次更新之前的读数；outer 结束的历史／留出读数对应 32 次更新全部完成后的权重。

## 4. 动态历史抽样

设已经完成 $m$ 个 batch，评估容量 $K=128$，定义：

$$
q_m=\left\lfloor\frac{128}{m}\right\rfloor,\qquad r_m=128-mq_m.
$$

$r_m$ 个 batch 各分配 $q_m+1$ 条，其余各分配 $q_m$ 条。只考虑本协议 $m\le50$，每批至少两条。

| 已训练 batch 数 | 配额                   |
| --------------- | ---------------------- |
| 1               | 128                    |
| 2               | 每批 64                |
| 3               | 两批 43，一批 42       |
| 10              | 八批 13，两批 12       |
| 25              | 三批 6，二十二批 5     |
| 50              | 二十八批 3，二十二批 2 |

每个 batch 和批内每个题目分别获得固定、独立的随机优先级，与 loss 和正确率无关；以稳定 ID 打破并列。batch 优先级最小的 $r_m$ 批获得额外一条，各批保留题目优先级最小的指定条数。相同训练题序的分支共享抽样优先级，实际回答 token 仍归各自分支。

旧批配额只会不变或减少：$q_m$ 不变时 $r_m$ 减少；$q_m$ 下降时，新配额最大值不超过旧配额最小值。因此从旧集合删减、从新批补入即可。退出评估集合不删除完整训练记录。

历史汇总保持 batch 等权。批内平均方式随第 5 节一起冻结；若采用逐题风险平均，形式为：

$$
\widehat R_m(\theta)=\frac1m\sum_{b=1}^{m}\frac1{n_b(m)}\sum_{i\in S_b(m)}R_\theta(x_{bi},y_{bi}^{\mathrm{train}}).
$$

所有完整训练 batch 同为 128 题，上式对应对完整历史题目等权平均。工程验收暂用批内 token-mean、再按 batch 等权，不能将两种口径混为一谈。无论最终采用哪种批内平均，都不能让抽 3 条的 batch 比抽 2 条的 batch 多占权重。

每轮集合变化，历史曲线同时受到参数更新、新批加入和成员替换影响，标记为“动态历史训练 RKL”。它不等价于固定测试集学习曲线；固定来源留出提供后者。相邻两轮都保留的轨迹可以单列配对变化，不拿前一轮不同集合的均值作为相对降幅分母。每批终点仅 2–3 条，不做精细的逐批难度排名。

## 5. 唯一分布指标：RKL

令 $p_\theta$ 为 student 条件分布，$q$ 为冻结 teacher 条件分布。对指定前缀 $s$：

$$
r_\theta(s)=\sum_v p_\theta(v\mid s)\log\frac{p_\theta(v\mid s)}{q(v\mid s)}.
$$

使用自然对数，单位为 nat；在共同、已验收的词表语义上计算 full-vocab RKL，不改成 sampled-token 估计或 top-k 近似。原有共同支持条件 RKL 的配对继续单列，输出支持范围与重新归一化定义；不把条件 RKL 与原生全支持 RKL 混入一个总榜。兼容性元数据属于验收记录，不是新增分布指标。

对实际保留的回答 $y_i$，首先保存不依赖平均方式的累计 RKL 和有效长度 $L_i$；生成受各集合已约定的 cap 限制：

$$
C_i=\sum_{t=1}^{L_i}r_\theta(x_i,y_{i,<t}).
$$

**训练 loss 与报告均值的归一化方式待定。** 有效 token 均值、逐回答 token 均值后按题平均、固定 $H$ 分母是不同候选，尚未选择其中一种。当前 verl full-RKL 采用有效 token 均值；不把固定 $128\times7,168$ 写成已确认目标，也不据此先改训练梯度。本文其他位置的 $R_i$ 泛指后续冻结的单题风险口径；比较时必须使用相同定义。

EOS 后的吸收状态贡献零，达到 cap 不补造 EOS；prompt 位置不计入回答 RKL。保存 RKL sum、有效 token、cap 和终止原因，使后续可以在相同原始读出上比较聚合方式。改变训练 loss 归一化仍会改变优化过程，不能靠事后换图等价替代。

固定面板报告初始绝对 RKL、终点绝对 RKL、绝对下降量和相对降幅：

$$
\mathrm{Reduction}=1-\frac{\overline R_{\mathrm{after}}}{\overline R_{\mathrm{initial}}}.
$$

初始风险为零时相对降幅不定义，接近零时以绝对量为主。公共面板先按每域 128 题平均，再按四域等权汇总；相对降幅由汇总后的初始／终点风险计算，不平均每题百分比。初始与终点使用同一前缀、同一时域及支持口径。

本阶段不计算 FKL、TV、JS 或熵，不为历史绘图兼容而在评分内部额外计算它们。teacher-rollout RKL 仍是固定 teacher 前缀上的条件风险，不据此命名为 teacher 到 student 的序列 KL。

## 6. 一轮执行顺序与保存内容

1. 读取第 $m$ 批 128 道新题，用该分支 current student 生成每题一条回答，cap7,168。
2. 保存完整 prompt／response token 及 mask、模型／模板／模式身份、seed、终止原因。
3. 同批回答复用 32 次，每次对当前参数计算 RKL 并更新；记录更新前 loss 及执行指标。
4. 更新 128 条历史评估集合，保存新配额及成员变化。
5. 若到相应评估点，在本轮完成后的权重上评分 128 条历史轨迹与 128 道来源留出，输出逐题 sum／count 及选定的集合汇总。
6. 若到公共评估点，用固定 initial student／teacher 银行评分公共 512 题的 RKL；低频 current student 生成与 accuracy 读出按第 11 节建议另行确认。

长期保存回答 token、题目与来源身份、抽样清单、模型配置、逐题 RKL 和训练日志。**禁止训练前预计算全题池 teacher hidden 并长期落盘；允许当前 outer／评估调用内临时缓存和复用。** 训练当前批 teacher 骨干算一次，hidden 在内存／TQ 保留供 reuse32 使用，完成后释放；未来训练批在真正生成后才准备 teacher 输出。TQ 存储后端及清理需保证不形成无界、跨 outer 的 latent 档案。

输出层按块重建完整词表分布，不保存整批 $[B,L,V]$ 概率。固定评估银行长期保留 token 即可；teacher hidden 在读出时准备，用完释放。逐 microbatch 工作张量及冻结 teacher 权重常驻都不属于全题池预缓存。

每题评分记录至少含 run、student／teacher revision、模式、输入模板、支持口径、outer／update、题目／轨迹 ID、来源域、状态来源、cap、有效 token、RKL sum、有效 token 及后续确定的归一化均值。历史样本另存原始 batch、配额、抽样优先级和成员变化。

检查点保存／续训策略仍待执行设计：本轮不承诺每 outer 导出模型或 Adam 状态；需要续训或容错时再明确必要保存点。逐题 token 与指标应足以重建评估输入，不能用它们冒充可恢复训练的完整状态。

## 8. 数据划分原则

先构造题族并隔离重复，再抽取训练与留出，所有研究分支使用共同保护清单。6,400 训练题之外预留本来源 128 题。公共 benchmark 题及近重复变体从各训练来源排除。原始数据集的 train/test 命名不替代项目内的使用角色。

DAPO 缺少可靠题型／难度元数据，先随机抽样并检查题长覆盖，不把题长命名为难度。DeepCoder 按来源，TextbookReasoning 按学科，IF 按约束类型和约束数量检查分层覆盖。具体比例、题族算法和随机种子尚未冻结；不依据 teacher 答对率、初始 KL 或后续结果挑题。

训练题选定后随机打乱分成 50 批；历史集合使用第 4 节的批均衡随机规则。所有 teacher 在相同 student／模式／训练来源下共享训练题 ID 和顺序，按批 refresh 后的真实轨迹随参数分叉，不能要求 token 也相同。

## 11. 评估执行与频率待定

student update 与 `_validate()` 都采用同一共享 GPU 池分阶段串行执行。训练当前批 teacher hidden 临时复用 32 次；评估也先 teacher、后 student，按评估块准备并清理临时 payload。四卡执行已验收；当前来源留出＋历史回调一次处理 256 条，公共双银行的大集合仍需补评估分块。固定 2＋2 等并行方案保留为历史性能资料，不再作为当前默认路线的待选项。

当前推荐的分任务频率见第 11.1 节；它尚未作为已运行配置，公共 32K 的成本仍需验收后确认。动态历史集合仍随每个新训练 batch 更新，是否实际评分由另一个调度决定。预算记录使用实际评分次数和位置数。

公共 current student 回答可以同时用于 accuracy 与 current-rollout RKL，无需分别生成；其生成与评分使用同一 checkpoint。teacher／initial student 固定银行按身份复用。具体容量估算与评估布置见[verl 接入方案](../../../infra/architecture/2026-10-31-四域RKL实验的verl接入方案.md)。

### 11.1 按题目集合与轨迹来源定义任务

Bank 是保存下来的轨迹集合，不是与 benchmark 并列的新题库。任务必须同时标明题目来自哪里、前缀由谁生成、使用哪个 current student checkpoint 评分，以及 teacher／模板／支持口径。以下频率属于讨论建议，尚未改动实际运行配置。

| 任务                         | 题目集合与轨迹来源                                                     | 观察内容                         | 建议 outer 读出点                    |
| ---------------------------- | ---------------------------------------------------------------------- | -------------------------------- | ------------------------------------ |
| 当前批训练 loss              | 当前 128 题，outer 开始时的 current student 回答                       | 同批 reuse 中的拟合              | 每次 optimizer update，自然记录 loss |
| History RKL                  | 已训练题，真实参与训练的回答                                           | 保持旧状态的拟合能力             | 每 outer 完成后                      |
| 来源留出 RKL                 | 永不参与梯度训练的本来源 128 题，固定 initial student 回答             | 同来源未见题的固定状态泛化       | 0 及每 outer 完成后                  |
| 公共固定 initial-student RKL | 公共四域共 512 题，由初始 accuracy 产物抽取的固定 initial student 回答 | 跨 teacher／训练域的共享前缀比较 | 0／1／2／5／10／…／50                |
| 公共固定 teacher RKL         | 同一公共 512 题，由 teacher accuracy 产物抽取的固定 teacher 回答       | 教师访问状态上的拟合             | 0／1／2／5／10／…／50                |
| 公共 current RKL＋任务正确率 | Accuracy 按其题目清单和 n 生成；current RKL 选其中指定 512 题各 1 条   | 当前策略访问状态的残差与任务表现 | 0／25／50；0 可复用 initial bank     |

“Future”需要明确含义：如果指未参与训练的同来源题，现有来源留出就承担此职责，建议继续标为 `source_heldout`。如果指以后确实将进入训练的 batch，则是另一种迁移诊断；同一轨迹需要在前一批更新前后配对评分，题目训练后也不能继续标作未见数据。当前不额外增加这一集合。

固定 bench RKL 就是对应 bench bank 上的 RKL，不另建重复的“bank RKL”任务。相同 checkpoint、teacher、支持口径和 token 轨迹的结果计算一次、多处引用；相同题目但不同回答不能去重。公共 current 回答一次生成，全部供任务 verifier 使用，其中指定题目与 sample index 的回答供 RKL 使用；RKL 仍需按相同前缀计算两侧全词表分布。outer0 的 current accuracy 复用初始完整评估结果，current RKL 复用 initial-student bank 读出；teacher accuracy 使用初始 teacher 评估的全部回答计算一次，bank 子集不替代 accuracy 的多次采样。

固定 bank 的回答不随训练改变，对这些回答重复运行 verifier 不会得到 current student 正确率的变化。当前能力的正确率必须来自当前 checkpoint 的新回答。Math／Science 报告正确率，Code 报告单次生成的 pass@1，IF 优先报告严格 prompt-level 通过率；保留逐题结果进行配对比较，不以这些成绩筛选训练题或 teacher。

主跨 teacher 比较优先使用共享 initial student 前缀。固定 teacher 与 current student 前缀各自成表；它们的状态分布不同，不混入同一个总 RKL。四域等权汇总也在同一种轨迹来源内进行。History 与来源留出的前缀来源不同，其均值差不直接命名为泛化 gap。

相邻读出共同保留的历史轨迹可直接从现有逐题结果计算配对变化，无需额外前向；与动态历史均值一起展示，有助于区分旧状态改善、遗忘及集合换样。当前批 loss 的跨 outer 跳变同样伴随题目和轨迹变化，应标出 batch 边界。

建议的常规 256 条 history＋来源留出读出，在 JustRL → R1-1.5B 验收中耗时约 25–27 s，包含完整状态哈希，约占 6 分钟 outer 的 7%。据此建议保留每 outer 的细曲线；其他模型及公共银行尚须测速。公共固定银行使用较稀疏的共同节点，current 生成／verifier 更稀疏；这些频率仍待确认。

以下频率为当前推荐，尚未作为已运行配置：来源留出与 history 每 outer；公共两类固定 bank 在 0／1／2 及每 5outer 读出；bench current accuracy＋RKL 在 0／25／50 读出；teacher accuracy 只在初始化读出。每个 outer 含 32 次更新，因此 bank 周期 5outer 对应 160 次更新，25／50outer 分别对应 800／1,600 次更新。初期补 outer1/2，是因为已完成的短验收显示前 64 次更新已有明显风险变化。

频率只控制何时读出，不改变训练预算或重新生成固定 bank。普通点评分 256 条；只加公共两类 bank 的点最多评分 1,280 条；同时进行 bench current 读出的训练后节点最多评分 1,792 条（各公共 bank512 条＋来源/history256 条）。初始化没有 history，且 current 与 initial bank 重合，最多评分 1,152 条轨迹记录。Accuracy 可以有更多回答，但 current RKL 仍只取指定 512 题的固定 sample index。

公共 32K 的完整银行尚未测速。每 5outer 是 RKL 优先的建议起点；若统一性能验收显示开销过大，可在正式矩阵启动前整体改成每 10outer 并保留 bench 节点，不依据各分支的 RKL 好坏临时改读出点。正常运行保留模型版本、token 身份、计数和 finite 检查，完整参数／Adam 哈希留在工程验收中。

### 11.2 验证调度与模型版本

只有固定银行任务时，沿用当前“actor 更新完成 → 固定 RKL → 同步 vLLM”顺序。若调度 current bench，必须先将本轮更新后的权重同步给 vLLM，再生成回答；不能在已有 `on_before_weight_sync` 位置直接用尚未同步的 rollout 引擎生成。收齐本轮所选回答后，按块串行 teacher→student 评分，复用同一回答做任务 verifier，完成后恢复生成引擎。

每个任务记录模型版本、题目集合、轨迹来源和生成协议。评估使用独立的生成 seed 管理；常规固定评分无需导出 checkpoint。不同任务可以共享一段 `_validate()` 调度，但不必每次全部运行。

### 11.3 初始化与完整 outer 的调度例子

开始训练前固定题序、bank 题目 ID、sample index 及各任务的 generation profile。分别对 initial student 和 teacher 运行 bench 评估，accuracy 使用其全部回答，导出各 512 条公共 bank。Initial student 另外生成本来源 128 条 7K 留出轨迹。初始化 RKL 始终比较 initial student 与 teacher，分别在来源留出、initial-student 公共 bank 和 teacher 公共 bank 上读出；teacher 生成回答不改变 KL 两侧身份。

每个 outer 先使用 current student 生成 128 道新训练题的回答（n1、cap7168），保存实际 token；teacher 用共享四卡评分并卸载，临时 hidden 在 CPU TQ 复用；student 用四卡完成 32 次更新；随后更新 128 条 history。

普通 outer 在 vLLM 休眠时计算来源留出／history；bank 节点额外加入两个公共固定 bank。Bench 节点先把该轮新权重同步给 vLLM，按各 bench 的 n 生成 current 回答，再休眠 vLLM；全部回答用于 accuracy，其中指定 512 条加入 current RKL 任务。将本轮待评分轨迹按完整样本组成有界评估块，每块执行 teacher→student→清理，GPU 微批和 CPU/TQ 总量分别受控。

读出完成后恢复 vLLM 到同一新权重版本，清理临时 payload，进入下一批。Teacher 基线与固定 bank 不重新生成；不同训练域或 teacher 分支能共享的初始化产物按模型／模式／模板／生成协议身份复用。若启用恢复点，在整个 outer 完成且 history、题序与模型计数一致后提交，不要求每次 validate 都存 checkpoint。
