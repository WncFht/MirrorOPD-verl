# 实验记录维护与分析复现

除明确注明进入日志仓库的命令外，命令从源码仓库根目录执行。日常分析读取本地 `wandb-logs`，不依赖先上传云端再下载。分析工具不启动训练、不登录切换账号、不上传指标，也不改模型环境。统计与 MFU 脚本使用 Python 标准库；通用解码器使用日志仓库的独立 `.venv`；绘图需要已有 Matplotlib、NumPy 与 figure-viz skill。实验交付统一使用 Markdown、静态 PNG/PDF/SVG 和可复算的 JSON/CSV；不维护离线 HTML 浏览页或交互 dashboard。

## 数据归属与更新实验运行记录

Polaris/E48–E49系列按2026-10-27用户要求单独整理：报告证据与复算输入位于[polaris-transfer/data](polaris-transfer/data/README.md)，大型模型与tensor缓存位于源码仓库`outputs/polaris-transfer-cache/`。该系列的新分析产物写入上述docs目录；原始`.wandb`与通用解码器仍按下文管理。历史来源字段保留采集时的路径。

源码仓库维护文档、运行表、报告展示图和分析脚本。实验数据集中在 `wandb-logs`：

| 日志仓库目录 | 内容 | 维护方式 |
| --- | --- | --- |
| `MirrorOPD-verl/wandb/` | 原始 .wandb 与附件 | 保留原始证据，进入 Git |
| `derived/MirrorOPD-verl/<run目录>/` | 解码得到的 config/history/summary | 通用解码器生成，不进 Git |
| `derived/MirrorOPD-verl/inventory/` | 当前运行汇总 JSON/CSV | 从解码结果重新生成，不复制各 run 配置 |
| `MirrorOPD-verl/analysis/<报告快照>/` | 报告冻结输入、逐项统计及图表数据 | 只在需要固定分析边界时归档，来源与覆盖范围写在快照说明中 |

原有实验数据已整体迁至日志仓库，数值与截断边界保持不变。迁移后的历史证据已归档于日志仓库提交 `188690d`；各报告中原始日志提交和 API 来源保持原义。本地证据链接使用源码仓库和日志仓库同级的布局；脚本通过 `--logs-repo` 或 `WANDB_LOGS_REPO` 指定其他位置。报告展示图保留在源码文档旁，便于直接阅读。

1. 在 `wandb-logs` 拉取并解码原始日志。本机 Git SSH 操作先加载既有 SSH 环境。
2. 只读核对云端项目清单，把时间和 `{id, name, state}` 保存到日志仓库；不要把凭据写入清单。
3. 运行下面的脚本。它先调用日志仓库的通用解码器刷新缓存，成功后再更新运行表；汇总 JSON/CSV 写入日志仓库的 `derived/`，不再创建日期配置副本。
4. 更新系列 README 中的执行／分析进度和待办。报告仍使用其注明的冻结快照，不随运行表刷新而自动替换旧结论。

```bash
# 从源码仓库根目录执行；将 cloud-index 参数替换为此次查询得到的完整清单。
python3 examples/mirroropd/docs/experiments/scripts/build_inventory.py \
  --logs-repo ../wandb-logs \
  --cloud-index ../wandb-logs/MirrorOPD-verl/analysis/inventory-20261025/cloud-index.json \
  --register examples/mirroropd/docs/experiments/运行记录.md
```

云端清单格式为 `{"observed_at":"带时区时间", "runs":[{"id":"run-id", "name":"实验名", "state":"finished"}]}`。示例中的日期清单只用于复算当时状态；更新时使用新查询结果。生成器对正式云端 run 缺少本地解码证据、重复 run ID 和不可用解码状态报错，先补齐来源再登记。

完整配置直接查看 `derived/MirrorOPD-verl/*-RUN_ID/config.json`，全量观测查看同目录 `history.jsonl`。运行表保留关键 setting 和 run ID；最后验证位置从 history 单独提取，缺失实际更新计数时不以 W&B `_step` 替代。性能、安装和指标验收不列入正式实验；新命名或 val-only 系列需明确接入分类规则。

## 职责划分与更新顺序

`wandb-logs` 负责原始文件、通用解码、缓存和报告证据存储；MirrorOPD 负责实验分类、实际更新／验证坐标、指标解释、统计与图表。同一份原始 `.wandb` 只由日志仓库的读取器解释，项目脚本不另写二进制解码逻辑。

解码采用文件级缓存：源文件变化后从头重放，完成后替换旧派生结果。未变文件直接复用。半截日志补齐后可重新得到完整 history/config/summary，不会重复追加已导出的行。具体缓存条件、CSV 失效和状态边界见日志仓库 README 的“原始日志更新后的解码”。

日常更新按“接收或拉取完成 → 解码完成 → 更新运行表与分析”串行执行。运行表生成器会自动完成中间的解码步骤，单独运行其他分析脚本前仍应先解码。当前派生目录替换没有读写锁；不要同时刷新与读取同一目录。

当前运行汇总是可覆盖的缓存。需要引用固定结果时，报告记录日志 Git 提交、run ID、最后完整 outer／最后 update／最后验证边界，以及分析源码版本。可从原始日志重建的中间产物通常留在 `derived/`；API-only 来源、旧截断输入或报告必须固定的统计证据才归档到 `analysis/`，不按每次刷新重复归档所有 run。

| 层次 | 唯一维护位置 | 职责 |

## 只读导出与数据边界

`export` 默认从本地日志仓库导出，必须显式传入 `--run entity/project/run`；工具没有默认实验。依次使用 `--logs-repo`、环境变量 `WANDB_LOGS_REPO`、源码同级的 Git 仓库 `wandb-logs`，最后才尝试 `~/src/wandb-logs`。同一 run ID 必须唯一匹配一个原始目录，记录中的 project/run ID 必须一致；离线记录没有 entity 时，将 entity 标为调用者显式提供。

每次选择新的导出目录，已有快照不覆盖。E15 示例：

```bash
python3 examples/mirroropd/docs/scripts/analyze_run.py export \
  --run wncfht/MirrorOPD-verl/krkmq098 \
  --out ../wandb-logs/derived/MirrorOPD-verl/e15-export-新快照

python3 examples/mirroropd/docs/experiments/scripts/analyze_policy_run.py \
  --snapshot-from ../wandb-logs/derived/MirrorOPD-verl/e15-export-新快照 \
  --data ../wandb-logs/MirrorOPD-verl/analysis/e15-新快照
```

导出器调用日志仓库的独立 Python，不复制一套解码实现，不读取凭据，也不会因找不到本地数据自动改用 API。history 保留原始稀疏行；配置中的密钥类字段脱敏，非有限数值不补零。系统监控写入 `system.jsonl.gz`，是所有成功解码的周期性记录，不经过 API 二次采样；同时保留 `_timestamp_ns` 和分析使用的 Unix 秒时间戳。旧 `system-sampled.jsonl.gz` 仍可读取，但不会把它改称全量数据。

`source.json` 记录来源、解码状态和记录数。`snapshot`、`partial_snapshot` 不能证明训练完整结束；`decode_error` 或源文件读取期间变化时停止导出，不自动补取云端数据。系统监控即使完整解码也只是周期性观测，不是连续 GPU trace。

硬件和软件版本来自该 run 的 metadata/requirements；metadata 附件缺失时，可读取日志仓库解码器 v2 的 `environment.jsonl`，按同一 writer 合并分批环境信息，不混用其他 run 或本机环境。来源写入 `source.json.environment_metadata_source`。metadata 的 Git commit 不能证明运行目录无额外修改。训练时间使用采集 `_timestamp`；离线同步后的服务端 `created_at` 不等于训练开始时间。

## 云端回读的保留用途

旧的 API 拉取流程退出日常分析入口，命令改为显式 `export-cloud`。仅在核对云端一致性，或本地没有该 run 的原始数据而需要补救时使用；它不替代完整原始日志归档。训练端记录、接收端上传和网页查看继续保留。

```bash
python3 examples/mirroropd/docs/scripts/analyze_run.py export-cloud \
  --run wncfht/MirrorOPD-verl/krkmq098 \
  --netrc-file /本机私密目录/netrc \
  --out ../wandb-logs/MirrorOPD-verl/analysis/e15-cloud-audit-新快照
```

凭据可由 SDK 环境提供；`--api-key-file` 与 `--netrc-file` 互斥，不把 key 写到命令行或仓库。默认 endpoint 为 `https://api.forge.coreweave.com`。history 使用 `scan_history(keys=None)` 并固定 `lastHistoryStep` 边界；system 使用 sampled history，增加 samples 不保证全量。历史报告中的 API 来源、系统采样口径和冻结数据保留原样，不因默认入口迁移而改写成离线来源。
