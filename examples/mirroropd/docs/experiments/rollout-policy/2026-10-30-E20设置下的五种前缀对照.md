# E20 设置下的五种前缀对照

更新日期：2026-10-30。状态：已获准实施，正式十组实验尚未开始。先完成[融合基础设施](../../infra/rollout/fusion/README.md)及热点优化、更新运行文档，再固定执行配置开始本实验。基础设施 smoke、容量预跑和调参样本不计入下述训练结果。

## 问题与实验矩阵

固定 learner 配方与目标 teacher，比较训练前缀来源对 full-vocab reverse KL（RKL）优化过程的影响。Learner 均从 `DeepSeek-R1-Distill-Qwen-1.5B` 初始化；teacher 分别为 `JustRL-DeepSeek-1.5B`（J）和 `Polaris-7B-Preview`（P）。每个 teacher 下独立运行五组，共十组，全部重新初始化 learner 与 AdamW，不在组间延续训练参数或 optimizer 状态。

| 分支后缀 | 前缀来源                          | 来源权重的更新                                | 生成定义                                                     |
| -------- | --------------------------------- | --------------------------------------------- | ------------------------------------------------------------ |
| S0       | initial student                   | 始终绑定原始 R1-1.5B checkpoint               | 每个 outer 在新题目上用冻结 student 生成                     |
| S        | current student                   | 每个 outer 使用已完成前一轮全部更新的 learner | 当前 student 生成                                            |
| LM       | 0.5 current student + 0.5 teacher | student 随训练更新，teacher 冻结              | 同一前缀下两侧原始 logits 各占一半，再公共采样一次           |
| TM       | 0.5 current student + 0.5 teacher | 同上                                          | 全局 batch64 中 32 条完整轨迹来自 student，32 条来自 teacher |
| T        | teacher                           | 始终绑定对应 teacher checkpoint               | teacher 生成                                                 |

完整标识为 `J-S0/J-S/J-LM/J-TM/J-T` 和 `P-S0/P-S/P-LM/P-TM/P-T`。LM 是逐 token logits 融合，TM 是整轨迹混合；TM 不在一条轨迹内部随机切换模型。两个混合系数在全部 40 个 outer 中固定为 0.5。

所有组的训练目标都指向同一个对应 teacher。融合仅改变生成前缀，不能把 LM 的混合分布另行替换成 RKL 目标，也不改成 sampled KL、forward KL 或 SFT。来源与失败协议沿用[可组合 Rollout 设计](../../infra/rollout/fusion/2026-10-28-可组合Rollout策略架构与实现方案.md)。

## E20 基线与明确覆盖项

配置依据为本地保存的 [E20 原始 config](../../../../../../wandb-logs/MirrorOPD-verl/analysis/batch-transfer-20261027/E20/config.json)，对应 run `lwgb5eex`；配方说明见[训练设置](../../settings/训练设置.md)，历史比较见[E18–E20 等更新预算报告](../reuse-budget/equal-update-budget/README.md)。这里复用 E20 配方，不把新的依赖版本、两卡硬件和前缀干预称为历史运行的逐位复现。

| 项目                | 固定设置                                                                                        |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| 数据                | DAPO，全量可用训练数据；shuffle=true，seed42；保留过长 prompt 过滤，关闭 group filtering/refill |
| 每轮题数与采样数    | prompt batch=64，n=1；optimizer mini-batch=64                                                   |
| 预算                | 40 outer；每批 reuse=16；每组预期 640 次成功 optimizer 更新，共 6,400 次                        |
| 长度                | prompt cap4096，response cap7168，不因并发或显存调参缩短                                        |
| 采样                | temperature=1、top-p=1、top-k=-1；沿用 R1 原生 EOS151643，不加入 Qwen3 的停止 ID                |
| Loss                | full-vocab RKL，token-mean；不使用 task reward 作为训练目标                                     |
| Optimizer           | AdamW，LR=1e-6，betas=(0.9,0.999)，eps=1e-8，weight decay=0.01，grad clip=1                     |
| Scheduler           | constant，warmup=0                                                                              |
| 精度基线            | E20 的 FP32 主参数与 BF16 forward、FP32 梯度归约；不以调参为由切换学习精度                      |
| Full-vocab 执行基线 | precompute，token chunk512、vocab chunk8192，async write/prefetch 开启                          |
| 验证                | 不做初始、周期或末轮验证；`val_before_train=false`、`test_freq=-1`                              |
| 保存                | 不保存模型 checkpoint，包括最后一轮；`save_freq=-1`                                             |
| 保留产物            | 完整配置、源码与模型绑定、数据/请求身份、训练指标、资源曲线、退出状态及分析图表                 |

40 outer、关闭验证/保存、两张 GPU、teacher 配对与前缀来源是明确覆盖项。其他学习设置保持 E20。允许优化执行拓扑、并发、KV 预算、计算微批、动态 token budget、数据传输与等价算子实现；执行优化必须先通过数值或梯度回归，并在十组实验开始前冻结、记录与 E20 执行参数的差异。不得随训练曲线改变 LR、长度、题目集合、reuse 或 loss 定义。

每个 outer 只生成一次新的 batch，随后在该批前缀上完成 16 次更新。S0 指固定生成器参数，不是把第一批轨迹重复训练 40 轮。各组使用相同题目顺序与请求种子派生规则；不要求不同来源生成相同自然轨迹。当前纯 student 可用现有轨迹混合的 teacher 配额 0 端点接入统一 plan/collector，保证种子与其他组一致；该端点不创建 teacher 生成阶段，legacy 默认 single 路径继续保留。

## 模型与词表兼容

三份模型都是 Qwen2 架构，不能直接套用只验收了 Qwen3 的后端入口。R1 与 JustRL 的输出 head 为 151,936 行，Polaris 为 152,064 行。实施前核对 tokenizer 的 token-ID 映射、原生 EOS、独立配置、embedding/head、KV 和 student 定向 refit；两组配对都要完成实际生成与训练切换检查。

研究入口现在为五种来源显式选择 `TRITON_ATTN`，与已验收的组合模型和独立组件探针保持一致。该设置属于本研究入口，不改变仓库默认 single 配置。原有短接线记录保留其实际配置；统一 backend 后的十组 CPU 配置检查通过，新的实际接线复验已排队，尚未启动正式 40 outer 研究。

五种来源统一使用可输入双方模型、且具有相同 tokenizer 定义的合法 token-ID 支持。Polaris 的 teacher 来源因此是该支持上的条件生成分布。逐 token 融合只对公共采样视图对齐输出宽度，不修改 teacher 原始 head。

训练 RKL 保持 E20 的完整输出定义：student 在其完整 head 上归一化，teacher 的 softmax 分母保留其全部 152,064 行。不能因为生成需要共同支持，就裁掉 Polaris 的额外 128 行或把训练目标改成条件化的 teacher。实际生成支持与历史 E20 的差异须记录，并在本次十组内保持一致。

## 优化与排程

仅使用物理 GPU 6、7。先以实际模型和 reuse16 负载测完整 outer，再选择稳定的执行配置。热点检查覆盖 prefill、早期和长历史 decode、teacher scoring、full-vocab precompute、16 次 update 的冷/热阶段、refit、sleep/wake、CPU 与 I/O；不把单独 decode TPS 当作端到端收益。

并发包含活跃生成请求数和同时运行的独立实验数。比较单卡任务、TP2/多 replica 以及受控多任务共置的完整吞吐和阶段峰值显存；有收益且容量稳定才增加并发。共置必须由同一个资源协调器持有 GPU 分配，隔离 Ray、IPC、输出目录和随机流，覆盖同时生成、同时更新及交错切换的压力检查。不得绕过现有占用保护直接叠加任务，也不使用 GPU 0–5。共享 GPU 时单组延迟包含资源竞争，整组实验的吞吐另按总墙钟报告，不把各任务观测到的整卡显存或 GPU-hours 相加。

调参使用独立预跑目录，不计入正式十组；固定候选后每组从原始 checkpoint 重启。正式运行保留全部失败记录，不通过删去失败批次凑满 40 outer。因为不保存模型 checkpoint，运行中断后的重跑从初始状态开始并使用新的运行标识。

运行入口与配置检查见[融合 benchmark 说明](../../../benchmarks/fusion/README.md#e20-五种前缀入口)。十组解析配置已逐项核对 E20 学习设置和本方案覆盖项，并检查禁止保存、验证和改动预算的失败分支；配置检查不等于训练已运行。关闭验证后，未使用的验证 cap 与训练 cap 对齐，以满足 RolloutConfig 的窗口约束；正式训练窗口仍为 4096+7168=11264，验证不会因此启用。

## 指标与分析边界

保留每次成功更新的实际 RKL/loss、梯度范数、LR、非有限值与跳过更新标记；按 outer 和批内 reuse 次序展开。报告每个新 batch 的首次 KL、同批第 1–16 次训练观测的下降、有效 response token、EOS/cap 数、长度分布、完整 outer 墙钟、各阶段时间、每卡显存和 CPU RSS。

训练日志中的 loss 是该次更新前的观测；第 1 次与第 16 次观测之间跨越 15 次更新，不把末次观测改称完成第 16 次更新后的额外评分。主要图使用 outer、成功 optimizer step 和累计有效训练 token 三种横轴，并把两种 teacher 分开解释。

不同来源的 KL 在不同前缀分布上测得。较低训练 KL 或较快批内下降不能单独证明泛化改善；本实验不执行验证，也不报告由这些曲线推断的 accuracy。全部十组完成并核对每组 40 outer/640 次成功更新后，再形成正式结果与分析。
