# 实验文档维护与复算

## 报告与实际 setting

每项研究说明要判断的问题、实际 setting、结果、分析及证据与复算；章节由材料决定，短实验可并入现有专题，不要求每次运行都新建报告。公共设置只提供参数和资料；报告记录实际 checkpoint、数据/state 来源、目标、optimizer/精度、预算、长度、seed 及验证。控制组与改变因素用表列明，不用“同默认设置”代替关键参数。

完成结果与待执行方案分开。单 run 各 checkpoint 不是独立 seed；短前缀、CPU 诊断和正式任务验证分别解释。当前以 acc 等已有指标讨论效果，“完全蒸馏”的定义保留开放。

## 矩阵与训练步数

矩阵用于定位实验、查看模型与实际 setting，不是要求补齐所有格子的运行清单。未执行格保留状态，新增实验由当前研究问题决定；同一配置的不同步数可作为不同观察窗口记录，不因没有达到早期计划步数而否定已有分析。

实际 outer、optimizer updates、reuse 和 token 量仍如实记录。训练时长可以根据运行效率、拟合进展和现象是否已充分暴露调整。分析先判断曲线是否已经覆盖所讨论的现象；只有预算差异确实影响结论时，才强调共同窗口或补充对照。效果与平台分析不机械要求步数相同；讨论学习速度、等预算收益或成本时，则明确相应的比较口径。没有后期证据时不外推更长训练结果。

## RQ 与正文归属

[研究入口](README.md)维护五个 RQ 及专题分工，[文档归属规则](../AGENTS.md)规定 experiments、infra、settings、theory、literature 和 progress 的边界。精度与 optimizer 的工程对照从研究正文链接到 infra。

同一对照维护一份完整正文，新 run、seed 或分析日期通常更新所属章节。跨 RQ 引用同一证据，公共定义引用 settings/theory。progress 只保存周报；研究入口直接链接正式正文。合并先迁入独有设置、推导、负结果和复算依赖，修复锚点与生成器后再删除旧正文。

## 当前运行与验证表

从仓库根目录执行：

```bash
python -m examples.mirroropd.research.studies.production.refresh_tables --logs-repo ../wandb-logs
```

默认先调用日志仓库的通用解码器；已有解码可用`--skip-decode`，仍拒绝过期来源。两张表从同一次本地读取生成，逐数据集保持自己的最后验证坐标。缺测不补零；旧 best/maj 不改名为 pass/majority；非零退出和缺少完整退出记录分开。

无需人工 catalog、study ID 或 manifest。实际 config 与 run 身份是数据来源，必要的历史命名例外留在 Python 工具中。生成的数值 JSON/CSV 属于程序产物，不作为另一层人工登记。

## 冻结证据

报告注明使用的 run 和输入边界。复核旧报告先定位其冻结输入，输出到临时目录；不要用最新 derived 覆盖旧统计。原始日志、模型、checkpoint 和历史 source 字段不因移动文档而修改。

`wandb-logs`、仓内数值原件和冻结源码保留原始路径与内容，正文通过相对引用连接证据。来源模型卡与检索原文在 literature 内保留。历史源码运行前复制到新位置，不在冻结目录直接执行会写文件的脚本。

## 活跃代码与检查

通用分析位于`examples.mirroropd.research.studies.production`，精度与 optimizer 工程实验的代码继续位于现有`precision`，文档归 infra，数值恒等式位于`objectives`/`rollout_policy`，性能及接入验收位于`benchmarks`。使用模块入口和显式输入/输出，不通过移动目录改变预算、mask、随机种子或统计公式。

修改 Python 后运行仓库 Ruff 与相应测试。文档格式化、检查范围和暂存验证统一见[维护流程](../infra/maintenance/README.md)。第三方原文和历史命令注明适用版本；2026-11-01 的迁移位置见[重构对照](../archive/2026-11-01-文档重构对照.md)。
