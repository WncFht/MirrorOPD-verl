# 实验文档维护与复算

## 报告与实际 setting

每项研究依次写背景/motivation、实际 setting、实验结果、分析、证据与复算。公共设置只提供参数和资料；报告记录实际 checkpoint、数据/state 来源、目标、optimizer/精度、预算、长度、seed 及验证。控制组与改变因素用表列明，不用“同默认设置”代替关键参数。

完成结果与待执行方案分开。单 run 各 checkpoint 不是独立 seed；短前缀、CPU 诊断和正式任务验证分别解释。当前以 acc 等已有指标讨论效果，“完全蒸馏”的定义保留开放。

## 四条研究线的归属

训练信号、reuse 预算、rollout 来源/混合的最终 acc、师生迁移与优化机制各有一个主入口。Polaris 固定 state 和跨 batch 控制归迁移机制，Qwen 修复及 E54 归 infra。小实验按目的放入报告章节或独立专题，不建立杂项小实验目录。

## 当前运行与验证表

从仓库根目录执行：

```bash
python -m examples.mirroropd.research.analysis.refresh_tables --logs-repo ../wandb-logs
```

默认先调用日志仓库的通用解码器；已有解码可用`--skip-decode`，仍拒绝过期来源。两张表从同一次本地读取生成，逐数据集保持自己的最后验证坐标。缺测不补零；旧 best/maj 不改名为 pass/majority；非零退出和缺少完整退出记录分开。

无需人工 catalog、study ID 或 manifest。实际 config 与 run 身份是数据来源，必要的历史命名例外留在 Python 工具中。生成的数值 JSON/CSV 属于程序产物，不作为另一层人工登记。

## 冻结证据

报告注明使用的 run 和输入边界。复核旧报告先定位其冻结输入，输出到临时目录；不要用最新 derived 覆盖旧统计。原始日志、模型、checkpoint 和历史 source 字段不因移动文档而修改。

`wandb-logs`原始路径保持不变；已有仓库内冻结证据随专题迁移，数值原件和冻结源码不改写。来源模型卡与检索原文在 literature 内保留。历史源码运行前复制到新位置，不在冻结目录直接执行会写文件的脚本。

## 活跃代码与检查

通用分析位于`examples.mirroropd.research.analysis`，科学精度实验位于现有`precision`，数值恒等式位于`objectives`/`rollout_policy`，性能及接入验收位于`benchmarks`。使用模块入口和显式输入/输出，不通过移动目录改变预算、mask、随机种子或统计公式。

修改 Python 后运行仓库 Ruff 与格式检查；文档使用`make docs-check`检查当前维护正文、图片、锚点和源码引用。第三方原文和冻结历史命令明确标注范围。迁移对照见[记录](../archive/2026-10-28-文档迁移对照.md)。

本次整理不启动训练、GPU benchmark、自动队列、联网下载或 W&B 同步。
