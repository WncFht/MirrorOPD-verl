# Reuse 与训练预算

## 背景与 motivation

多次复用减少新生成开销，但把更新预算更多花在固定前缀上。response cap 还影响完整推理覆盖、token 工作量和墙钟。这里以预算为主变量，rollout 来源尽量固定。

## Setting 与实验设计

| 对照        | 固定预算                 | 改变因素                             |
| ----------- | ------------------------ | ------------------------------------ |
| E13/E16/E17 | 相同 outer200            | reuse1/4/16，更新数随之变化          |
| E18/E19/E20 | 4096 次更新              | reuse64/32/16，新回答数按1:2:4变化   |
| E35/E17     | 共同 outer200/update3200 | cap15360/7168；硬件/代码存在历史差异 |

具体报告分别记录实际配置，固定更新不等于固定 token 或算力。

## 实验结果

增加 reuse 没有带来所有基准一致的末点提升。旧共同 2560-update 统计中，高 reuse E18 比 E20 少生成 74.77% 的 response token，任务排序混合。E35 共同 outer200 的 AIME 比 E17 高 3.96 个百分点，新 token 增加 22.71%、记录训练时间增加 45.18%。旧统计不外推为其他预算结果。
