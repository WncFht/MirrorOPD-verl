# E16/E17 位置指标与后期收敛

日期：2026-10-24。依据本地 `.wandb` 事务日志重新导出，未读取云端采样曲线。**这两个历史 run 没有按 response token 位置分桶的 KL/loss 指标。两组后期完整条件 KL 都还在下降；E17 的同批复用下降仍明显，不能把锯齿曲线的下沿当作新轨迹上的收敛水平。**

## 1. 当前日志能观察什么

| 指标 | 实际含义 | 能否回答位置问题 |
| --- | --- | --- |
| `distill/full_kl` | 一次更新前，全批有效 response token 的完整条件 reverse KL 均值 | 只有总体均值，不能分离前缀／后缀 |
| `optim/actor/loss`、`optim/actor/distillation_loss` | 当前两组纯 Full-KL 的优化目标 | 与上述 KL 数值一致至浮点聚合误差，不是独立的新诊断 |
| `rollout/response_length/p50,p95,p99` | 回答长度在样本之间的分位数 | 不能表示这些位置以前的 KL |
| `policy/*/log_ratio_p01,p50,p99` | sampled 路径中的 log-ratio 数值分布；E16/E17 没有这些记录 | 数值分位数，不是 token 位置分位数 |
| `eval/*/acc/prefix_mean@k` | 固定 sample index 顺序下前 k 个**回答**的准确率均值 | 不是一条回答前 k 个 token 的 loss |
| `rollout/data_reuse/epoch_index`、`update_index` | 同一批轨迹在第几轮复用／更新 | 可以分析批内 loss 下降，不能分解到词元位置 |

E16/E17 的实际 `distill/` 字段都只有 `distill/full_kl`。完整字段清单已保存在[数据目录](../../../../../../wandb-logs/MirrorOPD-verl/analysis/position-convergence-20261024/README.md)。不能从总体均值和长度分位数反推出前25%、中间区间或尾部的 KL。

代码中原本计算过每 token 的 KL，但没有保留位置统计：[PrecomputedKL.forward](../../../../../verl/trainer/distillation/full_vocab.py) 的 `kl = (p * lp).sum(-1)` 随后直接累加为 `total`；[engine 输出](../../../../../verl/workers/engine/fsdp/transformer_impl.py) 只有 `full_kl_sum/full_kl_count`；[loss 分支](../../../../../verl/trainer/distillation/losses.py) 汇总成全局 token mean。该函数名中的 token chunk 是计算分块，不是每条回答的位置区间。

## 3. 后期的 Loss 仍在下降

![E16/E17 的新批次起点、复用末次和批内下降](../../../../../../wandb-logs/MirrorOPD-verl/analysis/position-convergence-20261024/convergence.png)

左图和中图分别展示全程对数轴与后期线性轴，曲线为20批滚动均值；实线是每批第1次更新前 KL，虚线是最后一次更新前 KL。右图固定 outer 141–160，先将每批 KL 除以该批首个观测，再跨20批取均值。它显示重复使用同一批前缀时仍能下降，不是按 token 位置分桶的图。

### 3.1 每组最后20个有完整更新记录的批次

| 指标 | E16，outer 181–200 | E17，outer 159–178 |
| --- | ---: | ---: |
| 每批第1次更新前 KL 均值 | 0.00159928 | 0.00076594 |
| 每批最后一次更新前 KL 均值 | 0.00149275 | 0.00041153 |
| 逐批首末相对下降的均值 | 6.63% | 45.89% |
| 逐批最后相邻两个观测的相对下降均值 | 2.91% | 2.49% |
| 相比前一个不重叠20批窗口，第1次更新前均值下降 | 11.35% | 6.86% |
| 相比前一个不重叠20批窗口，末次更新前均值下降 | 11.65% | 11.14% |
| 最后一个单点 KL | 0.00144728 | 0.00040642 |
| 最后一个单点梯度范数，pre-clip | 0.02343 | 0.00834 |

单位为 nats/token。前一个不重叠窗口分别是 E16 的161–180、E17 的139–158。相对降幅逐批计算再平均，不能用表中两个均值的比值替代。

**这些 loss 都在对应 optimizer 更新之前测量。** E16 的第1→第4条覆盖3次已执行更新，E17 的第1→第16条覆盖15次；日志没有最后一次更新之后同批额外 forward 的结果。故不能把末点写成“做完4/16次更新后的 loss”。

E16 后期仍较稳定地下行。E17 的新批次起点下降更慢，局部接近平台，但旧批次上的优化仍有显著空间；末次相邻观测还能降约2.5%，并非同批目标已经不变。非零梯度或训练 loss 继续下降都不保证验证收益。

### 3.2 同一 Outer 区间比较

| Outer 141–160 | E16 | E17 |
| --- | ---: | ---: |
| 第1次更新前 KL 均值 | 0.00198573 | 0.00082887 |
| 最后一次更新前 KL 均值 | 0.00186135 | 0.00046412 |
| 批内相对下降均值 | 6.26% | 43.85% |

相同 outer 下 E17 的优化次数是 E16 的4倍，生成的具体回答也不同。上表用于描述实际运行，不是等计算预算或固定同一前缀的算法优劣结论。

### 3.3 换批后的起点明显高于旧批最低值

E17 最后窗口中，对相邻批计算“下一批第1条 KL／上一批最后一条 KL”，平均约 **1.85**；E16 约 **1.07**。E17 的旧批次拟合明显深于下一批的初始 loss，因此全局曲线形成较大的锯齿。

这里换了题目、生成回答及前缀测度，不能把上跳称为同一输入上的 loss 反弹，更不能仅凭它断言过拟合。应分别追踪新批次起点和同批末次，不把所有 update 点直接平滑成一条线来判定整体收敛。

最后窗口的训练回答均长约为 E16 的5738、E17 的5719 token，未见整体长度持续膨胀来解释 loss 下降。E17 长度统计只覆盖159–177的19批，因为178没有 outer 汇总。均长稳定仍不能排除位置分布、题目难度和回答质量的变化。

## 4. 已选择的后续观测：相对位置十分桶

后续按用户选择只采用 response 相对位置，每10%一桶，保存 KL总和、有效token数与均值。前30%可用前三桶的 sum/count 精确重建，不另存累计指标。当前代码已接入 Full-KL；该历史快照仍没有这些数据。具体位置定义、mask边界、后端支持和验收结果见[KL精度与相对位置分桶](../metrics/2026-10-24-评测预算语义与KL精度及位置分桶.md#4-已接入相对位置十分桶)。

仍按 outer/update/epoch_index 区分新批起点与同批复用。后续可用“outer × 相对位置桶”观察剩余误差集中在哪一段；固定 held-out prefix probe 是进一步区分前缀分布变化的可选诊断，当前未实现。
