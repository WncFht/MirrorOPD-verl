## 当前参数与证据边界

| 项目 | 仓库数学默认 | 四卡valid速度优先 | 四卡valid显存优先 |
| --- | --- | --- | --- |
| 验证提交窗口 | 128题 | 全量，`data.val_batch_size=null` | 全量 |
| 每引擎并发 | 64 | 128 | 96 |
| vLLM显存比例 | 0.5 | 0.65 | 0.5 |
| 调度token预算 | 8192 | 8192 | 8192 |
| 验证每题采样/回答上限 | 16 / 31744 | 保持 | 保持 |
| 编译与CUDA Graph / TP | 开启 / 1 | 保持 | 保持 |

当前选择停在已测配置。更高的160/192并发仅保留容量估算，尚未测试，不作为默认配置。全量提交和新并发仍通过环境变量及Hydra参数显式选择；公共启动代码没有随文档重构修改。

在四张H800、冻结初始checkpoint、完整570题×16下，全量64/0.5基线为30.08分钟、31,320 TPS；128/0.65为25.70分钟、36,503 TPS、单卡峰值55.49 GiB；96/0.5为27.14分钟、34,700 TPS、42.39 GiB。后两组均零抢占。完整条件、自然生成波动与质量检查见[完整验证章节](2026-10-22-训练与验证性能实测.md#1-完整验证与参数对照)。

八卡以相同每卡参数作为起点，只增加可见GPU与共享池大小；TP仍为1、独立teacher池仍为0，训练global batch和评测总量不随卡数加倍。[运行示例](2026-10-22-共享八卡运行与架构.md#验证执行配置与四卡八卡启动)已通过四卡/八卡配置解析。新候选在目标A100/A800八卡上的完整验证、训练/验证切换及保存恢复尚未完成GPU验收；不能从四卡结果承诺八卡速度翻倍。

普通领域入口仍为训练prompt/mini64、n1、epoch1；E7–E12为epochs16、D0、200个外层step，每50步验证、100步保存，不做初始验证。Actor动态micro预算32768保持不变。Coding/IF沿用各自默认与验收，不直接采用数学生成的性能结论。
