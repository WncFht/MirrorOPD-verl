# 八卡训练基础设施

**同步共享八卡已经实现，并且是公共领域配方的默认模式。** Student rollout、冻结 teacher FSDP2 评分与 actor 更新按阶段使用同一池，验证复用八个 student TP1 副本；`standalone` 保留旧 4+4。通用 verl 配置的默认值仍为 standalone，领域脚本负责选择共享模式并派生资源数。

当前已有目标环境共享八卡的12步真实训练指标，详见[速度与显存对照](../2026-10-21-训练管线速度与显存对照.md)。匹配训练窗口未观察到整步加速；共享run尚无完整验证，后续重点是完整验证、恢复和周期成本。既有CPU回归及两卡小模型测试仍作为独立证据保留。源码审阅基点为 `565a1fda2`，资料整理日期为 2026-10-21。

## 下一步

执行效率诊断按[调优顺序](2026-10-21-批量大小与GPU利用率调优.md#4-调试顺序先统计再短trace再做单变量对照)推进：轻量引擎统计、稳态decode短trace、固定checkpoint的Graph/并发对照，再单独比较batch变化的学习效果。本机前四张H800可用于机制验证，测量与目标A800训练分开报告。

在已观测的共享短训练基础上，补齐同预算完整验证与恢复，再比较相同token/更新/验证预算下的总成本。不要继续以“先实现共池 teacher”为待办，也不要把旧基线的 `gen` 除以二当作已取得的收益。

当前八卡约束、CPU offload 和 DP/TP1 支持边界见运行与架构。具体模型、数据、batch64、验证 570×16、长度与频率仍以[训练配方](../训练配方.md)为准；这里不复制一套参数表。改变 batch、loss 或采样分布的实验与基础设施对照分开报告。

数学算法只在 [OPD 目标文档](../opd-objective/README.md)维护；当前速度/显存对照与 MFU 分别见[运行对照](../2026-10-21-训练管线速度与显存对照.md)和 [MFU 推导](../2026-10-20-MFU计算.md)。原始数据、图和复算脚本继续位于上一级 `data/`、`figures/`、`scripts/`，本次合并不复制或改写实验数据。
