原生配对为 R1-1.5B learner 与 JustRL-1.5B，HF 配对为 Qwen3-1.7B-Base learner 与 Qwen3-8B。公共设置为 batch2、response cap16、单样本计算微批、参数和优化器卸载。HF 使用 E41 的原生提示协议及停止集合；测试预算单独覆盖为两轮、reuse1。验证每个来源固定两条样本，准确率不作为引擎通过条件。这些结果不构成正式负载性能或学习效果对照。

两个恢复场景的 schema 2 生成语义保持一致，恢复后的 applied update 均为 3。抽查 embedding、首层 q-projection 和末层 norm 的参数片段，FP32 与 BF16 转换后都存在参数变化；这证明实际更新发生，不等价于完整模型逐参数比对。结果分别见[默认 single 参数变化](../../../../../../../runs/rollout-architecture-review-20261031/gpu/default-checkpoint-delta.json)与[current schedule 参数变化](../../../../../../../runs/rollout-architecture-review-20261031/gpu/current-right-checkpoint-delta.json)。

失败证据也保留：首次测试目录预创建导致 launcher 拒绝启动；HF 最初暴露验证参数泄漏，修复后又因测试脚本沿用 R1 提示协议与停止集合而被拒绝，最终使用正确的 E41 协议通过。完整命令与排错记录在运行目录，不把失败尝试改写为通过。GPU 执行记录分别固定到 `ff5e73e6`、`75dbd9f9` 及其捕获的 patch；最后的可达性预检修正另由 CPU 检查覆盖。

此轮没有重新验收 native MoE、TP2、多 replica、CUDA graph、正式 batch64/cap7168 或性能重复测量，不把单卡短测外推到这些范围。源码已随 `c8b14ffb` 合入 main，正在运行的冻结实验保持原版本；后续 profiling 与扩展验收独立安排。

## 配置迁移

新运行只接受 `model/left/right/right_weight`；不增加旧字段自动转换层。`single` 的默认模型为 current，mixture 的默认左右引用为 current 和 teacher。明确指定配置时，single 使用 model，mixture 使用 left/right，禁止混用。

| 原字段                                    | 新字段                                                 |
| ----------------------------------------- | ------------------------------------------------------ |
| `source=student, student=current/initial` | `model.kind=current/initial`；mixture 使用 `left.kind` |
| `source=teacher`                          | `model.kind=teacher`                                   |
| `source=checkpoint, model_path=A`         | `model={kind: checkpoint, ref: A}`                     |
| `teacher_model_path=B`                    | `right={kind: checkpoint, ref: B}`                     |
| `teacher_weight`                          | `right_weight`                                         |

Fusion 默认选择 vLLM；HF 为显式参考后端。历史运行配置与数据不改写，复现时使用其冻结代码。资产 ID 解析保留；历史路径投影只用于读取历史材料。必要的 vLLM 子模型配置适配保留。

## 代码走读后的处理顺序

先处理能从代码合同和反例确定的问题，再采集性能基线。以下顺序不承诺吞吐提升，GPU profile、并发扫描和新科学训练暂缓。

| 顺序 | 问题与处理                                                                                                                                 | 验证                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 1    | 固定来源按每个 actor worker 建立单卡 replica，但复制的 rollout 配置可能继承 current 的 TP2；明确固定来源的 TP1 拓扑，并保持 current 原配置 | 双 worker、上游 TP2 的配置投影反例                               |
| 2    | 固定来源 KV 估算对显式 null 的 head_dim／KV head 数缺少回退；使用模型明确值或标准回退，保留显式 KV 预算                                    | 含 null、显式 head_dim 和显式 KV 预算的 CPU 检查                 |
| 3    | 生成计时包含随后执行的审计 RPC；分别记录生成和审计时间，保留进程生命周期显存峰值的真实口径                                                 | 用可控时钟检查阶段边界，不将旧指标解释为新口径                   |
| 4    | 公共采样器的过滤、归一化和概率融合包含重复遍历与临时张量；先列出可保持支持集和行为概率的等价改写                                           | 固定 logits 的 FP64 oracle、并列值和边界反例；未证明等价前不替换 |
| 5    | 固定来源的并发按首次阶段请求数截取，后续配额变化可能受旧上限限制；明确引擎容量和阶段请求数的区别                                           | 变配额生命周期检查后再决定容量策略；不直接增大 KV                |

第 1–3 项已在维护分支实现，属于合同修正和可观测性整理。公开策略预检原已要求普通引擎 TP1；第 1 项是把约束落实到固定 replica 的资源拥有处，不扩展多卡支持范围。新版本的 `rollout_policy_<source>_generate_seconds` 截止于 session 结果返回，随后审计单独写入 `rollout_policy_<source>_audit_seconds`；旧版本 generate 字段包含该审计成本。NVML 和 worker 显存高水位仍按各自原有时间范围解释。第 4–5 项先评审，完成后再决定 GPU 测量范围。shared_sync、sleep/wake、跨 rank 版本提交及失败排空约束保持。当前 Qwen 配对短生成通过只证明短请求执行可用，不替代同前缀数值或训练验收；已停止的自然生成测量不作为性能结论。
