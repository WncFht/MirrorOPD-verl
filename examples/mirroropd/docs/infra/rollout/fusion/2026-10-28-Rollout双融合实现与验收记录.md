## 实现入口

`verl/experimental/rollout_policy/plan.py` 定义不可变批计划、模型绑定、常数和线性系数、全局轨迹配额以及独立请求 seed。UUID 只用于 TQ 身份；稳定数据行、批内 occurrence、collection step 和 response index 参与路由与采样。线性 optimizer 时钟读取已成功应用的更新次数，旧 checkpoint 的未知计数会被拒绝。

`collector.py` 的 collector 是 parent 状态的唯一写入者。`AgentLoopWorkerTQ.generate_sessions` 负责指定 response index 的生成、判分和 TQ 发布，并阻塞返回。两个来源共享原有 submission；所有 session 完成后才发布 parent finished。任一来源失败则整批失败；远端排空不能确认时终止运行，不进入下一来源或训练。

`runtime.py` 在 shared-sync trainer 的提交入口执行计划。Trajectory mixture 使用现有 vLLM 整请求生成，两来源顺序执行。Frozen vLLM 引擎采用独立 replica rank 和名称，避免与默认 student 的 IPC 地址冲突。Token mixture 通过 `hf_fusion` adapter、replica 和请求微批服务执行；逐 token 的 logits、双 KV 和采样留在 actor worker 内的独立推理副本中。

`ActorRolloutRefWorker.update_weights(target="fusion_student")` 复用已有全 rank 流式参数导出。每个接收目标在复制前失效；接收错误后仍排空 tensor 流，全部 rank 汇总成功并完成 barrier 后才发布版本。Teacher 和 initial student 不接收 actor 更新。新模式按需同步 current 目标；验证仍使用默认 current student vLLM。

`hf_decoder.py` 保留双 KV、单次 prefill、末位置 logits 和每请求随机流。公共采样器使用 FP32 logits 融合，再施加一次公共温度和 top-k/top-p，记录最终选中 token 的 log-prob。合法词表掩码在微批内复用。可选活跃行压紧同时重排两侧 KV、请求身份、位置和完成状态。停止规则保持 raw-token 语义。

## 配置与运行

默认配置为 `rollout_policy.mode=single source=student student=current`，继续调用既有生成路径。新增模式首轮限定单节点 shared-sync、FSDP2、dense 文本 learner、同 token-ID 映射、单轮文本和 TP1。动态过滤、refill、多轮、LoRA、sampler top-k score payload 和异构权重 transport 尚未验收，启动前拒绝。

四卡功能验收入口：

```bash
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh token_mixture current
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh token_mixture initial
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh trajectory_mixture current
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh trajectory_mixture initial
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh single initial
bash examples/mirroropd/smoke/smoke_rollout_fusion.sh single current rollout_policy.source=teacher
```

脚本选择 1.7B-Base + 8B，显式使用 `[151643,151645]` 停止集合。`TEACHER_MODEL` 可切换到本地 30B-A3B-Instruct-2507。该脚本是短 cap 功能验收入口，不能替代正式 batch64/cap7168 性能结果。checkpoint 来源可设置 `rollout_policy.source=checkpoint rollout_policy.model_path=/本地/checkpoint`。原始 initial 始终由 learner 初始化路径定义，不随恢复路径改变。

每个生成批将计划写入 `trainer.default_local_dir/rollout_plans/step_<outer>.json`，包含来源、版本、系数、seed、采样规则及预期 session。训练日志增加各来源准备、生成、释放和完整批次墙钟；完整批次时间覆盖 `prepare_step` 内阻塞工作。

## 环境

旧 `envs/mirroropd` 使用 Torch 2.7.1、Transformers 4.57.6 和 vLLM 0.10，缺少 TransferQueue。隔离验收环境位于 `/tmp/mirroropd-fusion-venv`，安装 vLLM 0.25.1 的官方 CUDA 12.9 wheel、Torch 2.11.0+cu129、Transformers 5.12.1、TransferQueue 0.1.11。FlashAttention 2.8.3 已从源码构建并通过导入；TorchCodec 使用 0.17.0+cpu，避免其默认 CUDA 13 wheel 与当前 CUDA 12.9 环境冲突。W&B 固定为 0.22.2，以保留仓库离线日志测试使用的读取接口。

CUDA 兼容库解包在工作区 `cache/fusion-runtime/cuda-compat-12-9/`，只通过验收进程的 `LD_LIBRARY_PATH` 使用。没有修改系统驱动或其他环境。环境安装日志保存在原始记录目录中。官方文档说明了按应用选择兼容库的部署方式。[^cuda-compat]

## 待完成验收

后续需要在最终选定的优化实现上重复真实训练、验证、保存与恢复，补齐 initial 恢复和线性系数端点；完成两模型配对的 batch64/cap7168、三个可行微批点、至少三次重复，以及默认 current single 的同负载回归。Base/Instruct 的停止质量和自然长度单独报告。已有基础路径短训练不能替代最终优化路径验收。

数值门槛在测量前固定为 logits 绝对误差 0.25、最终概率绝对误差 0.01、选中 log-prob 绝对误差 0.125、FP64 采样 oracle 误差 2e-6。未通过的候选保留原始 JSON，不放宽门槛。Hopper 上关闭 BF16 split-K、采用 cuBLASLt 并禁用 cuDNN SDPA 的作用域只覆盖融合推理，退出后恢复 learner 设置。旧 cap128/cap256 扫描使用了不同的 chat-template kwargs，仅作为探索，不纳入正式 G7 对照。

默认路径回归采用相同的 compiled CUDA graph、固定权重和确定性请求。首次运行在两个版本比较之前遇到 Torch 2.11 的确定性模式与 Inductor combo-kernel benchmarking 冲突；重测仅关闭该 benchmarking，保留 combo kernels 和 CUDA graph，两版本配置一致。该失败启动不计入性能样本。

MoE 的参考与优化路径使用相同的固定算术：FP32 中间激活、固定 RMSNorm/router 计算，以及按逻辑 KV 位置分块的 causal GQA。参考路径通过完整前缀重算检查缓存，优化路径使用 append KV 与 CUDA graph；独立的 FP64 kernel oracle 检查 attention、GEMM 与 RMSNorm 数学。该对照不声称与未经修改的原生 BF16 HF 实现逐位相同，也不通过放宽容差接纳旧候选。

早期真实训练和 `fusion-final-20261028-*` 运行主要证明原 trainer 接口、更新、五集验证、保存及恢复可用。最终精度路径的完整短矩阵与正式长 cap 训练仍需独立验收，不能用早期较低精度候选的训练记录替代。

SKD、AdaSwitch 不进入实现和验收。完整学习曲线也不在基础设施短训练证据中冒充已完成结果。
