将本地计算、通信与数据等待分开

先看 driver 的 teacher / actor 总墙钟时间，再看各 rank 的 micro-batch、hidden IO 和计算区间，最后检查 Torch / Nsight 中的 kernel、NCCL 与 memcpy 重叠。各 rank 求和和所有 kernel 时长求和均不能替代关键路径。

当前 async write 覆盖 CPU → TQ，prefetch 覆盖 TQ → CPU；teacher hidden 的 GPU → CPU 仍是同步路径。默认 precompute 的 head 梯度在 forward 中准备，backward 应用缓存的梯度并继续 backbone 反传。

Teacher / actor 与 hidden IO

主机侧嵌套区间会重叠。线程不同的 read/write 用独立泳道展示。

Micro-batch 工作量

每点为一个完整 micro-batch 主机区间。输入 token 包含 prompt / response；Full-KL 有效 token 数需用 loss mask 另核对。rank 编号相同也可能属于不同角色。

原始 GPU trace 覆盖

Actor Torch trace 经同进程 backbone 事件校准后用于 GPU 区间统计；rollout trace 保持独立时钟。vLLM 的 Torch 窗口仅覆盖前 128 个 engine iteration；Nsight 此次只配置训练 worker。后续诊断须打开原始文件。
