# 融合算子接入与验证

## 接入方式

新增可选 `precompute_fused` backend，把已经通过 H800 算子和四卡固定输入对照的融合实现收敛到 `verl/trainer/distillation/full_vocab_triton.py`。原实验脚本 `fused_candidate.py` 保留兼容导入，避免维护两份实现。历史冻结工作树继续保存其当时的独立候选代码。

```bash
FULL_KL_BACKEND=precompute_fused \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E13
```

E13/E14 默认仍为 `precompute`；当前不因算子单测加速而更改默认训练配方。`precompute_fused` 的 GPU 实现仅用于 BF16 CUDA 输入，CPU 与其他 dtype 回退到原 `precompute`，使 FP64 参考与 CPU 测试保持可用。Triton 只在命中 CUDA BF16 分支时导入。原有 untied Qwen2、FSDP2、SP=1、温度 1、token-mean 等管线限制保持不变。

## 数值与内存

实现继续返回未归一化 token sum，teacher hidden/head 冻结，student hidden/head 两条一阶梯度同时返回。全局 token 归一化和 FSDP head hooks 仍由既有 engine/loss 层负责。Triton 负责分块统计与 logits 梯度，投影和 `dH/dW` 仍使用 cuBLAS；token chunk 控制 logits 工作区。

GPU 候选的已有证据见[首次测量](2026-10-23-首次测量与后续验证.md)。接入后的 CPU 检查共 32 项通过，包括新 backend 的 FP64 值/VJP、空本地 token、teacher 无梯度，以及 Triton CPU 解释器的 8 组边界与数值范围测试。生产名称下的四卡更新/恢复与非零学习率完整入口也已通过，最终数据、失败修复及启动方法见[优化结论与启动](2026-10-23-Full-KL优化结论与启动.md)。

## 交错复测

运行目录 `outputs/full-kl-confirmation-20261023`，冻结源码 `fc81ec6a9`。采用同 chunk=512、batch=32、token budget=16384、activation checkpointing 开启的 A–B–B–A 顺序：A 为 `precompute`，B 为原候选。每次运行 12 步，预热 3 步，保留 9 个无 profiler 样本。所有输入和 lr=0 权重相同。

复测用于判断真实管线收益和测量波动；不以 head 单卡中位数替代 actor/完整周期耗时，也不把 lr=0 试验作为质量评测。运行器持有与初始队列相同的 GPU 锁，每项开始前重新确认前四张卡持续空闲。
