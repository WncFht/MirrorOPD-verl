# Full-KL 分层测量与优化方案

## 目标与证据范围

在保持固定 prefix 上全词表 reverse KL 目标、有效 token 归一化和 teacher 冻结语义不变的条件下，定位当前 E13 路径的计算、传输、通信和显存瓶颈。采用 Aleph Alpha 的小规模筛选、时间线定位、扩大规模复核方法[^aleph]。本机结果只覆盖 H800 与当前模型；八卡 A100 集群结果需要独立验证。

当前生产 `precompute` 在 head forward 内预计算 student hidden 和 head 梯度，正常 backward 再乘上游归一化系数并传递到 backbone。比较不同 backend 时按投影、归一化、梯度计算分组，不按原始 forward/backward 标签推断节省了多少工作。

## 观测与分层实验

| 层级 | 固定项 | 改变量 | 输出与边界 |
| --- | --- | --- | --- |
| 单卡 head/loss | BF16、V=151936、d=1536、随机种子、有效 token 4096/32768 | backend、token chunk 128/256/512/1024 | loss/梯度误差、无 profiler 中位时间、显存；不含 backbone/FSDP/TQ |
| 四卡真实模型 | 同一 student/teacher、同一批历史数学回答重新分词、lr=0、batch=32 | head backend、chunk、checkpointing | teacher/actor 阶段、CUDA trace；直接调用生产 worker，不含 Ray/TQ/vLLM |
| 四卡完整训练 | 数学配方、batch=64、response 上限 7168、学习率 1e-6、4 步 | async write/prefetch 同开或同关 | 真实 Ray/TQ/vLLM；第 3 步采 profile；不保证两次生成 token 完全一致 |

固定输入管线的零学习率只用于保持比较权重一致，optimizer 仍执行并创建 AdamW 状态。其输入来自已保存的数学验证回答，重新分词可能不同于原始生成 token ID；该输入只用于工程测量，不用于宣称质量结果。第一步预热，最后一步采详细 trace，其余步骤提供未采集的时间样本。

完整训练为控制启动成本使用 eager rollout，区别于 E13 默认 graph rollout。它可定位 TQ 和阶段间开销，但不能直接充当 graph 配方的最终吞吐。每任务记录原始启动参数和源码提交。若需要正式发布 E13 吞吐收益，应补足更长无 profiler 窗口、交错重复顺序及 graph 配方确认。

## 工具与埋点

PyTorch Profiler[^torch] 采 CPU/CUDA 关联；Perfetto 读交互 trace；Nsight Systems[^nsys] 以 CUDA profiler API 截取 head 范围，并使用 NVTX 语义标签。显存快照可通过固定管线的 `--memory --trace` 额外启用，默认性能测量不记录堆栈。Nsight Compute 留给确定的热点，计数器权限需另行确认。

新增标记涵盖 student/teacher projection、KL 归一化、logits/hidden/head 梯度、backward 梯度应用、backbone、head loss、teacher hidden D2H、teacher head 获取、micro-batch H2D、TQ 读取等待和写入等待。标记不插入 CUDA synchronize；测量脚本只在明确计时边界同步。

Shared teacher 与 actor 在 shared_sync 中通过 colocated worker 构造。连续进程级 profiler 可覆盖同进程 teacher 操作，因此不能仅因 teacher 缺少独立 profiler 配置就断言没有 trace；也不能盲目为每个逻辑角色重复启动同一进程的 profiler。完整训练 trace 应检查 `full_vocab/teacher_forward` 是否实际存在。后台 IO 线程的 Torch annotation 可能受线程采集范围影响，等待标记与 nsys/NVTX 可补充定位。

## 融合候选

实验模块 `scripts/fused_candidate.py` 保留 cuBLAS 投影和梯度矩阵乘，把词表范围的归一化和 logits 梯度计算改成三个 Triton pass：

1. 每行每个词表块计算 student/teacher 最大值、指数和、加权 logit gap。
2. 合并分块统计，得到两边 log normalizer、student 加权 gap 均值和 KL。
3. 生成 BF16 logits 梯度，交给原有 FP32 梯度累加矩阵乘。

设 $d_a=z^p_a-z^T_a$，$\mu=\sum_a p_a d_a$，则

$$
K=\mu-\log Z_p+\log Z_T,\qquad \frac{\partial K}{\partial z^p_a}=p_a(d_a-\mu).
$$

该写法减少完整词表的 FP32 softmax/log-prob 中间张量。它仍有两份当前 token 块 logits、BF16 logits 梯度及完整 head 梯度累加器，不能宣称消除了所有词表相关内存。候选只支持 BF16 CUDA，一阶梯度；CPU/FP64 生产实现保持原样。

数值门控覆盖不整除词表、4096 块边界、实际词表 151936、较大 logits、相同 teacher/student logits、loss 和 hidden/head 梯度。只有通过算子门控才启动候选的四卡真实模型比较。候选用进程内显式替换进入 probe，不影响 E13 的配置或默认训练代码。

## 统计与改进判定

- 吞吐用相同工作量下的无 profiler 墙钟时间，报告预热、样本数及各次原始值。
- CUDA kernel duration 求和表示工作量；按设备求时间区间并集才能计算 busy 时间和计算/通信重叠。NCCL 未与计算重叠不自动表示关键路径等待。
- allocated、reserved 与整卡显存分开报告。PyTorch allocator 的快照不能完整覆盖 NCCL 等外部分配[^memory]。
- 算子快不等于整步快：额外显存可能缩小训练 micro-batch，或把瓶颈转移到 backbone/通信。
- 完整训练的 IO 开关对照至少同时检查生成长度、有效 token、各卡负载。四步诊断用于找瓶颈，不能单凭一个短窗口宣称稳定百分比收益。
- 优化完成需同时满足数值对照、真实 FSDP2 更新路径通过，以及目标硬件上可重复的收益。未满足时保留为实验候选。
