# Olmo3 与 Light-R1 阶段链接入验收

BayesRL／Olmo3-7B 与 Light-R1-14B 在本页记录的验收源码版本中使用 V1／FSDP2、Full-vocab RKL 和统一评估器。工程配置可由共同 Base 分别学习两类教师。Olmo3 的公开前序支持同一 SFT checkpoint 对照；Light-R1 在 R1-Distill 后另有 3K SFT，当前 E76／E77 不满足这个阶段匹配条件。公开训练前序与 revision 见[阶段链选型](../../../settings/模型与师生配对.md#olmo3)。两条链已通过 HF 梯度、32K 前向、vLLM 编译生成、原生更新、终点重载与独立 HF 加载验收；完整 50 outer 实验尚未启动。

## 2. 共同 SFT 输入协议

输入协议对齐与训练前序匹配分别核查。下述协议保证同一 token-ID 动作定义；工程验收不能证明 E77 就是 E76 的 RL 初始化权重。Light-R1 的额外 SFT 与缺失中间 checkpoint 见[阶段链核查](../../../settings/模型与师生配对.md#light-r1-lineage)。

每条链采用其 SFT tokenizer 与聊天模板。公开 checkpoint 保持原位，验收版本中的协议资产准备器 `assets/stage_protocols.py`创建独立的有效模型目录：权重文件链接到固定原版文件，tokenizer 和模板复制自固定 SFT 版本，配置只对齐 BOS／EOS／PAD 元数据。模型层数、注意力、RoPE、head 和参数数值均不改变。每个目录保存 `stage-protocol.json`，记录原始权重、tokenizer 来源、允许的标签变化及有效元数据哈希；checkpoint identity 同时绑定这份记录。

| 链       | 有效 Student 别名          | SFT Teacher 别名            | SFT+RL Teacher 别名        | 输入 family／停止 ID |
| -------- | -------------------------- | --------------------------- | -------------------------- | -------------------- |
| Olmo3    | `Olmo3-Base-BayesProtocol` | `Olmo3-SFT-BayesProtocol`   | `Olmo3-C3PO-BayesProtocol` | `default`／100257    |
| Light-R1 | `Qwen2.5-14B-R1Protocol`   | `R1-Distill-14B-R1Protocol` | `Light-R1-14B-R1Protocol`  | `deepseek`／151643   |

Olmo3 三份词表和 ID 定义相同，使用 IVON-SFT 发布的系统消息和 `<think>` 生成前缀。Base 原来没有聊天模板，采用共同模板是实验输入条件。HF 的 32 层结构、每四层中的三层 4096 滑窗与一层全注意力、YaRN 配置均保留。Full-vocab 适配调用原始主干及其线性 head，不把它替换成 Qwen 或 Llama 主干。

Light-R1 使用 R1-Distill-Qwen-14B 的模板和动作标签。Base 的七个特殊 ID 采用 R1 定义，其中角色、thinking 和 BOS 标签与原 Qwen 模板不同。参数行不重排；这是明确重定义输入／动作协议的 Base 初始化，不能解释成原生 Qwen 聊天协议下的实验。

|     ID | Qwen Base 标签           | 共同 R1 标签              |
| -----: | ------------------------ | ------------------------- |
| 151643 | `<\|endoftext\|>`        | `<｜end▁of▁sentence｜>`   |
| 151644 | `<\|im_start\|>`         | `<｜User｜>`              |
| 151645 | `<\|im_end\|>`           | `<｜Assistant｜>`         |
| 151646 | `<\|object_ref_start\|>` | `<｜begin▁of▁sentence｜>` |
| 151647 | `<\|object_ref_end\|>`   | `<\|EOT\|>`               |
| 151648 | `<\|box_start\|>`        | `<think>`                 |
| 151649 | `<\|box_end\|>`          | `</think>`                |

准备器比较 tokenizers 解析后的分词、归一化、decoder 和 BPE merges；旧版字符串 merges 与新版二元数组按相同解析定义比较。只允许明确登记的七个特殊 ID 采用 R1 的标签及 added-token 属性，其他差异会退出。四个配对的有效 tokenizer 均通过严格合同，输入映射为 identity；这个结果描述的是共同协议目录，不是原版 Base 与 R1 tokenizer 天然等价。评分保留原生完整 head，分别为 Olmo3 的 100278 维与 Qwen 的 152064 维，不合并 EOS 动作。

## 4. 已完成的验收与待完成项

环境沿用 MiMo 验收：H800、PyTorch 2.11.0+cu129、Transformers 5.12.1、vLLM 0.25.1+cu129、Ray 2.59.0。数据和模型版本分别由 prepared manifest 与模型 registry 固定。

| 检查                             | Olmo3                                        | Light-R1               |
| -------------------------------- | -------------------------------------------- | ---------------------- |
| tokenizer、head 工程合同         | E74／E75 通过                                | E76／E77 通过          |
| HF 普通 logits 与 callback       | 逐元素相等                                   | 逐元素相等             |
| 合成目标 RKL 反传                | 梯度有限                                     | 梯度有限               |
| HF 总长 32768                    | 通过，保留混合滑窗                           | 通过                   |
| vLLM 编译路径总长 32768          | 32767 输入＋1 生成通过                       | 32767 输入＋1 生成通过 |
| 跨样本打包隔离                   | 4203＋4307 token，改变第一条时第二条差异为 0 | 复用既有 Qwen2 路径    |
| 原生 bootstrap、更新与公共读出   | E74 已通过                                   | E76 已通过             |
| 终点导出、原生重载、独立 HF 加载 | 已通过                                       | 已通过                 |

六份协议目录的全部参数名、形状与 HF 原始主干相符，见[完整参数布局审计](../../../../../../runs/stage-chain-adaptation-20261101/checkpoint-layouts.json)。四个师生配置的 tokenizer／head [CPU 合同](../../../../../../runs/stage-chain-adaptation-20261101/pair-contracts.json)已保存。HF 证据分别见[Olmo3](../../../../../../runs/stage-chain-adaptation-20261101/olmo-hf-a02/complete.json)、[14B](../../../../../../runs/stage-chain-adaptation-20261101/light-hf-a02/complete.json)；vLLM 证据分别见[Olmo3](../../../../../../runs/stage-chain-adaptation-20261101/olmo-vllm-a01/complete.json)、[Light-R1](../../../../../../runs/stage-chain-adaptation-20261101/light-vllm-a01/complete.json)；[打包隔离结果](../../../../../../runs/stage-chain-adaptation-20261101/olmo-packed-complete.json)使用与原生 FSDP 相同的 attention patch。

原生验收使用 2 卡、8 道真实公共题、每题 1 答、公共回答 cap256；训练为 128 题、回答 cap128、reuse1、outer1。它覆盖每条链的 SFT+RL 教师，SFT 分支另外通过相同主干与输入协议的配对和入口合同。这个工程预算不计入四组正式训练，也不提供 SFT／RL 吸收结论。Olmo3 的[源码哈希](../../../../../../runs/stage-chain-adaptation-20261101/native-a01/source-hashes.json)与 14B 的[CPU offload 源码哈希](../../../../../../runs/stage-chain-adaptation-20261101/native-cpu-a03/source-hashes.json)分别保存。

14B 少于 4 卡时预设自动启用 `actor_rollout_ref.actor.fsdp_config.offload_policy=True`，以 FSDP2 逐层 CPU offload 保存完整 FP32 主权重与 AdamW 状态；两卡验收使用此设置；教师仍按阶段搬运。参数不冻结，也不降低主权重精度。该可选执行方式的生命周期见[教师与 actor 状态管理](../../architecture/teacher.md)。默认四卡配方继续使用阶段搬运，四卡吞吐尚未实测。

完整默认配置独立冻结在[预设计划](../../../../../../runs/stage-chain-adaptation-20261101/catalog-a02/plan.json)，这些配置保留 50 outer／reuse32，尚未提交完整训练。

两条链各完成 1 次真实 optimizer 更新，两个终点的原生重载逐题 RKL 最大误差均为 0。独立 HF 加载分别读入 355／579 个 FP32 张量，并完成有限前向。证据见[Olmo3 导出审计](../../../../../../runs/stage-chain-adaptation-20261101/native-a01/E74/run/evaluation/final-model/export-audit/manifest.json)、[Olmo3 HF 加载](../../../../../../runs/stage-chain-adaptation-20261101/native-a01/E74/hf-load.json)、[14B 导出审计](../../../../../../runs/stage-chain-adaptation-20261101/native-cpu-a03/E76/run/evaluation/final-model/export-audit/manifest.json)、[14B HF 加载](../../../../../../runs/stage-chain-adaptation-20261101/native-cpu-a03/E76/hf-load.json)与[完整验收状态](../../../../../../runs/stage-chain-adaptation-20261101/native-complete.json)。这项独立 HF 检查验证可移植加载与有限前向，数值相等证据来自原生重载。

## 5. 准备与入口

模型权重可通过已有 `assets.prepare_models` 下载上述六个公开别名，然后构建协议目录。命令从仓库根目录执行，使用已配置本项目依赖的 Python 环境。

```bash
python -m examples.mirroropd.assets.stage_protocols --models all
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E74
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E75
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E76
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E77
```

协议准备遇到未声明的 token／分词变化、已有目录元数据变化或原权重链接改变时会退出，不覆盖既有资产。训练入口遇到不完整的 teacher-specific bootstrap 也会退出。实际分配 GPU 后，按公共统一评估流程分别准备两个 Base 的 initial 银行和四个 teacher 银行，再进入各自训练；同一 Base 的两个分支可复用完全相同的 initial 产物，经 finalize 绑定核对。
