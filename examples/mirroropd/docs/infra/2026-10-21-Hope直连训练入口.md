# Hope 直接调用训练配方

## 决策

Hope 的 `worker.script` 直接执行 `examples/mirroropd/run_<领域>_deepseek_r1_1_5b_fsdp2.sh`，不再维护 `hope/mirroropd/run.sh`。该决策已落实到仓库内的 Hope 配置；接收端本地 `.hope` 文件需按下文完成一次迁移。

触发原因是共享八卡模式切换时，公共配方已经默认 `shared_sync`，接收端旧 Hope 包装脚本仍强制导出 `STUDENT_GPUS=4`、`TEACHER_GPUS=4`，启动检查因此退出。`hope/` 按传输约定保留在各机器本地，源码包不会覆盖它；独立维护包装脚本使训练默认值出现两个来源。

训练参数、执行模式和日志行为统一由[公共配方](../../_run_single_teacher_fsdp2.sh)负责。Hope 配置保留队列、镜像、资源申请、任务挂载路径、领域选择及明确的实验覆盖值。共享八卡默认 `8+0`、standalone 默认 `4+4`，均由公共配方派生，不在 Hope 命令中重复设置。

## Worker 命令

在开发机本地 `hope/mirroropd/mirroropd.hope` 的 `[roles]` 中，将 `worker.script` 替换为这一行：

```ini
worker.script = bash -lc 'CUDA_VISIBLE_DEVICES="${CUDA_VISIBLE_DEVICES:-0,1,2,3,4,5,6,7}" VERL_USE_UV=0 exec bash "/mnt/dolphinfs/hdd_pool/docker/user/hadoop-hmart-poistar/fanghaotian/MirrorOPD-verl/examples/mirroropd/run_${DOMAIN:-math}_deepseek_r1_1_5b_fsdp2.sh"'
```

该绝对路径是 Hope 容器内的共享挂载路径。脚本自行定位仓库并切换工作目录，因此不依赖平台最初的工作目录。本机研究 checkout 的 `/mnt/tidalfs-bdsz01/...` 路径不应复制进远端任务配置。

调度器提供的 `CUDA_VISIBLE_DEVICES` 原样保留；没有提供时，使用该八卡作业容器内的逻辑设备 `0..7`。`VERL_USE_UV=0` 固定原生 Python 路径。其余运行默认值位于公共配方：解释器为仓库 `.venv-native/bin/python`，W&B 默认 offline，`TOKENIZERS_PARALLELISM=false`，`OMP_NUM_THREADS=1`，stdout/stderr 写入 `train.log`。除明确固定的原生模式外，公共配方保留既有环境变量覆盖能力。

默认领域为 math。Code 或 IF 在 `.hope` 的 worker 环境中设置 `afo.role.worker.env.DOMAIN = code` 或 `if`；IF 还需提供 `OPENCOMPASS_ROOT` 和 `NLTK_DATA`。独立 4+4 对照设置 `afo.role.worker.env.DISTILLATION_EXECUTION_MODE = standalone`。这些设置不会改变单机申请八卡的资源声明。

## 预检与迁移

依赖检查继续使用 `make native-check`，数据检查使用 `make assets-check`。原 Hope 包装脚本中的依赖解压、导入检查及逐卡矩阵乘法不再每次启动自动执行。更换镜像或运行环境时，在目标 GPU 容器中单独完成依赖与 GPU 运行验收；开发机上的导入结果不能替代任务容器验收。

迁移步骤：

1. 将新版源码包解包到共享仓库；`examples/mirroropd/` 随源码更新。
2. 在开发机本地 `.hope` 中替换上述 `worker.script`；移除遗留的固定 `STUDENT_GPUS=4`、`TEACHER_GPUS=4` 覆盖，除非它们属于明确的 standalone 对照配置。
3. 旧 `hope/mirroropd/run.sh` 已无调用关系，可以删除。源码解包保留 `hope/`，不会代替用户修改本地 `.hope` 或删除这个旧文件。
4. 用 `DRY_RUN=1` 预览命令或 `CONFIG_ONLY=1` 解析配置，确认 shared 模式下 `trainer.n_gpus_per_node=8`、`distillation.n_gpus_per_node=0`、rollout TP=1。
5. 按原方式执行 `make opd-submit`。后续训练入口更新随源码包交付，通常无需再改 Hope 的启动命令。

直接预览三个领域的配方：

```bash
DRY_RUN=1 bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh
DRY_RUN=1 bash examples/mirroropd/run_code_deepseek_r1_1_5b_fsdp2.sh
DRY_RUN=1 bash examples/mirroropd/run_if_deepseek_r1_1_5b_fsdp2.sh
CONFIG_ONLY=1 bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh
```

## 验证范围

[启动测试](../../../../tests/examples/test_mirroropd_math_launcher_on_cpu.py)从真实 `.hope` 读取 `worker.script`，只将远端挂载前缀替换为本机 checkout 后执行，覆盖三个领域、shared/standalone 两种模式、原生解释器、八卡资源预算、设备 UUID 保留和设备环境缺省回退。现有源码归档启动测试覆盖日志、退出码与无需 Git 的解包目录。测试不启动 Hope 作业或 GPU 训练。
