# 四域 RKL 实验的 verl 接入方案

状态：2026-10-31。后续训练与 RKL 验证默认采用同一 GPU 池分阶段串行执行（`shared_sync`），保留各阶段内部的多卡 FSDP2；固定 2＋2 并行保留为历史性能对照。原生 Trainer 已接入来源留出与历史 RKL，JustRL → R1-1.5B 已完成四卡、batch128／reuse32／cap7168、两轮 64 次更新验收。完整四域协议尚有公共银行、数据冻结和恢复等缺口，见第 8 节。科学设置由[四域 RKL 协议](../../experiments/teacher-transfer/transfer-mechanism/2026-10-31-四域单域训练与RKL评估协议.md)维护，结果见[性能实测](../performance/full-vocab/training.md)。

允许当前 outer 内临时复用 teacher hidden，禁止训练前预计算、长期保存全题池 hidden；loss 平均方式仍待决定。串行决定固定执行路线，不同时冻结评估频率或 loss 归一化。

## 1. 推荐路线与已有能力

当前训练入口走 `verl.trainer.main_ppo` → V1 同步 Trainer → vLLM rollout → FSDP2 actor 与 full-vocab RKL。`examples/mirroropd`管理实验配置、数据 manifest、轨迹银行和分析；studies 保留历史与数值参考，不承担新协议的 optimizer 循环。

| 功能                                  | 当前状态                                                       | 接入动作                                                                 |
| ------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| batch128、n1、reuse32、50outer        | 已有配置与 optimizer 计数                                      | mini-batch128、ppo_epochs32、total_training_steps50，验收实际 1,600 更新 |
| current student rollout 与参数同步    | V1 同步 Trainer／vLLM 已具备                                   | 每 outer 完成 32 更新后同步，下一批使用新权重                            |
| 全词表 RKL 与有界 teacher hidden 复用 | shared-sync 已有                                               | 控制在当前 outer／评估调用内，不建立全题池 latent 目录                   |
| Loss 归一化                           | 当前 full-RKL 为有效 token 均值                                | 保持待定，先不按固定 128×7,168 分母改梯度                                |
| 固定 token 只读 RKL 评分              | 已接入可选固定轨迹回调及原生 engine 评分                       | 补公共银行、teacher rollout 和恢复验收                                   |
| 原始轨迹持久化                        | 已保存训练与 initial student 原始 tokens、mask、题目 ID 和版本 | 补完整模板身份、终止原因与跨运行 manifest                                |
| 动态历史 128 条                       | 50 批抽样算法检查与两轮真实训练接入均通过                      | 补随 checkpoint 的状态恢复                                               |
| 模型配对验收                          | shared-sync 严格检查 token-to-ID                               | 迁移 studies 的支持集／模板特殊条件，逐对检查                            |
| Checkpoint／optimizer 恢复            | verl 已有                                                      | 补历史抽样与轨迹引用状态，不复制保存器                                   |

仅使用物理 GPU0–5。128 不能整除 6，六卡 DP 需验收 padding 样本不进入抽样、均值和科学题数；也可按 2 卡或 4 卡分组比较吞吐。

## 2. RKL 需要的计算

给定相同前缀，teacher 和 student 分别产生下一 token 分布。RKL 对全词表使用 $p_\theta$ 和 $q$，因此需要两侧的骨干与输出层结果。两侧骨干在输入已知时没有先后数学依赖，可以串行，也可以在不同资源上并行；KL 归约必须等待对应位置的两侧输出就绪。

rollout 生成通常只保留采样 token 及少量 log-prob，并不能替代 full-vocab 分布。对 current-student 验证回答，默认仍让同一 checkpoint 重新 teacher-force 前向评分；避免把 vLLM 截断采样概率当成原生全词表概率。

teacher 冻结、当前 batch 前缀固定，因此 teacher 骨干算一次即可临时保存 hidden，供 32 次 student 更新复用。Student 每次更新都必须重新前向。teacher 输出层投影仍会按 token／vocab 块重算；不物化整批 $[B,L,V]$。本项目此前容量测算：128×7,168、Qwen 词表的整批 FP32 log-prob 约 519GiB，而 BF16 hidden 根据 teacher 尺寸约 3.5–7GiB。

## 3. 推荐的同步 outer 顺序

1. 同步好的 student vLLM 生成本批 128 条回答，保存真实 token；没有全题池 teacher 预计算。
2. vLLM 休眠。共享池加载 teacher，对当前训练批评分，临时将 hidden／positions 写入 CPU TQ。当前实现的训练评分与评估评分分别执行；合并 teacher 驻留尚未实施。
3. teacher 骨干卸载；actor 加载训练状态，复用本批 teacher hidden 执行 32 次更新。
4. 更新历史集合；若到评估点，在更新后的 student 权重上评分来源留出 128 题和历史 128 条，采用同一 RKL 算子。评估也先加载 teacher 准备临时 hidden，再卸载 teacher、加载 student 评分，读完清理。
5. 如到公共评估点，调度固定银行 RKL 及可选 current student 生成／任务评分／RKL。固定评估输入的 teacher 可提前算，current 回答生成前无法准备其完整 teacher 结果。
6. 固定 RKL 读出在 `on_before_weight_sync` 完成；正常 `on_step_end` 随后同步新权重到 vLLM。当前 outer 的临时 payload 按生命周期清理，再处理下一批新题。

训练与评估合并 teacher 驻留属于后续性能优化。历史候选集合可以在本批回答生成后确定，但其 student 读出必须在 32 次更新后。缓存始终有容量边界；公共 32K 银行应按评估批流式处理，不一次性保存所有 teacher hidden。TQ 后端可能有存储策略，需验收不会把临时 payload 变成无界磁盘档案。

暂不在 32 次更新未完成时，用旧权重抢先生成下一训练批。这会改变“每 outer 开始使用最新 student”的协议；异步生成可以后续单列带模型版本滞后的条件。更新完成后，若评估使用冻结快照和独立资源，下一批生成可与只读评估重叠，但先做同步版本更易验收。

## 4. 默认采用共享池串行执行

训练和验证都使用相同的已分配 GPU 池，teacher 与 student 分阶段加载。串行指两种模型的阶段先后；每个阶段仍使用全部分配 GPU 的分片与批处理。当前真实训练验收为四卡，不将它外推为六卡 DP 已验收。

Qwen3-1.7B student／Qwen3-8B teacher 的 768 条真实轨迹上，调优后的原生精度串行中位耗时为 75.8 s，固定 2＋2 为 92.7 s；串行约快 18.2%，也省去评估 mesh 切换与跨组 hidden 流管理。详见[完整配置和数值检查](../performance/full-vocab/training.md#串行与并行优化后的配对结果)。这一实测结合实现复杂度，支持采用串行作为默认路线。

同卡双模型共驻、固定 2＋2、2＋4／3＋3 和独立评估池保留为已有调研与可选性能实验，不作为当前接入前置任务。后续模型沿用串行路线，根据尺寸和实际长度调整微批 token budget；新的 GPU 数量或大模型组合仍需容量与数值验收。仅使用物理 GPU0–5。

## 6. _validate 的职责

可以让`_validate()`作为统一评估调度入口，但不把模型前向、KL kernel、文件管理、抽样和 accuracy verifier 都堆进这个函数。

建议三个可组合任务：

- `fixed_rkl`：输入固定 token 银行，评分 initial student／teacher 前缀；不生成。
- `history_rkl`：输入动态 128 条真实训练轨迹，调用同一固定 token scorer。
- `current_rollout_eval`：当前 checkpoint 先生成公共回答；同一份回答交给任务 verifier，并用固定 token scorer 计算 current-rollout RKL。

以上名称是拟议接口，不是已实现配置字段。`_validate()`／评估协调器只决定本轮有哪些任务、固定模型版本、调度资源并收集指标；数值服务复用 verl worker／engine 和 full-vocab 算子。训练与评分共用支持集、预测位置和精度合同，平均方式待定时先记录每题 sum／有效 token／cap。

来源留出、历史 RKL 和公共 current 生成的正式频率仍待实测。不要仅设置现有`test_freq=1`就沿用默认重新生成＋accuracy 流程。当前 V1 验证在更新后、TQ 清理前执行，适合作为接入点；历史记录和采样身份也必须在清理前保存。

### 6.1 原生固定轨迹读出的实现

`verl.trainer.distillation.readout.FixedRKLReadout` 已实现来源留出与历史训练轨迹的 RKL 读出，并通过四卡两轮短验收及 batch128／reuse32／cap7168 的 64 次更新验收。训练仍使用原生 V1 `shared_sync` 循环；`_validate()` 只分派回调，回调通过现有 shared teacher worker 和 actor engine 完成评分。

职责分为三层：`readout.py` 管理固定 token、历史抽样和逐题文件；actor worker 处理模型驻留及只读状态核对；`evaluation.py` 调用现有 `project` 和 Triton `weighted_rows(..., gradient=False)` 计算 RKL，不构造用不到的 logit 梯度。Teacher 评分仍复用 `SharedTeacherScorer`，没有另写训练循环。

来源留出在更新前由 initial student 生成一次，记录题目身份、prompt／response token、有效 mask、模型路径、来源文件哈希和采样配置。历史集合只取实际训练过的 rollout；训练过 $m$ 批后，每批保留 $\lfloor128/m\rfloor$ 或 $\lceil128/m\rceil$ 题，按固定随机优先级分配余数。原始训练 token 逐批保存，历史抽样不依赖 loss 或 RKL。

每次读出按“teacher 四卡评分并卸载 → actor 四卡评分并卸载”执行，临时 hidden 保存在 CPU TQ，评分后清理。训练期间 teacher hidden 在当前 outer 的 reuse32 内复用；不会预计算整个题池的 teacher hidden。每题保存 RKL sum 和有效 token 数，工程验收同时报告来源留出的 token-mean 与历史的逐批等权 token-mean，正式平均方式仍待定。

更新后的读出放在 `on_before_weight_sync`：此时 vLLM 已休眠，评分结束后沿用正常 `on_step_end` 同步权重。首次读出结束则显式重新同步权重到 vLLM；level-2 sleep 后仅 wake-up 不足以恢复丢弃的权重。短验收确认第二轮 rollout 使用更新后的版本。

配置通过 `trainer.readout_callback_class` 选择回调，`trainer.rkl_readout` 提供 `output`、`source_file`、`source_count`、`history_size`、`every`、`seed` 和 `audit_state`。当前要求 `val_before_train=True`、`val_files` 只包含对应来源留出、`resume_mode=disable`、n=1；来源留出 cap 与训练 cap 相同。`every=1` 仅用于工程验收，不冻结正式实验频率。每次评分保存并恢复随机数状态；`audit_state=True` 额外核对模型参数与 Adam 的完整内容哈希，常规性能运行可关闭该项以省去哈希成本。

实现目前覆盖新运行中的来源留出和历史轨迹。公共四域银行、teacher-rollout 银行、current-rollout 公共评估及断点恢复仍需接入；上述短验收不能替代这些功能的验收。两轮完整 batch128／reuse32／cap7168 的验收结果归[性能页](../performance/full-vocab/training.md)，与短长度接口检查分开记录。

公共 bank 的初始化采用“bench 生成产物→accuracy 与 bank builder 分别消费”的分工。Accuracy 的 n 按 benchmark 配置，bank 仍每题保留 1 条；公共 32K cap 与常规 n 已确认，来源留出继续 7K。详细证据与接口条件见[正确率与银行生成调研](../../literature/teacher-transfer/2026-10-31-四域正确率评测与RKL银行生成协议调研.md)。

## 7. 评估频率与单次_validate 容量

执行路线已确定：student update 与 `_validate()` 均采用共享池分阶段串行加载；本节保留容量分析，共驻估算作为备选资料。当前推荐来源/history 每 outer、公共固定 bank 每 5outer 并补 0/1/2、bench current 评估 0/25/50；正式频率待公共 32K 测速与确认，详见四域协议。历史集合成员更新仍随训练 batch 推进，不等于每轮必须评分。

一次读出若公共 512 题每题评分一条轨迹、来源留出 128 题和历史 128 条，共 768 条。公共 cap32,768，另外 256 条 cap7,168，最多 18,612,224 个回答位置。BF16 teacher hidden 的纯 payload 为位置数×teacher hidden size×2 字节：

| Teacher 示例         | Hidden size | 公共 512 条／GiB | 留出＋历史 256 条／GiB | 合计／GiB |
| -------------------- | ----------- | ---------------- | ---------------------- | --------- |
| R1-Distill-Qwen-1.5B | 1,536       | 48               | 5.25                   | 53.25     |
| Qwen3-1.7B           | 2,048       | 64               | 7                      | 71        |
| Qwen3-4B             | 2,560       | 80               | 8.75                   | 88.75     |
| R1-Distill-Qwen-7B   | 3,584       | 112              | 12.25                  | 124.25    |
| Qwen3-8B             | 4,096       | 128              | 14                     | 142       |

这是满 cap 上限，不含 prompt 骨干工作、位置／身份元数据、序列化和临时副本。若公共 initial student 和 teacher 两个银行都评分，公共部分翻倍，总量依次为 101.25／135／168.75／236.25／270GiB；再加 current 银行则公共部分三倍。题目数量与轨迹数量必须分开计数。

分阶段 teacher→CPU/TQ→student 路径至少有一次 D2H 与一次 H2D，因此上述单银行 teacher hidden 合计 71／88.75／142GiB，对应双向 GPU-host 搬运约 142／177.5／284GiB，尚未计入 TQ 进程间拷贝、网络和模型上下卡。分布式理想均分只降低每 rank 份额，不消除全节点总流量。真实时间须测有效吞吐与拷贝次数，不能拿 PCIe 理论带宽直接当实测。

完整 payload 主要施压 CPU/TQ 存储与传输，不等于全部必须进入显存。微批读取能控制 GPU 工作区，但若先算完整 768 条 teacher 再切换 student，CPU 侧仍可能积累完整集合；要控制 CPU 峰值需分块消费或更改共驻方式。prefetch 可能同时持有当前块与下一块，需计入预算。

作为备选的 `_validate` 共驻方案按一小批执行：teacher forward→student forward→两侧 head 投影／RKL→释放。两模型同时加载不等于两个 forward 必须同时运行。这样只保留该 microbatch hidden，通常无需将其通过 TQ 写出／读回。以单条 32,768 回答为例，teacher hidden 为 128MiB（Qwen3-1.7B）、160MiB（4B）、256MiB（8B）；微批 4 时分别 512／640／1024MiB，另有 student hidden、prompt 相关激活及算子工作区。

词表投影按 chunk256、词表 151,936、FP32 计算，一份 logits 约 148.4MiB，双方约 296.8MiB；log-softmax、概率及临时归约还占额外显存，不只两份 logits。共驻实际峰值包括双模型权重、head 精度副本、forward 激活与工作区；训练 optimizer 和梯度应在评估前卸载／释放，不误计为验证必须常驻。

先前单 H800、student Qwen3-1.7B FP32＋teacher Qwen3-8B BF16 的即时评分，在 prompt256、response7,168、microbatch1 下实测峰值 allocated 约 25.14GiB，提供小 student 共驻可行性证据；不是 16K、完整训练切换或所有模型对的显存验收。后续默认串行；若另做共驻实验，应比较完整窗口与内存峰值，评估频率仍单独决定。

### 7.1 TQ 的实际存储位置

查验本仓库 `verl/trainer/config/transfer_queue/transfer_queue.yaml` 及既有 full 验收配置：默认后端为 SimpleStorage，8 个 storage unit，SSD offload 关闭。已安装 TransferQueue 0.1.11 的 SimpleStorageUnit 在该条件下使用 StorageUnitData，按样本／字段在存储进程 CPU 内存中维护字典，经 ZMQ 接口读写；TQ 不是 CPU／GPU 之外的另一种内存。具体新运行仍需记录 resolved config，不能把默认值推断成所有运行状态。

teacher 选中 hidden 后 detach 并拷到 CPU，发布到 TQ。reuse32 期间，TQ 保留当前 batch 的 CPU 主副本；HiddenBatchIO 每个 microbatch 读取 CPU payload，再由 engine 送到 GPU，计算后移除注入字段。当前代码没有跨 32 次更新保留整批 GPU hidden 的默认行为。prefetch 还可能持有下一微批的 CPU 副本，序列化／传输也可能产生额外拷贝。

当前 128 条训练 batch、cap7,168 的 Qwen3-1.7B／4B／8B teacher hidden 本体分别 3.5／4.375／7GiB。容量在当前 outer 内受控；32 次 H2D 累计分别 112／140／224GiB，全作业汇总而非每卡量。可选优化是 actor 进程本地 CPU 缓存或本 rank GPU 缓存，前者减少 TQ 访问，后者进一步减少 H2D；两者都只保留当前 outer，与全题池长期 latent 缓存不同。

### 7.2 模型尺寸与备选布局的容量参考

当前主要 student 为 R1-1.5B、Qwen3-1.7B、Llama-3.2-3B，以及 R1-7B；teacher 覆盖同尺寸及 4B／7B／8B，后续考虑 14B。应按双模型真实权重精度、最大 prompt＋32K 回答、head 工作区评估，不只看模型名字的 B 数。

以公开 BF16 safetensors index 中的 tensor 数据量估算 R1-7B／R1-14B 权重：7B 为 15,231,233,024 字节，14B 为 29,540,067,328 字节。7B student FP32＋14B teacher BF16 仅权重约 55.88GiB；两者都 BF16 约 41.70GiB；14B student FP32＋7B teacher BF16 约 69.21GiB。均未包含额外 head 副本、激活、临时 logits、通信 buffer 与 allocator 余量，不能当成峰值显存。14B 官方配置 hidden_size 为 5,120。[^r1-14b]

评分时不能为省显存静默将 FP32 student 权重转成 BF16 再称原 checkpoint 风险；如要采用统一 BF16 评分，需单独记录执行精度，并验证它与基准口径的偏差。

| 模型对                                  | 曾讨论的备选评分布置                                 | 状态                                                       |
| --------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| 1.5B／1.7B／3B student＋1.5B–8B teacher | 每个评分 worker 共驻两模型；不同 worker 处理不同题目 | Qwen3-1.7B＋8B 的 7k 单卡测试已通过；其他组合及 16K 待验收 |
| 7B student＋14B teacher                 | 两模型在同一 2 卡组中共同分片；不同组处理不同题目    | 权重容量估算支持优先测试，不宣称已可运行                   |
| 双模型 2 卡组仍不足或通信过重           | 比较 3 卡组、当前完整 FSDP 组或分阶段加载            | 由实测峰值与总时间选择                                     |
| teacher 显著大于 student 且难以共驻     | 独立 teacher 组与 student 组，按实测耗时配卡         | 需有界 hidden 流传输和对齐，非当前默认路径                 |

“每组放两个模型、不同组分题”与“一个组只放 teacher、另一个组只放 student”不同。前者在评估上利用题目独立性并行，不需要跨组传递 hidden；组内仍可能有 FSDP／TP 通信。六卡可候选为 6 个单卡评分 worker、3 个 2 卡组或 2 个 3 卡组，但当前训练 worker 已有固定 mesh，不能只在_validate 中改一行 GPU 数量就重分组。当前串行实现复用既有 worker mesh；上述独立评分子组没有纳入默认实现。

后者在同一批题上分工：例如小模型 2 卡、大模型 4 卡，只是起始候选。分卡应平衡骨干、head 投影、传输与归约实测时间，不按参数量简单机械分配。full-vocab 需传紧凑 hidden 并处理 teacher head，而不是跨 GPU 传整块概率。不会使用物理 GPU6–7。

算力角度两侧都要 forward，但 RKL 不是对称量，不能交换 student 和 teacher 身份；其概率权重、方向和当前精度不同。公共 teacher-rollout 只是前缀来源变化，也保持 student→teacher 的 RKL 方向。

## 8. 已落地范围与剩余功能

### 8.1 最小可靠恢复的建议范围

短验收无需增加 checkpoint；50 outer 长跑建议支持仅在完整 outer 边界恢复。复用 verl 已有的模型／optimizer 分片、scheduler、各 rank RNG 和 dataloader 保存能力，新增部分主要是历史集合、固定银行身份与提交一致性，属于中等复杂度的接入工作。首版只覆盖同步训练、相同卡数和已完成整个 reuse 的边界，暂不支持 inner 中途或跨卡数恢复。

需要保存：训练精度的 student 权重、Adam 两份统计及 step、scheduler、driver／rank 随机数和显式 rollout seed 管理、outer／optimizer 计数、训练题序与游标、history 配额／优先级及轨迹引用、固定 bank 的路径／哈希、teacher revision 和输入协议、已完成评估节点。永久 token 文件和 manifest 以引用方式复用，不在每个 checkpoint 重复打包。

不保存 teacher 权重副本、teacher hidden／logits、vLLM KV cache 或已完成更新的梯度；恢复后重新装载冻结 teacher 和生成引擎。只保存模型而重置 Adam 会改变后续训练，不能算同条件续训。

当前 Trainer 的 checkpoint 调用在新增 history 回调之前；不能简单移除 `resume_mode=disable` 就声称恢复完整。保存点需要保证模型、题目游标和 history 对应同一已完成 outer，并区分保存点之后可能留下的未提交日志／轨迹。应以新文件完成并验证后再更新 latest 指针，旧可用 checkpoint 在此之前保留。

保存频率可先讨论每 5 outer 一次、常态只保留最近一个完整 checkpoint，写新文件时暂留旧文件，暂停时在最近完整 outer 补存。按当前小模型约 6 分钟／outer，这对应最多约半小时的已训练工作需要重跑；频率尚未冻结。R1-1.5B 本地权重 header 实际包含 1,777,088,000 个参数元素，FP32 参数加两份 FP32 Adam 统计的理论数据量约 21.3 GB（19.9 GiB，四卡合计），未含文件封装等开销，也不是实测 checkpoint 大小。

恢复验收应覆盖题序无跳过／重复、optimizer 计数与状态连续、history 成员和 bank 哈希一致，以及固定输入下恢复前后的更新数值。正确恢复训练进度与跨进程采样的逐 token bitwise 复现应分别验收。
