# 全层谱计算的 GPU、复用与调度加速

更新：2026-11-12。本文核查现有源码、历史计时和公开实现，记录已实现优化、真实矩阵验收，以及待测的执行方案。科学指标和模型配对由 [ISO 专题](../../../experiments/teacher-transfer/absorption/附录-定义与复算.md)维护，[历史计算预算](../../../experiments/teacher-transfer/absorption/附录-定义与复算.md)保留完整工作负载计时。

## 已实现与真实矩阵验收

新增 [分组扫描入口](../../../../research/studies/spectral/scan.md)，将纯谱统计从完整随机对照／方向生成中分开。每个 base 矩阵的 teacher 和全部 student 阶段共用一次 base SVD；κ 使用对角收缩；宽矩阵可转置后做精确 `gesvd`；内容寻址缓存仅保存标量与奇异值。暖缓存仍计算 base 与 missing。缓存计算和发布全程持锁，恢复重新核验原始内容 SHA256。

矩阵分片 `--shards 8 --shard-index 0..7` 已实现，同一矩阵的所有阶段留在一个 worker。没有新增分布式调度服务，资源继续经已有 broker/guard。三种形状数值、缓存、恢复、STOP、污染条件排除与分片无重叠共 6 项新测试通过；此前与旧谱实现的联测为 22 项通过。

本轮在 R1、Light、Qwen、Llama、MiMo 上各测第 0 层 q/k/up/down，FP64、H800、`gesvd`。五组 CPU FP64 δΣ/ρΣ/κ 参考最大相对误差 4.68×10⁻¹¹。MiMo 首个 attempt 的旧完整入口因额外 MTP 坐标差异失败；新版本在选中 backbone 范围完成数值验收，旧整 checkpoint 对照明确跳过，原失败保留。

## 九阶段 checkpoint 几何的执行优化

`trajectory-v2` 保留精确 FP64、九个 checkpoint、五个 rank 和全部科学指标。每矩阵的 29 次分解中，相邻增量的八次分解改用只返回奇异值的接口；完整权重与累计更新仍保留 frame 所需的 thin SVD。这个接口是否降低分解耗时由实际后端决定，不按调用名计算收益。

不同 rank 的投影共享最大 rank 的矩阵乘法，再用列能量前缀和取值。k=16/32/64/128/256 原先合计投影 496 列，现在投影 256 列。阶段 frame 比较共享最大交叉 Gram 矩阵；各 rank 的主角分解分别计算。角度摘要在奇异值一次回传 CPU 后聚合，减少逐标量 GPU 同步。

每卡只保留一个在途任务，空闲卡领取下一个矩阵。输出目录的 `STOP` 使活跃矩阵完成后停止派发；`--resume-from` 验证相同科学 manifest、逐矩阵任务身份、FP64 与阶段覆盖，复制已完成记录到新 attempt。solver 作为执行参数记录，不修改 pair、checkpoint、rank 或评分预算。接口与恢复命令见[测量入口](../../../../research/studies/spectral/README.md#本轮统一-checkpoint-几何入口)。

## 当前执行与可确认收益

现有 `spectral weights` 默认 FP64 CPU，支持显式 CUDA 和 solver。大规模 `absorption/directions.py` 则已经用 CUDA FP64 做 learned/base SVD 与随机框架；此前 17.38 单卡小时不是纯 CPU 流程。因此，加速要同时减少工作量和改善 GPU 执行。

本地历史真实 Qwen q_proj（2048×2048）上，`gesvdj` 为 3.577552 秒，`gesvd` 为 1.264279 秒，速度比 2.830；对应相对重构误差分别为 1.197e−12、1.307e−14。[原始基准副本](data/acceleration-20261111/solver-benchmark.json)包含冷／暖整任务计时。该结论仅适用于这一形状、权重和历史环境。

方向生成当前未显式选择 solver，使用 PyTorch 默认。官方文档说明 CUDA 默认优先 `gesvdj`，失败时回退 `gesvd`；高精度或病态矩阵可选 `gesvd`，`gesvda` 是近似方法[^pytorch-svd]。下一次分解应先对实际矩阵形状比较 solver 与转置策略，再固定协议，不自动将单矩阵速度比推广到全队列。

## 优先减少不需要的计算

### 谱标量与干预方向使用不同任务

现有 `weights.analyze` 的冷参考路径每个三元组调用九次 SVD／svdvals：base 一次；teacher update、teacher weight 各一次；Gaussian update、Gaussian-added weight 各一次；random-frame-added weight 一次；OPD weight、OPD update、teacher−OPD 各一次。随机框架还需要 QR。暖参考路径保留 base、OPD weight/update、missing 四次。

只测完整权重 δΣ、ρΣ、κ 时，base 需要 singular frames，teacher/OPD 只需要 singular values；更新范数与 κ 不需要分解更新。每个三元组可改成三次分解，省去随机 QR、方向重构和方向文件。如果同时要求精确更新谱和遗漏谱，则额外增加三个 svdvals，不能将它们也计为已省掉。

16 个有效 endpoint 条件共有 3248 个矩阵三元组。根据原始 tensor 内容哈希、名称和形状清点：

| 方案                         | SVD／svdvals 调用数 | 测量范围                            |
| ---------------------------- | ------------------: | ----------------------------------- |
| 旧完整冷分析                 |               29232 | 完整谱、更新谱、遗漏谱、随机对照    |
| 仅完整权重谱，无共享复用     |                9744 | δΣ、ρΣ、κ 所需分解                  |
| 仅完整权重谱，跨角色候选去重 |                7336 | 相同输入矩阵的 singular values 复用 |

候选唯一 base 矩阵为 1036，teacher 为 3052，endpoint 为 3248；上述数量已经合并共享 base 和重复 teacher；三个角色的候选数合计 7336。7336 相比 29232 少 74.9% 的分解调用，但两者输出范围不同，**不是相同实验的四倍实测加速**。缓存真正发布前还需包含源 dtype、算术精度、solver、指标版本和软件版本，不仅依靠裸哈希。

全面测量仍保留更新集中度、遗漏谱和关键随机对照：它们分配给各自任务并复用结果，不从研究问题中删除。更新 rank16／top1% 等是独立指标需求。可以复用既有精确分解，或单列近似筛查；近似结果不替换完整谱距离。完整计数见[操作清单](data/acceleration-20261111/operation-counts.json)。

### 同一 base 与训练阶段放在一起

现有共享参考缓存保存 teacher/control 的标量，但每个 OPD 阶段仍重算 base frame。新 `scan` 的任务单元是“一对对应矩阵及若干阶段”：读取并分解 base 一次，依次读 teacher 和各 student checkpoint。相同 teacher 的 thinking/non-thinking 模式在权重侧复用，功能 bank 仍分开。

GPU 内只保留一个 base frame 和当前 target，处理完该组后释放。Singular values 和标量落盘；大型 U/V 默认不全量持久化。需要跨模块复用时采用容量受限的内存缓存或明确的磁盘缓存预算，避免以大量 frame 写盘替代计算。

### κ 只需要对角收缩

记 base thin-SVD 为 $W_0=U\Sigma V^\top$，更新为 $D$。κ 的分子只需要 $c_i=u_i^\top Dv_i$ 的平方和，无需完整构造 diag/off/null 参数矩阵。按形状选择：

$$
c_i=\sum_a U_{ai}(DV)_{ai},\qquad
c_i=\sum_b(U^\top D)_{ib}V^\top_{ib}.
$$

宽矩阵用第一式，瘦高矩阵用第二式，使中间结果为较小的 $q\times q$。省去完整坐标变换的另一侧乘法和参数空间重构。需要真正 off/null 干预时仍构造那些方向。五组方／宽／高矩阵的 FP64 CPU 数值核对最大相对能量误差为 3.65e−16，见[恒等式核对](data/acceleration-20261111/diagonal-identity-check.json)；这不是 GPU 耗时基准。

## 外部实现核查

### ISO：转置宽矩阵、thin SVD 与 FP64

核查 revision `efc666054a017fb2b8d5f90b0734d3ca25d214d3`。`iso_merger.py::thin_svd` 在宽矩阵上先转置成瘦高矩阵，分解后交换回左右框架；全程 `full_matrices=False`。默认设备 CUDA，合并计算用 FP64[^iso-code]。这不改变奇异值，适合作为等价执行路径比较，但速度收益需实测。

它按 safetensors shard 打开 base，每次合并一个矩阵；超过一亿元素的矩阵回退 CPU。这个阈值针对其多 expert 合并的内存占用，不应直接成为我们的单 target 阈值。其每矩阵 `torch.cuda.empty_cache()` 可以缓解保留显存，未证明提升吞吐；我们的常驻 worker 应优先复用 allocator，仅在确有内存需求时清缓存。

公开 README 仍标注 ISO-Optimizer 未发布，当前可核查的是 Merger；不能宣称已经借用了其分布式 optimizer。论文[^iso-paper]另报告 16 卡布局下 Qwen3-4B 的 252 矩阵 SVD 为 26 秒；该数是作者训练布局中的单类分解成本，与我们包含随机框架、更新谱、读写的任务不等量。

### SPACE：按功能需求构造投影

核查 revision `2415d203cfa0d218bc2f4d409ca23518bf047d79`。`src/space_calibration/core.py` 在当前权重设备上以 FP32 做 base reduced SVD，按平方奇异值累计能量选 rank，并计算 $(DV_k)V_k^\top$，不显式构造完整投影矩阵 $V_kV_k^\top$[^space-code]。

可借鉴的是按需取 frame 和矩阵链乘法顺序。它的 FP32 校准目标与我们的微小谱漂移诊断不同；不据此把精确谱距离统一降为 FP32。

### Pion／Muon：批量小矩阵乘适用于更新变换

核查 Pion revision `87965014b360bde604632cba0aa12e423c6c63c6`。其 RL `muon.py` 包含 BF16 Newton–Schulz、多头 batch 运算和转置后的较小 Gram 运算[^pion-code]。这将优化器的矩阵变换转为 GPU 擅长的 GEMM。

Newton–Schulz 近似正交化不输出完整奇异值，不能直接替代 δΣ、ρΣ、完整 rank 和 spectrum restoration 所需的 SVD。它适合未来固定谱／极分解优化器原型，不能算当前精确测量的等价加速。

## GPU 并行与读写安排

当前 `scan` 使用每卡一个 worker 和确定性矩阵分片，阶段在矩阵内复用。动态任务块仍需单独评估，重点是共享存储读取与长尾。按历史方向准备耗时重放，整条件八卡为 3 小时 13 分 50 秒，矩阵级理想拆分为 2 小时 10 分 19 秒；实际分块收益要扣除共享文件系统与进程启动成本。

小 k/v 矩阵可以比较同形状小 batch SVD，PyTorch API 支持 batch；大 MLP 优先单矩阵精确分解。多个 CUDA stream 不保证 cuSOLVER 并发提速，可能增加 workspace 与峰值显存。batch size、stream 数和 solver 都需按形状验收，不能为了 util 数字同时堆多个大型 SVD。

CPU 负责读取、原始 dtype 内容哈希和任务准备；GPU 负责提升精度、相减、分解和标量聚合。当前扫描未启用异步预取。Pinned memory 与显式传输流只有在 trace 显示读取／H2D 可隐藏时启用。逐项 `float(tensor)` 会触发同步，标量可集中回传；计时使用正确 CUDA 同步边界，分别记录读取、H2D、SVD、投影、发布与总 wall time。

纯谱任务保存 singular values、标量和来源身份，不生成 11 份整矩阵方向。按当前 3248 个三元组形状计算，11 份 FP32 方向的裸 payload 合计约 1814.5 GB，准确字节数为[操作清单](data/acceleration-20261111/operation-counts.json)中的 `legacy_11_fp32_direction_payload_bytes`；它是形状算出的理论 payload，不是磁盘实测。需要功能干预时再按条件生成方向，或复用已有有效文件。

## 精度与验收

FP64 GPU 是当前精确谱默认候选。BF16／FP32 的输入提升后不恢复 master 权重，记录中保留实际存储精度。既比较重构／正交误差，也直接比较 δΣ、ρΣ、κ 与原 FP64 参考；重构误差小并不保证两个接近谱之差准确。

不把 $W^\top W$ 的特征值默认当作精确 SVD 替代：Gram 会平方条件数，尾部和相近谱之差更容易受舍入影响。近似 `gesvda`、randomized SVD 与低精度只进入独立筛查。PyTorch 的 lowrank 实现自身也提示稠密矩阵常规完整 SVD 可能更快，不能预设 randomized 总是更快[^pytorch-lowrank]。

下一轮验收按真实形状各取首／中／末层；比较原方向与等价转置、gesvdj／gesvd、单个／小 batch、冷／暖缓存。先保证相同输出的误差和身份 gate，再比较端到端吞吐。新轻量路径与旧完整路径工作量不同，分别列成本，不合成一个夸大速度比。

## 完整 bank 换谱评分的执行优化

换谱评分每个 checkpoint 分别测原始权重和恢复初始谱后的权重，两者各覆盖同一套 512 条完整响应。E94–E97 的第二个 checkpoint 在 H800 上实测：单次完整 bank 评分 58.52–66.36 秒，196 个完整权重矩阵的 SVD 恢复 164.94–166.46 秒，总计 285.42–301.52 秒。SVD 恢复占总时间约 55%–58%。首阶段还计算初始谱，不能用首阶段时间代替后续阶段。

评分已经复用教师 hidden、BF16／FA2 前向和主线 FP32 输出投影、Triton RKL 归约。新增可选的设备 hidden 缓存，跨阶段保留教师 head，减少逐题读盘与传输。缓存按显式字节上限使用 LRU；实际 11 个 pair 的完整 hidden 为 2.04–9.38 GiB。256／512／1024／2048 token 分块与设备缓存分别计时，逐题 RKL 误差随结果一起保存。四组长短完整响应探针中，1024 token 加设备缓存相对 256 token 加磁盘读取为 1.13–1.20 倍；这是 12 条响应的评分基准，完整 512 条端到端收益另测。

全权重恢复新增 Gram 候选。对高矩阵 $W=U\Sigma V^\top$，对较小矩阵 $W^\top W=V\Sigma^2V^\top$ 做 FP64 特征分解，恢复式为：

$$
W'=W+(WV)\operatorname{diag}(\sigma_0/\sigma-1)V^\top.
$$

对宽矩阵使用 $WW^\top$ 的左特征向量，恢复式为 $W'=W+U\operatorname{diag}(\sigma_0/\sigma-1)U^\top W$。两式使用完整谱，不裁 rank。Gram 会平方条件数，因此要求正定、条件数不超过 $10^8$、特征残差低于 $10^{-10}$，否则回退原精确 SVD。候选还须通过全部矩阵 FP32 权重差及端到端 RKL 差各不超过 $10^{-6}$ 的实测检查，才用于新正式 attempt。四组全层对照均通过；探针的评分收益不等同于完整任务的端到端加速。

各行在同一张卡、同一进程、同一 endpoint 上按矩阵交替计算两个后端；表中时间包含重构与数值 gate，不含独立的初始谱读取／分解，也不含 bank 评分。E94 有 50 个矩阵、E99／E102 各有 51 个矩阵触发 SVD 回退，已计入候选时间。BF16 权重比较覆盖全部矩阵；RKL 比较覆盖双 bank 三域各自最短与最长的完整有效响应，共 12 条。四个条件共 784 个矩阵的 BF16 权重逐元素相同，评分差为零。E103 有 56 个矩阵触发回退。详细计时、条件数、回退原因和逐矩阵误差见[独立附件](data/sigma0-bank-v2-20261112/summary.json)及相邻压缩数据。

基准入口为 [benchmark_spectrum_bank.py](../../../../research/studies/absorption_dynamics/benchmark_spectrum_bank.py)，执行协议见[完整 bank 评分接口](../../../../research/studies/spectral/README.md#各-checkpoint-的初始谱恢复与完整-bank-评分)。运行中的冻结版本保持原样。后续正式评分启用 `--edit-method gram --token-chunk 1024 --reference-cache-mib 16384`，使用新输出目录和源码快照；这个缓存上限覆盖所有已绑定 bank 的教师 hidden。科学报告只使用同路径成对重测的编辑前后分数；与原训练 FSDP 分数的执行误差独立记录。

## 当前实现与后续优化

谱专用路径、阶段分组、内容缓存、κ 对角收缩、宽矩阵转置和矩阵分片已实现，并完成五组真实矩阵验收。原完整方向与随机控制仍由旧入口负责，冻结源码与历史协议不变。
