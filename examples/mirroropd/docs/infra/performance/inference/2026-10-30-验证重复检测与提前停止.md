# 验证重复检测与提前停止

数学训练入口的 valid 默认启用 vLLM 精确重复检测：**16–128 token 的片段连续完全重复 8 次，就结束该回答。** 参数覆盖正常训练的初始验证、周期验证、末次验证，以及独立验证；是否执行各次验证仍由原有训练配置决定。训练 rollout 不应用这条停止规则。

在 1,280 条历史短程回答的离线回放中，这组参数截断 51 条，减少 10.16% 的输出 token，产生 1 条判对→判错、1 条判错→判对。它是优先降低已观察误停损失的选择，不是无损保证；真实 GPU 加速和独立样本上的风险上界尚未测量。

## 配置位置与训练调用路径

默认值定义在[公共 launcher](../../../../launchers/_run_single_teacher_fsdp2.sh)，不在独立验证脚本里单独设置。正常训练的调用路径是：

```text
run_math_opd_ablation_fsdp2.sh
  → launchers/math_experiment.py
  → launchers/_run_single_teacher_fsdp2.sh
  → actor_rollout_ref.rollout.val_kwargs.repetition_detection
  → 训练器每次 _validate()
  → agent loop 的 validate 分支
  → vLLM SamplingParams
```

| 层次             | 文件与职责                                                                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 训练入口         | [run_math_opd_ablation_fsdp2.sh](../../../../run_math_opd_ablation_fsdp2.sh) 经 [math_experiment.py](../../../../launchers/math_experiment.py) 选择实验预设，再进入公共 launcher                               |
| 默认值与参数传递 | [_run_single_teacher_fsdp2.sh](../../../../launchers/_run_single_teacher_fsdp2.sh) 在验证预算附近定义环境变量，在 `VALIDATION_ARGS` 中写入 `val_kwargs.repetition_detection`                                   |
| 周期性验证       | [trainer_base.py](../../../../../../verl/trainer/ppo/v1/trainer_base.py) 在验证时机调用 `_validate()`，为验证 batch 设置 `validate=True`                                                                       |
| 验证专用采样     | [agent_loop_tq.py](../../../../../../verl/trainer/ppo/v1/agent_loop_tq.py) 只在 `validate=True` 时加入重复参数；[legacy agent loop](../../../../../../verl/experimental/agent_loop/agent_loop.py) 采用相同约定 |
| 引擎执行         | [vllm_async_server.py](../../../../../../verl/workers/rollout/vllm_rollout/vllm_async_server.py) 将字典转换成原生 `RepetitionDetectionParams`，交给 vLLM 停止逻辑                                              |

因此，正常启动 E55/E56/E57 等数学训练时，周期性 valid 已经使用该规则，不需要额外调用 `run_math_validation_fsdp2.sh`。例如 E56 原有的每 10 outer 验证仍按原频率执行，每次都传入这组检测参数。

## 默认参数与生效范围

| 环境变量                     | 数学入口默认值 | 含义                          |
| ---------------------------- | -------------- | ----------------------------- |
| `VAL_REPETITION_DETECTION`   | `true`         | 启用验证重复停止              |
| `VAL_REPETITION_MIN_PATTERN` | `16`           | 候选重复片段的最小 token 长度 |
| `VAL_REPETITION_MAX_PATTERN` | `128`          | 候选重复片段的最大 token 长度 |
| `VAL_REPETITION_MIN_COUNT`   | `8`            | 完全相同片段的连续出现次数    |

对应最终配置：

```yaml
actor_rollout_ref:
  rollout:
    val_kwargs:
      repetition_detection:
        min_pattern_size: 16
        max_pattern_size: 128
        min_count: 8
```

| 使用方式                                                      | 默认是否生效                                      |
| ------------------------------------------------------------- | ------------------------------------------------- |
| 公共数学训练入口的 valid，包括初始、周期和末次验证            | 是，前提是该次验证按训练配置执行                  |
| 独立数学 student/teacher 验证入口                             | 是，复用相同 launcher                             |
| 训练数据的 rollout                                            | 否，采样参数仅从验证分支注入                      |
| 公共 launcher 的 code、IF 领域                                | 否                                                |
| 直接运行 `python -m verl.trainer.main_ppo`，绕过公共 launcher | 否，通用 YAML 默认 `null`；需要显式配置上面的字段 |
| 研究脚本直接调用 vLLM                                         | 不自动继承，需要查看该脚本实际参数                |
| 原生 vLLM 并发扫描中的 verl 复核                              | 显式关闭，以匹配其原生测速停止协议                |

该接入支持 vLLM 单轮 agent；其他后端或多轮配置会明确报错。参数必须为正整数，`min_count >= 2`，最小周期不能大于最大周期。已有运行不会热加载这些文件：默认值适用于从当前源码重新启动的进程，显式环境变量或末尾 Hydra override 优先。

## 启动、关闭与覆盖

从仓库根目录执行。下面使用 `DRY_RUN=1` 查看命令，不启动 GPU；实际训练时去掉它，并按已有约定配置设备和模型路径。

```bash
# 正常训练：valid 自动使用 16–128/8。
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E56

# 独立验证：使用相同默认值。
DRY_RUN=1 bash examples/mirroropd/run_math_validation_fsdp2.sh student

# 不含启发式停止的对照。
DRY_RUN=1 VAL_REPETITION_DETECTION=false \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E56

# 参数研究：显式扩大到 256，保持其他参数。
DRY_RUN=1 VAL_REPETITION_MAX_PATTERN=256 \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E56
```

也可以在命令末尾覆盖 `actor_rollout_ref.rollout.val_kwargs.repetition_detection=null` 来关闭。检查最终命令或保存的配置时，应看到三个参数 `16/128/8`；仅设置 `VAL_REPETITION_MAX_PATTERN` 不会覆盖显式的 `VAL_REPETITION_DETECTION=false`。

## 实际停止行为

检测只检查输出 token，不包含 prompt。设候选片段长度为 p，默认要求末尾的 8p 个 token 能分成八个完全相同、紧邻的片段；p 遍历 16 到 128。它不识别语义相似，也不要求片段边界是自然语言句子。[^vllm-utils]

- 21-token 算式连续重复八次可以触发。
- 一个 token 连续出现八次不会触发；连续出现 128 次可以按 16-token 块触发。
- 每轮修改编号、数字或措辞的推导可能漏检；完整周期超过 128 的循环也可能漏检。
- EOS、显式停止 token 和长度上限的原生检查优先；重复停止不追加或伪造 EOS。

终止后保留已经生成的前缀、token 长度和 verifier 分数，不丢弃该回答、不改变样本分母、不自动续跑。重复惩罚保持原值，不通过修改 logits 阻止某个 token。也不使用 `min_tokens` 来延后检测，因为它会同时影响正常停止。

## 指标、风险与验证证据

W&B 按 benchmark 记录：

- `eval/<dataset>/generation/finish_reason/repetition_count`：重复停止数量。
- `eval/<dataset>/generation/finish_reason/repetition_fraction`：实际返回回答中的重复停止比例。
- 同级 `stop_count`、`length_count`：原生停止与触顶数量，分别统计。

逐条验证记录的 `finish_reason` 为 `repetition`；后端输出另有 `backend_stop_reason=repetition_detected`。检测器截断造成的长度下降不能当作模型学会停止。不同模型或 κ 的对照应使用同一评测规则，并保留关闭检测的对照。

选定参数的判分损失为 1/1,280，即这批回答的 0.078 个百分点；同时有一条评分增加，不能抵消那条损失。正常推导误报、真正循环后的恢复以及 verifier 提取位置变化需要分别审计。正式统计沿用统一 verifier，不用标准答案决定在线停止，也不把出现 boxed 答案当作无风险停止证明。检测准确不等于停止安全。

已有 CPU 检查覆盖实验启动后的配置解析、TQ/legacy 在训练和验证之间隔离参数、vLLM 参数转换、原始 token 保留和独立停止指标。验证测试见[launcher 配置](../../../../../../tests/examples/test_mirroropd_math_launcher_on_cpu.py)与[agent loop 采样](../../../../../../tests/experimental/agent_loop/test_validation_logprobs_on_cpu.py)。这些检查确认调用路径，不替代实际 GPU 加速测量。
