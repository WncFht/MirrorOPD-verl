# 重复停止参数回放与误停分析

本文保存 Qwen3-1.7B-Base ← Qwen3-30B-A3B-Instruct-2507 短程实验的 1,280 条回答回放、传统规则对照、人工复核和恢复案例。输入、模型条件与判分均按原始实验解释；输出 token 的反事实节省量不等于已测 GPU 加速。

运行默认值、训练中 valid 的接入和开关统一见[使用说明](2026-10-30-验证重复检测与提前停止.md)。本文的“vLLM 参考规则”固定指 16–256 token 连续重复 8 次；16–128/8 是同一网格中的另一设置。所有方法使用相同 verifier，判错→判对不抵消判对→判错的风险。

## 离线回放条件与结果

回放使用 Qwen3-1.7B-Base ← Qwen3-30B-A3B-Instruct-2507 的十组已完成 MDPO 短程实验。每组有 64 条 MATH-500 和 64 条 heldout DAPO 回答，n=1、cap=31,744；MATH 使用温度 0.7、top-p 0.9，DAPO 使用温度 1、top-p 1。不同参数组重复使用同一批题目，因此是 1,280 条回答，不是 1,280 道独立题目。训练与旧模板条件见[原报告](../../model-compatibility/qwen-e54/2026-10-29-MDPO参数对照与长度恢复.md)。

回放逐条定位最早触发位置，用实际 tokenizer 解码保留的前缀，再调用项目同一数学 verifier。原始触发样本也重新判分，与归档标签的差异为零。原始回答共有 572 条判对、207 条触顶，总输出约 10.73M token。离线算法通过周期相等关系向量化扫描，已与原生检测器逐前缀核对；正式生成仍调用 vLLM 的原生实现。

回答由十组学生模型在最终 outer5 生成，不是初始 Base 或 teacher 的独立生成。各组从共同的 Full-RKL outer2 预热状态恢复，再训练 3 个 outer；每个模型累计 80 次优化器更新。参数为 κ=0 的 η=0.1/0.2，以及 κ=0.5/1 的 η=0.05/0.1/0.2/0.3。输入来自两个归档目录的 `evaluation/*/scored.jsonl`：`wandb-logs/MirrorOPD-verl/analysis/e54-mdpo-20261029/runs/e54-topd-mdpo-20261029` 与同级 `e54-mdpo-sweep-20261029`。这些回答沿用旧空 think 前缀，不属于 E55/E56/E57 的长程、五 benchmark、n=16 验证。

参考 vLLM 规则的 83 条中，57 条原本触顶、26 条原本自然结束；6 条原本判对，其中 4 条截断后仍判对。平均长度从 8.38k 降至 6.97k，判对数从 572 降至 571，准确率净变化为 −0.08 个百分点。剩余 150 条原本触顶的回答未被参考 vLLM 规则截断。

### 旧回答的重复程度与检测覆盖

重复率按单条回答内的 token 窗口定义：重复 n-gram 比例为 $1-U_n/W_n$，其中 $W_n=\max(L-n+1,0)$ 是窗口总数，$U_n$ 是不同窗口数，零窗口时定义为零。它衡量文本重复程度；正常公式、复查和枚举也可能贡献重复，不等于人工标注的病理循环概率。32-gram 比 8-gram 更长，可减少只重复短语或公式片段的影响，但仍不能代替语义判断。

| 判据              | 全部回答，分母 1,280 | 触顶回答，分母 207 | 自然停止回答，分母 1,073 |
| ----------------- | -------------------: | -----------------: | -----------------------: |
| 重复 8-gram ≥50%  |         347（27.1%） |       201（97.1%） |             146（13.6%） |
| 重复 8-gram ≥80%  |         256（20.0%） |       179（86.5%） |               77（7.2%） |
| 重复 8-gram ≥90%  |         143（11.2%） |       122（58.9%） |               21（2.0%） |
| 重复 32-gram ≥50% |         283（22.1%） |       185（89.4%） |               98（9.1%） |
| 重复 32-gram ≥80% |         145（11.3%） |       115（55.6%） |               30（2.8%） |

全部回答按窗口数加权的重复率为 8-gram 76.64%、32-gram 61.39%；按回答等权的均值分别为 36.09%、20.30%。长回答更重复，因而加权结果明显更高。重复 8-gram ≥80% 的 256 条回答贡献了全部输出 token 的 67.8%，这指这些回答的总长度占比，不是证明其中每个 token 都无效。

参考 vLLM 检测遗漏的 150 条触顶回答中，有 131 条重复 8-gram ≥80%，129 条重复 32-gram ≥50%。所以该参考规则只节省 16.80%，不能解释为剩余长尾多数没有重复。它要求精确、连续、指定周期和次数的重复，比全篇重复率的条件严格。

为区分最大周期的影响，额外只做停止位置回放，把周期范围扩大到 1,024 和 2,048，最小周期与次数仍为 16 和 8：

| 最大周期 | 全部回答触发数 | 207 条触顶回答中触发数 | 全部输出 token 减少 | 截断后重新判分 |
| -------- | -------------: | ---------------------: | ------------------: | -------------- |
| 256      |             83 |                     57 |              16.80% | 已完成，见上表 |
| 512      |            129 |                     89 |              25.68% | 已完成，见上表 |
| 1,024    |            156 |                    101 |              29.51% | 未执行         |
| 2,048    |            162 |                    105 |              30.14% | 未执行         |

即使扩大到 2,048，仍有 102 条触顶回答未触发，其中 83 条重复 8-gram ≥80%，81 条重复 32-gram ≥50%。继续扩大周期的边际收益已经下降；这些统计不能单独区分变化式重复、间歇重复、次数不足与更长周期，也没有证明宽窗口设置保持准确率。该候选按 256 回放；当前运行选择见[使用说明](2026-10-30-验证重复检测与提前停止.md)。

还人工检查了全部 6 条重复 8-gram <50% 的触顶回答的末尾 1,500 个字符。一条 DAPO train-2792 在末尾已经原样循环；其余五条在不断替换数字继续枚举，例如 train-3427 试到 Step200，MATH-500:110 试到 Step298，MATH-500:285 持续尝试 `(220,220,0)`、`(221,221,0)` 等。低全篇精确重复率也不保证是有效长推导。这里只对末尾作了人工观察，没有给全部 1,280 条回答作完整的语义循环标注。

## 完整步骤匹配与 MD-OPD 压缩规则对照

该对照仍使用同一批 1,280 条回答，所有规则只做 CPU 离线回放与保留前缀的重新判分，没有修改在线默认值。需要区分三种“完全相同”：当前 vLLM 的连续 token 周期、包含步骤编号的完整步骤相同、仅去掉步骤编号后完整步骤相同。

完整步骤规则使用最近 32 个块的历史。开始按空行分段，观察到第一个完整 `Step N` 或 `步骤N` 标题后改按步骤切分；步骤必须等下一个完整标题出现才算完成，不使用未来内容决定较早的分段。每块至少 64 token；短块或新内容重置连续重复计数。归一化仅统一空白、去掉步骤标题的数字，保留数学内容中的数字和符号。该候选条件为连续 3 个步骤都出现过，且它们合计至少 512 token。

| 完全匹配规则                              | 提前停止回答 | 输出 token 减少 | 判对→判错 / 判错→判对 |
| ----------------------------------------- | -----------: | --------------: | --------------------: |
| 当前 vLLM：16–256 token 连续重复 8 次     |           83 |          16.80% |                 2 / 1 |
| 完整步骤，保留步骤编号，3 步且 ≥512 token |            4 |           0.48% |                 0 / 0 |
| 完整步骤，去掉步骤编号，3 步且 ≥512 token |          110 |          21.47% |                 4 / 0 |
| 完整步骤，去掉步骤编号，4 步且 ≥512 token |          105 |          20.59% |                 3 / 0 |
| 完整步骤，去掉步骤编号，6 步且 ≥512 token |          102 |          19.76% |                 3 / 1 |

去掉标题编号能捕获一部分反复重启的推导，但整块匹配仍会漏掉段内措辞和公式变化。它比 vLLM 参考规则多省约 4.7 个百分点的 token，并伴随更多原本判对回答变为判错；不是无损替代。

### MD-OPD 实际实现

MD-OPD 的离线脚本与训练监控使用字符滑窗 zlib 压缩比：窗口 1,024 字符、步长 256 字符、zlib level9，分数为原始 UTF-8 字节数除以压缩后字节数；任意窗口分数 ≥10，就将整条回答标为 repetition。它检测的是可压缩性，不要求同一 token 片段连续完全重复，也不是已接入生成中止的模块。[^mdopd-rule]

在线回放必须在窗口末尾才允许发出告警。原实现的 `onset_frac` 使用首次超标窗口起点，因此不能把 `post_onset_frac` 直接解释成在线能节省的比例。对齐尾部的额外窗口若到 EOS 才能确定，也不能计入提前停止收益。本对照使用原始采样 token 到字符的映射，核对全部 1,280 条解码文本与保存输出一致，避免重分词改变 token 数。

| 窗口字符数 / 阈值，步长均为 256 字符 | 提前停止回答 | 207 条触顶回答中截断数 | 输出 token 减少 | 判对→判错 / 判错→判对 |
| ------------------------------------ | -----------: | ---------------------: | --------------: | --------------------: |
| **1,024 / 10，MD-OPD 原默认**        |       **18** |                 **13** |       **3.70%** |             **0 / 0** |
| 1,024 / 8                            |           29 |                     19 |           5.63% |                 2 / 0 |
| 1,024 / 6                            |           52 |                     34 |          10.28% |                 3 / 0 |
| 1,024 / 4                            |          165 |                     85 |          29.07% |                14 / 0 |
| 4,096 / 10                           |          167 |                    107 |          32.56% |                 5 / 0 |
| 4,096 / 6                            |          280 |                    175 |          55.35% |                 8 / 2 |
| 8,192 / 10                           |          278 |                    178 |          52.23% |                 7 / 2 |

1,024/4 的离线整条标记数为 166，实际提前停止数为 165，因为其中一条只在终末检查时满足条件。其余表中压缩设置的两个计数相同。

原默认在这批长段落循环上很保守。以 MATH-500:422 为例，同一韦达推导反复重启，但 1,024 字符窗口内的最大压缩比只有 3.81；扩大到 4,096 和 8,192 字符后，分别为 10.76 和 19.49。小窗口可能只容纳长推导的一次出现，无法看到足够多的重复副本。简单降低小窗口阈值则会把正常数学格式一起纳入：已复核的正常叉积解答 MATH-500:298，1,024 窗口分数为 3.47，高于多条明确循环回答的 2.49–3.03。

### 漏检与 AUC 的证据边界

在全量回答中，重复 8-gram ≥80% 的参考集合共有 256 条。MD-OPD 原默认提前截到其中 13 条，未截到 243 条；8,192/10 截到 235 条，未截到 21 条。这个集合由另一个文本重复统计定义，不能直接作为“语义循环真值”来报告 recall。

已有 16 条人工复核记录中，9 条被判断为明确循环或末尾循环，1 条为正常推进，其余 6 条属于回溯、枚举或不确定情况。只在这 10 条上比较：

| 规则                            | 9 条确认循环中截到 / 漏掉 | 1 条正常反例误截 | 最大窗口压缩比分数的探索性 AUC |
| ------------------------------- | ------------------------: | ---------------: | -----------------------------: |
| vLLM 参考规则                   |                     1 / 8 |                0 |                         不适用 |
| 完整步骤去编号，3 步 ≥512 token |                     5 / 4 |                0 |                         不适用 |
| MD-OPD 1,024/10                 |                     0 / 9 |                0 |                          0.333 |
| 4,096/10                        |                     5 / 4 |                0 |                          1.000 |
| 8,192/10                        |                     9 / 0 |                0 |                          1.000 |

AUC 用连续分数比较每个已审正例与已审反例的排序，平分计 0.5，与单个阈值无关。这里总共只有 9 个正负配对，反例仅一条，正例还包含同题不同参数的回答；抽样本来就包含“当前检测器漏掉的高重复回答”。因此 **0.333 和 1.000 只描述这十条的分数排序，不是总体检测性能估计**，不能据此声称宽窗口没有误报或当前 vLLM 总体漏检率为 8/9。要估计总体 AUC、precision 与 recall，需要独立、覆盖正常证明和复杂枚举的标注集，并按题目分组划分与计算不确定性。

保留前缀的判分变化也不能代替语义误报。8,192/10 的 7 条判对→判错中，既有原本就循环但 verifier 标记正确的回答，也包含 DAPO train-7319 这类长时间循环后确实恢复并给出答案的轨迹。净判对数从 572 变为 567，不代表只误截了五条。

### 成本与复算

原实现全量扫描的 CPU 时间：1,024 窗口约 2.71 秒／102,235 次压缩，4,096 约 4.61 秒／92,634 次，8,192 约 6.26 秒／83,814 次，平均每窗约 26、50、75 微秒。这只包含压缩窗口计算，不含解码、队列、跨进程通信及 GPU 调度；不能直接换成真实 valid 加速倍率。8,192/10 可作为离线诊断的高覆盖候选，但已出现判对→判错，需要按可接受的风险上限另行评估。MD-OPD 原默认 1,024/10 在这批数据中零判分损失，只能说明该批未观察到损失，不能保证新回答安全。

## 人工复核：相似表达与无进展循环

统计阈值尚未形成覆盖全部 1,280 条回答的语义标注。为检查其含义，用 seed20261030 从四个层各抽四条：高 32-gram 重复且参考 vLLM 检测遗漏的触顶回答、高 8-gram 重复但自然停止的回答、中等重复率且自然停止的回答、低全篇重复率的触顶回答。共复核 16 条，其中一条短回答阅读全文，其余检查多个中间片段与末尾。这个抽样用于寻找机制与反例，不用于估计总体病理循环比例；审阅时可见原始分数，不是盲评。

| 案例                         | 实际内容                                                                                    | 对停止判据的含义                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| MATH-500:422，κ=1、η=0.2     | 重复定义根的配对和 S/T/U、重写韦达关系，到了乘积就说复杂，再以新 Step 编号重启，直到 Step85 | 不是仅有共同词语；相同数学操作与失败点反复出现，删除步骤编号后的块匹配有机会覆盖 |
| MATH-500:305，κ=0.5、η=0.3   | 不断解得 9/19，代回时漏掉分母根号，宣称无解，然后再解同一方程                               | 有明确循环；归档 verifier 判对并不意味着过程正常，循环标签与正确性标签应分开     |
| DAPO train-15290，κ=1、η=0.2 | 反复推得面积比 `2-sqrt(3)`，计算 k+m=1 后却称不是整数，再重做同一弦长推导                   | 语义与结论都循环，局部措辞和标题变化使短周期精确检测不足                         |
| MATH-500:298，κ=0.5、η=0.1   | 全文按叉积展开、反对称、代入向量、分量相加依次推进并结束                                    | 8-gram 重复 38.1%，32-gram 仅 0.27%；这是正常数学格式和变量复用，不能截断        |
| MATH-500:285，κ=1、η=0.2     | 原题要求正整数根，却持续试 `(74,74,0)` 到 `(228,228,0)`                                     | 数字在变，但候选持续违反已知正整数约束；比单纯相似词语更有力的无进展证据         |
| DAPO train-5639，κ=0、η=0.2  | 计算不同 n 对应的相邻项 gcd，n 持续增加                                                     | 可能是低效枚举，也可能在寻找规律；不能把数字统一替换后直接宣布循环               |

八条高重复分层样本的抽读片段都显示了反复重启相同推导的现象。中等重复组则同时包含正常推进、反复改口和仍在探索的过程。这个差异支持把“新前提／新候选／新结论是否出现”作为复核对象；不支持用最终答错或余弦相似度高，单独定义循环。

[逐例复核记录](data/semantic-stop-study-20261030/review.json)包含抽样层、实验来源、题目 ID、判断、审阅范围和原文片段。后续分类器应保留 `continue`、`loop`、`uncertain` 三种结果；不确定时继续生成。完整标注还需要记录循环开始位置、是否后来恢复，以及正常证明、有限枚举、回溯纠错等负例。按题目 ID 划分训练与验证，不能把同一道题的不同 κ 回答或相邻窗口分到两侧。

## 循环后的恢复与判分损失

生成中的循环不是程序回到完全相同的机器状态：前缀仍在增长，下一 token 的条件分布依赖整个可见历史；这里还使用随机采样。只要脱离当前模式的替代 token 仍有非零采样概率，连续重复多次后依然可能换一种表达或推导路径。温度、top-p 和上下文会影响这个概率；top-p 也可能把退出候选排除。因此，“重复很久”和“采样支持已经锁定循环”不同。相关研究分别分析了学习误差导致的偏好循环，以及采样截断如何关闭退出路径；这些机制解释不等于已经测出本模型各状态的退出概率。[^loop-learning][^loop-lock]

以保留的 verifier 标签统计，四种规则命中后的结局如下。`自然停止` 只表示实际生成了 EOS，并不证明已经脱离循环或完成了证明。

| 规则            | 命中回答数 | 最终自然停止 | 最终自然停止且判对 | 截断导致判对→判错 | 其中最终自然停止且判对 |
| --------------- | ---------: | -----------: | -----------------: | ----------------: | ---------------------: |
| vLLM 16–256 / 8 |         83 |           26 |                  2 |                 2 |                      1 |
| zlib 1,024 / 10 |         18 |            5 |                  0 |                 0 |                      0 |
| zlib 4,096 / 10 |        167 |           60 |                  3 |                 5 |                      2 |
| zlib 8,192 / 10 |        278 |          100 |                  4 |                 7 |                      3 |

vLLM 规则的两条损失中，DAPO train-7319 在约 3.94k token 已满足精确重复条件，后续重复过后转为中文重述，用复数幂的实部求和，最终在约 30.67k token 输出 `boxed{1004}` 并结束。这是实际的恢复反例。另一条 MATH-500:119 始终触顶且没有 boxed 答案，末尾仍循环枚举 −9、13、3；其标签变化与 verifier 的提取位置有关，不能算作恢复成功。

对 zlib 8,192/10 的七条损失逐例检查，四条触顶回答都没有 boxed 答案，结束前仍在重复；另外三条自然停止并生成被判对的最终 boxed 答案，分别为 train-11504、train-11949、train-7319。三个回答的首个 boxed 标记约在 15.07k、23.59k、30.66k token，候选停止位置分别为 5.54k、7.92k、4.58k。train-11504 的末段仍有不一致的推导，所以“最终答案被判对”也不等于完整证明有效。不能把七条评分损失全部叫作七次真实推理恢复。

[逐例审计](data/recovery-risk-20261030/audit.json)保存了原始分数、格式分数、触顶／EOS、boxed 数量、截断与原始结尾。官方判分口径仍保留全部损失，不剔除提取敏感案例来制造无损结论。也没有逐条标注所有命中回答的语义退出位置，因此尚无总体的“离开循环概率”估计。

风险评估至少要区分：正常推导被判循环的概率；每次触发停止后损失原本正确答案的概率；全部评测回答中额外正确性损失的比例。现有数据中，vLLM 规则为 2/83=2.41% 的触发后评分损失，折合全部回答 2/1,280=0.156 个百分点；zlib 8,192/10 为 7/278=2.52%，折合 0.547 个百分点。这些是调参样本内描述，不能直接用作部署风险上界。

可以研究“首次报警后继续观察 512–1,024 个新 token；出现实质新步骤则撤销告警”的低成本规则，但它未经过回放验证，也无法保证保住十几 k token 后才恢复的轨迹。相邻重叠窗口的多次报警并非独立证据。参数选择应固定风险目标后，在独立题目与新 checkpoint 上验证，而不是在同一批回答上反复调到零损失。以独立同分布试验为例，零损失的约 3,000 条样本才对应约 0.1% 的单侧 95% 风险上界；这里仅有 128 道题的十组回答，不满足把 1,280 条都当独立试验的条件。

## 原生检测器的 CPU 成本

对原生检测器做了单独的 CPU 微测量：用 vLLM `ConstantList` 包装 8,192 个随机 token，固定最小周期 16、重复次数 8，每种最大周期执行 5 轮、每轮 2,000 次检测。最大周期为 128、256、512 时，单次检查中位耗时分别约 38、87、181 微秒。[原始测量](data/repetition-stop-20261030/cpu-cost.json)仅反映本机合成非重复输入上的检测成本，不包含 GPU decode、IPC 或真实文本下的比较开销。若同一轮检查 64 条序列，256 的设置仅检测部分就可能需要约 5.5 毫秒串行 CPU 时间。该开销也是没有直接选用 512 的理由；实际是否更快仍需完整验证墙钟对照。
