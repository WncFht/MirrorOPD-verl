# EOS 补偿融合实现与训练验收

更新日期：2026-11-01。EOS 合并已接入普通 Full-KL 与一般 MDPO 的 `precompute_fused` 路径。实现复用已有稳定行归约和 PrecomputedKL，保留 FP32 大张量、逐行 EOS 高精度修正、FP16 AMP 保护以及既有指标定义。两卡真实 Qwen3-1.7B 的固定 actor 对照中，中位耗时为 34.45→11.52 秒，allocated 峰值为 25.60→17.25 GiB；这不是完整训练任务或八卡长序列的速度承诺。

## 实现与精度合同

| 层次            | 实现与边界                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| 停止动作映射    | `TerminationActionMap` 一次构造固定整数索引，在所有 token chunk 中复用；同一类逻辑服务 teacher-only KL 与 MDPO |
| 高精度范围      | 仅停止 ID 子集和逐行修正使用 FP64；非停止 logits 与融合工作区保持 FP32，临时高精度量按 token 数×停止 ID 数增长 |
| 稳定行代数      | 继续使用相对差分、归一化加权矩、小量余项与主梯度重建；保留历史局部 FP64 差分                                   |
| EOS 梯度        | 合并动作的梯度按学生的类内概率分回原 token，再执行既有梯度和修正及 dtype 转换                                  |
| Precompute／AMP | 继续共用一次前向中的 VJP 和 dH/dW 累计；FP16 在收到上游 loss scale 前保留 FP32 梯度                            |
| 诊断            | Torch 路径改用只返回值的 KL 接口，融合路径沿用 `gradient=False`；完整诊断保留                                  |
| 状态管理        | 没有新增跨更新的 target 缓存、动态精度开关或诊断调度，anchor 生命周期沿用原框架                                |

对于一个停止类，令 b 是原 EOS logits 的最大值，u 是排除最大项后的稳定 log1p 归一化修正。FP32 主值 h 与 FP64 修正 e 分开保存：

$$
h=\operatorname{round}_{32}(b+u),\qquad e=(b-h)+u.
$$

后续相对差分先处理 FP32 主值的公共偏移，再加入相应的 e 差，避免先形成一个大数后丢掉小修正。概率权重和主要归约仍使用 FP32；这是经误差预算验收的混合精度实现，不是逐位复现全 FP64。

停止类合并必须先分别作用于 student、anchor 和 teacher，再构造目标。若合并 logit 的梯度为 g_E，原停止 token i 的梯度为：

$$
g_i=g_E\,\frac{p_i}{\sum_{j\in E}p_j}.
$$

`precompute` 保留高精度参考；`precompute_fused` 在 CUDA FP16/BF16/FP32 输入上使用补偿融合。EOS 配置继续要求相同词表及至少两个合法停止 ID，不扩展到 sampled 或 BPO。CPU／FP64 参考回退不能充当 CUDA 验收。

Teacher-only endpoint 的 loss 使用合并动作空间，`full_kl` 和位置指标仍保留原始词表语义，`termination_equiv_kl` 单独记录合并目标。一般 MDPO 的 teacher/anchor/target 诊断使用合并动作空间。没有通过删除 EOS 配置、减少诊断或改变最终 1/η 来取得速度收益。

代码入口：[停止类映射](../../../../../../verl/trainer/distillation/termination.py)、[共享 loss 分派](../../../../../../verl/trainer/distillation/full_vocab.py)、[稳定融合行公式](../../../../../../verl/trainer/distillation/full_vocab_triton.py)。

## 数值与分布式验收

核心 CPU 检查 101 项、实际 CUDA 检查 144 项通过；配置与 launcher 的 233 个检查最终通过。CUDA 检查包含原始非 EOS 数值回归、实际词表 BF16、FP16 loss scaling、FP32、公共偏移、κ/η 边界、hidden/head VJP 和冻结 teacher。新增 EOS 独立 80 位参考的梯度预算为 rtol=2e-4、atol=1e-22，标量预算为 rtol=2e-4、atol=1e-24；既有非 EOS 强数值测试没有放宽。

部分极小信号的相对误差仍会很大，绝对容差明确覆盖这一范围；不能称为所有实数输入上的精确计算。此前固定 logits 的实验反例与原始读数保留在同级日志仓库 `analysis/eos-precision-study-20261101/`，没有删除失败样例来制造通过结论。

| 两卡 Qwen3 验收          | 覆盖                                                         | Fused／参考三次更新后的最大参数绝对差 |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------: |
| BF16                     | tied head、长度 129、梯度检查点、空局部 mask、恢复           |                                     0 |
| FP16                     | AMP scale 增长、冻结 anchor、实际更新、恢复                  |                               1.96e-8 |
| BF16 GEMM＋FP32 中间表示 | 独立 teacher 精度、实际更新、恢复                            |                                     0 |
| η=1 endpoint             | 与原 Full-KL 入口的参数、Adam 和 scheduler 比较              |                              逐位一致 |
| BF16 累积                | 长度 129、token budget129，强制拆分 micro-batch；空局部 mask |                                     0 |

五组共执行 63 次有效更新，数值有限、anchor 冻结与跨 outer 刷新、head hooks、上下卡和适用分支的 checkpoint 恢复通过。小模型验收验证执行合同，不证明长期训练的任务效果。完整测试入口见[验证矩阵](../../numerics/full-vocab/validation.md)。

## 真实模型的固定 actor 对照

Student 为初始 Qwen3-1.7B-Base，teacher 为 Qwen3-30B-A3B-Instruct-2507。使用现有银行的八条原始 token 轨迹，每条 response 最多 512，共 4460 个输入 token、3164 个 loss token；teacher hidden 只准备一次。两张 H800、FSDP2、FP32 master、BF16 计算参数、FP32 reduction、activation checkpointing、token budget8192、reuse16、κ=0.5、η=0.1，完整诊断开启，梯度累积 no-sync 关闭。

计时包含 actor/anchor 前后向、head、AdamW、FSDP 通信及参数／optimizer 上下卡，不含 teacher hidden 准备、TQ、rollout 或验证。LR=0 使各实现始终看到相同参数；AdamW 仍执行并分配状态，参数哈希核对通过。固定对照关闭输入 shuffle，并开启确定性 attention backward。首次未固定重排的准备性运行在 FP64 基线内部出现约 0.12% 的梯度范数波动，未进入正式性能表；随后固定了比较条件。

每个 backend 单独预热一轮，随后按 A–B、B–A 各测一轮。下表来自独立复跑，torchrun 明确返回 0；保留两个原始耗时，不宣称置信区间。

| Backend                    | 两次 actor 耗时 | 中位耗时 | Allocated 峰值 |
| -------------------------- | --------------- | -------: | -------------: |
| precompute，高精度参考     | 32.52 / 36.37 s |  34.45 s |      25.60 GiB |
| precompute_fused，EOS 补偿 | 11.57 / 11.46 s |  11.52 s |      17.25 GiB |

中位速度为 **2.99×**，耗时减少约 **66.6%**，峰值减少约 **8.36 GiB**。两条路径的记录 loss 分别为 0.4139291644 / 0.4139291942，梯度范数为 5.251047 / 5.252157，范数相对差约 **0.0211%**。这验证固定模型和输入下的完整 actor 收益；token 数、GPU 数、序列长度及 IO 范围与正式 E59–E62 不同，不能外推为八卡长程速度或任务质量。

## 新实验与使用

E59/E60/E61/E62 分别对应原 E55/E56/E57/E58，模型、数据、目标、训练与验证预算保持对应；新编号使用 `precompute_fused/chunk512` 和显式 actor/anchor `bf16`。旧编号及已记录结果保持其历史配置。具体矩阵、覆盖优先级及统一启动命令见[训练设置](../../../settings/训练设置.md#e59e62eos-补偿融合对照)。这些是已通过基础 infra 验收的预设，尚未执行四组 100 outer 正式实验。

可以关闭诊断或调整 chunk 的既有开关继续保留；新预设保持完整诊断，不增加诊断频率或自动降精度机制。冻结目标的逐 token 缓存需要跨重排、样本位置和 anchor version 管理；当前已测收益主要来自行代数融合，没有为未测收益引入额外缓存状态。
