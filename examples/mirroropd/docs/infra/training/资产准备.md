# 模型与数学数据准备

本文记录数学资产的准备、目录与 CPU 检查范围。命令均从仓库根目录执行。

## 数学资产准备与检查

原始模型默认放在仓库同级的 `model/hub/<组织--仓库>/<revision>/<subfolder>/`，训练导出的模型统一放在 `model/checkpoints/`，数据仍放同级 `data/`。`MODEL_ROOT` 指向总根目录 `model/`；调用方通过模型注册表解析具体版本，不在根目录后直接拼模型简称。目录、历史位置投影及正式引擎集成计划见[统一模型资产维护方案](2026-10-30-统一模型资产与正式引擎集成维护方案.md)。

本机工作区为 `/mnt/tidalfs-bdsz01/dataset/llm_dataset/zkn_data/fht_data`；其他机器显式设置 `MIRROROPD_WORKSPACE` 和 `MODEL_ROOT`。资产不放入源码 checkout，多个 worktree 共用同一根目录：

```text
WORK/
├── MirrorOPD-verl/
├── model/
│   ├── hub/<组织--仓库>/<revision>/<subfolder>/
│   ├── checkpoints/<run-relative-path>/
│   ├── migrations/<migration-id>/
│   └── registry.json
└── data/
    ├── math_manifest.json
    └── math/
        ├── DAPO/train.parquet
        ├── MATH-500/test.parquet
        ├── AMC23/test.parquet
        ├── AIME24/test.parquet
        ├── AIME25/test.parquet
        └── AIME26/test.parquet
```

需要实际模型目录时，在仓库根目录运行：

```bash
python -m examples.mirroropd.assets.paths --alias DeepSeek-R1-Distill-Qwen-1.5B
python -m examples.mirroropd.assets.paths --alias Qwen3-8B
```

别名必须唯一指向已登记的不可变模型；存在不同权重变体时使用对应的明确别名，不能按短名称猜测。导入和下载后的完整目录使用实体文件，旧位置不保留软链接或兼容目录。

| 脚本                                                         | 用途                                                                                                 |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| [prepare_models.py](../../../assets/prepare_models.py)       | 导入／下载选定模型，支持单文件和索引分片，写入按身份解析的实体目录                                   |
| [prepare_math_data.py](../../../assets/prepare_math_data.py) | 导入已有 parquet，或从原始文件重建 DAPO 与五个数学验证集；统一 Arrow schema，写 `math_manifest.json` |
| [check_assets.py](../../../assets/check_assets.py)           | 模型仅检查必要文件；逐行检查数据，统计 prompt 长度、重复与训练/验证题面重叠，写 `asset_check.json`   |

在已有资产的机器上，可以离线导入采用相同注册布局的模型根目录；路径参数填写该机器的实际绝对路径：

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py \
  --source-root /已有的/model --model-root /目标/model
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py \
  --source-root /已有的/MD-OPD/data --data-root /目标/data \
  --datasets DAPO MATH-500 AMC23 AIME25
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py \
  --download --data-root /目标/data --datasets AIME24 AIME26
```

显式导入时来源文件保留，目标文件按注册身份创建。数据输出已存在时默认拒绝覆盖；确认要重建时显式传 `--overwrite`。模型目标已存在时只检查必要文件并跳过，不覆盖权重。默认仍选择原来的两个 1.5B 模型，约 7.1 GB；`--models all` 选择本准备入口支持的十个公共配方模型（原 A–F 八个、Polaris 和 30B-A3B 教师），也可在 `--models` 后列出具体目录名。2026-10-24 的扁平目录归集属于历史操作；2026-10-30 本机统一为不可变身份目录，原分散位置不再保留。历史原文通过位置清单读取，不作为当前下载或执行入口。

从原始数据重建时使用 `--raw-dir`；源目录包含 `dapo-math-17k.parquet`、`math500_test.jsonl`、`amc23.parquet`、`aime2025-I.jsonl`、`aime2025-II.jsonl`，以及新增的 `aime2024.parquet`、`aime2026.parquet`。转换沿用固定 MD-OPD 的数学规则：DAPO 按源 `extra_info.index` 保留第一次出现，去掉原始 Answer 格式包装；AMC/AIME 与 MATH-500 保留各自题面和答案，AIME 按 I、II 顺序合并。[^math-prep]

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py --raw-dir /原始文件目录

# 仅在能访问外网的机器上显式下载；不会安装新的 Python 包。
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download
# 准备本入口的十个公共配方模型，或用 --models 指定其中几个；已有目标只检查并跳过。
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download --models all
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py --download
```

模型身份以可版本管理的 `examples/mirroropd/assets/model_registry.json` 为准，包含完整 revision 和必要的子目录。原有两个模型分别固定为 DeepSeek `ad9f0ae0`、JustRL `0637e409`；其他登记模型也按对应身份解析，不能把默认分支当作固定快照。[^student-model] [^teacher-model] 数据下载使用 ModelScope 的上述原始数据镜像，镜像 revision 为 `master`；manifest 记录来源与数据行数。重复实验应保留原始文件，不把浮动镜像 revision 当作不可变版本。

E48 另使用 `POLARIS-Project/Polaris-7B-Preview`，本地目录名为 `Polaris-7B-Preview`。2026-10-26 起模型目录支持该模型，当时的 `--models all` 包含原 A–F 八个模型及 Polaris，共九个。单独准备：

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download --models Polaris-7B-Preview
```

准备完成后在开发机执行：

```bash
make assets-check
# 检查本入口支持的全部公共配方模型：
make assets-check ASSET_CHECK_ARGS="--models all"
# 只检查数据，不要求模型已到位：
make assets-check ASSET_CHECK_ARGS=--data-only
```

模型检查要求三个配置／tokenizer JSON 存在、非空且可解析。权重支持 `model.safetensors`，或者 `model.safetensors.index.json` 引用的全部分片；缺少任意一个分片都会报错。`generation_config.json` 是可选文件，缺少时不报错；准备脚本在来源中有该文件时会保留它。检查不读取完整权重或逐张量核对，也不计算文件摘要。student tokenizer 仅用于计算数据 prompt 长度；`--data-only` 跳过模型和 tokenizer，不计算 token 长度。

检查要求 DAPO、MATH-500、AMC23、AIME24、AIME25、AIME26 分别为 17917、500、40、30、30、30 行，六个字段及嵌套类型一致；每行必须有非空 user prompt、正确 `data_source`、`ability=math`、非空字符串答案、`style=rule`、正确 split 和唯一 `extra_info.index`。直接检查实际 parquet 内容，不依赖 manifest。prompt 长度使用 student 的 chat template 和 generation prompt 计算；超过限制的数量会报告，训练端仍按 `filter_overlong_prompts` 处理。这些检查确认数据格式与训练入口兼容，不能判定题目的标准答案是否正确。

重复题面和训练/验证交集只报告，不自动改变配方。2026-10-20 本机重建的 18487 行与既有数据逐行一致；DAPO 有 662 行重复题面，与 MATH-500、AMC23、AIME25 分别有 2、5、0 道完全相同的题面。完整词面匹配不是语义去污染；若要删除重叠，应另建数据版本和对照实验。

同次 CPU 检查确认四份数据的最大 prompt 长度分别为 1493、796、220、258 token，均未超过 4096；没有执行 GPU 训练。

模型和数据需要另行上传一次，不进入 `make archive-pack` 的源码包。数据传输包应包含顶层 `data/`，在目标机器解压到共享 WORK 基目录后再运行检查；这类资产包使用普通 `tar -xzf ... -C <基目录>`，不使用会保护运行目录的源码 `archive-unpack`。

## AIME24、AIME26 与 30B 教师

默认数学验证现包含五集。原始文件增加 `aime2024.parquet`、`aime2026.parquet`，转换只提取题目和答案；源 ID 完整性、revision、许可及训练题面重合见[数学验证协议](../../settings/验证设置.md)。`--datasets` 可只导入或准备指定集，避免覆盖已有数据。

E54 的教师为官方 `Qwen/Qwen3-30B-A3B-Instruct-2507`，模型注册表固定 revision `0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe`；目标目录通过注册表解析为共享的 `model/hub/Qwen--Qwen3-30B-A3B-Instruct-2507/0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe/`。它是非思考模式的 MoE 模型，训练中的 teacher 使用八卡 FSDP2 分片。包括该模型后，`--models all` 共选择十个模型。

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py \
  --download --models Qwen3-30B-A3B-Instruct-2507
```
