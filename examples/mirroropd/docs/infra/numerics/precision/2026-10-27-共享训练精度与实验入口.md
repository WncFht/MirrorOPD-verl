# 共享训练精度与 OPD／MDPO 实验入口

本文说明从诊断原型进入生产执行层的精度策略。它解决配置、模型执行、教师投影、AMP 恢复和实验入口的一致性；候选精度能否提高完整训练的任务分数，仍须正式对照。机制证据见[精度报告](../../../experiments/teacher-transfer/optimizer-precision/mechanism/2026-10-27-MDPO反弹机制与浮点精度研究报告.md)。

## 1. 配置与目标

唯一训练入口仍是 `examples/mirroropd/run_math_opd_ablation_fsdp2.sh`。`--precision` 只选择 actor 的执行策略，anchor 从同一个 actor 捕获，因此自动使用相同策略。Teacher 与 rollout 各自保留明确的独立精度；选项不改变蒸馏目标、κ/η、动作积分方式或优化器学习率。

| CLI / TRAIN_PRECISION | 计算参数 | 中间表示与输出头                                                                                          | Attention                             | 用途                     |
| --------------------- | -------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------ |
| `bf16`                | BF16     | 原生模型行为；full-vocab 投影输出 FP32                                                                    | 原生 FA2                              | 基线                     |
| `fp16`                | FP16     | 原生模型行为；full-vocab 投影输出 FP32                                                                    | 原生 FA2                              | 精度候选，带 GradScaler  |
| `bf16_fp32`           | BF16     | 主干 Linear 使用 BF16 输入／权重、FP32 输出；embedding 输出、残差、norm、gating 与最后 head 计算保留 FP32 | FA2，Q/K/V 进入 attention 时降至 BF16 | 保留部分低精度计算的候选 |
| `fp32`                | FP32     | FP32                                                                                                      | 按 packed 边界分段的 SDPA math        | 较慢的参考执行路径       |

`bf16_fp32` 不等于完整 FP32 forward/backward：主干 Linear 的反向矩阵乘仍使用低精度操作数，FA2 仍是低精度。该模式最后 head 使用 FP32 算术，不能声称全部 GEMM 都维持原 BF16 成本。FP32 参考关闭 TF32；分段 math attention 的时间与内存开销不适合直接作为长序列吞吐方案。

原生配置字段是 `actor_rollout_ref.actor.fsdp_config.forward_precision`。省略或设为 null 时沿用原有 `mixed_precision` 行为；显式 profile 与低层 `mixed_precision.param_dtype` 冲突时报错。预设、环境变量、CLI、末尾 Hydra 的优先级保持不变。配置解析后，actor 的 `strategy` 才同步到 engine，因此 FSDP2／SP 等能力约束在加载前检查。

混合 profile 要求 FlashAttention2，避免仅更换 attention backend 就悄悄改变计算精度。首版训练 profile 保持 FP32 master 参数；支持 dense Qwen2/Qwen3、FSDP2、SP=1，拒绝 LoRA、`model.use_liger` 模型补丁、通用 fused PPO 和 QAT 组合。FP32 reference 要求 packed 输入，不支持 sliding-window 或 KV-cache attention。其他模型扩展应增加执行能力验证，不增加 OPD／MDPO 各自的精度分支。

| [模型精度适配](../../../../../../verl/models/transformers/precision.py)                     | 模型实例内的 Linear／Embedding 适配与 FP32 packed attention     |
| [共享线性投影](../../../../../../verl/utils/linear.py)                                      | 低精度 CUDA GEMM 的 FP32 输出及一阶 VJP；主干与 full-vocab 共用 |
| [FSDP 引擎](../../../../../../verl/workers/engine/fsdp/transformer_impl.py)                 | FSDP 模块边界、autocast、教师独立投影与 scaler 传递             |

混合 profile 在当前模型实例上安装 forward 方法，不替换 HF 的全局模型类。参数对象、state-dict 名称、tied embedding、root/head FSDP hook 保持一致。FP32 attention 注册独立名称，只有显式选择该 profile 的模型使用它。Anchor 无需额外模型副本或另一套精度参数。

FSDP 的 `param_dtype` 决定 all-gather 后的参数精度；混合 profile 关闭 block 边界的强制输入降精度，并关闭外层 autocast，避免 FP32 中间表示被再次降精度。主干 Linear 在自己的实现内明确形成 BF16 操作数。

### 2.1 Teacher 不随学生精度改变

旧引擎按学生 hidden dtype 转换教师 hidden/head。现在教师 head 按教师 hidden 的 dtype 获取，教师投影使用自己的操作数类型；学生换精度不再隐式改变教师的输出投影。此前的 RoPE buffer 保真修复继续默认生效。

因此新实验应重新构建 teacher hidden 缓存，并使用同一版本教师。历史异精度诊断的 loss 数字不能直接当成新执行路径的结果。既有 BF16 学生／BF16 教师路径保持相同类型。

### 2.2 复用 full-vocab 优化

`precompute_fused` 现在接收 CUDA FP16／BF16／FP32 学生输入，共用稳定行归约、分块和提前计算 VJP。FP16 的 dZ、预计算 dH/dW 在收到上游 loss scale 之前保持 FP32，缩放后才转回模型 dtype；不能在 forward 中提前舍入小梯度。

Dense、precompute、fused 的值和 hidden/head VJP 与独立 FP64 参考对照，包含不同师生精度、额外教师支持、MDPO／BPO、η=1 和小 η。融合路径扩展不修改目标或 1/η。第三方 `full_vocab.backend=liger` 不属于这组数值验收。

HF 权重导出保持原始参数名，不把模型实例上的执行适配编码成标准 HF 模型结构。恢复训练需要相同 profile 配置；单独加载导出的 HF 权重进行原生推理，不能视为恢复了混合精度中间表示策略。

### 2.3 AMP 与 checkpoint

FP16 使用现有 ShardedGradScaler，生产 growth interval 保持 400。新增 checkpoint extra 字段保存 scale、growth/backoff factor、growth interval 和 growth tracker；加载旧 checkpoint 缺少 scaler 状态时明确告警并使用新 scaler。

测试使用更短 growth interval 跨越增长与恢复边界；这验证 scaler 状态语义，不代表已经完成超过 400 次更新的真实长训练。只加载模型权重也不等于恢复完整训练状态。

## 3. 正式实验设置

| Full-KL OPD | MDPO | Actor / anchor           | 目标             |
| ----------- | ---- | ------------------------ | ---------------- |
| E44         | E45  | 默认 BF16                | 当前版本基线     |
| E50         | E51  | FP16                     | 比较更细表示精度 |
| E52         | E53  | BF16 GEMM＋FP32 中间表示 | 比较混合精度折中 |

OPD 使用 η=1；MDPO 使用 κ=0、η=0.3。新增四组复用 E44/E45：R1-Distill-Qwen-1.5B／JustRL-DeepSeek-1.5B，batch=mini-batch=64，LR=1e-6，256 outer、reuse16、计划 4096 次更新，每 128 outer 保存，VAL_N=16。正式预设不会被短训练验收的覆盖参数改写。

```bash
# 检查完整配置；不启动 Ray 或训练。
CONFIG_ONLY=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E52

# 正式实验；GPU 按实际分配指定。
CUDA_VISIBLE_DEVICES=0,1,2,3 STUDENT_GPUS=4 \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E52

# 相同预算下的 MDPO 对照。
CUDA_VISIBLE_DEVICES=0,1,2,3 STUDENT_GPUS=4 \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E53

# 在已有方法上选择执行策略；fp32 应先限制规模作参考。
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E45 --precision fp16
```

实验名称记录显式 precision。末尾 Hydra 仍可覆盖字段，所以最终配置和实际初始化日志是执行依据；独立验证入口不接收训练 precision 选项。Teacher 与 rollout 默认仍为 BF16：高精度训练和 BF16 rollout 的策略差异必须测量，不能把行为 IS 分母换成训练端概率来掩盖差异。

## 4. 验收与结果边界

验收环境为 H800、PyTorch 2.11.0+cu128、Transformers 5.12.1、FlashAttention 2.8.3。其他依赖版本与硬件未在这里验收。结果汇总到 [共享精度验收数据](../../../experiments/teacher-transfer/optimizer-precision/mechanism/data/training-precision-20261027.json)。原始配置、终端日志和逐更新记录保存在 `outputs/training-precision-20261027/`。

| 验收                                    | 结果                                                         |
| --------------------------------------- | ------------------------------------------------------------ |
| 入口、配置与优化器 CPU                  | 205 passed                                                   |
| 蒸馏及恢复 CPU 回归                     | 357 passed                                                   |
| 最终 profile 边界 CPU                   | 11 passed                                                    |
| FP16／FP32 值、VJP、小梯度与稳定行 CUDA | 108 passed                                                   |
| 两卡实际 FSDP2                          | 7 组、93 次更新，含恢复分支；全部通过                        |
| 四卡真实模型 E50–E53                    | 每组 2 outer × 2 reuse，合计 16 次成功更新；每轮权重同步完成 |

CPU 套件有重叠，不将计数相加。四组真实短训练使用 batch=8、prompt/response cap=1024/128、自有 precompute_fused、chunk=32、eager rollout；正式验证关闭。两组真实 MDPO 在每个 outer 起点的 anchor KL 均为零。训练日志中的每次 loss 是更新前值，不把最后一次训练前向误称为最后更新后的独立评分。

两卡集成覆盖不等长 packed 序列、空局部 loss mask、tied head、教师额外词表、anchor 生命周期、gradient checkpointing、CPU/GPU offload、checkpoint 后的模型／optimizer／scheduler／scaler 恢复，以及 η=1 与旧 Full-KL 入口等价。测试直接捕获 embedding、MLP 投影和末层 norm 的实际输出 dtype。

长序列 FA2 backward 的非确定性会造成极小参数差异；逐参数严格恢复检查显式启用 `FLASH_ATTENTION_DETERMINISTIC=1`。该测试设置不改变正式实验默认值，也不把非确定性差异当成 scaler 恢复错误。

四卡真实模型验收通过同一个公开入口运行 E50–E53 的缩小版本，检查 rollout、teacher hidden、anchor、更新和权重同步。短训练证明链路可运行，不用于排名精度候选的任务质量或吞吐。完整 256-outer、多 seed、长回答和正式验证仍由上表实验完成。

复查两卡 MDPO 与恢复语义：

```bash
FLASH_ATTENTION_DETERMINISTIC=1 CUDA_VISIBLE_DEVICES=0,1 OMP_NUM_THREADS=1 PYTHONPATH=. \
  python -m torch.distributed.run --standalone --nproc-per-node=2 \
  tests/special_distributed/test_mirror_fsdp2.py \
  --precision bf16_fp32 --model-type qwen2 --checkpoint \
  --gradient-checkpointing --sequence-length 129 --output /实际输出目录/mixed-mdpo.json
```

加 `--eta 1 --compare-legacy` 验证普通 Full-KL endpoint；`--estimator sampled` 验证 sampled MDPO；`--precision fp16 --model-type qwen3` 覆盖 AMP 与另一模型族。保持相同参数时，checkpoint 恢复后的下一轮必须与连续训练一致；独立切换 profile 是另一项实验。
