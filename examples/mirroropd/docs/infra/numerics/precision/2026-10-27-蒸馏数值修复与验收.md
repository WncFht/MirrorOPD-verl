# 蒸馏数值修复与验收

本次将已复现的 BPO、普通 Full-KL、mirror target 编码、近零标量与 sampled CE 数值问题接入生产路径。目标函数、最终的 1/η、anchor 生命周期和 token/DP 分母保持原定义。Precompute 仍在当前 token block 中提前求 VJP，再累计 dH/dW；没有跨 optimizer 更新缓存学生梯度。

**算子修复与训练反弹分开验收。** 修复后的真实 BF16 重放仍出现 target KL 上升，因此此次不能标记为默认 BF16 训练反弹已经解决。本次修复集中在输出目标和梯度表达式，模型前向精度由原有配置决定。

此前的缺陷、因果隔离与前向舍入证据见 [2026-10-26 审计](../../../experiments/teacher-transfer/optimizer-precision/mechanism/2026-10-26-MDPO内层KL反弹与数值链路审计.md)。本文说明后续生产补丁及其验证范围，不改写历史测量结果。

作者参考实现与上游 PR 的逐项对照见 [Softmax 上游修复调研](../../../literature/optimization/2026-10-27-Softmax上游修复调研.md)，其中区分已合入、未合入与本项目目标独有的数值处理。

## 2. 目标与数值表达式

### 2.1 先消去公共偏移，再做中心化

对权重分布 w，先选择参考位置 a，构造相对残差 r，再求归一化加权均值。MDPO/普通 KL 使用当前 p，BPO 使用冻结 q。梯度为

$$
G_i=w_i(r_i-\mathbb E_w r).
$$

在写回低精度 dZ 前，用其他分量重建参考分量。此操作建立在正确的小残差之上，不是给错误梯度事后减均值。BF16/FP16 cast 仍会引入舍入，不能据此承诺 cast 后逐位严格零和。

还有一层容易遗漏：分别用 FP32 计算 `z_i-z_a` 和 `u_i-u_a`，也可能先丢失 z 与 u 之间的小差异。因此 CUDA 将这几次减法放在 FP64 寄存器中完成，再存为 FP32；大矩阵投影没有改成 FP64，也不为这些减法分配全词表 FP64 临时矩阵。Torch CPU/FP64 参考保留直接的高精度表达。

### 2.2 保留 KL 的二阶小量

同支持时，令 x 是 teacher 与 student 的相对 logit 差，归一化权重为 p：

$$
\mathrm{KL}(p\Vert T)=\log\mathbb E_p e^x-\mathbb E_p x.
$$

先减去参考分量和加权均值。对中心化的 x，分别归约

$$
A=\mathbb E_p x,\qquad B=\mathbb E_p[\operatorname{expm1}(x)-x].
$$

近零值用下式计算，保留 B 的二阶项：

$$
\log\left(1+\frac{B}{1+A}\right)+[\operatorname{log1p}(A)-A].
$$

两种小余项使用局部多项式，远离零时使用稳定的常规表达和 shifted log-sum-exp。源码中的局部 clamp 用于未选中分支的计算域保护；最终 KL 输出没有 clamp。Teacher 额外词表的质量修正另行保留。

### 2.3 Target 不再要求先编码成完整 b

κ=0 时，梯度残差直接使用

$$
r=(z-z_q)-\eta(u-z_q),
$$

并在相对坐标中计算。这避免把微小增量加到大 log-weight 上。一般 κ 根据完整 teacher/anchor normalizer 计算 log ratio，再保留小的相对增量；参考点的混合权重接近教师时，改用教师作为表达基底，避免 η 接近 1 时再次丢失微小的 anchor 贡献。表达方式改变，冻结目标的数学定义不变。

底层返回的训练标量仍为

$$
j_{\mathrm{MDPO}}=\mathrm{KL}(p\Vert m)-\log Z_m,\qquad
j_{\mathrm{BPO}}=\tfrac12\operatorname{Var}_q[\log(p/m)].
$$

最终 loss 层统一执行 `normalize_token_sum(j_sum) / eta`。

### 2.4 冻结的 log Z 也避免近数相减

设 ℓ=log(T/q)，fκ 是 power-mean 增量，M=(1−η)q+ηT，A 是 M 在 student 支持内的总质量。逐位置计算

$$
c_i=f_1(\ell_i)-f_\kappa(\ell_i),\qquad
D=\sum_iM_i[-\operatorname{expm1}(-c_i)],\qquad
Z_m=A-D.
$$

D 很小时，用 `log(A)+log1p(-D/A)`，避免从接近 1 的总质量中丢掉小差异；D/A 大时使用普通 log-space 归约。近零 ℓ 的展开先提出 `(1−κ)`，κ 极接近 1 时使用受控小区间差商，误差按 FP32 精度与独立高精度参考验收。这个稳定化只用于冻结常数，不替代 target 的梯度表达。

η=1 和 κ=1 有明确端点，teacher 额外输出行仍影响完整 normalizer。log Z 只由冻结 q/T 决定，不依赖当前 p。

## 3. 实现组织与兼容

| 文件                                                         | 职责                                                                               |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `verl/trainer/distillation/numerics.py`                      | Torch 稳定 KL、方差、分离 target、canonical log Z 与显式 VJP                       |
| `verl/trainer/distillation/full_vocab_triton.py`             | 共用分块权重/矩/余项归约、主分量重建，以及原始 logits 的 target 路径               |
| `verl/trainer/distillation/full_vocab.py`                    | 投影、token/vocab 分块、precompute/recompute 缓存及 dH/dW；保留 FP16 的 AMP 前保护 |
| `verl/trainer/distillation/objectives.py`、`losses.py`       | 兼容行接口、sampled residual 与最终 η/DP 缩放                                      |
| `verl/utils/stable_logprobs.py`、`stable_logprobs_triton.py` | 稳定 selected log-prob 和 CE 反向                                                  |

BPO 在不请求诊断时仍不计算 student softmax。普通 Full-KL 与 MDPO η=1 继续共用 endpoint dispatcher，没有新增训练模式或配置开关。

`build_log_weights` / `fused_log_weights` 和接收完整 b 的行接口保留兼容语义。它们无法从已经量化的 FP32 b 中恢复丢失的增量。生产 full-vocab 使用原始 logits 接口，sampled MDPO 使用分离 residual；不能再用“先编码 b 的旧审计调用”代替实际训练路径验收。

Sampled CUDA 路径替换的是本项目对 FlashAttention CE 的消费入口，没有修改安装的第三方包。原 `VERL_DISABLE_FLASH_ATTN_CE` 开关仍可选择 Torch fallback，两条路径均保留高置信度目标梯度。非有限分布继续暴露非有限值，不会伪装成零 loss。

## 5. 成本与尚未覆盖的范围

Precompute 的分块、提前计算梯度和统一累计仍保留；稳定表达式增加了部分归约与算术成本，不能声称修复没有性能代价。配对微基准使用相同输入、预热及交替 AB/BA，记录在归档摘要中；共享 GPU 的计时不作为端到端训练速度承诺。

本次配对基准使用 H800，N=128、V=151936、d=1536、BF16、chunk=128、κ=0.5、η=0.3，预热后 9 组交替 AB/BA。时间包括三次 head 投影、target、loss 和 hidden/head VJP；额外 allocated 峰值扣除了输入常驻量，包含梯度工作区和输出。两版在同一张共享 GPU 上测量。

| 设置                   | 旧版 → 修复后 wall 中位数 | 旧版 → 修复后额外峰值（MiB） |
| ---------------------- | ------------------------- | ---------------------------- |
| MDPO，diagnostics=True | 9.074 → 16.021 ms         | 1337.38 → 1337.38            |
| BPO，diagnostics=True  | 9.418 → 19.035 ms         | 1337.38 → 1337.38            |
| BPO，diagnostics=False | 9.010 → 9.261 ms          | 1337.38 → 1337.38            |

详细诊断现在执行更多稳定归约，有明显开销。此表说明修复保留了当前 chunk 下的额外显存水平，不说明速度不变；也不能把共享卡的局部耗时比值直接外推成训练速度变化。

Streaming/cached 的高精度逐块统计、termination-equivalent 路径的 FP64 行代数都有额外成本。它们通过数值验证，不代表已完成所有长序列压力与吞吐优化。没有用取消分块或整批保存全词表 target 来换取正确性。

修复后的独立 FP64 更新前后评估为：

| 真实四卡分支，κ=0.5、η=0.3、LR=1e-6 | 起始 target KL | 完成 16 次更新后 |
| ----------------------------------- | -------------- | ---------------- |
| MDPO                                | 6.703e-5       | 1.085e-4         |
| BPO                                 | 6.703e-5       | 8.832e-5         |

四卡重放从旧 MDPO 训练得到的同一模型和 Adam 状态恢复，修复后 MDPO/BPO 的 target KL 仍高于各自起点。这是集成与残余问题证据，不是正式训练质量比较。原晚期 checkpoint、完整 on-policy 长序列、多 seed、A100/A800、第三方 Liger 与 NPU 仍不属于本轮已完成的验收范围。

**因此，本次完成的是已确认算子问题的生产修复；默认 BF16 内层拟合反弹没有被宣称解决。**
