# 共享八卡流水线的运行与测试

公共配方现已默认选择 `shared_sync`：student vLLM rollout → 休眠 student → 冻结 FSDP2 teacher 评分并卸载 → actor 更新 → 同步 student 推理权重。验证直接复用八个 student TP1 副本。原 `standalone` 4+4 路径保留，通用 verl 配置的默认值仍为 standalone。

本页记录已落地行为与验收范围。算法推导见[固定前缀目标](../opd-objective/2026-10-20-固定前缀下的优势估计与重要性采样.md)，完整调用图及架构依据见[实现方案](2026-10-21-同步共享八卡实现方案.md)，指标定义见[最小指标方案](2026-10-21-最小指标实现方案.md)，不在这里重复。

## 1. 启动与回退

在已准备原生环境与模型数据的机器上，从仓库根目录执行：

```bash
# 默认共享八卡；batch、采样和 loss 沿用原配方。
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh

# 显式恢复原 standalone 4+4。
DISTILLATION_EXECUTION_MODE=standalone \
  CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh

# 只看命令，不访问 GPU、不安装依赖、不创建训练目录。
DRY_RUN=1 bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh
```

Math、coding、IF 共用 [_run_single_teacher_fsdp2.sh](../../_run_single_teacher_fsdp2.sh)，都采用上述默认执行模式；各领域数据与 verifier 要求见[训练配方](../训练配方.md)。

| 环境变量 | 默认值及用途 |
| --- | --- |
| `DISTILLATION_EXECUTION_MODE` | `shared_sync`；可选 `standalone` |
| `STUDENT_GPUS` | 共享模式为 8，表示整个池；独立模式为 4 |
| `TEACHER_GPUS` | 共享模式必须为 0；独立模式默认 4 |
| `ROLLOUT_TP` | 共享首版必须为 1 |
| `TEACHER_FSDP_TOKEN_BUDGET` | 32768；共享 teacher 每卡动态前向 token budget，必须容纳完整训练序列 |
| `TEACHER_FSDP_DTYPE` | `bfloat16`；同时设置共享 teacher 的模型存储和前向参数精度 |
| `PARAM_OFFLOAD` / `OPTIMIZER_OFFLOAD` | 共享模式必须为 True |
| 原 `ROLLOUT_*` 容量参数 | 继续控制 student vLLM，本次不改变原调参值 |
| 原 teacher vLLM 参数 | `TEACHER_TP`、`TEACHER_TOKEN_BUDGET` 等只用于 standalone |

执行模式应通过环境变量选择，让脚本同时派生资源数。若直接用 Hydra 修改模式，调用者也必须提供匹配的资源与 engine 配置；不一致时会在初始化前报错。可以设置更小 `STUDENT_GPUS` 做 smoke test，但仍需保持全局 batch 可整除。

## 2. 实现边界

- Trainer 在同一 global pool 注册 actor 与既有 `TrainingWorker` teacher，没有新增 worker 子类、队列状态或调度器。
- Teacher 配置从自己的模型路径新建；检查 token-to-ID 词表及特殊 token ID 兼容，不复制 student 已解析的 HF 配置。
- Teacher 使用 BF16 默认前向、无 optimizer、`torch.no_grad()`；模型与 optimizer checkpoint 仍只属于 student。
- 评分放在 `_balance_batch()` 后、old-log-prob 前。Teacher metadata 与原 batch 隔离，TQ trajectory keys 保持一致。
- 输出沿用完整序列的 next-token 概率布局，末维补 1，每行末尾补 dummy；FP32 log-prob 和 int32 teacher IDs 对齐原协议。
- 继续复用 actor 的 old-log-prob、current-policy advantage、`k1 + PG`、backward、naive 权重同步和验证链。
- FSDP2 forward-only engine 可关闭默认逐层 CPU policy，改为阶段迁移。新分支的 `to()` 返回前同步设备，确保 transfer 计时包含搬运完成；旧 actor/ref 路径保持原行为。
- 共享模式产生 `timing_s/teacher_forward`、`timing_s/teacher_transfer`，走现有 driver logger，进入 console 与离线 W&B run。前者含 RPC/TQ 往返，不是纯 GPU kernel 时间。

首版拒绝多机、异步、多个 teacher、SP/TP 扩展、MoE、多模态、LoRA、top-k 蒸馏、critic/reference/learned reward model、custom sampler、DAPO 过滤和 rollout skip。Actor/teacher 沿用兼容的非 fused 路径，避免同模型类的全局 forward patch 相互覆盖。

评分错误不会发布 teacher 字段或进入 actor 更新。普通异常尽力卸载并保留原异常；rank/NCCL 故障终止作业，不承诺自动恢复评分。重启沿原 student checkpoint 恢复并重新生成数据。

## 3. 已执行测试

CPU 回归 **139 项通过**（完整回归 137 项，加两项初始化顺序与失败隔离测试），包含：

- 新默认配置、teacher 精度/token budget、非法组合、旧 standalone 副本推导和三个领域入口。
- 共池映射、teacher 独立配置、tokenizer 不兼容拒绝。
- 评分调用顺序、future 等待、metadata 隔离、异常不发布输出。
- 不等长序列的 next-token 对齐、dummy、response mask，以及实际蒸馏 loss 的梯度检查。
- 原 Trainer、AgentLoop TQ、pipeline metrics、FSDP 搬运和 TQ bridge 回归。

测试命令：

```bash
python -m pytest -q \
  tests/trainer/ppo/v1/test_shared_teacher_on_cpu.py \
  tests/examples/test_mirroropd_math_launcher_on_cpu.py \

  tests/trainer/ppo/v1/test_agent_loop_tq_on_cpu.py \

```

真实 GPU 测试使用 **2 张空闲 H800**、PyTorch 2.6、Transformers 4.51.1、FlashAttention 2.7.4，执行本地生成的小型 Qwen2 模型：

```bash
CUDA_VISIBLE_DEVICES=0,1 OMP_NUM_THREADS=1 \
  torchrun --standalone --nproc-per-node=2 \
  tests/special_distributed/test_shared_teacher_fsdp2.py
```

测试通过 teacher 初始化前后 actor 输出不变、三轮 teacher 加载/评分/卸载与 actor 更新、teacher 无梯度且概率不变、真实 actor 参数更新，以及 student checkpoint 保存和恢复。默认不共享 embedding 权重的模型通过后，又使用 `--tie-word-embeddings` 验证了共享 embedding 权重的模型，覆盖 root FSDP 参数的迁移。Teacher packed FSDP 前向与普通 HF 逐序列前向做概率对照；小模型测试使用 `atol=0.03, rtol=0.01`，不作为生产模型的误差验收阈值。

CPU 测试使用隔离的 TensorDict 0.10 / TransferQueue 0.1.11 依赖目录，不修改宿主环境。GPU 测试调用真实 `TrainingWorker`、FSDP2、NCCL 和 checkpoint；没有启动 vLLM/Ray rollout。

Ruff、Bash 语法、配置生成一致性、设备 API、DataProto 使用及文档链接检查通过。测试目录检查在允许仓库已有 `tests/examples` 后通过。仓库级 license 检查尚未收录本项目已有的 `MirrorOPD-verl contributors` 标头；脚本命名检查不接受既有下划线公共 helper；uv 检查硬编码默认值 1，与本项目既有原生 Python 默认值 0 冲突。这三项仓库规则冲突保留，未为通过检查而修改原生运行约定。

## 4. 部署验收与传输

本机 vLLM 为 0.8.5，且四张卡正在运行其他任务；没有进行完整八卡 vLLM/Ray 端到端训练。目标环境为先前记录的 PyTorch 2.11 / vLLM 0.25.1。部署后仍需用实际模型跑短训练、一次验证及恢复，检查完整阶段切换、八副本权重同步和离线 W&B history，再用固定预算比较两种模式步时。不能把两卡小模型测试当成生产吞吐或质量收益。

源码按[人工传输流程](../../../../meituan/README.md)打包：

```bash
make archive-pack
# 上传生成的包或全部分卷；在接收端执行：
make archive-unpack ARCHIVE=/实际上传路径/archive_MirrorOPD-verl_....tar.gz.part.000
```

`hope/` 不在源码包中。接收端应按[Hope 直连训练入口决策](2026-10-21-Hope直连训练入口.md)一次性修改本地 `.hope` 的 `worker.script`，后续训练入口随源码更新，不再维护独立包装脚本。模型、数据、运行环境不随源码包传输。
