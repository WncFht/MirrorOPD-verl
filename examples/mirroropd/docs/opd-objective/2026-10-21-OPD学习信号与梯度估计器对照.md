核对日期：2026-10-21。本仓参照为 `5bb952d8c`。本文比较 sampled-token、KL baseline、TA-OPD、ResOPD 与 full-vocab，并补充能解释它们关系的 top-k、HETS、TT-OPD、SC-TA 和多候选 Monte Carlo。论文与开源实现已经读取；本轮只做调研、容量计算和 CPU 数学验算，没有实现这些新增训练模式，也没有测量它们在本项目上的 GPU 步时或准确率。

这里的方案不能全部视为互斥的 reward。**Sampled-token / full-vocab 是梯度估计方式，KL baseline 是控制变量，TA-OPD 是粗粒度散度目标，ResOPD / SC-TA 是稀疏反馈下的随机梯度估计器。** 先固定目标和采样条件，再比较估计器，才能解释差异。

## 4. Sampled-token 与 KL baseline

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#3-sampled-token-与-kl-baseline)。

### 4.3 作者实现与本仓的工程差距

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#3-sampled-token-与-kl-baseline)。

vOPD 作者实现继承 TRL `MiniLLMTrainer`。`compute_loss()` 先运行 student，再在 `no_grad` 下运行 teacher，得到两份 logits；`kl_top_k` 控制 baseline，`opd_top_k` 控制直接 distillation loss 的支持。代码在形成 `centered_gap` 后 detach。默认 top-k YAML 是 100，论文主设置为 20；复现时必须显式区分。[^vopd-code]

源码并未在所有 baseline 运算外包一层 `no_grad`：student 侧部分临时图直到最后 detach 才断开。移植时应将 baseline 的选集、归一化、求和整体放入 `no_grad`，避免建立随后丢弃的图。Teacher/student logits 同时可用是作者代码“无需额外 inference”的前提。我们的共享 teacher 先评分再 offload，只保留 sampled 分数，不能直接套用这个成本结论。

论文报告的 4B 单 H200 步时为 top-k vOPD 32.88 秒、full-vocab OPD 77.66 秒；作者默认配置另有 LoRA、1024/2048 长度、cosine LR 等差异。该数据说明其实现上的相对成本，不用于预测我们全参数 FSDP2、7168 response 的速度。[^vopd][^vopd-code]

## 5. Top-k、TA-OPD 与随机尾部修正

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#4-top-kta-opd-与随机尾部修正)。

### 5.1 直接截断、归一化与 TA 是三个目标

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#41-直接截断归一化与-ta-是三个目标)。

TA 作者代码使用 `logsumexp` 和 `log1mexp` 计算 tail log-mass，比 BF16 下直接 `1-sum(exp(logp))` 更稳健。仍需监测尾质量接近零时的数值保护，并保证用于质量计算的是全词表归一化概率，而非已在 top-k 内归一化的数值。[^ta-code]

### 5.2 HETS 与 TT-OPD：需要补入的对照

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#42-hets-与-tt-opd需要补入的对照)。

源码名称不保证梯度一致。EMA-PG 审阅版本的 `search/verl/trainer/ppo/core_algos.py::compute_memory_efficient_kl(full_reverse)` 对头部 $\sum_{i\in S}p_i\ell_i$ 保留普通 autograd，尾部却使用 stopped log-ratio；对普通可微输入，头部多出 $\nabla p_S$。我们抽取该 primitive、枚举四个动作后，期望与 full-rKL 梯度最大差为 0.13，减去 $\nabla p_S$ 后误差回到浮点精度。因此这里只将它作为头尾拆分的工程参考，不把这个已审阅代码路径直接称为标准 HETS 的通过验收实现；结论限于该 primitive，不代替整个 EMA-PG RL 系统的效果评价。[^ema-code]

### 5.3 ResOPD：对尾事件使用向量控制变量

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#43-resopd对尾事件使用向量控制变量)。

作者 `resopd.py` 使用等价的 centered-event surrogate，停止 score 系数和事件中心化质量的梯度，并通过 `value.detach() + surrogate - surrogate.detach()` 保留指定日志值。其前向数值与反向 surrogate 的角色不同；不能用该标量直接当作每次都非负的真实 full KL。源码会物化 FP32 的全词表 `log_softmax`，所以“稀疏 teacher 反馈”不等于“常数显存的 student loss”。[^res-code]

### 5.4 SC-TA 与 ResOPD 不是同一个估计器

推导已集中到[条件梯度估计与控制变量](../theory/2026-10-22-条件梯度估计与控制变量.md#44-sc-ta-与-resopd-不是同一个估计器)。

TA 作者仓库的 SC-TA helper 支持 `behavior_logp_y`；直接 loss 的调用方实际传入 `old_log_probs`，不是 vLLM 的 `rollout_log_probs`。在本仓移植时要使用真实行为分母，不能把变量名当作分布一致性的证明。另一个静态代码问题是该调用方在 PG 分支将 `behavior_logp_y` 设为 None，随后无条件 `.detach()`；该分支不能未经修正和测试就照搬。这里只报告源码审计，未运行作者完整训练栈。[^ta-code]

## 6. Full-vocab 与高效 baseline 的实现取舍

Full-vocab reverse KL 的直接梯度、baseline 抵消和计算图见[Full-vocab 理论](../theory/2026-10-22-Full-vocab计算图与四种更新.md#graphs)。

高效实现的公共选择如下，详细算法、内存公式和预算只在[计算与显存预算](../full-vocab/2026-10-22-词表蒸馏的计算与显存预算.md)维护：

| 目标 | 建议的数据通路 | 主要注意点 |
| --- | --- | --- |
| Teacher-top-k baseline / TA / HETS / Res / SC-TA | teacher 一次前向返回完整归一化 top-k，另保留 actual sampled score | 同一 payload 支持多种算法；拒绝把 sampled token 混入 baseline 支持集 |
| 原版 student-top-k baseline | student 先产生选集，再让 teacher 对这些 IDs 评分；或保留 teacher hidden states | 需调整现有 teacher→old-log-prob 顺序；多轮重选支持集要重新取 teacher 值 |
| Full baseline | teacher hidden states + 冻结 LM head，在 `no_grad` 下流式累积 KL，最终仅保存 scalar | 没有额外 critic，但当前架构必须补 teacher 信息通路 |
| Full-vocab rKL | hidden states + 分块重建，定制 backward 或重计算 | 不能先物化 `[N,V]` 再声称消除了 logits 显存 |

原版 student-top-k baseline 的归一化还允许直接在选出的 student/teacher logits 上各自做 `log_softmax`，共同的 full-vocab log-normalizer 会抵消。这个技巧只能用于支持内归一化 baseline；TA/Res 的 tail mass 与 sampled reward 仍需要真实全词表归一化值。

## 8. 可以组合的方案与不能机械组合的方案

| 组合 | 判断 | 条件或原因 |
| --- | --- | --- |
| Sampled-token + full/top-k/coarse KL baseline | 可以 | baseline 独立于当前抽样动作、detach，采样/IS 合法 |
| Sampled-token + 多个局部候选 + baseline | 可以 | 固定前缀独立有放回抽样；不是额外生成多条完整回答 |
| HETS + 尾事件向量控制 | 就是 ResOPD 所属族 | 不能只加 TA loss 而不减重复项 |
| ResOPD + 条件尾部 score 控制 | 可以，SC-TA 是一个端点 | 系数 $\gamma$ 改变方差；不可预设越大越好 |
| ResOPD + 全局标量 baseline | 数学上可构造 | 减去 $C(s)\psi_a$ 的零均值项会重新引入 head 分支随机性；只在 tail 减 baseline 而不补均值会有偏 |
| Full-vocab + scalar baseline | 梯度不变，不必单列 | 条件动作期望已精确求和 |
| TA + 任意 sampled correction | 不一定合法 | 必须使用 SC-TA/Res 这类消除重复粗项的推导 |
| 任一估计器 + token 位置加权/teacher 变换 | 可以研究，但另开实验轴 | action-dependent 权重或选择会改变目标和无偏性条件 |
| 任一直接散度 + E1–E6 全套 PPO/NoIS 开关 | 不应直接组合 | 直接积分的头部/全词表不需要 sampled action ratio |

多候选估计在固定参数、独立抽样下，平均 $M$ 个估计器的协方差缩小为 $1/M$。重复 token 应保留频次，不应去重后直接等权；deterministic top-k 也不是 $M$ 次 Monte Carlo 抽样。候选数、完整 rollout 数、词表 top-k、采样 top-k 是四个不同参数。

## 9. 在当前 math setting 下的实验安排

方法比较顺序、必要负对照和支持集选择统一在[实验排序与支持集](2026-10-21-Reverse-KL实验排序与Top-k支持集.md#1-reverse-kl-实验优先级)维护；实际预算由[训练配方](../experiments/sampled-ablation/README.md)或[冻结队列](../full-vocab/2026-10-22-Math消融队列与对照设计.md)定义。

### 9.1 先固定一次更新，再比较估计器

固定同一前缀、teacher 反馈、支持集与参数，先核对估计梯度是否对应相同目标，再比较方差与工程成本。端到端实验只改变所研究的因素；使用 E 系列入口时，显式检查批内复用次数，不能把不同预设预算直接当作估计器对照。

### 9.2 再研究复用与资源预算

筛选估计器后再单独改变复用次数，与 E 系列的相应预设连接。随机部分采用真实行为 IS，精确部分每轮按当前 student 重算。Full baseline 可缓存 rollout 时的 scalar，仍作为 action-independent 近似 baseline，但它不再是每轮当前模型的精确 KL baseline，需独立命名。

比较至少同时报告：实际 optimizer 更新数、生成 response token 数、teacher 评分 token 数、完整训练/验证墙钟与 GPU 小时。等更新次数、等生成预算、等墙钟是不同问题，不能只按外层 step 对齐。共享 fixed-prefix 审计使用同一批真实轨迹；端到端各组后续轨迹会分叉，同 seed 不保证相同回答。

### 9.3 需要记录的量

固定前缀：真实 full rKL、估计梯度均值偏差、协方差迹、梯度方向，以及 teacher-top-k 下 student mass/tail mass。小模型或少量位置可枚举完整词表；大模型可记录 logit/hidden/head 梯度代理，但必须标明它们不等于全参数梯度协方差。

端到端：三个数学验证集各自的 `acc/mean@16`，以及 grad norm、clip/数值保护/跳步比例、teacher forward/transfer、actor update、整卡峰值和主机 payload 峰值。不同方法的 surrogate loss 数值不直接横比；ResOPD 的日志 surrogate 和真实 KL 应分列。既有 GPU busy、FSDP allocated 和整卡显存的口径沿用 infra 文档。

## 10. 本轮数学验算与证据边界

[验算脚本](scripts/verify_reward_estimators.py)在 16 个种子、4 个支持大小、7 个动作上枚举 sampled、三种 baseline、HETS、Res、SC-TA 的期望梯度；还检查 TA 链式分解、随机尾项的行为 IS，以及两遍词表分块的值/hidden/head 梯度。可选加载已审阅的作者 ResOPD kernel，逐动作比较，共 448 次源码梯度对照。
