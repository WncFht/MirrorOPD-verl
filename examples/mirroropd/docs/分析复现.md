# 训练分析的数据与图表复现

除明确注明进入日志仓库的命令外，命令从源码仓库根目录执行。日常分析读取本地 `wandb-logs`，不依赖先上传云端再下载。分析工具不启动训练、不登录切换账号、不上传指标，也不改模型环境。统计与 MFU 脚本使用 Python 标准库；通用解码器使用日志仓库的独立 `.venv`；绘图需要已有 Matplotlib、NumPy 与 figure-viz skill。

## 工具位置与日常入口

| 层次 | 唯一维护位置 | 职责 |
| --- | --- | --- |
| 原始日志与通用解码 | 独立 `wandb-logs` 仓库的 `tools/wandb_local.py`、README | 保留 `.wandb` 和附属文件，解码 history、系统监控、config、summary；派生数据不进入 Git |
| 接收、上传与 Git 同步 | 本仓库 `meituan/` 和 Makefile | 解包到日志仓库，从临时副本上传 W&B，提交并推送项目日志 |
| MirrorOPD 快照适配 | `docs/scripts/analyze_run.py export` | 调用上述解码器，生成项目分析可读的快照和来源说明 |
| 指标语义、统计与图表 | `docs/scripts/analyze_policy_run.py`、`plot_policy_run.py` 等 | 区分 outer/update/optimizer 轴，复算训练、验证及资源结果 |

日志原始数据不复制回源码目录，也不在源码仓库维护兼容 `wandb` 链接。详细解码参数以日志仓库 README 为准；本页维护项目接入与分析方法。

Mac 首次在 `~/src/wandb-logs` 执行 `make setup`；本机日志仓库通常与源码仓库并列。之后在日志仓库执行 `make refresh` 拉取并解码，或 `make decode` 只处理现有文件。传输步骤见[开发机同步说明](../../../meituan/README.md#日志下载)。本机 Git SSH 操作先按根目录 AGENTS.md 激活 SSH 环境。

  --data "$COMPARE_DATA" --output "$COMPARE_DATA/dashboard.html"

## E15 policy-v3 完整指标分析

E15 `krkmq098` 的入口为[训练动态与指标分析](research/2026-10-23-E15训练动态与指标分析.md)，数据集中在 [e15-krkmq098-20261023](data/e15-krkmq098-20261023/README.md)。新脚本区分 outer/update/optimizer 三条轴，不将 600 条 W&B 事件误算成 600 步。它仅读取显式指定的单个快照。

以下命令离线重算已有快照，不需要凭据。统计脚本复用已冻结的横轴映射，仅需标准库；绘图另需 NumPy、Matplotlib 与 figure-viz。若 skill 未在默认位置，可设置 `FIGURE_VIZ_MPL` 指向其 `assets/mpl`。本机已验证的 Python 是 `/root/.local/share/mirroropd/venvs/profile-cu128/bin/python`，style 路径是 `/mnt/tidalfs-bdsz01/dataset/llm_dataset/zkn_data/fht_data/dotfiles/.agents/skills/figure-viz/assets/mpl`。

```bash
python3 examples/mirroropd/docs/scripts/analyze_policy_run.py \
  --data examples/mirroropd/docs/data/e15-krkmq098-20261023

python3 examples/mirroropd/docs/scripts/plot_policy_run.py \
  --data examples/mirroropd/docs/data/e15-krkmq098-20261023 \
  --out examples/mirroropd/docs/figures/e15-krkmq098-20261023

CUDA_VISIBLE_DEVICES='' python3 -m pytest -q \
  tests/utils/test_policy_run_analysis_on_cpu.py
```

首次从本地导出目录或保留的旧 API 导出目录归档时，使用 `analyze_policy_run.py --snapshot-from /导出目录/krkmq098 --data /新的快照目录`；已存在的原始快照禁止覆盖。该步骤为新指标调用仓库 `metric_axis` 并冻结映射，需要仓库 Python 依赖。只传 `--data` 则重算派生文件，不修改原始 history。旧 `analyze_run.py summarize` 仅适用于旧字段；policy-v3 使用本节脚本，导出时不再自动生成旧字段汇总。

八组图均保存 PNG、PDF 和 audit 文本。分位数、题目置信区间、设备间范围分别标注，不混作同一种误差带。测试覆盖稀疏值、更新前计数、重复事件冲突、计时嵌套和真实快照的一致性。

## 只读导出与数据边界

`export` 默认从本地日志仓库导出，必须显式传入 `--run entity/project/run`；工具没有默认实验。依次使用 `--logs-repo`、环境变量 `WANDB_LOGS_REPO`、源码同级的 Git 仓库 `wandb-logs`，最后才尝试 `~/src/wandb-logs`。同一 run ID 必须唯一匹配一个原始目录，记录中的 project/run ID 必须一致；离线记录没有 entity 时，将 entity 标为调用者显式提供。

每次选择新的导出目录，已有快照不覆盖。E15 示例：

```bash
python3 examples/mirroropd/docs/scripts/analyze_run.py export \
  --run wncfht/MirrorOPD-verl/krkmq098 \
  --out outputs/e15-local-新快照

python3 examples/mirroropd/docs/scripts/analyze_policy_run.py \
  --snapshot-from outputs/e15-local-新快照 \
  --data outputs/e15-local-新分析
```

导出器调用日志仓库的独立 Python，不复制一套解码实现，不读取凭据，也不会因找不到本地数据自动改用 API。history 保留原始稀疏行；配置中的密钥类字段脱敏，非有限数值不补零。系统监控写入 `system.jsonl.gz`，是所有成功解码的周期性记录，不经过 API 二次采样；同时保留 `_timestamp_ns` 和分析使用的 Unix 秒时间戳。旧 `system-sampled.jsonl.gz` 仍可读取，但不会把它改称全量数据。

`source.json` 记录来源、解码状态和记录数。`snapshot`、`partial_snapshot` 不能证明训练完整结束；`decode_error` 或源文件读取期间变化时停止导出，不自动补取云端数据。系统监控即使完整解码也只是周期性观测，不是连续 GPU trace。

硬件和软件版本来自该 run 的 metadata/requirements；metadata 附件缺失时，可读取日志仓库解码器 v2 的 `environment.jsonl`，按同一 writer 合并分批环境信息，不混用其他 run 或本机环境。来源写入 `source.json.environment_metadata_source`。metadata 的 Git commit 不能证明运行目录无额外修改。训练时间使用采集 `_timestamp`；离线同步后的服务端 `created_at` 不等于训练开始时间。

## 云端回读的保留用途

旧的 API 拉取流程退出日常分析入口，命令改为显式 `export-cloud`。仅在核对云端一致性，或本地没有该 run 的原始数据而需要补救时使用；它不替代完整原始日志归档。训练端记录、接收端上传和网页查看继续保留。

```bash
python3 examples/mirroropd/docs/scripts/analyze_run.py export-cloud \
  --run wncfht/MirrorOPD-verl/krkmq098 \
  --netrc-file /本机私密目录/netrc \
  --out outputs/e15-cloud-audit-新快照
```

凭据可由 SDK 环境提供；`--api-key-file` 与 `--netrc-file` 互斥，不把 key 写到命令行或仓库。默认 endpoint 为 `https://api.forge.coreweave.com`。history 使用 `scan_history(keys=None)` 并固定 `lastHistoryStep` 边界；system 使用 sampled history，增加 samples 不保证全量。历史报告中的 API 来源、系统采样口径和冻结数据保留原样，不因默认入口迁移而改写成离线来源。

## 本地日志与其他测量

```bash
python3 examples/mirroropd/docs/scripts/analyze_run.py import-log \
  --log /实验目录/train.log \
  --out outputs/本地日志快照
```

已知 run 时追加 `--run entity/project/run`；未知时来源记为 null，不继承其他实验身份。该入口面向 `step:N - key:value` 旧字段日志；policy-v3 的完整分析使用结构化 history。日志不会补出未记录的配置、验证或 GPU 数据；资源分母 `--gpus`、`--batch` 应按实际条件填写。
