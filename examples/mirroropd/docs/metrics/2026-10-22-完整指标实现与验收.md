Last updated: 2026-10-22。

主实现提交 `818400a81` 已完成；随后补充 bypass 作用位置、实际工具调用数和已有 variance proxy 输入接线。当前字段定义见[指标字典](2026-10-22-指标字典.md)。第一版 64 字段不再是允许列表，原始快照和旧迁移决定保持原样。

## 实现范围

- Eval：所有共同支持的 k；标准 pass、投票、prefix mean、连续评分 best/worst、题内波动、跨题 CI；混合评分源按数据源区分。
- Pair：三组基础 token 统计、全局分位数、sequence 累积与长度归一化统计；原始 ratio 与实际 IS 权重分别记录。
- 训练：实际 loss 分项、clip/dual clip、RS、top-k、critic 独立计数、stale、负载均衡、结束原因和工具调用观测；不改优化公式。
- 记录：完整原始 final-session 记录含失败占位；已知字段统一命名；未知自定义标量告警保留；Console 展示与 W&B/file 记录分开。
- 适用性：内置 FSDP/FSDP2 完整 response 路径接入新 raw 观察。其他 engine 保留已有诊断并显式报告 observations_available=0，不将未验证 CP/TP 片段当作完整 sequence。

## 四卡 E3 实验：已通过

W&B run `ls7cx2p3` 已完成并上传[^e3-run]。运行使用固定源码提交 `4b6447950`，格式为 `policy-v3`；原始文件位于 `examples/mirroropd/outputs/metrics-v3-e3-20261022-141750/`。运行耗时 409.68 秒，退出码为 0。

| 项目 | 设置或结果 |
| --- | --- |
| 硬件与训练 | GPU 0–3，FSDP2 shared_sync，DeepSeek-R1-Distill-Qwen-1.5B + JustRL teacher，E3 current advantage + token PPO |
| 更新 | batch/mini-batch 均为 8，2 outer × 4 PPO epochs，8 次成功 optimizer 更新 |
| 长度 | 训练 response 上限 512，validation 上限 2048 |
| 验证 | 初始及每个 outer 结束；optimizer 横轴为 0、4、8 |
| 数据 | AIME25、AMC23、MATH-500，每个数据集 2 题，每题 4 回答 |
| 记录 | 900 个不同标量字段，其中 eval 669 个；13 行标量，3 个样例表快照 |
| 云端回读 | 16 行 history；所有本地标量与云端值一致；样例表分别有 1、2、3 行 |
| 数值与定义 | 所有标量有限；没有 undefined/nonfinite 事件字段 |

从 `training/validation/records/{0,1,2}.jsonl` 独立枚举回答子集，逐数据集、逐轮验证 `pass@1…4`、`all_correct@1…4`、`majority@1…4` 和 `prefix_mean@1…4`，结果全部一致，并检查 CI 边界。验收脚本为 [verify_metrics_smoke.py](../../verify_metrics_smoke.py)。900 个字段是这一设置的实际观测数，不是字段上限；条件功能在启用后还会产生其他字段。可直接查看[实测字段与横轴](data/metrics-v3-20261022/observed-fields.csv)和[结构化验收结果](data/metrics-v3-20261022/verification.json)。

各数据集只有 2 题，这个实验只能验证指标接线与数值，不能比较算法质量。W&B 清理阶段曾打印 `ConnectionResetError`，但进程正常退出，云端所有标量和样例表已回读验证完整。

## IS/RS 补充实验：按用户要求暂缓重跑

第一次 IS/RS 尝试使用 `rollout_rs_threshold=0.01`，这是我配置错误：该参数表示 ratio 上界，推导下界为 100，导致上下界颠倒。程序在更新前抛出 `ValueError`，退出码为 1；此次失败不算 GPU 验收，也未上传 W&B。失败日志保留在 `examples/mirroropd/outputs/metrics-v3-is-rs-20261022-142504/`。

启动预设已改为显式 ratio 区间 `0.99_1.01`。提交 `94e91aad6` 还修复了 vanilla 路径中嵌套 IS 权重转 dense，以及空样例或样例数量变化时的表格列对齐问题；这些修改通过上述 CPU 回归，晚于 E3 使用的源码提交，尚无 GPU 实测。用户要求保留当前结果、暂不跑 IS/RS，因此不继续占用 GPU，也不把这部分标记为 GPU 验收通过。

## 复现入口

[启动脚本](../../run_metrics_smoke_fsdp2.sh)默认 E3、2 个 outer step、每批 4 次更新，训练前及每步结束验证三个数据集各 2 题 × 4 回答。分位数每次更新记录；禁用 checkpoint 保存。默认离线 W&B，完整输出位于 `examples/mirroropd/outputs/<实验名>/`。

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 bash examples/mirroropd/run_metrics_smoke_fsdp2.sh
```

IS/RS 预设仅作为后续复现入口保留；当前不执行：

```bash
METRICS_SMOKE_MODE=is-rs CUDA_VISIBLE_DEVICES=0,1,2,3 bash examples/mirroropd/run_metrics_smoke_fsdp2.sh
```

IS/RS 模式为 vanilla OPD + token IS + token_k1 RS，1 outer × 2 PPO epochs，不做 validation。
