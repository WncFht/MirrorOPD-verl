# 训练指标系统设计与调研：最小替换方案

更新日期：2026-10-22。Last updated: 2026-10-22。状态：已按本方案接入代码；测试范围与未完成的 GPU 验收见[实现与验证](2026-10-22-实现与验证.md)。训练代码审计基点为 `f807da825`，上一版文档提交为 `df5969c38`。新方案取代上一版的兼容迁移与通用事件设计。

## 1. 实施范围与简化决定

保留优化与损失、策略分布、优势信号、更新修正、蒸馏关系、数据与采样、评估、系统效率八类。实施后只输出新字段，旧名字、旧别名、旧外层 loss 摘要和原有 val-aux 展开不再双写。历史 W&B run 原样保留，不回填、不兼容旧分析脚本。

“最小改动”指复用现有计算、worker 返回、trainer 计数、Tracking 后端和 checkpoint；不要求在训练模块内一次性改写所有临时字典名称。旧名字可以暂留在内部计算结果中，但对外出口必须显式转换或删除，不允许透传。字段替换不改变优化 loss 的数学归一化或梯度，这与兼容旧字段是两件事。

| 上一版设计 | 修订决定 | 理由 |
| --- | --- | --- |
| 保留旧字段、schema 切换、兼容双写 | 删除，直接使用新输出 | 用户不需要兼容，减少重复统计与面板 |
| 统计聚合 | 明确区分观察状态与优化贡献 | 为统计正确性修改必要接口，不以少改文件为目标 |
| session/event/schema/context/coverage 多层记录对象 | 删除 | 当前集中写入路径不需要新增事件协议 |
| 每条记录保存 batch、epoch、mini、版本、checkpoint 标识 | 大部分删除 | 三个现有累计计数已满足当前绘图和恢复 |
| standard/detailed 多个采集档位 | 删除 | 一个固定指标集合，只有 p99 的频率可调 |
| 指标命名 | 使用有意义的多斜杠路径 | 按类别、角色/pair、统计量组织，优先保证可读性 |
| 固定 prefix probe | 不实现 | 本轮明确排除 |
| full-vocab teacher KL | 不实现 | 本轮明确排除 |
| 按层梯度、参数更新范数 | 不实现 | 本轮明确排除 |
| 自动样本转储、直方图、分桶和自适应采样 | 不实现 | 保留研究结论，不进入当前开发范围 |

第一批验收覆盖当前 V1 sync/FSDP2 数学配方：E1–E6，以及普通 sampled-token vanilla 路径的新字段输出。vanilla 的 PPO 分母、dual clip 和 loss 行为保持原义；没有适配的系数诊断不输出。其他 engine、异步和多教师不因为新增日志而自动获得支持。通用计算函数按输入角色设计，后续按需求接入。

## 2. W&B 的层级限制与命名规则

### 2.1 官方行为与本地验证

W&B 的 Run.log 文档说明，自动分组只提供一层 section；`a/b/c` 的文档示例生成名为 `a/b` 的 section，而不是可逐级展开的三层树。多斜杠字符串可以作为 metric key 写入，所以“不能写入三层名字”和“没有三层目录展示”不能混为一谈。[^wandb-run]

本机 W&B 0.28.1 离线检查同时写入 `optim/actor/grad_norm_preclip` 和 `optim/actor_grad_norm_preclip`，回读 `.wandb` history 后两个键和值均完整保留。这验证 SDK 存储接受两种字符串，不验证 CoreWeave 在线 workspace 的具体 UI 设置；分组结论以官方文档为依据。

### 2.2 新字段规则

按语义使用 `类别/角色或pair/统计名`；无独立子对象的字段可以保持 `类别/统计名`。`log_ratio_m2`、`grad_norm_preclip` 等完整统计名称内部仍使用下划线，不机械拆分每个词。所有后端直接使用同一完整字符串，不增加下划线版别名或 W&B 专用改名层。

| 类别 | 名字示例 | 子层含义 |
| --- | --- | --- |
| 优化 | `optim/actor/grad_norm_preclip` | actor 角色 |
| 策略比较 | `policy/current_behavior/log_ratio_m2` | current/behavior pair |
| 优势 | `advantage/distillation/abs_mean` | distillation component |
| PPO 修正 | `correction/behavior_ppo/active_fraction` | 使用 behavior 分母的 PPO 分支 |
| 验证 | `eval/math500/acc_mean` | math500 数据集 |
| 性能 | `perf/timing/update_actor_seconds` | timing 类型 |
| 数据 | `rollout/response_count` | 无额外子对象，直接记录 |

八类仍是本方案的语义分类，W&B 可按完整前缀显示平面 section；不要求 UI 提供同样的多层折叠树。需要集中看某个大类时用前缀筛选或 workspace 布局，不为展示限制牺牲字段名，也不新增管理面板的代码。

采样数 N、模型、loss 模式、clip 边界和采样温度写在已有 run config。数据集名称使用固定映射，启动时检查新名字碰撞；不静默将两个数据源合并。`step/*` 仅作为隐藏坐标，不算第九类业务面板。

## 3. 进度字段必要性审计

### 3.1 其他框架的实际做法

slime 的 W&B 入口定义 `train/step`、`rollout/step`、`eval/step`；Megatron 训练循环将局部 step 映射为累计 `train/step`。它使用了局部 `step_id`，但在审阅的这条训练标量路径中没有把 PPO epoch、mini-batch ID、session/event ID 全部逐条导出。[^slime-counter]

NeMo RL 的 GRPO 状态保存 `current_step`、`current_epoch`、`total_steps`；logger 使用 `nemo_rl/step` 与 W&B 内部序号分离。这证明累计训练进度和恢复状态的必要性，不证明本项目上一版的所有逐行元数据都必要。[^nemo-counter]

以下“未见同形字段”仅指所审阅的训练标量路径，不是对整个仓库所有调试、trace 或异步分支的不存在声明。

| 上一版字段 | 实际用途/外部参考 | 决定 |
| --- | --- | --- |
| outer step | slime rollout step；NeMo trainer step；本项目已有 global_steps | 保留为 `step/outer` |
| 累计更新尝试 | slime 累计 train step；本项目已有 attempts | 保留为 `step/update`，不使用配置乘法伪造 |
| 累计成功更新 | 本项目已有实际执行计数，能区分 skipped update | 保留为 `step/optimizer` |
| `policy_update_before` | 解释 forward 参数位置，但当前同步路径可由上一条成功更新计数得到 | 不导出；测量前后约定写在本文 |
| `update_applied` | worker 已报告的实际执行事实 | 内部保留，用来更新计数，不再导出重复布尔字段 |
| `train_batch_id` | 异步混合/重放时有用，当前一 outer 一批 | 不新增 |
| `ppo_epoch_index`、`mini_batch_index` | 内部循环已有位置，当前固定配置可由批内更新序号解释 | 不新增逐行字段；配置保存 epochs/mini-batch 大小 |
| `data_epoch` | NeMo 等保存数据集遍历状态；本项目已有状态 | 继续由 trainer/checkpoint 管理，本轮不导出重复横轴 |
| `behavior_version`、`anchor_version` | 异步真实年龄分析需要 | 当前不新增导出，也不做 age 分位数 |
| `checkpoint_id` | 异步评估关联需要；当前同步评估可由 outer 与 checkpoint 目录关联 | 不重复写每行 |
| `session_id`、`event_seq` | 上一版自建日志协议 | 删除，复用 W&B run ID、内部序号和现有输出目录 |
| `event_type`、`schema_version` | 上一版完整事件封装 | 不放每行；记录用途由调用位置与指标集合确定，新格式版本写一次 config |
| 每条记录的 `status`、方法、coverage 对象 | 大量固定或可由采集频率解释的信息 | 删除嵌套对象；异常用有限的 nonfinite 指标和日志说明 |

局部位置仍有解释价值：64/64×4 PPO epochs 与 256/64×1 epoch 都有四次更新，但数据复用不同。当前配方固定、无动态过滤，run config 与累计步数足够重建该区别。以后支持动态 mini-batch 或重放时再增加必要字段，不为未来可能性现在扩展协议。

### 3.2 测量与计数约定

一次 mini-batch 前后向加一次 optimizer 调用记为一个 update attempt，micro-batch 和 DP 卡数不推进计数。loss、ratio、advantage、grad norm 属于该次更新前的参数；`step/optimizer` 是该次调用结束后的成功更新累计数。这个固定约定写一次，不每条日志重复保存 before/after 两套坐标。

出现 skipped update 时 `step/update` 增加而 `step/optimizer` 不变，所以保留第三个计数有实际用途。计数未知时沿用当前 unknown 行为，不填零、不用 outer×epochs 补值；该 run 的图使用已知的 outer 轴，细粒度绝对进度不可恢复，基于绝对 update 的 p99 调度停用并提示。模型恢复继续读取现有 `trainer_state.json`，不用为了指标改名重写 checkpoint 格式。旧 checkpoint 的读取行为不等于保留旧 metric 字段。

本轮不改验证周期、保存周期、学习率 scheduler 的推进单位；它们仍按当前训练配置运行。首次评估写 0；之后同步评估带被评估时的 outer/成功更新数。异步评估不在首批支持范围。

下表描述新输出合同；实际字段说明以[指标字典](2026-10-22-指标字典.md)为准。字段采用第 2 节的语义路径。无适用算法时不输出该字段，不用零占位。

| 类别/section | 本轮维护的字段或集合 | 审计理由 |
| --- | --- | --- |
| 优化与损失 `optim` | `actor/loss`、`actor/lr`、`actor/grad_norm_preclip` | 复用实际 loss、实际使用的 LR、裁剪前梯度；纯蒸馏不再额外输出同值 distill loss |
| 策略分布 `policy` | 第 6 节的三个 pair，另有 `entropy/pre_update` | 实测概率偏移与学生不确定性；不新增 forward |
| 优势信号 `advantage` | `distillation/mean`、`distillation/abs_mean`、`distillation/rms`、`distillation/positive_fraction` | 实际使用的 advantage；rms 与 abs_mean 可观察大信号集中程度 |
| 更新修正 `correction` | `behavior_ppo/active_fraction`、`behavior_ppo/active_mass`、`log_ratio_guard/fraction`、`is/coeff_change` | 数量与系数影响不同；clip 两项仅在相应模式存在，IS 系数比较可在 NoIS 做反事实诊断 |
| 蒸馏关系 `distill` | `advantage/sign_flip_fraction`、`advantage/source_coeff_change` | 回答 frozen/current 消融；删除仅重复 pair 差值的指标 |
| 数据与采样 `rollout` | `score_mean`、`response_length_mean`、`length_limit_fraction`、`aborted_fraction`、`response_count`、`response_tokens` | 质量与实际分母/规模；长度触顶不作稳定性告警 |
| 评估 `eval` | 每个数据集的 `<dataset>/acc_mean`、`<dataset>/failed_count`、`<dataset>/response_count` | 使用原有评估/失败处理；N 和采样协议在 config 中，不再展开 best/worst/majority/重复 reward 字段 |
| 系统效率 `perf` | 核心阶段秒数、吞吐、MFU、已测资源峰值 | 复用现有计时和内存口径，不新增 profiler 或同步屏障 |

vanilla 的实际 PPO 分母是 anchor，已有 active fraction 输出为 `correction/anchor_ppo/active_fraction`，不能与 E1/E3 的 behavior clip 混用同名字段。其 dual clip 和系数质量需要单独适配，未适配的 active_mass 不输出。其他算法的 advantage 使用相应 component 名，当前不实现多 component 自动注册器。

评估的 failed_count 取预期 session 与返回 session 的差及明确的失败状态，沿用现有失败处理，不把回答错误的 acc=0 当作系统失败。response_count 使用准确率实际采用的回答分母，包含按既有规则计零的失败回答。数据集、N、temperature、top-p 和判分协议继续写入 run config。

以下字段经过审计未进入实现：gradient clipping scale 可由 grad norm 和配置阈值离线推导；update_skipped 可由两个累计计数之差得到；累计新/复用 token 预算暂不新增状态；零 advantage 比例对当前 OPD 不是优先信号；top-k mass/overlap 属于其他蒸馏配方；参考策略 pair 在当前配方未启用。

## 6. IS pair 与固定统计集合

### 6.1 概率身份

记号遵循[符号约定](../符号约定.md)：$\beta$ 是实际行为分布，$q_k$ 是批次入口冻结锚点，$p_{k,n}$ 是当前学生，$T$ 是教师。代码分别来自 rollout_log_probs、old_log_probs、当前 log_probs、teacher_logprobs。

| Pair | 原始比值 | 回答的问题 | 采集时刻 |
| --- | --- | --- | --- |
| current_behavior | $w_{cb}=p_{k,n}/\beta$ | 总共偏离真实生成策略多少 | 每次更新前的 forward |
| anchor_behavior | $w_{ab}=q_k/\beta$ | 本批开始训练时已有多少偏移 | 每批入口 |
| current_anchor | $w_{ca}=p_{k,n}/q_k$ | 批内训练相对冻结锚点改变多少 | 每次更新前的 forward |

同一 prefix/token 上令 $z=\log w$，有：

$$
z_{cb}=z_{ca}+z_{ab},\qquad w_{cb}=w_{ca}w_{ab}.
$$

M2 含交叉项，不能直接相加；p99 不能相乘。入口 pair 在整批记录、更新 pair 在 mini-batch 记录时，连均值也不能直接相加。三组输入已在当前路径存在，不为了指标保存第三份学生模型。

当前同步且同版本时，anchor/behavior 主要观察引擎差异；将来 stale 时含已有参数滞后。current/anchor 也会受 train/eval forward 或 batch 形状数值差异影响。教师关系属于学习目标，不生成 teacher/behavior 等额外 IS pair。

### 6.2 字段裁剪后的固定集合

| Pair | 新字段的 `policy/` 后缀 | 频率 |
| --- | --- | --- |
| current_behavior | `current_behavior/log_ratio_mean`、`current_behavior/log_ratio_m2`、`current_behavior/log_ratio_abs_max`、`current_behavior/ess_fraction`、`current_behavior/ratio_lt_half_fraction`、`current_behavior/ratio_gt_2_fraction` | 每次更新 |
| current_behavior | `current_behavior/ratio_p99` | 第一次及每 8 次更新尝试 |
| anchor_behavior | `anchor_behavior/log_ratio_abs_mean`、`anchor_behavior/log_ratio_abs_max`、`anchor_behavior/k3` | 每批入口 |
| current_anchor | `current_anchor/log_ratio_m2`、`current_anchor/log_ratio_abs_max` | 每次更新 |
| 三组各自 | `current_behavior/nonfinite_fraction`、`anchor_behavior/nonfinite_fraction`、`current_anchor/nonfinite_fraction` | 与所属 pair 同频 |

默认 pair 统计从上一版 20 个精简为 12 个，加 3 个必要的输入异常比例，共 15 个固定系列。删除每组的统一统计笛卡尔积、p01、p999、ratio mean、详细档位与直方图。低尾部由 ratio<0.5 比例覆盖；少于 1% 的极端值由 abs_max 和尾部比例覆盖；p99 提供常用尾部分位数。阈值 0.5/2 是描述刻度，不是通用报警边界。

### 6.3 定义与数值处理

对观察范围内 $N$ 个有效 response token，M2 为 $\sum z_i^2/N$；abs_mean 为 $\sum\lvert z_i\rvert/N$；abs_max 为全局最大绝对 log-ratio。current/behavior 的 ESS/N 为：

$$
\mathrm{ESS}/N=\frac{(\sum_iw_i)^2}{N\sum_iw_i^2}.
$$

它表示非负比值的集中度，不把相关 token 当作独立统计样本。K3 为 $\sum_i(\operatorname{expm1}(z_i)-z_i)/N$。只有样本来自分母分布且支持/归一化条件满足时才有相应 KL 估计意义；current/anchor 不默认输出 KL。全部指标以已访问 prefix 为条件，不校正 prefix 分布。

raw pair 在 guard、clip、RS 之前计算；所有诊断输入 detach。采用 FP64 计算必要的和与平方和，原始 ratio/平方和溢出时该派生值不输出并记录警告，不静默 clamp 后标为 raw。log-space 的 M2、abs_max 与尾部计数仍保留。ESS 已使用专用 log-sum-exp 状态，合并后再计算，避免有限但极端的 log-ratio 直接 exp 溢出。

有效位置存在非有限 log-prob 时，记录 nonfinite_fraction，跳过该 pair 的普通统计并在日志中给出原因；padding 内非有限值先按 mask 排除。全 mask 范围不产生伪零均值。有效 token 数作为内部聚合分母保留，不为每个 pair 再输出一个重复 count 字段。

p99 使用全局 nearest-rank：有效 log-ratio 排序后取第 $\max(1,\lceil0.99N\rceil)$ 个，再 exp。只在选定更新保留所需数据，合并到一个报告端计算，不平均各 GPU 的 p99。实现不做抽样近似和方法切换，也不建立分布式内存不足降级协议。分位数存储随有效 token 数增长；资源受限时可将频率设为 0，不会静默截断样本伪装成全量分位数。

默认只记录 token ratio。sequence product 与 geometric ratio 数学上不同，本轮不为当前未使用的方法建立输出；将来接入时必须独立命名和验收。当前 E5/E6 不使用 IS 更新，但仍计算 raw current/behavior 诊断。

## 7. Correction 与蒸馏系数

实际 PPO clip fraction 使用 loss 的激活分支，不用 ratio 越界替代；active mass 为激活 token 占未截断绝对 score 系数的比例。数值 guard 独立统计。E 系列并未启用额外 TIS/RS，因此不输出另一套 applied-weight mean/std/ESS，也不为 NoIS 输出恒 1 权重。以后真实启用 correction 时再接入对应有限字段。

当前信号为：

$$
A^{\mathrm{cur}}=\log T-\log p,\qquad A^{\mathrm{roll}}=\log T-\log\beta.
$$

frozen 指 rollout 信号，不是 $\log T-\log q_k$。guard 未触发时，忽略共同归一化和负号，E2/E4/E5 的 score 系数分别是 $c_2=w_{cb}A^{\mathrm{roll}}$、$c_4=w_{cb}A^{\mathrm{cur}}$、$c_5=A^{\mathrm{cur}}$。

$$
D_A=\frac{\sum\lvert c_2-c_4\rvert}{\sum\lvert c_4\rvert},\qquad
D_{\mathrm{IS}}=\frac{\sum\lvert c_4-c_5\rvert}{\sum\lvert c_4\rvert}.
$$

$D_A$ 对应 distill/advantage/source*coeff_change，$D*{\mathrm{IS}}$ 对应 correction/is/coeff_change。它们是同一 forward 的反事实系数诊断，不是完整参数梯度距离或论文验证的稳定性阈值。分子分母内部合并，分母为零则不输出比值；同时参考实际 advantage 幅度，不加任意 epsilon 制造稳定结果。

PPO 激活 clip 时局部 score 系数为零，不是 clamp(w)×A。guard 外侧导数同样需按真实 loss 分支处理，不能仅使用上述未触发 guard 的简式。边界与 autograd 小例子对照，不新增模型 backward。vanilla 的 dual clip 系数未适配时明确缺席。

## 8. 最小代码改动

### 8.1 明确的统计状态与归约

最小改动以职责清楚、统计正确为目标。现有 Metric 的 loss contribution 保持数学归一化规则；新增原始观察使用可合并状态，明确 mean 的分子分母、sum、max、ESS 和分位数。计算、空间合并、逐更新记录与输出分开，不靠字段名或 DP 因子抵消推断语义。

micro-batch 在本地更新统计状态；DP 合并相同观察范围的状态；之后计算一次全局结果。条件分组允许空 rank 和不等 token 数。已全局计算的 grad norm 只记录一次。不同 optimizer update 保留时间顺序，不进入空间归约。为此需要修改现有 Metric/worker 的必要接口，不建立一套绕开主链路的临时补丁。

只有 p99 需要保留选定更新的分布数据；sum/count 与极值使用有界状态。并行组由 engine 决定。算法适配器提供概率角色、优势和实际 correction 分支；统计器不读取算法配置来猜测对象。诊断输入全部 detach，空间合并不会修改 loss 或训练 RNG。

### 8.2 返回与写入

worker 在现有返回对象里增加一个有序 `update_metrics` 列表，每项是一份已经完成空间聚合的平面数值字典及内部执行状态。trainer 按顺序推进已有三个计数、补 `step/*` 字段，经过固定的新字段输出表调用 Tracking。无需自建 event 对象、schema dataclass、分布式 logger actor 或动态 registry。

外层的入口 entropy、入口 pair、rollout、eval、perf 在原来的计算位置产生，按新字段输出；不再与逐更新 loss 混成一份外层 loss 摘要。worker 调用结束后再批量交给 trainer，首版不保证 worker 崩溃前每次更新的日志都已实时到达。

单次输出示例中的数值仅展示格式：

```json
{
  "step/outer": 2,
  "step/update": 5,
  "step/optimizer": 5,
  "optim/actor/grad_norm_preclip": 0.3,
  "policy/current_behavior/log_ratio_m2": 0.001,
  "advantage/distillation/abs_mean": 0.1
}
```

### 8.3 后端与参数

W&B 不再传显式 SDK `step=`；写入顺序由 SDK 维护，业务字段通过具体 metric name 的 `define_metric` 绑定，并设置 step_sync=False。每条记录携带所需坐标。验证样例表和已有 DAPO 表的 writer 一并改走入口，避免把旧 outer step 当 W&B 内部序号。[^wandb-run]

更新类字段默认以 step/update 作横轴，入口与性能以 step/outer 为轴，评估以 step/optimizer 为轴。TensorBoard 接收相应的数值 step；Console 默认输出外层概览；已有 file backend 在启用时保存相同平面 data，不增加独立 session 文件协议或强制额外落盘。

只新增一个参数 `trainer.metrics_quantile_interval=8`，0 表示关闭 p99。不增加 schema 开关、preserve_legacy_metrics、采集 profile、probe 或多套采样控制。改动生效后新 run 固定使用新字段。配置中写一次 metrics 格式版本，便于人工区分历史实验，不实施旧格式读取器。

## 10. 任务拆分与验收

| 提交阶段 | 范围 | 验收 |
| --- | --- | --- |
| A：新字段出口 | 固定命名表、Tracking 轴与表格路径、旧字段删除 | 输出路径无空段/重名，493 个旧键各有处置；没有双写 |
| B：逐更新记录 | worker 列表、trainer 三计数与输出 | 2 outer×4 更新得到 8 条更新记录；skip 正确 |
| C：诊断 helper | pair、实际 advantage、E 系列 correction/distill | 与单进程统计及 autograd 小例子一致，loss/梯度不变 |
| D：短训练验证 | 当前配方 vanilla 与 E 系列抽样、保存恢复、W&B/file 回读 | 无字段遗漏或错误轴，记录开销可接受 |

必要测试包括：不等长度 micro-batch/DP、空 rank、padding、有效位置 NaN、零分母、原始与 guard/clip 后系数、全局 p99 与平均局部 p99 的反例、真实更新跳过与计数未知。开启诊断不得改变训练 RNG、loss、梯度或参数更新；不更改 LR scheduler 节奏。

W&B 离线测试验证键能写入、业务轴定义和交错记录完整；在线 section 显示需要单独检查，不能把离线文件测试声称为 UI 验收。测试不自动更新历史 W&B run。性能比较报告 actor-update 时间和峰值内存增量，不新增计时同步来“证明”零开销。

本轮不实现固定 prefix probe、full-vocab teacher KL、按层梯度/参数更新统计，也不为它们增加配置、空接口或数据对象。未来需求实际出现时再扩展统计状态和有限字段表。
