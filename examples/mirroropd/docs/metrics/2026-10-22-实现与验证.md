## 1. 已实现的结构

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 算法观察 | [policy_metrics.py](../../../../verl/trainer/ppo/policy_metrics.py) | 明确概率角色、优势和实际 correction 分支，产生 detached 统计 |
| 状态与归约 | [observations.py](../../../../verl/utils/metric/observations.py)、[Metric](../../../../verl/utils/metric/utils.py) | raw sum/count、RMS、极值、log-space ESS、nearest-rank p99；与已归一化 loss contribution 分开 |
| Worker | [engine_workers.py](../../../../verl/workers/engine_workers.py) | micro-batch/DP 合并、读取实际使用的 LR、保留每次更新记录 |
| Trainer | [trainer_base.py](../../../../verl/trainer/ppo/v1/trainer_base.py) | 三个已有累计计数、入口观察、逐更新写出、验证分母与字段出口 |
| 输出 | [schema.py](../../../../verl/utils/metric/schema.py)、[tracking.py](../../../../verl/utils/tracking.py) | 稳定命名、业务横轴、表格统一写入、文件追加和后端转发 |

Observation 接入已有 Metric 的收集协议，但使用显式原始统计合并，DP 不取局部均值的均值。旧 loss contribution 仍按局部累积求和、DP 平均处理，移除了不必要的等长列表限制。将 raw Observation 混入 loss contribution reducer 会报错。

标量状态合并后一起搬到 CPU，再走既有对象通信；p99 只保留选定更新的 raw log-ratio 数据。一次 update 的记录在完成空间归约后立即固定，多个 update 不再做时间平均。worker RPC 完成后，driver 在长验证之前写出这批更新记录。W&B 的写入时间不代表每次更新真实结束的时刻，不能用批量写出的 `_timestamp` 差推算 inner 耗时。

## 2. 配置与默认行为

唯一新增用户配置：

```yaml
trainer:
  metrics_quantile_interval: 8
```

- 0：关闭 p99。
- 1：每次更新尝试记录 p99。
- N>1：第一次更新以及每 N 次累计更新尝试记录 p99。

参数必须是非负整数，bool、负数、浮点数和字符串都会在 logger 初始化前拒绝。该参数只控制分位数，不影响训练 loss、IS 开关、entropy bonus、参数同步、LR scheduler 或验证周期。

```bash
# 只预览启动参数，不启动 GPU 作业。
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E4 \
  trainer.metrics_quantile_interval=8
```

默认日志后端仍由 `trainer.logger` 决定。需要本地结构化标量可使用已有 `file` backend；文件追加写入，不覆盖前次记录，不建立新的 session/event 数据库。W&B 的模式与目录显式传入 init，避免同进程先前 SDK session 的环境缓存干扰后续 run。

## 3. 字段、时间与缺测

完整定义见[指标字典](2026-10-22-指标字典.md)。八类语义目录和多个斜杠保留；W&B 自动 section 不等同于多层目录树。

- `step/outer` 对齐调度轮次；`step/update` 对齐更新尝试；`step/optimizer` 对齐实际成功更新。
- 更新指标在 forward/梯度计算时测量，行内成功计数表示本次 optimizer 操作结束后的状态。
- `policy/anchor_behavior/*` 与 entropy 在本批更新前写出，不复制到每个 inner。
- W&B 不传显式 transport step；每个实际 metric key 只定义一次业务轴，step_sync=False。
- counter 起初未知时默认使用 outer 轴；若已绑定的绝对计数后来变未知，保留已有轴定义和 raw 记录，提示可用 outer 坐标，不回填虚假计数。可手动以 outer 轴检查这些记录。
- p99 非采集步、无对应算法、空分母和非有限普通标量均缺席，不能当作零。原始 pair 的非有限比例单独记录。
- 原始 pair 在有效 response token 上观察；普通 PG 的 RS 路径另外保存筛选前 mask，优势仍按 loss 使用的 mask 统计。普通 PG 的 bypass 适配不把 behavior 的别名伪装成独立 anchor；OPD 的首批验收配置关闭 bypass。

验证使用原先的题目等权均值，缺失 acc 回答按预期 session 数补零；错误答案 0 不计为系统失败。没有 acc 的一般 reward 任务输出 score_mean，避免把 reward 冒称准确率。对外不再计算/发布 378 个 val-aux 展开系列。

## 5. 未验收与不实现的范围

检查时八张 GPU 均被占用，已授权的前四张也在运行任务，未启动新的 GPU 实验。完整 FSDP2/Ray/vLLM 训练、NCCL、线上 W&B UI 和统计开销百分比尚未验收，不宣称额外耗时低于某个百分比。精确 p99 的存储随有效 token 数增长，没有自动抽样或分布式 OOM 恢复协议；可用唯一的频率配置关闭它。

主要数值诊断接入 FSDP/FSDP2、SP=1、V1 sync 路径。其他 engine/异步可保留通用更新记录，但未声明与本次完整数值诊断等价。Vanilla 的 dual-clip 系数质量未适配，相关反事实系数诊断缺席；原始 pair 和其实际优势仍可观察。

固定 prefix probe、full-vocab teacher KL、按层梯度与参数更新统计没有实现，也没有新增相关配置。没有改变归档解包对正在运行源码的替换行为；部署新包仍应在使用该 checkout 的训练结束后进行。
