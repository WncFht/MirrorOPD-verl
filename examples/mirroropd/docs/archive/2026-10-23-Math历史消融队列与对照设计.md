## 2. 统一训练条件

主对照使用 student DeepSeek-R1-Distill-Qwen-1.5B、teacher JustRL-DeepSeek-1.5B、DAPO，batch=mini-batch=64、n=1、每批更新一次、AdamW lr=1e-6、weight decay=0.01、grad clip=1、token-mean。Prompt 上限 4096、训练 response 上限 7168、actor/teacher micro-token 预算 32768；训练采样 temperature=1、top-p=1、top-k=-1。任务奖励不进入 loss，entropy bonus 为零。

每个主实验执行 100 次 optimizer 更新，对齐历史的最后共同完整验证点；每 20 步验证完整 MATH-500/AMC23/AIME25，共 570 题×16。验证 response≤31744、temperature=0.7、top-p=0.9，与参考保持一致。每 50 步保存 checkpoint，只保留该 run 最新一份，避免无界积累。

Student 数据顺序、actor engine seed、actor dataloader seed 和 rollout seed 均显式设置。Seed 42 的方法比较共享这些种子；seed 43 对关键方法重复。所有 run 从同一初始 checkpoint 开始，不串接前一实验的权重。

Rollout 使用本机已验证可运行的 TRITON_ATTN，默认先测试编译/Graph 模式。若启动预检失败，仅重试一次 eager 模式；若 eager 通过，所有后续训练使用同一 eager profile，并将实际选择记录在队列状态及各 run 配置中。两次预检均失败则停止剩余训练，不静默切换方法或降低训练/验证预算。

当前 sampled 与 full 路径还存在已实现的数值策略差别：sampled 沿用原 log-prob 计算，full head 使用 BF16 输入、FP32 projection 输出与累积。不能将很小的准确率差异完全归因于动作抽样方差。固定前缀数学/数值检查已完成，但长程学习效果仍由这些实验判断。

## 3. 已排入的 13 个任务

| 顺序 | 任务 | 预算 | 目的 |
| --- | --- | --- | --- |
| 1 | preflight | batch 8，2 步，response≤128，不验证 | 验证实际运行环境、W&B、完整数据通路；保留正式引擎上下文长度 |
| 2–4 | kernel-c512 / c256 / c1024 | 4096、32768 个预测位置 | 比较 backend 与 token tile；固定 synthetic hidden/head |
| 5 | quality-vanilla-s42 | 100 步，完整验证 | 当前代码、当前硬件的 sampled 参照 |
| 6 | quality-full-s42 | 100 步，完整验证 | full reverse KL 主实验，precompute backend |
| 7 | quality-token_is-s42 | 100 步，完整验证 | current sampled signal + 行为 token IS，区分旧 vanilla 的影响 |
| 8–11 | I/O 四组合 | 每组 8 步，不验证 | 分离 async write、prefetch 及两者组合 |
| 12 | quality-full-s43 | 100 步，完整验证 | full 方法第二个种子 |
| 13 | quality-vanilla-s43 | 100 步，完整验证 | 与 seed 43 full 配对 |

算子组的 token chunk 为 256/512/1024，vocab chunk 固定 8192，backends 包含 recompute、cached、streaming、precompute；512 组额外比较 Liger。32768 位置避免 dense 分配，以 streaming 作为跨实现参照，小规模 dense/FP64 验算复用已有证据。Liger 的内部 tile 由该入口选择，不将外部 token chunk 当作已经修改了 Liger tile。

I/O 组均使用 full reverse KL、precompute、seed 42 和正式训练长度，分别为写关/读关、写开/读关、写关/读开、写开/读开。报告排除首步后的 teacher/actor 阶段时间、总步时和 response token 数；一轮短测试只能作初步性能比较，若生成长度或轨迹明显不同，应在解释速度差异前检查。算子组使用固定输入，更适合比较纯计算成本。

五个主实验合计 500 次更新、25 轮完整验证。按之前 H800 四卡完整验证约 25.7 分钟的实测，验证部分就约需 10.7 小时，另有训练、初始化和工程组；这不是完成时间保证。Eager fallback、模型输出长度变化或等待其他任务释放 GPU 都会延长时间。

## 4. 后台执行与隔离

执行器为 [queue_full_vocab_ablations.py](../../tools/queue_full_vocab_ablations.py)，使用固定 commit 的独立 worktree。资产路径显式指定，Ray worker 的 PYTHONPATH 指向该 worktree，后续编辑主工作区不会改变已排实验。

队列根目录为仓库 `outputs/full-vocab-math-ablation-20261022/`。`plan.json` 保存任务与固定源码版本；`status.json` 原子更新 PID、当前任务、等待状态和已完成结果。每项任务有独立 `attempt-*` 目录，包含命令、公开环境配置、driver 日志、完整 metrics JSONL、W&B run 和退出状态。凭据只在启动时从用户指定 netrc 读取到子进程环境，不写入计划、配置参数或日志。

所有训练使用 GPU 0–3，算子组只使用 GPU 0。启动每项任务前，要求四张卡连续 60 秒同时满足：无 compute process、显存占用低于 1024 MiB、utilization 低于 10%；每 30 秒检查一次。查询失败按不可用处理。Advisory lock 协调使用该执行器的队列，但不是系统级 GPU 预约，不能阻止外部调度器后来占卡。

单项失败会记录并继续其他独立任务；启动预检是例外，两种 profile 都失败则阻止后续训练。工程/预检/算子任务上限 1 小时，主实验上限 12 小时。清理只针对本次子进程树中记录的 PID 与创建时间，不调用全局 `ray stop` 或 `pkill`，不终止其他任务。

W&B 使用同一 `wncfht/MirrorOPD-verl` 项目，group 为 `full-vocab-math-ablation-20261022`。`status.json` 在每项任务完成后记录实际 run URL。所有任务结束后写 `results.json`，包含验证结果和排除首步后的阶段时间。主实验的 outer-step 时间可能包含验证，不能与无验证工程组直接比较。

成功不仅要求退出码 0：训练还检查 optimizer 更新数、无跳步，主实验检查每个计划验证点以及 8000/640/480 个有效回答。验证失败或缺失会标为失败，原始输出仍保留。

## 5. 查看与停止

无需人工持续盯运行；队列会等待 GPU 并依次启动。按需查看状态：

```bash
cat outputs/full-vocab-math-ablation-20261022/status.json
tail -n 30 outputs/full-vocab-math-ablation-20261022/queue.log
```

停止后续排队任务、允许当前任务完成：

```bash
touch outputs/full-vocab-math-ablation-20261022/STOP
```

立即停止当前任务及队列时，对 `status.json` 中记录的队列 PID 发送 SIGTERM，执行器会清理自己启动的进程。相同队列根目录不能重复启动；需要重试时准备新的队列目录，避免覆盖已有结果。

本轮是本机后台实验，不需要人工传包才能开始。长程准确率与工程收益尚未产生，排队成功不能写成实验成功。
