## 2. 初始走读定位的缺口

1. **重复调度入口。** 当前`_validate`遇到固定 RKL 回调立即返回，常规 accuracy 逻辑不会执行；继续拼接多个 callback 会形成不同触发时机和多个模型切换所有者。
2. **全局生成配置。** `__rollout_n__`已有，但温度／top-p／cap 来自 worker 配置；`generate_sessions`目前还硬编码训练用途。必须把 resolved protocol 逐请求传递，不能在多任务间修改共享 DictConfig。
3. **科学身份不足。** `_validate`使用随机 uid 与来源内 ordinal，原`capture_rows`在没有 index 时回退传输 key，本轮改为 prompt token 哈希；这不足以支持跨运行银行、不同 bench 重复 ID 和可靠 retry。
4. **推理 padding 耦合训练。** 例如 CPU 预算只容纳 60 条时，训练 balancer 可能补到 128，当前 callback 再因行数改变报错。推理适配层只按实际 DP 布局补齐，并剔除 padding 统计。
5. **CPU payload 与 GPU 微批混淆。** 把`infer_max_token_len`变小不能阻止 teacher 把整个 32K 公共 bank 的 hidden 留在 TQ。
6. **评分定义尚未完全参数化。** 当前只读 helper 支持 student 输出行不大于 teacher，并加原生 teacher 额外支持修正；它不是 small-teacher→large-student 的共享支持条件 RKL，也没有自动继承所有 EOS 合并训练目标。
7. **评估副作用。** 当前保存／恢复 driver 和 actor RNG，不等于 vLLM 所有生成流的逐 token 复现；需要按请求 seed 隔离及独立的复现验收。
8. **完整性标记。** 关闭`audit_state`后，`end_rkl_readout()`仍返回`unchanged=True`且 digest 为空，原生回调现已显式标记 not_requested／passed；底层返回仍不能独立当完整哈希证据。
9. **checkpoint 顺序。** `fit`先 save 再执行 history 回调；worker 可能淘汰旧 actor 后 driver 仍在保存 data；latest 指针在 callback 之前更新。这些是未来可靠续训的前置缺口；本轮仅保存最终模型，不实施周期恢复。
10. **长预算启动。** 公共回答 32768 再加 prompt 会超过当前训练用 32768 推理 token 预算；vLLM 又可能按其 max_model_len 裁 cap。需要渲染后预算预检与独立推理 profile。
11. **评测器并非四域齐全。** one_shot 路由含数学、代码与 MultiIF；GPQA 和单轮 IFEval 需独立适配，不能用 MultiIF 三轮语义代替。
12. **保存也需要 GPU 生命周期。** `FSDPEngine.save_checkpoint`在 actor 位于 CPU 时可能先加载到 GPU；保存后是否卸载还受配置控制。最终导出应在 vLLM 休眠期间保存并显式核对释放，结束运行，不能将 checkpoint 当纯 CPU 后台工作。
13. **图表归一化不能误继承。** 旧图用固定 horizon 分母；新报告应依据当前 protocol 的 aggregation_id，保留 raw sum/count，不复用旧H1024常量。

## 5. 必须保留的测试矩阵

- **协议**：各 bench 不同 n 与 cap；sample0 并非最快／正确样本；模型模板不兼容时明确失败；requested/effective cap 不得静默不同。
- **计划**：重叠 schedule 只执行一次；initial 与 current 在 step0 共享；teacher 只在初始化生成；相同问题不同轨迹不错误合并；纯 bank 点无 generation。
- **生命周期**：prepare 部分失败、请求失败、CPU verifier 失败、超时与取消；确认所有 GPU/TQ 写入者 drain 后才切换；无法确认时停止该运行。
- **数值**：teacher-copy、近零 RKL、FP64 小样本、不同 token chunk／window／DP padding、真实长前缀；条件支持与原生支持单列。
- **持久化**：Parquet 回读 token 完全一致、history 仅存引用、对象级 manifest 发布前不可读、选择视图计数一致、bank 内容 hash 变化被拒、两 builder 竞争不会覆盖已绑定银行、未完成 manifest 不可读。
- **最终导出**：只保留一个最终权重产物，不含 optimizer／恢复包；权重精度与固定输入 RKL 重载一致；失败 attempt 不混入新运行。
- **可观测性**：每个任务 expected/observed/failed 齐全；缺字段 availability=false；host/CUDA/端到端耗时不混加；常规观测不引入逐 kernel 同步。

## 6. 已基础实现的范围

新增`verl/trainer/evaluation`薄库并接入现有 FixedRKLReadout，具体契约见[组件 README](../../../../../../verl/trainer/evaluation/README.md)：

- ArtifactStore：流式 Parquet/Zstd、固定 schema、int32 原始 token、hash 和 row-group 读取、文件锁、单 manifest 发布；文件不可覆盖。
- History：保存真实训练 shard 引用；driver 不保留 6400 条长 token，仅评分时加载被选轨迹。
- Metrics：按题 RKL、history 批等权、固定 source 降幅、共同 history 轨迹变化、无效记录 coverage；训练 loss 不改。
- Schedule：outer 的 at/every/final 并集；原生回调已支持 source_every 和 history_every 独立频率。
- 发布：评分／审计／清理／必要权重恢复失败时不发布完整评分事件；关闭审计明确标记 not_requested。
- 兼容：旧 JSON 报告保留 token-mean 复算，新 Parquet 报告使用 question-mean；新运行不直接复用旧 JSON 银行。

CPU 定向检查 144 通过，覆盖原生形状的两轮回调、异常路径、RKL 数值 oracle、存储／聚合、logger 与 rollout 契约。另将冻结 JustRL 验收的真实 128 条 source 及 256 条训练轨迹写入 Parquet，逐 token／mask 回读一致；256 条终点评分原值一致，128 条 history 引用回读一致，旧 64 次更新验收仍通过。[检查摘要与源码哈希](../../../infra/architecture/evaluation/data/parquet-foundation-20261031/checks-final.json)、[真实数据往返结果](../../../infra/architecture/evaluation/data/parquet-foundation-20261031/real-roundtrip.json)及[真实配置初始化](../../../infra/architecture/evaluation/data/parquet-foundation-20261031/native-config-check.json)已保存；原始 CPU 日志与复算产物在`runs/evaluation-parquet-implementation/`。
