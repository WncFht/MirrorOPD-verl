Last updated: 2026-10-22。

主实现提交 `818400a81` 已完成；随后补充 bypass 作用位置、实际工具调用数和已有 variance proxy 输入接线。当前字段定义见[指标字典](../../experiments/metrics/指标字典.md)。第一版 64 字段不再是允许列表，原始快照和旧迁移决定保持原样。

## 实现范围

- Eval：所有共同支持的 k；标准 pass、投票、prefix mean、连续评分 best/worst、题内波动、跨题 CI；混合评分源按数据源区分。
- Pair：三组基础 token 统计、全局分位数、sequence 累积与长度归一化统计；原始 ratio 与实际 IS 权重分别记录。
- 训练：实际 loss 分项、clip/dual clip、RS、top-k、critic 独立计数、stale、负载均衡、结束原因和工具调用观测；不改优化公式。
- 记录：完整原始 final-session 记录含失败占位；已知字段统一命名；未知自定义标量告警保留；Console 展示与 W&B/file 记录分开。
- 适用性：内置 FSDP/FSDP2 完整 response 路径接入新 raw 观察。其他 engine 保留已有诊断并显式报告 observations_available=0，不将未验证 CP/TP 片段当作完整 sequence。

## IS/RS 补充实验：已通过

第一次 IS/RS 尝试使用 `rollout_rs_threshold=0.01`，这是我配置错误：该参数表示 ratio 上界，推导下界为 100，导致上下界颠倒。程序在更新前抛出 `ValueError`，退出码为 1；此次失败不算 GPU 验收，也未上传 W&B。失败日志保留在 `examples/mirroropd/outputs/metrics-v3-is-rs-20261022-142504/`。

用户随后提供空闲窗口，使用固定源码 `6c3c27d69` 完成重跑；它包含 `94e91aad6` 的嵌套 IS 权重修复。W&B run `43gx44nh` 已上传并回读[^is-rs-run]，运行目录为 `examples/mirroropd/outputs/metrics-v3-is-rs-20261022-165531/`。运行耗时 323.43 秒，退出码为 0，GPU 0–3 已释放。

设置为 vanilla OPD + token IS + token_k1 RS，1 outer × 2 PPO epochs，无 validation。`rollout_is_threshold=2.0`，RS 阈值为 `0.99_1.01`。helper 使用 `token_k1 = -log(anchor/behavior)`，因此这个区间约束的是 `behavior/anchor`；对应未归一化 IS 权重区间为 `[1/1.01, 1/0.99]`，上界约 1.010101。实际最大权重 1.010076 在此范围内。

| 观测                                 | 第 1 次更新 | 第 2 次更新 |
| ------------------------------------ | ----------- | ----------- |
| optimizer step                       | 1           | 2           |
| 原始 response token 数               | 4096        | 4096        |
| 保留并参与训练的 token 数            | 3122        | 3122        |
| RS token 拒绝比例 / 实际权重为零比例 | 23.7793%    | 23.7793%    |
| 实际 IS 权重 ESS                     | 3121.9836   | 3121.9836   |
| 实际 IS 权重 ESS / 原 token 数       | 0.762203    | 0.762203    |
| current/behavior 原始 ratio ESS/N    | 0.999063    | 0.999071    |
| current/behavior 原始 ratio p99      | 1.113741    | 1.110301    |
| loss                                 | 0.0529396   | 0.0524185   |
| 裁剪前梯度范数                       | 1.155810    | 1.137257    |

两次更新使用同一批生成样本，入口 anchor/behavior IS 权重及 RS mask 固定，所以实际权重和保留 token 数不变；current/behavior 随模型更新变化。原始 ratio 的 ESS 接近 1，而实际权重 ESS/N 约 0.762，主要来自这次刻意设置的窄 RS 区间，不能把二者当成同一个指标，也不能据此得出训练 stale 严重的结论。

独立验收检查了原始分母、保留计数、拒绝比例、零权重比例、ESS 与 ESS/N 的关系，以及两次 optimizer 更新均实际执行。所有 289 个标量字段均为有限数值，无 undefined/nonfinite 事件；本地 4 行记录与 W&B 云端 4 行逐值一致。字段列表见 [IS/RS 实测字段](data/metrics-v3-20261022/is-rs-observed-fields.csv)。

这个实验验证了 token IS + token_k1 RS 的 vanilla/FSDP2 路径。其他 IS/RS 选项、其他 engine 和长期稳定性不由这两次更新覆盖。空样例表修复仍由 CPU 测试覆盖，这轮无 validation，不能作为该表格分支的 GPU 实测。

## 复现入口

[启动脚本](../../../smoke/run_metrics_smoke_fsdp2.sh)默认 E3、2 个 outer step、每批 4 次更新，训练前及每步结束验证三个数据集各 2 题 × 4 回答。分位数每次更新记录；禁用 checkpoint 保存。默认离线 W&B，完整输出位于 `examples/mirroropd/outputs/<实验名>/`。

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 bash examples/mirroropd/smoke/run_metrics_smoke_fsdp2.sh
```

IS/RS 验收复现命令：

```bash
METRICS_SMOKE_MODE=is-rs CUDA_VISIBLE_DEVICES=0,1,2,3 bash examples/mirroropd/smoke/run_metrics_smoke_fsdp2.sh
```

IS/RS 模式为 vanilla OPD + token IS + token_k1 RS，1 outer × 2 PPO epochs，不做 validation。
