## 2. 变化汇总与出口问题

| 旧快照范围             | 换名 | 重测 | 停止输出 | 合计 |
| ---------------------- | ---: | ---: | -------: | ---: |
| eval：val-core/val-aux |    3 |    0 |      390 |  393 |
| 训练与系统             |   26 |    8 |       66 |  100 |
| 总计                   |   29 |    8 |      456 |  493 |

这张表复述第一版的处置分类，不是最终的信息损失计数。例如旧整步时间已有新名字；skipped updates 在两个累计计数已知时可相减得到；旧 worker 显存与新全 rank MAX 则不是完全相同的测量范围。

当前 [outer_metrics](../../../../../verl/utils/metric/schema.py) 只接受固定改名映射、canonical 字段和 `eval/*`。大部分训练统计仍由生产端计算，随后被出口裁掉；eval 则由新的三字段聚合替代，V1 不再调用旧的预算展开统计。普通 file backend 也在这个出口之后，无法找回被裁掉的数据。

还有三项覆盖限制：

- 新逐更新观察主要接在同步 FSDP/FSDP2、SP=1 路径。其他 backend 的采集不完整，不能因为新采集受限就删除其已有诊断。
- `finite_metrics` 会省略 NaN/Inf。更新路径有 warning，但 loss/grad 异常没有独立曲线；空分母、无有效样本和真正数值异常需要区分。
- Console 会跳过纯 update 记录；这些新 loss/grad/policy 行可在 W&B 中存在，却不出现在终端概览。显示精简与停止记录是不同问题。

后续应恢复到 `optim/policy/advantage/correction/distill/rollout/eval/perf` 八类及已有 `step/*` 坐标，不恢复两套名字。已丢失的历史统计只能在原始样本或本地明细足够时重算，不能靠改面板自动恢复。

### 不能按字符串等价迁移的项目

- 原 `training/rollout_probs_diff_*` 在 exp 后的概率空间计算；新 `log_ratio_*` 在 log-prob 空间计算。两者都能诊断不一致，但数值不等价。
- `critic/advantages/*` 是原 task reward 通路信号。纯 OPD 实际用的蒸馏优势不是它；普通 PG 已有部分 `advantage/task/*` 逐更新观察，也不能当作原 batch 摘要的逐点别名。
- `actor/lr` 的旧聚合可能记录 scheduler 推进后的值；新 `optim/actor/lr` 记录本次更新实际使用值。
- 原 `response_length/clip_ratio` 比较的是响应长度与 batch padded width；不能不核对 finish reason 就改成“真实达到配置长度上限的比例”。长度触顶不直接作为 OPD 不稳定告警。
- 原 `rollout_corr/kl` 的符号是 behavior−anchor；新 pair 的 log-ratio 是 anchor−behavior。旧 PPL/log-PPL 含先按序列聚合的口径，不等价于 token 全局均值。
- `perf/total_num_tokens` 含 prompt 与 response；新 `rollout/response_tokens` 不足以代替总工作量。

## 4. Eval 的 393 个旧字段与新需求

当前实现对每个数据源只输出 `acc_mean`（reward-only 输入用 `score_mean`）、`failed_count`、`response_count`。三个数学数据集共九个标量；它没有 pass/majority 预算曲线。

旧字段按模式归并如下，实际 393 行均在历史对照 CSV 中保留。`acc_success_only` 指有有效评分的回答，不是“只看答对的回答”。

| 原字段模式 | 当前输出 | 拟补齐方向 | 统计边界 |
| --- | --- | --- | --- |
| `val-core/{dataset}/acc/mean@16` | `eval/{dataset}/acc_mean` | 拟统一到 `eval/{dataset}/acc/mean` | 平均单次正确率；命名调整不是已实施 |
| acc 的 `best@k/mean` | 无 | `eval/{dataset}/acc/pass@k`，覆盖 1…K | 使用标准组合估计器；不是把旧 best 改字符串 |
| acc 的 `maj@k/mean` | 无 | `eval/{dataset}/acc/majority@k`，覆盖 1…K | 答案等价关系、无放回子集、平票与失败处理需明确 |
| acc 的 `worst@k/*` | 无 | 候选 `all_correct@k` 或明细复算 | 是否默认常驻待评审；二值最差值是全部正确事件 |
| acc 的 `std@N` | 无 | `acc/within_prompt_std` | 题内回答波动，不能当作整体准确率 CI |
| best/maj/worst 的 `/std` | 无 | 单独定义子集估计误差或跨题 CI | 不直接继承旧名字；旧 std 是另一种随机量 |
| `acc_success_only/*` | 无 | 至少保留 `acc_observed/mean` 诊断；预算展开待评审 | 主指标仍包含失败回答，不能只剩成功返回样本 |
| `format_score/*` | 无 | 保留独立 format 评分；均值、题内波动及适用的预算统计 | 不对所有评分强行套多数投票 |
| `reward/*`、`score/*` | 有 acc 时不单独输出 | 保留独立评分；只有证明同义时才合并 | 连续 reward 的 best/worst 与二值 pass 不同 |
| `val-aux/num_turns/{min,max,mean}` | 无 | `eval/num_turns/*` | 多轮任务的 session 口径 |
| 以前没有完整记录的覆盖信息 | 仅失败数、预期回答分母 | prompt 数、实际有效评分数、必要的 k 覆盖范围 | 不等 N 时不能静默删除困难题 |

### 采样预算口径

K 来自验证的 `rollout.val_kwargs.n` 或逐题 `__rollout_n__`，与训练 rollout 数分开。旧代码只展开 2、4、8、…、N；它的 best/majority 使用有放回 bootstrap，并调用全局 `np.random.seed`。新方案必须使用局部 RNG，避免统计改变训练随机状态。

对一道有 N 个回答、c 个正确回答的题，拟使用 HumanEval 的标准 pass@k 估计器[^human-eval]：

$$
\widehat{\operatorname{pass@k}}=1-\frac{\binom{N-c}{k}}{\binom Nk},\qquad 1\leq k\leq N.
$$

对题目等权平均。二值条件下 pass@1 等于平均正确率，保留完整预算曲线时这是有意识的重复端点。N=16、c=1 时，新 pass@16 为 1；旧有放回 best@16 的期望为 $1-(15/16)^{16}\approx0.644$，历史数值不能直接拼接成新曲线。

随机抽 k 个回答求均值再对抽样求期望，对所有 k 都等于总体均值。固定 sample index 前 k 个回答的 `prefix_mean@k` 则反映估计随样本数变化的波动，依赖排序；是否新增仍待评审，不能按 RPC 返回时间排序。

majority 仅用于可定义规范化答案等价关系的任务。K 点直接使用全部回答；小 k 的子集估计、平票、缺失答案处理和重采样预算待定。旧 `calc_maj_val` 的平票受输入顺序影响，不能沿用后宣称口径已稳定。跨题 CI 也需要明确方法与置信水平，不代表跨训练 seed 的不确定性。

当前 `evaluation_metrics` 在整轮 infos 级选择 acc 或 reward；混合 acc 与 reward-only 数据源的逐源能力判断仍有缺口。拟议实现应按数据源定义评分能力，不能让其他数据源的 acc 导致 reward-only 源误标准确率。

原始验证明细复用 `validation_data_dir`，但稳定题目身份、sample index、规范化答案、所有评分、失败占位和长度还需核对补齐。当前验证 uid 每轮随机生成，不能直接作为跨 checkpoint 的稳定题目 ID。现有 dump 主要来自已物化输出，不能保证已经包含所有失败 session。

## 6. Pair、IS 与实际学习信号的完成度

| Pair | 当前已有字段（省略 policy/pair 前缀） | 拟补齐 |
| --- | --- | --- |
| current_behavior | log_ratio_mean、log_ratio_m2、log_ratio_abs_max、ess_fraction、ratio_lt_half_fraction、ratio_gt_2_fraction、ratio_p99、nonfinite_fraction | ratio_mean/std、log-ratio 分位数、sequence 统计 |
| anchor_behavior | log_ratio_abs_mean、log_ratio_abs_max、k3、nonfinite_fraction | 有符号 mean、M2、分位数；入口 IS 用途适用时的权重统计 |
| current_anchor | log_ratio_m2、log_ratio_abs_max、nonfinite_fraction | 有符号 mean、abs_mean、分位数、sequence 统计及实际 PPO 分支诊断 |

当前 current_behavior 的 p99 仅按首次及每 N 次更新尝试记录，0 关闭。当前 ESS 是原始 token ratio 的 ESS/N，不是截断、归一化、RS 之后实际权重的 ESS。

令 $z_{it}$ 为第 i 条回答第 t 个有效 token 的 log-ratio。当前 M2 与拟增加的 sequence M2 分别为：

$$
M_{2,\mathrm{token}}=\frac{\sum_i\sum_{t=1}^{L_i}z_{it}^{2}}{\sum_iL_i},\qquad
M_{2,\mathrm{sequence}}=\frac1B\sum_i\left(\sum_{t=1}^{L_i}z_{it}\right)^2.
$$

B 是有效回答数，$L_i$ 是有效 response token 数。后者含 token 间交叉项，不能由前者直接推导。此前讨论的 total_log_ratio_m2 若指后者，则仍未实现。序列内先取平均再求跨序列统计也应单独命名，用于区分长度与平均偏移；SP 拆分时必须先还原序列统计，再做 DP 归约。

当前真实学习信号已有 mean、abs_mean、RMS、positive_fraction；蒸馏和 task component 分开。当前 E 分支已有 sign_flip_fraction、IS/NoIS 系数差、current/frozen 系数差、behavior clip active_fraction/active_mass 与 guard。它们比较 score-function 系数，不是完整参数梯度或 optimizer 更新距离。vanilla 已有 anchor active_fraction，但 dual clip、active_mass 和通用 PPO 分支尚未完整适配。

以下仍是待办：

- 实际处理后 IS 权重与 raw ratio 分开；补齐权重统计、拒绝比例、有效样本量及分母。
- 优势的零值、极值、尾部及有效性；当前 teacher/student sampled gap 与 frozen advantage 的口径不能混为一谈。
- Top-k 支持集信息与 loss 分项迁回新分类，不增加 full-vocab teacher KL。
- Stale 的权重版本 age、跨版本跨度、数据复用和淘汰量恢复。optimizer age 必须有真实执行版本元数据，不能用 outer×epochs 猜测。
- 每个 pair 的样本来源、方向、mask 与权重明确。current_anchor 的数据由 behavior 采样时，不把任意 ratio 统计直接称作严格的 KL 或校正 ESS。
