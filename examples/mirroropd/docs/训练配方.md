# Math、Coding 与 IF 训练配方

本页维护领域默认值、实验编号及学习/评测预算。部署命令和通用环境见[运行与架构](infra/2026-10-22-共享八卡运行与架构.md)。下文最短入口均假设已显式设置获分配的 `CUDA_VISIBLE_DEVICES`、资源池与原生环境，并从仓库根目录执行。Hope 统一通过 `make opd-submit` 提交。

## 单教师数学 full-data 配方

统一入口的 `custom --method sampled`默认使用 V1 同步 trainer、FSDP2 student 和共池冻结 FSDP2 teacher。数学设置参考 One-Shot-OPD 当前可执行配方：DeepSeek-R1-Distill-Qwen-1.5B student、JustRL-DeepSeek-1.5B teacher、完整 DAPO 数据、sampled-token `k1 + PG`、batch 与 mini-batch 均为 64、每批一次更新、AdamW 学习率 1e-6。该默认路径在 loss 中构造 current-policy advantage，未启用 frozen 信号；current/frozen 对照由[优势与 IS 消融入口](opd-objective/2026-10-21-优势与IS消融及更新计数实现方案.md)提供。默认配方不能称为原研究实现的完整等价复现。

默认资源与长度：

| 项目 | 默认值 |
| --- | --- |
| 共享资源池 | 8 张 GPU；rollout、teacher 评分、actor 更新分阶段使用 |
| Student rollout | TP=1，共 8 个推理副本，验证复用 |
| Student 执行模式 | 默认编译＋CUDA Graph；`ROLLOUT_ENFORCE_EAGER=True` 可回退 eager |
| Teacher | FSDP2 DP8，无 optimizer，整批评分后卸载到 CPU |
| Prompt / 训练 response | 4096 / 7168 token |
| 验证 response | 31744 token |
| Student 最大 context / teacher forward 预算 | 35841 / 每卡 32768 token；teacher 预算必须容纳完整训练序列 |
| 验证集 | MATH-500、AMC23、AIME25；500 + 40 + 30 题 |
| 验证采样 | 每题 16 次，temperature=0.7、top-p=0.9 |
| 验证提交窗口 / 推理并发 | 数学全量提交（`VAL_BATCH_SIZE=null`）；每个 student 推理副本最多 128 条序列 |
| 推理显存比例 / 调度 token 预算 | 数学 0.65 / 8192；均为每引擎配置 |
| Actor 动态 micro-token 预算 | 每卡 32768，按完整 prompt＋response 拆分并累积梯度 |
| 采样概率输出 | 训练保留；验证省略未用于评分的概率输出 |
| 训练预算 | 1 epoch；全量 17917 条数据未过滤时约 279 steps |
| 验证 / 保存间隔 | 20 / 50 global steps，并在最后一步触发 |

默认训练 1 epoch。当前 17917 条 DAPO 的 prompt 均未超过 4096，过滤后仍是 17917 条；V1 trainer 按 `floor(17917 / 64) = 279` 计算步数，最后不足一个 batch 的 61 条不参与这个 epoch。每步全局采样 64 道题，每题生成 1 条回答；`ppo_mini_batch_size=64`、`ppo_epochs=1`，每步做一次全局参数更新。64 是整个 student 资源池的 batch；8 个 student 训练 rank 平均各处理 8 条，内部动态 token batching 与梯度累积按实际序列长度安排。

验证发生在 step 20、40、……、260 和最终 step 279，共 14 次；`val_before_train=False`，训练前不额外验证。每次完整覆盖 MATH-500 的 500 题、AMC23 的 40 题、AIME25 的 30 题，合计 570 题，每题采样 16 次，共生成 9120 条回答。`VAL_BATCH_SIZE=null`默认一次提交全部 570 道题。正整数值可恢复窗口提交；实际同时运行的请求数受每个推理副本`max_num_seqs=128`约束，八卡合计上限 1024。提交窗口与引擎活跃并发是不同参数。每条验证回答最多 31744 token。checkpoint 保存于 step 50、100、150、200、250、279。

Student Graph 的 capture sizes 根据 `ROLLOUT_MAX_NUM_SEQS` 派生为 2 的幂并包含最后的并发上限；数学默认是 `[1,2,4,8,16,32,64,128]`。仍可通过末尾 Hydra 参数覆盖现有 `actor_rollout_ref.rollout.cudagraph_capture_sizes` 字段。训练 batch64 和更新预算保持不变；早期测量使用 eager、验证窗口 16，复算时以对应运行的冻结配置为准。

默认值的本机验证依据见[完整验证实测](infra/2026-10-22-训练与验证性能实测.md#1-完整验证与参数对照)；batch128/256 的学习配置边界与验证窗口建议见[批量与 rollout 调优](infra/2026-10-22-批量大小与GPU利用率调优.md)。全量验证已完成 H800 四卡初始 checkpoint 测量；新默认在目标八卡上的完整训练/验证周期仍须独立验收。

共享/独立池的角色、卸载要求与覆盖参数见[运行与架构](infra/2026-10-22-共享八卡运行与架构.md#共享与独立池配置)。选择部署方式时保持本页的学习与评测预算不变。

脚本将常用环境变量集中在前半部分，按模型与数据、GPU、训练与验证预算分组；原生 Hydra 参数按 data、actor、rollout、validation、distillation、algorithm、trainer 分成数组，最后统一组装。通常改顶部默认值或使用环境变量即可；新增原生配置放入对应数组。

模型默认从仓库相邻的 `model/` 读取，数据默认从相邻 `data/` 读取；可用 `MODEL_ROOT`、`DATA_ROOT` 或各文件变量覆盖。目录、准备与检查入口见[资产准备](资产准备.md)。数据文件分别是 `math/DAPO/train.parquet`、`math/MATH-500/test.parquet`、`math/AMC23/test.parquet` 和 `math/AIME25/test.parquet`。

```bash

```

GPU 分配、shared/standalone 切换、配置预览见[启动与配置](infra/2026-10-22-共享八卡运行与架构.md#启动与配置)；Python、运行目录、日志、恢复与人工部署约定见[通用运行合同](infra/2026-10-22-共享八卡运行与架构.md#通用运行合同)。

## 独立验证长度

新增 `actor_rollout_ref.rollout.val_kwargs.max_tokens`，默认 `null`，保留原有训练/验证共用 response budget 的行为。非空时，验证请求和最终 response、mask、log-prob、router replay 输出使用同一预算；V1 的 TQ 保存未 padding 的实际输出，旧 DataProto 路径按验证预算 padding。

当前支持 vLLM/SGLang 的 `single_turn_agent`；本配方使用 vLLM。配置或数据行选择其他 agent 时会拒绝独立验证预算，避免多轮 agent 静默沿用训练上限；会覆盖请求长度的其他后端也会被配置检查拒绝。应显式配置足以容纳 prompt 与验证预算的 `rollout.max_model_len`；底层服务仍受模型 context 和显存约束。该设置不改变 teacher 的训练评分长度。

ResOPD 的公开版本 `3bdf019d` 只设置一个 `MAX_RESPONSE_LENGTH`，没有这条独立验证长度配置；本配方不依赖它的启动脚本。[^resopd]

## 实验预设与运行记录

训练实验统一从 [run_math_opd_ablation_fsdp2.sh](../run_math_opd_ablation_fsdp2.sh) 进入。E1–E47 提供模型、长度、学习率、reuse、验证和保存预算及默认方法；`--method` 只切换算法，`custom` 使用公共配方而不加载编号预算。

| 方法 | 配置与含义 | 可用选项 |
| --- | --- | --- |
| `sampled` | 原 `k1` sampled OPD，保留 current/rollout、vanilla/token PPO/token IS/NoIS | `--advantage current/rollout`、`--policy-loss vanilla/token_is/token_ppo/reinforce` |
| `full_kl` | 规范化为 `mirror: mdpo + full_vocab + eta=1`，无需 anchor | `FULL_KL_*`；eta 固定为 1 |
| `full_forward_kl` | 完整student输出支持上的Forward KL，无anchor | `FULL_KL_*`；不等head显式设置`FULL_KL_FORWARD_TEACHER_SUPPORT=student` |
| `mdpo` | Weighted teacher + scaled MDPO，保留外部 1/eta | `--estimator sampled/full_vocab`、`--kappa`、`--eta` |
| `bpo` | Weighted teacher + q 加权中心化回归 | 只支持 full_vocab；`--kappa`、`--eta` |

旧 sampled 的 frozen、PPO、NoIS 不是 MDPO 的 eta=1 特例。Current token-IS 只在旧 ±20 ratio guard 未触发时与 sampled MDPO eta=1 相同。入口统一复用代码，保留这些不同目标和估计器的语义。

```bash
# 原编号默认不变：E15 sampled vanilla，E13 普通 Full-KL。
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E15
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E13

# 同一 E17 模型与 16 次 reuse 预算，比较 MDPO/BPO。
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E17 --method mdpo --kappa 0.5 --eta 0.3
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E17 --method bpo --kappa 0.5 --eta 0.3

# 使用 E13 的模型和预算，换成 sampled MDPO。
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E13 --method mdpo --estimator sampled --eta 0.3

# 不加载编号预算；通过环境或 Hydra 明确自己的实验设置。
PPO_EPOCHS=4 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh custom --method full_kl
DRY_RUN=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E28 --method bpo --eta 0.5
```

优先级为预设默认值 < 环境变量 < 方法选项 < 末尾 Hydra overrides。环境方法变量是 `EXPERIMENT_METHOD`，mirror 参数沿用 `MIRROR_ESTIMATOR/KAPPA/ETA/DIAGNOSTICS`；旧 sampled 沿用 `OPD_ADVANTAGE_SOURCE/POLICY_LOSS_MODE/CLIP_EPS`。CLI 的 `--kappa/--eta` 只适用于 MDPO/BPO，sampled 专用选项只适用于 `--method sampled`，冲突组合在启动前报错。

加 `--method` 后不再是原编号算法的原样复现；自动实验名附带方法/形状参数，最终以保存的 config 为准。`-valid-student/-valid-teacher` 仍验证原始模型，不接受方法选项，也不把融合分布 m 当成一个可直接生成的模型。

Math 训练只维护一个公共入口。[math_experiment.py](../launchers/math_experiment.py) 用不可变的 ModelPair/Budget/Preset 数据表生成预设并合并参数；算法参数由 [\_distillation_args.sh](../launchers/_distillation_args.sh) 构造，资源和数据由公共 launcher 管理。E13–E43 中的编号 full 预设保持 precompute、IO 开启；E44–E47 默认 precompute_fused、chunk=128、IO 开启；`custom --method full_kl` 默认 precompute、IO 关闭。需要其他 backend 时显式设置 FULL_KL_BACKEND。 CUDA BF16 的一般 MDPO/BPO 可设置 `FULL_KL_BACKEND=precompute_fused`，启用融合 target 与诊断归约；chunk=128/512 的时间和显存比较见[数值层优化实测](infra/profile/operators.md#mdpo-bpo-target-与诊断融合)。这里的收益不代表整轮吞吐，也不改变普通 Full-KL endpoint 的运算路径。

入口头部保留分组对齐速查表，分别展示模型/长度对照、sampled 信号和训练预算；`--overview` 显示同一份概览，`--list-presets` 列出逐编号的完整模型信息。注释表由预设数据生成，并通过测试检查同步，配置仍只在 Python 中维护一份。规划器只依赖 PATH 中的 Python 3 标准库；PYTHON_BIN 仍单独指定训练与 Ray 的原生环境。

### Polaris 跨源教师 E48

E48 将 E20 的教师替换为 `Polaris-7B-Preview`，学生保持 `DeepSeek-R1-Distill-Qwen-1.5B`，开启训练前验证。Full-KL（MDPO eta=1）、DAPO、batch=mini-batch=64、n=1、reuse16、256 outer／4096 次更新、LR=1e-6、seed42 均保留；训练 prompt/response cap=4096/7168，验证 cap=31744、n=16。每32 outer验证、每64 outer保存，保留4个checkpoint；关闭group filtering和失败组refill。

Teacher FSDP评分预算沿用32768，未降低。Backend保留`precompute`、token chunk512、vocab chunk8192，async write/prefetch开启。资源池默认8卡；本机四卡短测通过`STUDENT_GPUS=4`覆盖，实际GPU由调用者明确分配。短测配置与结果见[E48四卡验收](experiments/polaris-transfer/README.md)。

```bash

bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E48-valid-student
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E48-valid-teacher
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E48
```

上述命令还需设置当前机器的`CUDA_VISIBLE_DEVICES`、`STUDENT_GPUS`、`PYTHON_BIN`、`MODEL_ROOT`和`DATA_ROOT`。Teacher独立生成评测默认并发32；这不改变训练阶段FSDP teacher评分预算32768。

```bash
bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E49
```

和E48做同版本对照时，建议显式给两组设置`FULL_KL_BACKEND=precompute_fused FULL_KL_TOKEN_CHUNK=512`。不要把历史E48与新代码的全部差异都归因于KL方向。

### Full-KL / MDPO / BPO 正式对照 E44–E47

<a id="mirror-comparison"></a>

这四组已登记为完整预设，可直接用编号启动。预算沿用 E20：256 outer、每批 reuse=16；按默认 batch=mini-batch=64、n=1 计算，每组计划 4096 次 optimizer 更新。保存间隔按用户要求改为 128 outer。

| 编号 | 方法 | Estimator | κ | η | 对照目的 |
| --- | --- | --- | --- | --- | --- |
| E44 | 普通 Full-KL，即 MDPO eta=1 endpoint | full_vocab | — | 1 | 当前实现下的教师 KL 基线，无 anchor |
| E45 | MDPO | full_vocab | 0 | 0.3 | 几何融合目标及 anchor 约束 |
| E46 | BPO | full_vocab | 0 | 0.3 | 与 E45 相同融合目标下的内层拟合方式 |
| E47 | MDPO | full_vocab | 0.5 | 0.3 | 与 E45 比较 weighted teacher 的形状 |

| 共同设置 | 默认值 |
| --- | --- |
| Student / teacher | DeepSeek-R1-Distill-Qwen-1.5B / JustRL-DeepSeek-1.5B |
| 训练数据 | DAPO，全量可用数据；关闭 group filtering 与失败组 refill，与 E20 一致 |
| Batch / mini-batch / rollout n | 64 / 64 / 1 |
| LR / scheduler / seed | 1e-6 / constant、无 warmup / 42；数据、actor 和 rollout seed 对齐 |
| Outer / reuse / 更新数 | 256 / 16 / 4096 |
| 训练 prompt / response cap | 4096 / 7168 |
| 验证 | MATH-500、AMC23、AIME25；VAL_N=16，temperature=0.7，top-p=0.9，response cap=31744 |
| 验证时机 | 沿用 E20，不做初始验证；outer 32、64、96、128、160、192、224、256 |
| Checkpoint | 每 128 outer 保存；正常完整运行保存 outer 128、256，保留上限 4 份 |
| Full-vocab backend / token chunk | precompute_fused / 128 |
| Hidden IO | async write 与 prefetch 均开启 |
| 诊断 | E45–E47 开启 mirror diagnostics；E44 沿用 Full-KL endpoint 指标，不额外建立 anchor |

κ=0 时，E45 的实际训练目标为 $\mathrm{KL}(p\Vert T)+(1/\eta-1)\mathrm{KL}(p\Vert q)$。E46 使用同一个冻结目标 b，但优化 q 加权残差方差；E47 改变融合形状。各目标均保留规定的 $1/\eta$ 缩放，具体定义见[实现方案](mirror-descent/实现方案.md#kernels)。不同 objective 的原始 loss 不直接横向排名，比较任务验证、teacher KL、anchor 漂移和相同更新预算下的实际耗时。

```bash
# 配置检查不启动 Ray 或训练。
CONFIG_ONLY=1 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E45

# 按实际分配的卡启动；E44/E46/E47 只需替换编号。
CUDA_VISIBLE_DEVICES=0,1,2,3 STUDENT_GPUS=4 \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E45
```

师生资产和原生 Python 路径遵循仓库运行约定；本机旧目录可用 MODEL_ROOT、DATA_ROOT、PYTHON_BIN 显式指定。卡数属于运行资源，不改变默认 global batch 和更新预算。正式长序列运行前仍需验证容量：已有 1.5B smoke 的 response cap 为 64，不能作为 7168 长度下的显存保证。

E44–E47 沿用现有覆盖优先级：预设 < 环境变量 < 方法选项 < Hydra。直接调用编号即得到上表配置；覆盖方法、预算或评测参数后应按衍生设置登记，最终以 resolved_config.yaml 为准。现有命名还没有实现对所有覆盖项的自动衍生标记，不能仅凭 E 编号推断实际配置。E44 与历史 E20 的 backend、chunk、保存间隔不同，需要重新运行作为同版本对照。

配置验收已通过 247 项入口、Hydra 配置和日志识别测试；E1–E43 的 43 组启动计划与改动前一致，E46 的实际 CONFIG_ONLY 解析也通过。验收日志位于 outputs/mirror-screening-presets/acceptance.log，E46 解析配置位于同目录 E46-resolved.yaml。四组正式训练尚未启动；实际 run 产生后再进入运行记录，数值层短测和既有历史结果不计作 E44–E47 完成。

## OPD／MDPO 训练精度对照

E50/E51 是 E44/E45 的 FP16 对照；E52/E53 是 BF16 GEMM＋FP32 中间表示对照。四组保留 256 outer、reuse16、save128 和 VAL_N=16。`--precision bf16|fp16|bf16_fp32|fp32` 可在同一公开入口选择 actor/anchor 执行策略；fp32 是较慢的 packed math attention 参考。Teacher 与 rollout 精度保持独立，详细语义、命令及验收范围见[共享训练精度](mirror-descent/2026-10-27-共享训练精度与实验入口.md)。

## Coding 与 IF 训练入口

三个领域共用 [\_run_single_teacher_fsdp2.sh](../launchers/_run_single_teacher_fsdp2.sh)，默认均为 DeepSeek-R1-Distill-Qwen-1.5B student、共享八卡、student TP=1 和 sampled-token `k1 + PG`。训练 batch 与 loss 保持原设置。coding 与 IF 的模型、训练数据和验证方式参考 One-Shot-OPD 的 `recipe/opd.sh`。[^oneshot]

| 入口 | Teacher | 训练数据 | 训练期间验证 |
| --- | --- | --- | --- |
| [math](../run_math_opd_ablation_fsdp2.sh) | `JustRL-DeepSeek-1.5B` | `math/DAPO/train.parquet` | MATH-500、AMC23、AIME25 |
| [coding](../run_code_deepseek_r1_1_5b_fsdp2.sh) | `DeepCoder-1.5B-Preview` | `code/TACO/train.parquet` | `code/LCBv6/test.parquet` |
| [IF](../run_if_deepseek_r1_1_5b_fsdp2.sh) | `UltraData-IF-1.5B` | `if/MultiIF/train.parquet`，第一轮 | 关闭；正式 MultiIF 需要独立三轮评测 |

模型默认放在仓库同级 `model/`，数据默认放在同级 `data/`；已有目录可用 `MODEL_ROOT`、`DATA_ROOT` 指定。coding 可用 `CODE_VAL_FILE` 选择另一份单轮验证 parquet。现有 `prepare_models.py`、`prepare_math_data.py` 和 `make assets-check` 仍用于数学资产；coding / IF 的 teacher 和 parquet 需要另行准备。训练启动前会检查选中领域的数据文件。

```bash
bash examples/mirroropd/run_code_deepseek_r1_1_5b_fsdp2.sh

OPENCOMPASS_ROOT=/共享目录/opencompass NLTK_DATA=/共享目录/nltk_data \
  bash examples/mirroropd/run_if_deepseek_r1_1_5b_fsdp2.sh
```

IF 默认设置 `data.val_files=[]`、`TEST_FREQ=-1` 和 `trainer.val_before_train=False`，不会把三轮数据当作单轮验证。V1 支持这种只训练的配置；空验证列表配合启用验证的选项会报错。MultiIF checker 仍会对训练回答计算诊断分数，因此 IF 启动时会检查 `OPENCOMPASS_ROOT` 并加载 checker；该变量和可选的 `NLTK_DATA` 会显式传给 Ray worker。依赖见[判分器与依赖](判分器与依赖.md)。完整三轮生成程序尚未迁入本仓，不能把训练分数当作正式 MultiIF 评测结果。

coding / IF 即使关闭 task reward 对 loss 的贡献，仍会计算 verifier 诊断分数。coding 的 `gen` 还包含 CPU 测试执行成本；LCB runner 的全局等待预算包含新进程启动时间，部署前应使用已知正确的小程序检查判分环境。数学的采样耗时不能直接外推到这两个领域。

Hope 仍通过 `make opd-submit` 提交，worker 直接调用带领域前缀的配方，默认 math。`.hope` 的一次性迁移、DOMAIN 设置与预检边界见[Hope 直连入口](infra/2026-10-22-共享八卡运行与架构.md#hope-直连入口)。
