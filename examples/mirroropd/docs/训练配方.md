# Math、Coding 与 IF 训练配方

本页维护领域默认值、实验编号及学习/评测预算。部署命令和通用环境见[运行与架构](infra/2026-10-22-共享八卡运行与架构.md)。下文最短入口均假设已显式设置获分配的 `CUDA_VISIBLE_DEVICES`、资源池与原生环境，并从仓库根目录执行。Hope 统一通过 `make opd-submit` 提交。

## 单教师数学 full-data 配方

[run_math_deepseek_r1_1_5b_fsdp2.sh](../run_math_deepseek_r1_1_5b_fsdp2.sh) 默认使用 V1 同步 trainer、FSDP2 student 和共池冻结 FSDP2 teacher。数学设置参考 One-Shot-OPD 当前可执行配方：DeepSeek-R1-Distill-Qwen-1.5B student、JustRL-DeepSeek-1.5B teacher、完整 DAPO 数据、sampled-token `k1 + PG`、batch 与 mini-batch 均为 64、每批一次更新、AdamW 学习率 1e-6。该默认路径在 loss 中构造 current-policy advantage，未启用 frozen 信号；current/frozen 对照由[优势与 IS 消融入口](opd-objective/2026-10-21-优势与IS消融及更新计数实现方案.md)提供。默认配方不能称为原研究实现的完整等价复现。

默认资源与长度：

| 项目 | 默认值 |
| --- | --- |
| 共享资源池 | 8 张 GPU；rollout、teacher 评分、actor 更新分阶段使用 |
| Student rollout | TP=1，共 8 个推理副本，验证复用 |
| Student 执行模式 | 默认编译＋CUDA Graph；`ROLLOUT_ENFORCE_EAGER=True` 可回退 eager |
| Teacher | FSDP2 DP8，无 optimizer，整批评分后卸载到 CPU |
| Prompt / 训练 response | 4096 / 7168 token |
| 验证 response | 31744 token |
| Student 最大 context / teacher forward 预算 | 35841 / 每卡 32768 token；teacher 预算必须容纳完整训练序列 |
| 验证集 | MATH-500、AMC23、AIME25；500 + 40 + 30 题 |
| 验证采样 | 每题 16 次，temperature=0.7、top-p=0.9 |
| 验证提交窗口 / 推理并发 | 数学全量提交（`VAL_BATCH_SIZE=null`）；每个 student 推理副本最多 128 条序列 |
| 推理显存比例 / 调度token预算 | 数学0.65 / 8192；均为每引擎配置 |
| Actor 动态 micro-token 预算 | 每卡 32768，按完整 prompt＋response 拆分并累积梯度 |
| 采样概率输出 | 训练保留；验证省略未用于评分的概率输出 |
| 训练预算 | 1 epoch；全量 17917 条数据未过滤时约 279 steps |
| 验证 / 保存间隔 | 20 / 50 global steps，并在最后一步触发 |

默认训练 1 epoch。当前 17917 条 DAPO 的 prompt 均未超过 4096，过滤后仍是 17917 条；V1 trainer 按 `floor(17917 / 64) = 279` 计算步数，最后不足一个 batch 的 61 条不参与这个 epoch。每步全局采样 64 道题，每题生成 1 条回答；`ppo_mini_batch_size=64`、`ppo_epochs=1`，每步做一次全局参数更新。64 是整个 student 资源池的 batch；8 个 student 训练 rank 平均各处理 8 条，内部动态 token batching 与梯度累积按实际序列长度安排。

验证发生在 step 20、40、……、260 和最终 step 279，共 14 次；`val_before_train=False`，训练前不额外验证。每次完整覆盖 MATH-500 的 500 题、AMC23 的 40 题、AIME25 的 30 题，合计 570 题，每题采样 16 次，共生成 9120 条回答。`VAL_BATCH_SIZE=null`默认一次提交全部570道题。正整数值可恢复窗口提交；实际同时运行的请求数受每个推理副本`max_num_seqs=128`约束，八卡合计上限1024。提交窗口与引擎活跃并发是不同参数。每条验证回答最多 31744 token。checkpoint 保存于 step 50、100、150、200、250、279。

Student Graph 的 capture sizes 根据 `ROLLOUT_MAX_NUM_SEQS` 派生为2的幂并包含最后的并发上限；数学默认是 `[1,2,4,8,16,32,64,128]`。仍可通过末尾 Hydra 参数覆盖现有 `actor_rollout_ref.rollout.cudagraph_capture_sizes` 字段。训练 batch64 和更新预算保持不变；早期测量使用 eager、验证窗口16，复算时以对应运行的冻结配置为准。

默认值的本机验证依据见[完整验证实测](infra/2026-10-22-训练与验证性能实测.md#1-完整验证与参数对照)；batch128/256的学习配置边界与验证窗口建议见[批量与rollout调优](infra/2026-10-22-批量大小与GPU利用率调优.md)。全量验证已完成H800四卡初始checkpoint测量；新默认在目标八卡上的完整训练/验证周期仍须独立验收。

共享/独立池的角色、卸载要求与覆盖参数见[运行与架构](infra/2026-10-22-共享八卡运行与架构.md#共享与独立池配置)。选择部署方式时保持本页的学习与评测预算不变。

脚本将常用环境变量集中在前半部分，按模型与数据、GPU、训练与验证预算分组；原生 Hydra 参数按 data、actor、rollout、validation、distillation、algorithm、trainer 分成数组，最后统一组装。通常改顶部默认值或使用环境变量即可；新增原生配置放入对应数组。

模型默认从仓库相邻的 `model/` 读取，数据默认从相邻 `data/` 读取；可用 `MODEL_ROOT`、`DATA_ROOT` 或各文件变量覆盖。目录、准备与检查入口见[资产准备](资产准备.md)。数据文件分别是 `math/DAPO/train.parquet`、`math/MATH-500/test.parquet`、`math/AMC23/test.parquet` 和 `math/AIME25/test.parquet`。

从仓库根目录、在已分配的 GPU 与原生环境中运行数学入口：

```bash
bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh
```

GPU 分配、shared/standalone 切换、配置预览见[启动与配置](infra/2026-10-22-共享八卡运行与架构.md#启动与配置)；Python、运行目录、日志、恢复与人工部署约定见[通用运行合同](infra/2026-10-22-共享八卡运行与架构.md#通用运行合同)。

### Actor 执行配置

以下是公共数学配方继承的执行默认，学习预算与计算拆分分别维护。参数作用及候选测试见[调优文档](infra/2026-10-22-批量大小与GPU利用率调优.md#73-actor-重算micro-与梯度同步联合筛选)。

| 调优项 | 公共数学配方的解析值 | 实现与边界 |
| --- | --- | --- |
| `GRADIENT_CHECKPOINTING` | True | 调用 HF `gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})`；没有逐算子 selective-AC 的配方入口 |
| `PPO_MAX_TOKEN_LEN_PER_GPU` | 32768 | Actor 动态 micro token 预算；与训练 global mini64 分开 |
| `actor.fsdp_config.fsdp_size` | -1 | 默认使用整个 actor world size 分片 |
| `actor.fsdp_config.use_no_sync_for_gradient_accumulation` | False | 实现允许只在最后一个 micro-batch 同步梯度；当前配方关闭 |

## 独立验证长度

新增 `actor_rollout_ref.rollout.val_kwargs.max_tokens`，默认 `null`，保留原有训练/验证共用 response budget 的行为。非空时，验证请求和最终 response、mask、log-prob、router replay 输出使用同一预算；V1 的 TQ 保存未 padding 的实际输出，旧 DataProto 路径按验证预算 padding。

当前支持 vLLM/SGLang 的 `single_turn_agent`；本配方使用 vLLM。配置或数据行选择其他 agent 时会拒绝独立验证预算，避免多轮 agent 静默沿用训练上限；会覆盖请求长度的其他后端也会被配置检查拒绝。应显式配置足以容纳 prompt 与验证预算的 `rollout.max_model_len`；底层服务仍受模型 context 和显存约束。该设置不改变 teacher 的训练评分长度。

ResOPD 的公开版本 `3bdf019d` 只设置一个 `MAX_RESPONSE_LENGTH`，没有这条独立验证长度配置；本配方不依赖它的启动脚本。[^resopd]

| Profile | `VAL_BATCH_SIZE` | `ROLLOUT_MAX_NUM_SEQS` | `ROLLOUT_GPU_MEMORY_UTILIZATION` | `ROLLOUT_TOKEN_BUDGET` |
| --- | --- | ---: | ---: | ---: |

## 采样消融与长程复用

所有 E 系列使用 [run_math_opd_ablation_fsdp2.sh](../run_math_opd_ablation_fsdp2.sh)，下表是编号与算法的唯一配方映射。`rollout` 信号使用生成时的行为 log-prob，不自动等于训练端冻结锚点信号。

| 短程编号 | 长程编号 | `advantage_source` | `policy_loss_mode` |
| --- | --- | --- | --- |
| E1 | E7 | `rollout` | `token_ppo` |
| E2 | E8 | `rollout` | `token_is` |
| E3 | E9 | `current` | `token_ppo` |
| E4 | E10 | `current` | `token_is` |
| E5 | E11 | `current` | `reinforce`，NoIS |
| E6 | E12 | `rollout` | `reinforce`，NoIS |

| 预设 | `PPO_EPOCHS` | 外层 step | 验证间隔 | 保存间隔 | 无跳步时 optimizer 更新数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| E1–E6 | 4 | 32 | 末步 | 末步 | 128 |
| E7–E12 | 16 | 200 | 50 | 100 | 3200 |
| E13–E15 | 1 | 200 | 20 | 100 | 200 |
| E16 | 4 | 200 | 20 | 100 | 800 |
| E17 | 16 | 200 | 20 | 100 | 3200 |

间隔均按外层 step 计；各组默认 batch=mini-batch=64、每题 1 条回答、不做初始验证、constant LR 与零 warmup，D=0 表示没有延迟队列。E7–E12 的 16 次批内复用不等于 D=16。E1–E12 沿用数学学习率，E13–E17 的学习率见下一节；各 mode 的 clipping 和支持限制见[实现合同](opd-objective/2026-10-21-优势与IS消融及更新计数实现方案.md#3-配置契约只增加一个字段扩展一个已有枚举)。

环境变量可覆盖预设预算，末尾 Hydra 参数优先级最高；应以实际 optimizer 更新数比较。每次调用独立启动一个 run，不自动连续执行其他编号。资源覆盖和 checkpoint 恢复见[运行与架构](infra/2026-10-22-共享八卡运行与架构.md#验证执行配置与四卡八卡启动)。

## Full-KL 与 sampled 对照入口

E13–E15 比较一次更新下的 full-KL 与 sampled；E16/E17 比较 Full-KL 的批内复用次数。公共预算见[采样消融与长程复用](#采样消融与长程复用)。

| 编号 | 目标 | 默认学习率 | 每批更新次数 |
| --- | --- | ---: | ---: |
| E13 | Full-vocab reverse KL | 1e-6 | 1 |
| E14 | Full-vocab reverse KL，半学习率消融 | 5e-7 | 1 |
| E15 | 原 sampled-token k1 + current signal + vanilla PPO | 1e-6 | 1 |
| E16 | Full-vocab current + IS，批内复用 | 1e-6 | 4 |
| E17 | Full-vocab current + IS，批内复用 | 1e-6 | 16 |

E13/E14 的默认配置只在学习率上不同。E13–E17 保留最近两份 checkpoint，训练/验证长度及采样沿用数学配方；默认 seed=42，并将数据、actor 与 rollout 的 seed 同步到 `SEED`。

E13/E14/E16/E17 复用 [full-KL 入口](../run_full_reverse_kl.sh)，默认 `precompute`、异步写入和预取开启；可用 `FULL_KL_BACKEND`、`FULL_KL_TOKEN_CHUNK`、`FULL_KL_VOCAB_CHUNK`、`FULL_KL_ASYNC_WRITE`、`FULL_KL_PREFETCH` 覆盖，支持边界与验收见 [full-KL 实现文档](full-vocab/2026-10-22-Full-KL实现与验收.md)。这四组要求 shared-sync。E15 使用原 vanilla loss，不改为 E4 的行为 token IS；默认调度仍为共享八卡，不是历史 4+4 部署的完全复刻。

各实验独立申请八卡后，从仓库根目录运行；`CUDA_VISIBLE_DEVICES` 使用调度器分配的值，原生 Python 和资产路径沿用公共配置：

```bash
STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E13
STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E14
STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E15
```

只有两个实验名额时，探索性比较可先选 E13/E14；需要同版本 sampled 对照时选 E13/E15。一次更新对照可再补 `SEED=43` 的 E13/E15；批内复用使用下面的 E16/E17。

```bash
# 重复种子，或显式覆盖学习率/预算；末尾 Hydra 参数优先级最高。
SEED=43 STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E13
LEARNING_RATE=7e-7 TOTAL_TRAINING_STEPS=100 \
  bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E14
```

这些是默认预设，`PPO_EPOCHS` 等环境变量仍可覆盖；覆盖后应按实际 optimizer 更新数比较。集群 rollout backend 沿用当地已验证配置，不自动写入本机 smoke 使用的 TRITON_ATTN。已排的本机后台队列使用冻结 checkout，不会因增加这些入口自动改变。

### Full-KL current + IS 批内复用

E16/E17 复用已有 `full_reverse_kl`，分别将 `PPO_EPOCHS` 默认设为 4/16。它们与 E13 只在复用次数上不同：200 个外层 step、全局 batch=mini-batch=64、LR=1e-6、验证每 20 步、保存每 100 步、保留最近两份 checkpoint。无跳步时分别更新 800/3200 次；这是 D=0 的同批复用，不是延迟旧轨迹。

这里 current + IS 指固定前缀下精确积分的梯度对应关系，见[全词表四种更新](theory/2026-10-22-Full-vocab计算图与四种更新.md#four-cases)。配置仍为 `use_policy_gradient=False`、`policy_loss_mode=vanilla`，不额外乘 sampled token ratio、不使用 PPO clip，也不新增 anchor、NoIS 或 frozen 分支。Optimizer 原有的梯度范数裁剪保持不变。

从仓库根目录，在各自分配的八卡作业中运行：

```bash
# 同批更新 4 次。
STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E16

# 同批更新 16 次。
STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E17

# 只打印启动配置，不加载模型或启动训练。
DRY_RUN=1 STUDENT_GPUS=8 bash examples/mirroropd/run_math_opd_ablation_fsdp2.sh E17
```

默认 backend 仍为 `precompute`，async write/prefetch 开启；可显式设置 `FULL_KL_BACKEND=precompute_fused`，但对照组应保持同一 backend。四卡作业同时设置 `CUDA_VISIBLE_DEVICES=0,1,2,3 STUDENT_GPUS=4`；Python、模型和数据路径使用目标机器配置。`PPO_EPOCHS` 仍可覆盖默认值。

E13/E16/E17 固定生成预算，optimizer 更新预算不同。与 sampled E4/E10 比较时，还应对齐外层步数、验证频率和种子等设置；不能只按实验编号比较训练耗时。

## Coding 与 IF 训练入口

三个领域共用 [\_run_single_teacher_fsdp2.sh](../_run_single_teacher_fsdp2.sh)，默认均为 DeepSeek-R1-Distill-Qwen-1.5B student、共享八卡、student TP=1 和 sampled-token `k1 + PG`。训练 batch 与 loss 保持原设置。coding 与 IF 的模型、训练数据和验证方式参考 One-Shot-OPD 的 `recipe/opd.sh`。[^oneshot]

| 入口 | Teacher | 训练数据 | 训练期间验证 |
| --- | --- | --- | --- |
| [math](../run_math_deepseek_r1_1_5b_fsdp2.sh) | `JustRL-DeepSeek-1.5B` | `math/DAPO/train.parquet` | MATH-500、AMC23、AIME25 |
| [coding](../run_code_deepseek_r1_1_5b_fsdp2.sh) | `DeepCoder-1.5B-Preview` | `code/TACO/train.parquet` | `code/LCBv6/test.parquet` |
| [IF](../run_if_deepseek_r1_1_5b_fsdp2.sh) | `UltraData-IF-1.5B` | `if/MultiIF/train.parquet`，第一轮 | 关闭；正式 MultiIF 需要独立三轮评测 |

模型默认放在仓库同级 `model/`，数据默认放在同级 `data/`；已有目录可用 `MODEL_ROOT`、`DATA_ROOT` 指定。coding 可用 `CODE_VAL_FILE` 选择另一份单轮验证 parquet。现有 `prepare_models.py`、`prepare_math_data.py` 和 `make assets-check` 仍用于数学资产；coding / IF 的 teacher 和 parquet 需要另行准备。训练启动前会检查选中领域的数据文件。

```bash
bash examples/mirroropd/run_code_deepseek_r1_1_5b_fsdp2.sh

OPENCOMPASS_ROOT=/共享目录/opencompass NLTK_DATA=/共享目录/nltk_data \
  bash examples/mirroropd/run_if_deepseek_r1_1_5b_fsdp2.sh
```

IF 默认设置 `data.val_files=[]`、`TEST_FREQ=-1` 和 `trainer.val_before_train=False`，不会把三轮数据当作单轮验证。V1 支持这种只训练的配置；空验证列表配合启用验证的选项会报错。MultiIF checker 仍会对训练回答计算诊断分数，因此 IF 启动时会检查 `OPENCOMPASS_ROOT` 并加载 checker；该变量和可选的 `NLTK_DATA` 会显式传给 Ray worker。依赖见[判分器与依赖](判分器与依赖.md)。完整三轮生成程序尚未迁入本仓，不能把训练分数当作正式 MultiIF 评测结果。

coding / IF 即使关闭 task reward 对 loss 的贡献，仍会计算 verifier 诊断分数。coding 的 `gen` 还包含 CPU 测试执行成本；LCB runner 的全局等待预算包含新进程启动时间，部署前应使用已知正确的小程序检查判分环境。数学的采样耗时不能直接外推到这两个领域。

Hope 仍通过 `make opd-submit` 提交，worker 直接调用带领域前缀的配方，默认 math。`.hope` 的一次性迁移、DOMAIN 设置与预检边界见[Hope 直连入口](infra/2026-10-22-共享八卡运行与架构.md#hope-直连入口)。
