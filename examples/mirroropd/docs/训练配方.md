# Math、Coding 与 IF 训练配方

统一提交入口是 `make opd-submit`，Hope worker 通过 `worker.script` 直接调用领域脚本，领域由 `DOMAIN=math|code|if` 选择。命令均从仓库根目录执行。

## 单教师数学 full-data 配方

[run_math_deepseek_r1_1_5b_fsdp2.sh](../run_math_deepseek_r1_1_5b_fsdp2.sh) 默认使用 V1 同步 trainer、FSDP2 student 和共池冻结 FSDP2 teacher。数学设置参考 One-Shot-OPD 当前可执行配方：DeepSeek-R1-Distill-Qwen-1.5B student、JustRL-DeepSeek-1.5B teacher、完整 DAPO 数据、sampled-token `k1 + PG`、batch 与 mini-batch 均为 64、每批一次更新、AdamW 学习率 1e-6。目前仍采用主线在 loss 中构造的 current-policy advantage；未加入 frozen-reward 分支，不能称为原研究实现的完整等价复现。

默认资源与长度：

| 项目 | 默认值 |
| --- | --- |
| 共享资源池 | 8 张 GPU；rollout、teacher 评分、actor 更新分阶段使用 |
| Student rollout | TP=1，共 8 个推理副本，验证复用 |
| Student 执行模式 | 默认编译＋CUDA Graph；`ROLLOUT_ENFORCE_EAGER=True` 可回退 eager |
| Teacher | FSDP2 DP8，无 optimizer，整批评分后卸载到 CPU |
| Prompt / 训练 response | 4096 / 7168 token |
| 验证 response | 31744 token |
| Student 最大 context / teacher forward 预算 | 35841 / 每卡 32768 token；teacher 预算必须容纳完整训练序列 |
| 验证集 | MATH-500、AMC23、AIME25；500 + 40 + 30 题 |
| 验证采样 | 每题 16 次，temperature=0.7、top-p=0.9 |
| 验证提交窗口 / 推理并发 | 数学每窗口 128 题；每个 student 推理副本最多 64 条序列 |
| 采样概率输出 | 训练保留；验证省略未用于评分的概率输出 |
| 训练预算 | 1 epoch；全量 17917 条数据未过滤时约 279 steps |
| 验证 / 保存间隔 | 20 / 50 global steps，并在最后一步触发 |

默认训练 1 epoch。当前 17917 条 DAPO 的 prompt 均未超过 4096，过滤后仍是 17917 条；V1 trainer 按 `floor(17917 / 64) = 279` 计算步数，最后不足一个 batch 的 61 条不参与这个 epoch。每步全局采样 64 道题，每题生成 1 条回答；`ppo_mini_batch_size=64`、`ppo_epochs=1`，每步做一次全局参数更新。64 是整个 student 资源池的 batch；8 个 student 训练 rank 平均各处理 8 条，内部动态 token batching 与梯度累积按实际序列长度安排。

验证发生在 step 20、40、……、260 和最终 step 279，共 14 次；`val_before_train=False`，训练前不额外验证。每次完整覆盖 MATH-500 的 500 题、AMC23 的 40 题、AIME25 的 30 题，合计 570 题，每题采样 16 次，共生成 9120 条回答。`VAL_BATCH_SIZE=128` 是每次向推理端提交 128 道题的窗口，最多展开为 2048 条回答请求；实际同时运行的请求数还受每个推理副本 `max_num_seqs=64` 约束，提交窗口与引擎活跃并发是不同参数。每条验证回答最多 31744 token。checkpoint 保存于 step 50、100、150、200、250、279。

Student Graph 的 capture sizes 根据 `ROLLOUT_MAX_NUM_SEQS` 派生为2的幂并包含最后的并发上限；数学默认是 `[1,2,4,8,16,32,64]`。仍可通过末尾 Hydra 参数覆盖现有 `actor_rollout_ref.rollout.cudagraph_capture_sizes` 字段。训练 batch64 和更新预算保持不变；早期测量使用 eager、验证窗口16，复算时以对应运行的冻结配置为准。

默认值的本机验证依据见[本机实测](infra/2026-10-22-训练与验证性能实测.md#3-本机编译与训练优化)；batch128/256的学习配置边界与验证窗口建议见[批量与rollout调优](infra/2026-10-22-批量大小与GPU利用率调优.md)。全量验证和目标八卡性能仍须独立验收。

默认 `DISTILLATION_EXECUTION_MODE=shared_sync`：八个 TP1 student 副本生成整批回答，student vLLM 休眠后，冻结 teacher 在八卡上做 FSDP2 前向并卸载，然后 actor 在八卡上更新。TP 是单个推理副本的张量并行卡数；当前 TP=1，训练 FSDP2 是独立的参数分片配置。共享模式要求 actor 参数与 optimizer offload 开启。

旧路径通过 `DISTILLATION_EXECUTION_MODE=standalone` 保留，默认 student 4 卡、teacher 4 卡；teacher 用 vLLM 对已完成的回答在线评分，可以与其余回答的生成重叠。该模式下 `STUDENT_GPUS` 与 `TEACHER_GPUS` 相加，`TEACHER_GPUS=1` 可配置为 4+1。已上传的 A800 [基线记录](infra/2026-10-22-训练与验证性能实测.md#4-八卡历史与one-shot对照)属于旧路径；共享模式的端到端性能需要在目标环境另做对照。

共享模式中 `STUDENT_GPUS=8` 表示整个池，`TEACHER_GPUS=0` 表示不申请独立 teacher 卡。`TEACHER_FSDP_TOKEN_BUDGET=32768` 控制 teacher 单卡前向的动态 token budget；`TEACHER_FSDP_DTYPE=bfloat16` 同时设置 teacher 权重和前向参数精度。`TEACHER_TOKEN_BUDGET`、`TEACHER_TP`、`TEACHER_MAX_NUM_SEQS` 等 vLLM teacher 参数只在 standalone 生效。回退命令、测试范围和部署要求见[共享八卡运行与架构](infra/2026-10-22-共享八卡运行与架构.md)。

脚本将常用环境变量集中在前半部分，按模型与数据、GPU、训练与验证预算分组；原生 Hydra 参数按 data、actor、rollout、validation、distillation、algorithm、trainer 分成数组，最后统一组装。通常改顶部默认值或使用环境变量即可；新增原生配置放入对应数组。

模型默认从仓库相邻的 `model/` 读取，数据默认从相邻 `data/` 读取；可用 `MODEL_ROOT`、`DATA_ROOT` 或各文件变量覆盖。目录、准备与检查入口见[资产准备](资产准备.md)。数据文件分别是 `math/DAPO/train.parquet`、`math/MATH-500/test.parquet`、`math/AMC23/test.parquet` 和 `math/AIME25/test.parquet`。

```bash
# 仅打印启动命令，不启动 Ray，也不安装依赖。
DRY_RUN=1 bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh

# 只解析 Hydra 配置；默认使用本仓库的 .venv-native/bin/python。
CONFIG_ONLY=1 bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh

# 获得整机 8 张卡的分配、激活原生 Python 环境后运行。
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 VERL_USE_UV=0 \
  bash examples/mirroropd/run_math_deepseek_r1_1_5b_fsdp2.sh
```

默认使用本仓库 `.venv-native/bin/python` 的绝对路径，同时设置 driver 和 Ray worker 的解释器，无需依赖终端是否激活环境。已有其他独立环境可设置 `PYTHON_BIN=/absolute/path/to/python`；环境需具备当前 verl 的 V1/TransferQueue 和 verifier 依赖。上游锁文件环境只在显式设置 `VERL_USE_UV=1` 时启用。正式启动要求显式设置 `CUDA_VISIBLE_DEVICES`，并检查四个 parquet 文件存在。

`RUN_DIR` 必须是新目录，默认在 `outputs/` 下；保存实际命令、Git commit、相对 HEAD 的工作区 patch、解析配置、checkpoint 和验证输出。CLI 末尾参数仍是原生 Hydra overrides。改变训练步数时还要给足 `TOTAL_EPOCHS`，因为外层训练同时受 epoch 与 total step 限制。

正式运行会将 stdout/stderr 同时显示在终端并保存到 `$RUN_DIR/train.log`，默认路径为 `outputs/<实验名>/train.log`。Python 使用无缓冲输出；训练失败时保留非零退出码。启动时打印日志的完整路径，可用 `tail -f <日志完整路径>` 跟踪。`DRY_RUN=1` 和 `CONFIG_ONLY=1` 不创建日志或实验目录。

通过人工源码包部署、没有 `.git` 的目录同样可以启动；此时 `source_commit.txt` 标记版本不可用，`source_changes.patch` 为空。开发机已有本地 Hope 配置时，可通过 `make opd-submit` 提交单机 8 卡任务；`hope/` 不随源码包同步，完整操作见 [Hope 说明](../../../hope/README.md)。

配方默认记录 console 与离线 W&B。SDK 写入根目录固定为本仓库，实际 run 位于 `wandb/offline-run-*/`；Ray 训练进程使用同样的路径和模式。可用 `make sync-log-pack` 打包后人工下载，完整流程见 [美团开发机同步说明](../../../meituan/README.md)。

## 独立验证长度

新增 `actor_rollout_ref.rollout.val_kwargs.max_tokens`，默认 `null`，保留原有训练/验证共用 response budget 的行为。非空时，验证请求和最终 response、mask、log-prob、router replay 输出使用同一预算；V1 的 TQ 保存未 padding 的实际输出，旧 DataProto 路径按验证预算 padding。

当前支持 vLLM/SGLang 的 `single_turn_agent`；本配方使用 vLLM。配置或数据行选择其他 agent 时会拒绝独立验证预算，避免多轮 agent 静默沿用训练上限；会覆盖请求长度的其他后端也会被配置检查拒绝。应显式配置足以容纳 prompt 与验证预算的 `rollout.max_model_len`；底层服务仍受模型 context 和显存约束。该设置不改变 teacher 的训练评分长度。

ResOPD 的公开版本 `3bdf019d` 只设置一个 `MAX_RESPONSE_LENGTH`，没有这条独立验证长度配置；本配方不依赖它的启动脚本。[^resopd]

数学窗口128/并发64的四卡对照见[验证窗口与并发测量](infra/2026-10-22-训练与验证性能实测.md#2-验证窗口筛选与多轮更新基线)。可用 `VAL_BATCH_SIZE=32 ROLLOUT_MAX_NUM_SEQS=32` 回退；Coding/IF 保留这组旧默认，未直接套用数学测量。

## Coding 与 IF 训练入口

三个领域共用 [\_run_single_teacher_fsdp2.sh](../_run_single_teacher_fsdp2.sh)，默认均为 DeepSeek-R1-Distill-Qwen-1.5B student、共享八卡、student TP=1 和 sampled-token `k1 + PG`。训练 batch 与 loss 保持原设置。coding 与 IF 的模型、训练数据和验证方式参考 One-Shot-OPD 的 `recipe/opd.sh`。[^oneshot]

| 入口 | Teacher | 训练数据 | 训练期间验证 |
| --- | --- | --- | --- |
| [math](../run_math_deepseek_r1_1_5b_fsdp2.sh) | `JustRL-DeepSeek-1.5B` | `math/DAPO/train.parquet` | MATH-500、AMC23、AIME25 |
| [coding](../run_code_deepseek_r1_1_5b_fsdp2.sh) | `DeepCoder-1.5B-Preview` | `code/TACO/train.parquet` | `code/LCBv6/test.parquet` |
| [IF](../run_if_deepseek_r1_1_5b_fsdp2.sh) | `UltraData-IF-1.5B` | `if/MultiIF/train.parquet`，第一轮 | 关闭；正式 MultiIF 需要独立三轮评测 |

模型默认放在仓库同级 `model/`，数据默认放在同级 `data/`；已有目录可用 `MODEL_ROOT`、`DATA_ROOT` 指定。coding 可用 `CODE_VAL_FILE` 选择另一份单轮验证 parquet。现有 `prepare_models.py`、`prepare_math_data.py` 和 `make assets-check` 仍用于数学资产；coding / IF 的 teacher 和 parquet 需要另行准备。训练启动前会检查选中领域的数据文件。

```bash
DRY_RUN=1 bash examples/mirroropd/run_code_deepseek_r1_1_5b_fsdp2.sh
DRY_RUN=1 bash examples/mirroropd/run_if_deepseek_r1_1_5b_fsdp2.sh

CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  bash examples/mirroropd/run_code_deepseek_r1_1_5b_fsdp2.sh

OPENCOMPASS_ROOT=/共享目录/opencompass NLTK_DATA=/共享目录/nltk_data \
  CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  bash examples/mirroropd/run_if_deepseek_r1_1_5b_fsdp2.sh
```

IF 默认设置 `data.val_files=[]`、`TEST_FREQ=-1` 和 `trainer.val_before_train=False`，不会把三轮数据当作单轮验证。V1 支持这种只训练的配置；空验证列表配合启用验证的选项会报错。MultiIF checker 仍会对训练回答计算诊断分数，因此 IF 启动时会检查 `OPENCOMPASS_ROOT` 并加载 checker；该变量和可选的 `NLTK_DATA` 会显式传给 Ray worker。依赖见[判分器与依赖](判分器与依赖.md)。完整三轮生成程序尚未迁入本仓，不能把训练分数当作正式 MultiIF 评测结果。

coding / IF 即使关闭 task reward 对 loss 的贡献，仍会计算 verifier 诊断分数。coding 的 `gen` 还包含 CPU 测试执行成本；LCB runner 的全局等待预算包含新进程启动时间，部署前应使用已知正确的小程序检查判分环境。数学的采样耗时不能直接外推到这两个领域。

Hope 仍通过 `make opd-submit` 提交，worker 直接调用带领域前缀的配方，默认 math。`.hope` 的一次性迁移、DOMAIN 设置与预检边界见[Hope 直连入口](infra/2026-10-22-共享八卡运行与架构.md#hope-直连入口)。
