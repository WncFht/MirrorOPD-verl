# 模型与数学数据准备

本文记录数学资产的准备、目录与 CPU 检查范围。命令均从仓库根目录执行。

| 脚本 | 用途 |
| --- | --- |
| [prepare_models.py](../assets/prepare_models.py) | 导入／下载选定模型，支持单文件和索引分片，物化缓存符号链接；不写模型 manifest |
| [prepare_math_data.py](../assets/prepare_math_data.py) | 导入已有 parquet，或从五个原始文件重建四份数学数据；统一 Arrow schema，写 `math_manifest.json` |
| [check_assets.py](../assets/check_assets.py) | 模型仅检查必要文件；逐行检查数据，统计 prompt 长度、重复与训练/验证题面重叠，写 `asset_check.json` |

在已有资产的机器上，可以离线导入旧目录；路径参数填写该机器的实际绝对路径：

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py \
  --source-root /已有的/models --model-root /目标/model
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py \
  --source-root /已有的/MD-OPD/data --data-root /目标/data
```

原文件保留，目标文件按新目录创建。数据输出已存在时默认拒绝覆盖；确认要重建时显式传 `--overwrite`。模型目标已存在时只检查必要文件并跳过，不覆盖权重。默认仍选择原来的两个 1.5B 模型，约 7.1 GB；`--models all` 选择全部已登记模型（原 A–F 八个及 E48 的 Polaris），也可在 `--models` 后列出具体目录名。2026-10-24 本机已将全部 8 个模型实体放入 `fht_data/model/`，旧 `fht_data/models/` 与上级 `zkn_data/models/` 保留作原始来源，其他项目的引用不受影响。

从原始数据重建时使用 `--raw-dir`；源目录包含 `dapo-math-17k.parquet`、`math500_test.jsonl`、`amc23.parquet`、`aime2025-I.jsonl`、`aime2025-II.jsonl`。转换沿用固定 MD-OPD 的数学规则：DAPO 按源 `extra_info.index` 保留第一次出现，去掉原始 Answer 格式包装；AMC/AIME 与 MATH-500 保留各自题面和答案，AIME 按 I、II 顺序合并。[^math-prep]

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py --raw-dir /原始文件目录

# 仅在能访问外网的机器上显式下载；不会安装新的 Python 包。
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download
# 准备全部已登记模型，或用 --models 指定其中几个；已有目标只检查并跳过。
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download --models all
.venv-native/bin/python examples/mirroropd/assets/prepare_math_data.py --download
```

原有两个模型下载固定为 DeepSeek `ad9f0ae0`、JustRL `0637e409`；新增六个模型当前使用对应官方 Hub 仓库的默认 revision，不能把浮动 revision 当作固定快照。[^student-model] [^teacher-model] 数据下载使用 ModelScope 的上述原始数据镜像，镜像 revision 为 `master`；manifest 记录来源与数据行数。重复实验应保留原始文件，不把浮动镜像 revision 当作不可变版本。

E48 另使用 `POLARIS-Project/Polaris-7B-Preview`，本地目录名为 `Polaris-7B-Preview`。2026-10-26 起模型目录支持该模型，`--models all` 包含原 A–F 八个模型及 Polaris，共九个。单独准备：

```bash
.venv-native/bin/python examples/mirroropd/assets/prepare_models.py --download --models Polaris-7B-Preview
```

准备完成后在开发机执行：

```bash
make assets-check
# 检查全部已登记模型：
make assets-check ASSET_CHECK_ARGS="--models all"
# 只检查数据，不要求模型已到位：
make assets-check ASSET_CHECK_ARGS=--data-only
```

模型检查要求三个配置／tokenizer JSON 存在、非空且可解析。权重支持 `model.safetensors`，或者 `model.safetensors.index.json` 引用的全部分片；缺少任意一个分片都会报错。`generation_config.json` 是可选文件，缺少时不报错；准备脚本在来源中有该文件时会保留它。检查不读取完整权重或逐张量核对，也不计算文件摘要。student tokenizer 仅用于计算数据 prompt 长度；`--data-only` 跳过模型和 tokenizer，不计算 token 长度。

检查要求四份数据分别为 17917、500、40、30 行，五个字段及嵌套类型一致；每行必须有非空 user prompt、正确 `data_source`、`ability=math`、非空字符串答案、`style=rule`、正确 split 和唯一 `extra_info.index`。直接检查实际 parquet 内容，不依赖 manifest。prompt 长度使用 student 的 chat template 和 generation prompt 计算；超过限制的数量会报告，训练端仍按 `filter_overlong_prompts` 处理。这些检查确认数据格式与训练入口兼容，不能判定题目的标准答案是否正确。

重复题面和训练/验证交集只报告，不自动改变配方。2026-10-20 本机重建的 18487 行与既有数据逐行一致；DAPO 有 662 行重复题面，与 MATH-500、AMC23、AIME25 分别有 2、5、0 道完全相同的题面。完整词面匹配不是语义去污染；若要删除重叠，应另建数据版本和对照实验。

同次 CPU 检查确认四份数据的最大 prompt 长度分别为 1493、796、220、258 token，均未超过 4096；没有执行 GPU 训练。

模型和数据需要另行上传一次，不进入 `make archive-pack` 的源码包。数据传输包应包含顶层 `data/`，在开发机解压到上述 `fanghaotian/` 基目录后再运行检查；这类资产包使用普通 `tar -xzf ... -C <基目录>`，不使用会保护运行目录的源码 `archive-unpack`。
