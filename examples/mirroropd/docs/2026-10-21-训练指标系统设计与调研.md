# 训练指标系统设计与调研

日期：2026-10-21。状态：待实施设计，本文和配套数据已经落盘；训练指标实现尚未按本方案修改。代码审计基点为 `f807da825`。文中新增字段、接口、配置和提交阶段均为拟议内容，不代表当前启动脚本已经支持。

本方案面向 MirrorOPD-verl 的策略优化与蒸馏训练，保留八类指标，不收缩为 train/rollout/eval/perf 四组。分类用于表达指标含义；更新、数据批次、评估和系统时间区间用于表达采集范围。两者独立，指标名称不包含 inner 编号。统计底层以 verl 的 State-based metrics 方案为主要参考，记录与后端适配参考 NeMo RL；AReaL 和 slime 提供局部实现依据。

## 1. 设计决策

| 项目 | 决定 |
| --- | --- |
| 指标分类 | 优化与损失、策略分布、优势信号、更新修正、蒸馏关系、数据与采样、评估、系统效率，共八类 |
| 策略 pair | 固定支持 current/behavior、anchor/behavior、current/anchor；每组有明确角色，不自动枚举所有分布组合 |
| IS 记录 | 原始概率比、应用后的非负权重、实际 score 梯度系数分别定义 |
| 每组统计量 | 共用四个 log-ratio 基础统计；根据 pair 的用途增加权重统计、分位数或 K3 |
| 记录粒度 | 一次 optimizer 更新尝试一条记录；入口重算每批一条；评估关联 checkpoint；系统时间保持原有范围 |
| 进度 | 复用现有 outer、更新尝试、成功更新计数，增加 PPO epoch/mini-batch 位置作为上下文 |
| 统计实现 | 可合并状态；空间合并和时间汇总分开；旧 loss contribution 的 DP 语义保持兼容 |
| 输出 | 复用 Tracking 和现有后端；W&B 写入序号与训练计数分离；结构化文件保留完整坐标 |
| 开销 | 基础标量每次更新；分位数低频；固定 prefix 和样本诊断按需开启 |
| 当前实施边界 | 先覆盖 FSDP2、V1 sync、sampled-token E1–E6；通用接口可扩展，其他后端和算法逐项验收 |

首版不改变 loss、clip、IS、advantage、采样策略、学习率调度、验证预算和参数同步节奏。长度触顶作为数据上下文记录，不作为当前 OPD 稳定性的主要告警。现有全词表 entropy 继续保留。

### 2.3 当前设置与未来适用范围

[validate_sampled_token_distillation](../../../verl/utils/config.py) 当前要求 E 系列使用 V1 sync、FSDP2、单轮、温度 1、top-p 1、无 top-k 截断，并关闭额外 rollout IS/RS、参考 KL 和 score centering。数学域普通启动器仍有 legacy vanilla 路径，不能把 E 系列分母语义套给所有已有 run。

本方案为异步、GRPO、PPO、混合任务和多教师保留接口，但不通过放宽现有校验自动支持这些组合。每个新增适配器必须明确概率身份、数据支持、loss mask、归一化及执行状态来源。

## 4. 训练循环、进度与测量时刻

典型层次是 outer → 消费 train batch → PPO epoch → mini-batch/update attempt → micro-batch accumulation。同步 E 系列的 parameter_sync_step=1，outer 与本批消费一一对应；通用 V1 中不能假定这一关系。

| 上下文字段（拟议） | 含义与维护方式 |
| --- | --- |
| `progress/outer_step` | 所属外层轮次，映射现有 global_steps；begin 记录可指向正在执行的轮次 |
| `progress/update_attempt` | 累计更新尝试次数，复用现有 attempts；micro-batch 和 DP 不增加它 |
| `progress/optimizer_step` | 该事件完成后的累计成功更新数，复用现有实际计数 |
| `policy_update_before` | 本次 forward 对应的成功更新进度；用于解释 ratio 和 age |
| `update_applied` | true/false/unknown；未知不能当作成功或零 |
| `train_batch_id` | 在 run/session 范围内识别所消费的批次 |
| `ppo_epoch_index`、`mini_batch_index` | 从 0 开始的局部位置；不是贯穿 run 的横轴 |
| `data_epoch` | 数据集遍历位置，保持与 PPO epoch 区分 |
| `behavior_version`、`anchor_version` | 概率所属版本；可附对应成功更新数，未来用于真实 age |
| `checkpoint_id`、`session_id` | 评估对象和日志会话；支持恢复与离线关联 |

字段属于记录上下文，默认隐藏自动生成的计数面板。每条记录明确 `event_type`：batch_begin、optimizer_update、outer_summary、evaluation 或 probe。系统时间区间沿用现有追踪设施。

在无过滤、整除且每批遍历相同次数时，配置预期为：

$$
N_{\mathrm{attempt},b}=E_{\mathrm{PPO},b}\frac{B_{\mathrm{rollout},b}}{B_{\mathrm{mini},b}}.
$$

实际计数取执行事实。64/64×4 epochs 与 256/64×1 epoch 都有四次更新，但每条 response 的复用次数不同，局部 epoch/mini-batch 必须保留。optimizer 调用成功表示该后端执行了 step，不保证每个参数数值都发生变化。

### 4.1 Age 的定位

当前同步、同批四次成功更新时，更新前 age 为 0/1/2/3，属于执行条件。首版不额外建立 age mean/p95/p99 面板。需要排查数据管线时，用生成权重对应的成功更新数与 `policy_update_before` 相减。异步版本混合、partial rollout 或多次同步时，再增加实际年龄分布；只有版本范围时报告上下界，不能补造精确 token age。

### 4.2 恢复与预算

复用 `trainer_state.json` 中的 outer/attempts/successful counts；旧 checkpoint 缺失的绝对计数继续标记未知。PPO epoch/mini-batch 仅是事件位置，首版仍在 outer checkpoint 边界恢复，不宣称支持批内恢复。日志进度可能领先最后一个 checkpoint，续训不能把重复计算当作新的模型版本；默认新 session 并关联恢复来源，同一云端 run 的续接另做明确配置。

预算字段按实际数据边界定义：已消费的新 rollout response token 数每批计一次，训练 token observations 每次更新计一次。前者不是异步系统已生成但尚未消费的数据总量；若需 producer 生成量，由 rollout 侧另行计数。prompt token、response token、复用次数不混为同一个 total_tokens。

## 5. 八类指标目录

以下为新语义目录。旧字段继续兼容，默认面板显示一套口径；指标种类与采集事件互相独立。通用指标不因首个接入算法是 OPD 而放入 distill 命名空间。

| 类别 | 拟议前缀 | 核心定义 | 可选内容 |
| --- | --- | --- | --- |
| 1. 优化与损失 | `optim/<role>/*`、`loss/<component>` | lr_used、grad_norm_preclip、grad_clip_scale、update_applied、实际 loss component | 参数更新范数、分层梯度；critic 仅有该角色时启用 |
| 2. 策略分布 | `policy/<pair>/*`、`policy/entropy/*` | 三个 pair 的分级统计；现有更新前 entropy | 参考策略 pair、固定 prefix probe、位置/confidence 分桶 |
| 3. 优势信号 | `advantage/<component>/*` | mean、abs_mean、rms、positive_fraction、zero_fraction | 处理前优势；按任务或正负分组 |
| 4. 更新修正 | `correction/<mechanism>/*` | 实际 PPO clip、guard、IS/RS 处理和系数变化 | dual clip、CISPO、额外 correction 各有适配器 |
| 5. 蒸馏关系 | `distill/*` | current/rollout advantage 差、符号翻转、带权翻转、来源切换系数差 | teacher/student top-k mass、overlap、tail、full-vocab KL |
| 6. 数据与采样 | `data/*`、`rollout/*` | 数量、有效 token、score/reward、失败率、长度、turns | 有限 data_source 分组、样本明细关联 |
| 7. 评估 | `eval/<dataset>/*` | 主要准确率、题数/回答数/失败数、协议和 checkpoint | pass@k/majority、按题结果、置信区间、OOD |
| 8. 系统效率 | `perf/*`、`timing/*`、`memory/*` | 阶段耗时、吞吐、MFU、资源峰值和负载 | queue、service、细粒度 profiler；复用已有设施 |

`<role>`、`<component>`、`<pair>`、`<mechanism>` 都来自有限配置集合，不允许每条样本动态创建新 metric key。混合 RL+OPD 分别维护 task/distillation advantage component；同一 component 的统计工具通用，但单位和来源随配方记录，幅度不能无条件跨算法排名。

### 5.1 精简与兼容

保留完整八类，精简的是各类内部的重复统计：新核心集合不同时要求 K1 与 signed log-ratio mean、K2 与 M2、同义 score/reward/acc 的所有展开、PPL 与 log-PPL 的全部衍生量。旧字段不在本次静默删除；新字段的默认面板隐藏兼容别名。`critic/advantages` 不重命名成真实 OPD advantage，真实信号直接从算法测量点产生。

val-aux 保持兼容，后续增加独立评估输出档位再控制展开。completion dispersion、bootstrap std、按题均值置信区间和 Bayes posterior SD 用不同字段，不将现有 378 个辅助字段统一解释成置信度。

## 6. 概率角色与 pair 合同

记号遵循[符号约定](符号约定.md)：$\beta$ 为实际行为分布，$q_k$ 为更新前冻结锚点，$p_{k,n}$ 为当前学生，$T$ 为冻结教师。代码角色名分别为 behavior、anchor、current、teacher。行为 IS 使用 $w$，不占用核心稿中教师/锚点比值的 $\rho$。

| 角色 | 对应输入 | 时间属性 |
| --- | --- | --- |
| behavior / $\beta$ | `rollout_log_probs` | 生成时记录，随 response 保存 |
| anchor / $q_k$ | `old_log_probs` | 本批更新前训练引擎重算，批内冻结 |
| current / $p_{k,n}$ | 当前 forward `log_probs` | 每次更新前重算 |
| teacher / $T$ | `teacher_logprobs` | 教师对同一 prefix/token 的评分；权重固定 |
| reference | 可选 `ref_log_prob` | 额外正则参照，身份与 teacher 区分 |

所有比较要求同一 prefix、同一 response token、相同位置对齐；生成分布还需匹配温度、top-p/top-k、repetition penalty 等语义。概率角色是完整的计算/采样合同，只有权重版本一致不保证逐位相等。teacher/student 词表不同的场景需要另外的映射方案，首版不支持直接逐 token 比值。

### 6.1 固定 pair

| Pair 名称 | 比值 | 解释 | 默认事件 |
| --- | --- | --- | --- |
| `current_behavior` | $w_{cb}=p_{k,n}/\beta$ | 当前学生相对真实生成策略的总偏移；E 系列 IS 分母 | optimizer_update |
| `anchor_behavior` | $w_{ab}=q_k/\beta$ | 进入本批训练时已有的偏移 | batch_begin，整批一次 |
| `current_anchor` | $w_{ca}=p_{k,n}/q_k$ | 相对本批冻结锚点的偏移 | optimizer_update |
| `current_reference` | $p_{k,n}/p_{\mathrm{ref}}$ | 可选参考正则诊断 | 仅相应正则启用时 |

教师比较归入 distill 信号，不自动创建 teacher/behavior、teacher/reference 等 IS pair。若以后某算法确实使用 teacher-generated proposal，由该算法显式声明 proposal 身份，不能沿用学生 behavior 的解释。

逐 token 定义 $z_{xy}=\log w_{xy}$，则：

$$
z_{cb}=z_{ca}+z_{ab},\qquad w_{cb}=w_{ca}w_{ab}.
$$

这是输入对齐后的代数恒等式。对相同 token 集合和权重，signed mean 可加；平方均值含交叉项：

$$
\mathbb E[z_{cb}^2]=\mathbb E[z_{ca}^2]+\mathbb E[z_{ab}^2]+2\mathbb E[z_{ca}z_{ab}].
$$

因此不能相加 M2，也不能相乘 p99。默认 anchor/behavior 在整批记录，其他 pair 在当前 mini-batch 记录，连均值也不能直接跨这些不同集合相加。若做分解验算，应在同一更新中重新选取该 mini-batch 的 anchor/behavior token。

当前同步下 anchor/behavior 可作为同权重引擎差异的观察；跨批 stale 时它同时包含已有权重滞后。current/anchor 还可能包含不同 micro-batch、train/eval forward 路径的数值差异，第一次更新前的非零值应保留为基线，不强制置零。

### 6.2 算法与 pair 的关系

| 模式 | 优化实际使用的比值 | 记录要求 |
| --- | --- | --- |
| E1/E3 token PPO | current/behavior，加 PPO clip | 三个可用 pair 按默认档位；clip 声明所用 pair |
| E2/E4 token IS | current/behavior，无 PPO clip | 同上；实际 guard 与 raw ratio 分开 |
| E5/E6 NoIS | 不使用概率比加权 | 仍记录 current/behavior 作为诊断；不输出虚构的恒 1 applied IS 权重 |
| Legacy vanilla | current/anchor，可另有 rollout correction | 独立适配，dual clip 等按真实分支记录，不套 E 系列系数公式 |
| Decoupled PPO | current/anchor 与 anchor/behavior correction | correction 明确来源；clip/截断后不能用原始乘法关系断言目标等价 |
| Bypass | denominator 指向 behavior | anchor 如果只是 behavior 的别名，则不重复输出“零 mismatch”pair；缺失即标不适用 |

## 7. 每个 pair 具体记录哪些指标

### 7.1 统计包定义

对当前观察范围内 $N$ 个有效 token 定义 $z_i=\log w_i$。默认采用 token 等权；sequence-mean 视图是另一统计口径，不能混入同名字段。

| 包 | 字段后缀 | 定义 |
| --- | --- | --- |
| M：基础偏移 | `log_ratio_mean` | $\sum_i z_i/N$ |
| M | `log_ratio_abs_mean` | $\sum_i\lvert z_i\rvert/N$ |
| M | `log_ratio_m2` | $\sum_i z_i^2/N$，不是 $\mathbb E[w^2]$ |
| M | `log_ratio_abs_max` | $\max_i\lvert z_i\rvert$，补充稀少极端值 |
| W：权重分布 | `ratio_mean` | $\sum_i w_i/N$ |
| W | `ratio_ess_fraction` | $(\sum_i w_i)^2/(N\sum_i w_i^2)$ |
| W | `ratio_lt_half_fraction` | $\#\{i:z_i<\log(0.5)\}/N$ |
| W | `ratio_gt_2_fraction` | $\#\{i:z_i>\log 2\}/N$ |
| Q：分位数 | `ratio_p01`、`ratio_p99`、`ratio_p999` | 有效 token 上原始比值的全局分位数 |
| K：KL 对照 | `k3_estimate` | $\sum_i(\exp(z_i)-1-z_i)/N$；适用条件见下文 |

每个 pair 还携带 `token_count`、`nonfinite_fraction`、`status`，Q 包携带 `quantile_method` 与实际参与 token 数。count 可写为标量，方法/状态放结构化记录；覆盖信息不自动生成大量面板。异常统计单独可见。

M2 与 K2 只差因子 2，K1 与 signed mean 只差符号，所以不在新核心集合重复存两套。保留 K3 是为了与已有入口日志对照，而非把每组数学变换都变成常驻字段。

### 7.2 默认与详细档位

| Pair | standard 档位 | detailed 增量 | 频率 |
| --- | --- | --- | --- |
| current/behavior | M + W + Q | K、分布直方图、有限条件分组 | M/W 每次更新；Q 首次及每 8 次累计更新尝试 |
| anchor/behavior | M + K | W + Q | M/K 每批入口；详细 Q 首批及每 8 个 train batch |
| current/anchor | M | W + Q | M 每次更新；详细 Q 首次及每 8 次累计更新尝试 |
| current/reference | 沿用已有实际正则诊断，首版不新建通用面板 | 经适配器验证的 M/Q 或 full-vocab KL | 随正则/probe，默认无额外 forward |

standard 共定义 20 个 pair 统计系列：current/behavior 的 11 个、anchor/behavior 的 5 个、current/anchor 的 4 个；另有覆盖/异常字段。Q 低频，非诊断步缺席。这个数量不随 PPO epochs、mini-batch 数或 DP 卡数增长。4 个是基础 log-ratio 统计，ESS 与分位数主要服务 current/behavior；详细档位才将 W/Q 扩到其他 pair。

频率是拟议默认，可按记录粒度配置；不因为异常发生在未采样步就声称已有分位数证据。基础 abs_max、尾部计数和 M2 每步保留。首版不自动调整采样频率，不增加复杂的自适应监控状态。

### 7.3 估计器与数值语义

ESS/N 是该组非负权重的集中度诊断，不把同一序列中相关 token 当成独立样本来解释统计样本量。对 current/anchor，数据通常来自 behavior，ESS 仍可描述比值集中度，但不能因此声称已经完成合法的分布校正。

K3 在 token 来自分母分布、概率归一化且支持条件成立时，对固定 prefix 的相应 KL 有估计意义。anchor/behavior 与 current/behavior 可在这些条件下解释；current/anchor 的样本通常不来自 anchor，所以默认只用 M，不将 K3 命名为该 pair 的真实 KL。批内复用时模型依赖该批数据，不能额外声称有限样本诊断具有独立验证集的无偏保证。所有 token 级指标都以已访问 prefix 为条件，不自动校正 prefix 分布。

raw 统计在 loss guard、PPO clip、TIS/RS 之前计算。用 FP64 累积必要的和/矩；ESS 通过可合并 log-sum-exp 状态计算：

$$
\log(\mathrm{ESS}/N)=2\operatorname{LSE}(z)-\operatorname{LSE}(2z)-\log N.
$$

ratio mean 由 $\exp(\operatorname{LSE}(z)-\log N)$ 得到。若输出溢出，保留 log-space 证据与 overflow 状态，不静默 clamp 成“原始 ratio”。K3 用 expm1 改善近零精度。有效位置存在非有限输入时，该 pair 的普通数值统计标为不可用，并记录异常比例；不把剔除异常后的值伪装成全量统计。全 mask 范围表示 empty，不是健康的 0。

Q 首版采用全局 nearest-rank：将有效 $z$ 排序，选第 $\max(1,\lceil uN\rceil)$ 个，再取 exp。单调变换下这与同定义的 ratio 分位数一致；不采用“先线性插值 log 分位数再 exp”冒充另一种 quantile 约定。采集点合并真实 token，不能平均各 rank 的 p99。若数据量超过配置的诊断内存上限，报告未测及原因；将来采用抽样/直方图近似时使用新方法标识，不静默改变旧字段精度。

### 7.4 Token、sequence 和 geometric ratio

默认 pair 明确为 token 比值。真实 trajectory ratio 是 $\exp(\sum_t z_t)$，GSPO 风格 geometric ratio 是 $\exp(\frac{1}{L}\sum_t z_t)$，两者不同。sequence 方法启用时使用独立后缀或层级，并按非空 sequence 计数；禁止把广播到 token 上的 sequence 权重当作 token 等权分布重复计数。现有 `chi2_seq` 保留兼容，不进入新默认健康面板。

## 8. 实际 correction、advantage 与 OPD 信号

### 8.1 原始比值、应用权重、梯度系数

| 对象 | 例子 | 记录位置 |
| --- | --- | --- |
| 原始比值 | $w=p/\beta$ | policy/current_behavior |
| 应用的非负权重 | TIS 的 $\min(w,c)$，RS 的 0/1 | correction/rollout_is 或 correction/rs；显式声明 source_pair |
| score 梯度系数 | $wA$ 或 $A$，以及 clip/guard 后的实际系数 | correction 的信号影响统计 |

对显式非负权重，维护 mean、ESS fraction、changed_fraction、zero_fraction；需要时记录归一化因子。全零权重的 ESS 数学上为 0/0，标记 undefined，并用 zero_fraction=1 表达，不伪造正常 ESS。带符号 advantage 或系数不能直接套普通 ESS。

PPO surrogate 激活 clip 的 token，局部 score 梯度系数为零；它不是 `clamp(w)*A`。ratio 越界和实际 clip 激活必须分开。clip active_fraction、上下分支、active_coefficient_mass 与数值 guard 分别记录。旧 dual clip、CISPO 和其他分支需要自己的精确适配，不从相似名字推断梯度。

### 8.2 通用 advantage 统计

每个实际使用的 component 记录 mean、abs_mean、rms、positive_fraction、zero_fraction。默认对象是 normalization/clamp 后真正进入 loss 的信号；处理前视图仅在算法存在该变换时开启。优势与 ratio 共用对齐后的 token，但 source role 和 transform 元数据分开。current/frozen 都接近零时，符号翻转数量不能单独代表重要的学习变化。

### 8.3 E 系列的蒸馏比较

E 系列使用未中心化信号：

$$
A^{\mathrm{cur}}=\log T-\log p,\qquad A^{\mathrm{roll}}=\log T-\log\beta,\qquad A^{\mathrm{roll}}-A^{\mathrm{cur}}=z_{cb}.
$$

这里 frozen 指 rollout 信号，不是 $\log T-\log q_k$；两者只有在 $\beta=q_k$ 时一致。所有 advantage 均按现有 loss 停止梯度。设数值 guard 未触发，忽略共同归一化和负号，未做 PPO clip 的 score 系数为：

$$
c_{\mathrm{E2}}=w_{cb}A^{\mathrm{roll}},\quad c_{\mathrm{E4}}=w_{cb}A^{\mathrm{cur}},\quad c_{\mathrm{E5}}=A^{\mathrm{cur}}.
$$

在同一 forward 上计算两个 counterfactual 诊断：

$$
D_A=\frac{\sum\lvert c_{\mathrm{E2}}-c_{\mathrm{E4}}\rvert}{\sum\lvert c_{\mathrm{E4}}\rvert},\qquad
D_{\mathrm{IS}}=\frac{\sum\lvert c_{\mathrm{E4}}-c_{\mathrm{E5}}\rvert}{\sum\lvert c_{\mathrm{E4}}\rvert}.
$$

$D_A$ 归 distill，$D_{\mathrm{IS}}$ 归 correction。二者是本项目提出的系数差异诊断，不是论文已经验证的预警阈值，也不是完整参数梯度的距离。记录分子、分母和比值；分母为零时比值 undefined，接近零时结合绝对量解释，不靠添加任意 epsilon 制造稳定结果。

对实际 guard，使用 loss 对当前 log-prob 的局部分支导数来构造系数：本项目 clamp 外侧导数为零，边界规则与 PyTorch 实现一致。上述简式只用于 guard 未触发范围；实现时按真实分支处理全部 token，并与 autograd 小例子对照。诊断不改变 loss 或重新执行模型 backward。

蒸馏组还记录 `advantage_abs_diff_mean`、`advantage_sign_flip_fraction`、`advantage_sign_flip_coefficient_mass`。clip 信号占比为实际激活 token 上的未截断绝对系数之和，除以同批全部未截断绝对系数之和。分组依据、基准 component 和 denominator 同样保存。当前任务只做 token 等权版本；其他 loss_agg_mode 需要带入真实 sequence/token 系数，不能沿用同名值。

## 9. 数据流与实现架构

### 9.1 三个边界

```text
算法测量点：明确概率角色、advantage component、mask 和 transform
    ↓ detached 输入
统计状态：本地累积 → 指定并行组合并 → 完成一次观察
    ↓ 已定义的数值/覆盖信息
观察记录：worker 返回逐更新结果，trainer 附加执行进度与版本
    ↓ 单一逻辑写入口
Tracking：W&B / JSONL / TensorBoard / Console
```

系统 span 继续走 profiler/RL-Insight，样本 token 明细走低频诊断文件。两者通过 run/session、batch、参数版本关联，不让普通 metrics 字典承载大张量或全量样本文本。

### 9.2 主要复用与最小扩展

以 `verl/utils/metric` 为统计核心，参考 #5600 的 accumulate/merge/aggregate 生命周期，兼容当前 append/extend 调用。新增原始观察状态与旧 loss contribution 明确分支，不能靠一种 SUM 同时覆盖两种含义。组件仅需少量状态类型：sum/count、可合并 moments、extrema、log-sum-exp、受限分布容器。

静态指标定义表记录 name、单位、采集 scope、reducer、mask/权重口径、默认轴和采集等级。概率比较计算器接收 pair 输入，不自行查找全局配置；算法适配器负责注册哪些 pair/component 存在。首版使用小型 Python 定义表，不引入 DSL、插件发现服务或每个指标一个类。

worker 使用已有 DP 通信边界打包统计状态。先只覆盖 FSDP2、SP=1；TP/CP 后端必须说明一个逻辑 token 在哪些 rank 上复制，按有效 group 和 owner 合并。复制到每卡的全局计数不重复相加。条件分组按语义 key 合并，不要求每卡具有相同数量的局部观测；空 rank 贡献零分子/零分母。

逐更新记录走独立的非张量返回字段 `update_records`，与现有外层 metrics 并存；在进入按名字推断聚合的旧 reducer 之前分流。第一版按 worker 调用批量返回，不增加远端日志 actor。driver 收到后在长验证之前写出逐更新记录。若 worker 在返回前失败，该调用尚未返回的记录可能缺失，首版明确接受此边界，不承诺崩溃前逐步实时上传。

```json
}
```

`event_seq` 只在 session 内递增，用于回读和去重；不是训练横轴。worker 测量时刻可额外保存，但 arrival time 不能替代参数版本。异步评估使用被评估 checkpoint 的进度，即使到达时 learner 已继续训练。

### 9.4 统计与缺测规则

空间合并完成一条观察；时间汇总从观察记录产生，不提前将四次更新压为一个数。时间上的“平均 p99”可以作为单独派生系列，但不称为 pooled token p99。外层若保留新 mean，合并分子分母；若显示最大值，明确为 update 范围最大值。

统计区分生成有效 mask 与实际 loss mask：原始 pair 分布默认在进入该更新的原始有效 response token 上测量，RS 保留比例也以筛选前集合为分母；实际 advantage/系数视图使用 loss 消费的范围并声明分母。当前 E 系列没有 RS，二者一致。不同 mask 的统计不能无标签混合。

缺失、empty、nonfinite、unsupported、skipped_by_schedule 分开处理。JSONL 可写 null 与状态；W&B 对普通不可用值不填零，显式记录有效性/异常状态。诊断采样若引入随机性，使用独立 RNG，不能推进训练或 rollout 的随机数状态。所有统计只观察 detached 数据，不修改共享 mask、log-prob 或 loss tensor。

## 10. 输出、配置与开销

### 10.1 后端与横轴

| 记录 | 默认业务轴 | 附带其他坐标 |
| --- | --- | --- |
| optimizer_update | 累计 update_attempt | successful updates、outer、局部 epoch/mini |
| batch_begin | outer；通用多批场景可选 train_batch 序号 | 入口前成功更新数、数据版本 |
| outer_summary | outer | 累计更新与预算 |
| evaluation | 被评估 checkpoint 的 successful updates | outer、采样预算、评估协议 |
| 固定 prefix probe | 被测参数的 successful updates | probe ID、温度、数据版本 |

八类默认分别显示，不强制折叠成四类。坐标字段默认隐藏。一个 metric key 的观测粒度和默认轴保持固定；同名字段不能在部分 run 表示外层平均、另一些 run 表示单次更新。

W&B 适配参考 NeMo RL：内部 `_step` 自动递增，业务进度写入 data 并以具体 metric name 注册 `step_metric`；不把 inner/outer 混传到 SDK 的 `step=`。标量、验证样例表和 DAPO 表均由同一入口提交，避免表格绕过适配器。每条事件显式附带坐标，禁用依赖前次值的隐式 step 填充。服务端 glob 支持不作为正确性前提。

TensorBoard 按对应事件的业务轴写入，Console 默认只输出外层概览和执行异常，格式按单位设置，LR 使用科学记数法。JSONL 保存完整记录，使用 session 独立文件并保留 checkpoint lineage；不覆盖已有同名日志。初版复用已有 FileLogger 的输出机制与路径约定，扩展 schema/打开方式，不另建存储服务。

W&B 0.28.1 的独立离线可行性检查已回读 8 条更新、2 条外层、2 条验证记录，共 12 条完整 history；这只验证多业务轴写入方式，不代表上述 trainer/worker 改造已经完成或远端面板已经验收。

### 10.2 配置草案

以下字段为拟议配置，不可直接用于当前 launcher。

```yaml
trainer:
  metrics:
    schema: v2
    profile: standard
    update_log_interval: 1
    quantile_update_interval: 8
    quantile_batch_interval: 8
    quantile_max_tokens: 1000000
    write_jsonl: true
    preserve_legacy_metrics: true
```

pair/component 由算法适配器按输入能力启用，不要求用户逐个开十几个布尔参数。standard/detailed 是固定定义集合；频率与算法 correction 开关互不绑定。基础记录每更新默认开启；将来降低写出频率时，本地仍保留哪些记录必须明确，不用静默时间平均冒充逐更新点。

普通配置不新增 teacher 或学生 forward。分位数仅在选定更新保留所需 log-ratio 数据，批量搬到 CPU 并合并，结束后释放；当前 64×7168 最多约 45.9 万 response token，一个 FP32 log-ratio 数组约 1.84 MB，但实际峰值包含排序、复制和并发 buffer，必须测量。不得只依据原始数组大小声称开销可忽略。

固定 prefix probe、full-vocab teacher KL、按层梯度/参数更新统计属于后续可选能力。每项有独立前向/通信成本预算。采集开销计入可观察 timing，不默默从性能统计中扣除；主面板用原始实验 wall time 比较。

## 11. 迁移与实施阶段

| 阶段 | 主要代码位置 | 可审查结果 |
| --- | --- | --- |
| A：统计基础 | `verl/utils/metric/`、CPU/分布式统计测试 | raw state 与 legacy loss contribution 分离；不等长/空分组正确 |
| B：观察记录 | `engine_workers.py`、V1 trainer、tracking | 每次更新记录、真实计数和业务横轴；表格一致；JSONL 回读 |
| C：通用诊断 | 通用 pair/advantage/correction helper，算法入口适配 | 三个 pair 与固定统计包，不因 OPD 增加通用统计副本 |
| D：OPD 比较 | distillation loss 及其测试 | current/rollout 比较和实际系数影响，E1–E6 全覆盖 |
| E：兼容与资源验收 | launcher 文档、恢复测试、短训练 | 旧指标含义、性能开销和 W&B/文件结果一致 |

每阶段单独 commit，保持可回退。已有普通 PPO/legacy 指标优先原样保留，新 namespace 的旧字段映射逐项增加。升级仅日志不能改变 optimizer LR scheduler 的调用单位；当前 engine worker 在最后一个内部 mini-batch 推进 scheduler，这个行为不在 metrics 改造中调整。

### 11.1 旧到新的映射原则

| 旧字段 | 新视图 | 处理方式 |
| --- | --- | --- |
| `actor/grad_norm` | `optim/actor/grad_norm_preclip` | 前者保留外层摘要；后者单次更新，不能只做字符串重命名 |
| `actor/lr` | `optim/actor/lr_used` | 新值取本次 optimizer 使用前的参数组 LR，不直接复制 scheduler 后的报告值 |
| `actor/entropy` | `policy/entropy/pre_update_mean` | 保持入口和全词表定义；逐更新/probe 用不同名字 |
| `rollout_corr/k3_kl` | `policy/anchor_behavior/k3_estimate` | 在同 mask/范围时复用计算；修复 padding 口径时声明版本差异 |
| `critic/advantages/*` | `advantage/task/*` | 来源匹配时映射；OPD advantage 另从实际 loss 产生 |
| `actor/distillation/ppo_clip_fraction` | `correction/ppo/active_fraction` | 新视图逐更新，旧视图兼容；source_pair 在配方元数据中保存 |
| `actor/distillation/advantage_sign_flip_fraction` | `distill/advantage_sign_flip_fraction` | 保留比较对象为 current 与 rollout 信号 |
| `val-core/*` | `eval/<dataset>/*` | 同一份评估结果提供兼容别名；保持原 N 和采样协议 |

不将不同估计器的 loss 数值作为统一质量排序。已有 raw pair 诊断不等于新 applied-weight 诊断；NoIS 不能为了填齐面板被赋予假的 correction 指标。稀疏蒸馏、critic、额外参考策略仅在确有能力时出现。

## 12. 测试与验收

### 12.1 数学与统计

1. 同一全局 token 集合换 micro-batch 切法和 DP 分片，mean、M2、比例、ESS 与单进程参考一致。
2. 加入全 padding 行、空 rank、某组无正 advantage 的 rank，分母和结果保持正确。
3. 不等 token 数的局部均值不能等权平均；moments 合并不要求相同列表长度。
4. 原始 $w$、guard 后值、PPO clip 分支、显式 TIS/RS 权重分别检查，padding 中的 NaN 不污染有效统计，有效位置 NaN 不被隐藏。
5. nearest-rank 分位数与全局排序一致；每卡 p99 平均的反例必须失败；调度跳过和内存限额触发明确缺测。
6. 同一 token 上检验 $z_{cb}=z_{ca}+z_{ab}$；验证 M2 的交叉项与不等集合不能相加。
7. 在有限小词表/单 token 例子中将系数统计与实际 autograd 梯度分支对照，覆盖 guard 边界、PPO active/inactive、NoIS、零分母。

### 12.2 执行、日志与恢复

1. 2 个 outer、每个 4 次更新产生 8 条 update 记录；micro-batch 数和卡数变化不改变尝试数。
2. 64/64×4 epochs 与 256/64×1 epoch 的更新总数相同，但局部 epoch/mini 元数据不同。
3. 模拟 skipped update：attempt 递增，success 不递增；unknown 状态不伪造绝对计数。
4. checkpoint 恢复后计数连续；旧 checkpoint unknown 分支可读，session 文件不覆盖，重复日志可按 session/event_seq 辨认。
5. W&B 离线 history、JSONL、TensorBoard 的语义坐标一致；初始评估、延迟评估、样例表交错不丢记录。
6. 所有 backend 的 finish 幂等、缓冲提交完整；旧后端调用保持兼容。
7. 开启/关闭诊断时，固定输入的 loss、梯度、参数更新和训练 RNG 一致；CPU 数学测试通过后再验分布式路径。

### 12.3 性能与适用性

用同输入和同配置分别测关闭、新基础统计、新分布统计的额外时间与峰值内存。基础统计先设稳态 actor-update 开销不超过 2% 的工程目标，分布诊断的摊销开销先设不超过 5% 的目标；它们是待测预算，不是已有结果。超过预算时优先减少同步次数、搬运和频率，不能用错误的平均 p99 换性能。

GPU 验证需在已授权且空闲资源上执行；文档交付不启动训练。FSDP2/SP=1 通过后，再分别验收 PPO/GRPO、异步、其他 engine、TP/CP、多个 advantage component。接口可扩展不等于这些路径已被支持。

## 13. 后续扩展边界

新增算法主要提供概率角色、advantage component、实际 correction 与归一化声明，共用统计工具。新增分布摘要实现只替换状态合并与 finalization，明确方法版本。新增输出后端只适配记录，不重复算法公式。

异步训练扩展行为版本分布与 generation-time train probe；多教师扩展有限 teacher ID 和有明确权重的 component；条件分析增加固定 confidence/位置区间。样本 ID、response 文本、路由详情保持在关联文件，避免指标 key 数随数据量增长。

主面板保留八类，每类默认展示关键系列，扩展诊断仍在所属类中。维护对象是有限的定义及其计算合同，不是手工为所有数据源、epoch 和 mini-batch 展开的几百个字段。
