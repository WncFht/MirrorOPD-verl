# OPD 评测领域与泛化迁移基准调研

核验日期：2026-10-30。本文回答两个问题：在策略蒸馏（On-Policy Distillation，OPD）通常评测哪些能力；研究泛化与迁移时，哪些任务和分布变化值得加入。针对项目的选择、题量与评测预算见[transfer-mechanism 扩展提案](../../archive/experiments/teacher-transfer/2026-10-30-评测领域候选.md)。本文维护外部证据，提案维护项目取舍。

## 1. 结论与统计口径

对当前文本模型研究，优先覆盖 **数学、代码、科学推理、指令遵循**。若结论涉及“通用能力迁移”，还应加入 **通用知识与常识、逻辑与规划**。工具使用与交互 Agent 已形成独立研究线；多模态也有直接 OPD 工作，但需要匹配的学生与输入管线。早期 OPD 还评测摘要和翻译。

泛化应按“训练与评测之间改变了什么”组织：同域新题、跨领域、跨语言、难度外推、组合与推理跨度、轨迹分布变化、旧能力保持、知识内化。增加若干 AIME 年份增加的是数学覆盖，不能替代这些分布变化。

统计采用一个**按研究问题选择的 14 篇样本**，覆盖奠基方法、外部教师、自蒸馏、泛化研究、失败分析、Agent 与视觉迁移。它是便于审计的覆盖统计，**不是全领域普查，也不是随机样本**；比例只能描述这 14 篇，不能当作全部 OPD 论文的占比。检索时间范围为 2023–2026，截止 2026-10-30；同论文多个版本只计一次，计入正文和附录中的实际任务评测，训练数据名称本身不构成评测领域。

宽泛检索使用 arXiv 与 OpenAlex，各返回 45 条，合并为 66 条；两个来源均无错误诊断。检索结果受到每来源截断、关键词与排序影响，明显偏向标题包含 self-distillation 的新论文。14 篇核验样本由宽泛结果、精确题名检索和既有文献补充组成，不能写成“从 66 篇完整筛选得到 14 篇”。综述、图像生成扩散蒸馏、仅以教师答案做 SFT 的工作不进入这份样本。

附件保留[完整原始检索报告](data/benchmark-survey-20261030/paper-search-complete.md)、[逐篇编码 CSV](data/benchmark-survey-20261030/papers.csv)与[领域统计 CSV](data/benchmark-survey-20261030/domain-counts.csv)。原始检索报告的引用数、自动排序和阅读建议未经人工背书；人工归类以本文和 CSV 为准。

## 2. OPD 常见评测领域

一篇可计入多个领域，因此百分比不相加为 100%。科学包括专业科学与医学任务；知识包括 MMLU 系列、事实问答与常识保持。ScienceWorld 归交互 Agent；视觉数学归多模态；OPD² 的 ReasoningGym Math/Algorithm 按论文归数学/代码。GKD 的指令微调分支用 MMLU/BBH 评测，分别归知识/逻辑，未当作 IFEval 类指令评测重复计数。

| 领域                 | 样本中篇数 | 占 14 篇比例 | 常见或代表性 benchmark                                   | 对当前研究的作用                              |
| -------------------- | ---------: | -----------: | -------------------------------------------------------- | --------------------------------------------- |
| 文本数学推理         |          9 |        64.3% | GSM8K、MATH500、AIME、AMC、HMMT、Minerva、OlympiadBench  | 与既有数学训练对接，检查域内收益与难度变化    |
| 代码生成与算法       |          8 |        57.1% | HumanEval+、MBPP+、LiveCodeBench、CodeContests           | 可执行评分，检查数学训练是否迁移到程序解题    |
| 指令遵循与对话       |          6 |        42.9% | IFEval、IFBench、Multi-IF、AlpacaEval、DollyEval         | 识别通用行为保持、约束执行及负迁移            |
| 科学与专业推理       |          6 |        42.9% | GPQA-Diamond、SciKnowEval、SciBench、SuperGPQA、医学问答 | 连接领域知识与推理，检验数学域外迁移          |
| 工具使用与交互 Agent |          4 |        28.6% | ToolAlpaca、ALFWorld、ScienceWorld、WebShop              | 检验 API 调用、长程决策和错误后的恢复         |
| 通用知识、事实与常识 |          3 |        21.4% | MMLU、MMLU-Pro、HellaSwag、TruthfulQA、WinoGrande        | 测新知识与旧能力保持，覆盖非数学学科          |
| 独立文本逻辑任务     |          1 |         7.1% | BBH                                                      | 为推理迁移提供区别于数学/代码的任务证据       |
| 多模态理解与推理     |          1 |         7.1% | MMMU-Pro、MathVista、MathVision、LogicVista              | 检验文本教师到视觉学生的迁移                  |
| 摘要与机器翻译       |          1 |         7.1% | XSum、WMT 英德翻译                                       | 奠基 OPD 的生成任务；当前推理迁移线优先级较低 |

后面三类样本数少，只说明这份样本覆盖少，不能据此断言整个领域很少研究。尤其逻辑与谜题在相邻 RL/SFT 泛化文献中有独立地位，见第 4 节。

### 2.2 对选 benchmark 最有用的外部证据

EOPD 在纯数学训练后，用 GPQA-Diamond、MMLU-Pro、AlpacaEval 2.0 评测 OOD；它支持把科学、知识和指令/对话纳入观察，而不是只看数学总分。OPD² 用更广的数学、科学、代码任务检验同一方法，适合参考领域覆盖。二者并不共同证明任意 OPD 都能跨域正迁移。[^eopd][^opd2]

Every Coin Has Two Sides 对当前 teacher-transfer 问题更直接：它比较数学、代码、科学和 IF，追踪教师较弱能力造成的负迁移，也比较跨语言和组合跨度。完整图表解读已在[既有 v3 笔记](2026-10-26-策略蒸馏泛化的双重性实验与设置.md)，这里不重列其终点数字。[^coin]

SDFT 在学习新任务/新事实时测旧能力保持；SDPO 研究富反馈带来的学习收益。近期复查工作则指出，其测试配置中的 SDPO 代码收益未迁移到未见题，部分科学训练还降低其他学科表现。正向结果与复查的任务划分、信息来源和指标需要对齐，不能按论文标题投票。[^sdft][^sdpo][^revisit]

## 3. 泛化迁移的主要评测轴

“领域”描述题目内容；“泛化轴”描述相对于训练变化的因素。同一个 benchmark 可以参与多个轴，但必须由实验划分支持。以下是研究设计分类，不是文献占比统计。

| 评测轴            | 训练→评测的变化                         | 合适的 benchmark/构造                   | 能支持的结论与必要条件                                  |
| ----------------- | --------------------------------------- | --------------------------------------- | ------------------------------------------------------- |
| 同域新题          | 相同任务分布，题目未参与更新            | 数学、代码、科学的独立留出集            | 域内泛化；固定 state 的 KL 与 fresh 任务成功率分别报告  |
| 跨领域            | 只训练 Math，评测 Code/Science/IF/Logic | HumanEval+、LCB、GPQA、IFEval、BBH      | 正迁移/负迁移；必须报告相对 S0 的变化和该教师能力       |
| 跨语言            | 保持题义，改变输入语言                  | MGSM 中英配对；OlymMATH 中英文配置      | 语言迁移；优先按同题 ID 配对，确认题目是否逐一对齐      |
| 难度外推          | 控制任务族，提高难度                    | ReasoningGym 难度档、组合函数更深嵌套   | 已知机制的难度泛化；只比较 MATH 与 AIME 会混入题型差异  |
| 组合/推理跨度     | 学过原子任务，测试新组合及依赖链        | From f(x)…、R-HORIZON、程序生成多跳关系 | 新组合能力；记录原子技能是否具备，跨度不是输出 token 数 |
| 轨迹/状态分布     | 固定 S0 前缀→当前学生访问状态           | 同题 fixed 与 fresh；Agent 错误恢复     | 学到的局部条件分布能否在当前 rollout 上生效             |
| 能力保持/顺序迁移 | 当前任务训练后复测其他能力；A→B         | MMLU-Pro 非数学学科、IFEval、HumanEval+ | 新任务收益与旧能力回退；顺序效应需要真实顺序训练对照    |
| 知识内化          | teacher 能看新信息，student 测试时撤去  | SE-Bench 随机 API、合成新事实           | 新信息是否进入参数；区分看文档会做、闭卷会做和新组合    |

MGSM 是同一组 250 道 GSM8K 题的多语言版本，适合以题目为配对单位比较中文和英文。IFBench 专门加入 58 类新的可验证约束，适合在 IFEval 之后检查约束泛化；这不自动保证模型训练史没有见过其约束或题目。[^mgsm][^ifbench]

R-HORIZON 通过题目组合增加相互依赖的子问题，可检验推理跨度；ReasoningGym 支持程序生成与复杂度控制，适合构造同任务族的新 seed 与难度外推。实际采用前必须固定生成器版本、难度参数及评分器，并记录教师是否曾训练相同生成任务。[^rhorizon][^reasoninggym]

教师来源、尺寸、SFT/RL 阶段与 tokenizer 是另一个维度。它们改变的是迁移条件，应作为实验分组，不能把“跨模型教师”当成一个 benchmark 领域；相同架构也不意味着相同初始化或相同训练史。

## 4. 相邻泛化文献提供的补充领域

这组材料用于找评测设计，不进入上述 14 篇 OPD 统计。仓库已有[RL/SFT 迁移泛化总调研](../transfer-generalization/2026-10-31-泛化迁移研究问题与证据综述.md)与[合成任务专题](../transfer-generalization/2026-10-27-合成数据与RL新知识新技能论文专题.md)，此处只提取影响 benchmark 选择的内容。

| 工作                                                                 | 主要任务/领域                                                | 对当前扩展的启发                                                 |
| -------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| Does Math Reasoning Improve General LLM Capabilities?[^mathtransfer] | Math→科学、代码、规划、IF；含 GPQA、LCB、ACPBench            | 数学训练至少需要一组跨域任务和一组通用行为保持任务               |
| When Domains Interact[^domains]                                      | 数学、科学、逻辑、谜题；含 MATH500、GPQA、Knights-and-Knaves | 逻辑/谜题应独立于数学；训练方向与顺序可能不对称                  |
| SFT Memorizes, RL Generalizes[^sft-rl]                               | GeneralPoints 规则变化与 V-IRL 视觉导航                      | 用明确规则变化检验泛化；不能把其结论直接推广到全部文本任务       |
| Rethinking Generalization in Reasoning SFT[^rethinking]              | 数学及跨域推理；优化长度、数据质量与底模能力                 | 比较共同 checkpoint，避免只选早期或最好终点                      |
| From f(x)…[^composition]                                             | 字符串函数组合、深度外推、Countdown 迁移                     | 若主张新技能，补受控原子技能/新组合实验                          |
| SE-Bench[^sebench]                                                   | 随机命名 API 的闭卷调用与组合代码                            | 若主张新知识，补能隔离已有知识的实验                             |
| Learning from Synthetic Data Improves Multi-hop Reasoning[^multihop] | 合成关系/逻辑→真实多跳问答                                   | 后续可增加知识组合任务，不能将虚构事实训练理解成学习真实测试事实 |

对 transfer-mechanism，最有增量的组合是：**四个核心领域 + 通用知识 + 一个独立逻辑任务族**。跨语言与组合跨度在同一套题上另外设计。Agent、多模态、长上下文检索/问答、开放对话偏好评测可以扩展研究范围，但它们需要新的交互、输入或评审协议；当前先完成可执行、可规则评分的文本评测更便于解释教师差异。

## 5. 候选 benchmark 与选用边界

| benchmark             | 覆盖的能力               | 选用理由                                             | 解释边界                                                                                  |
| --------------------- | ------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| GPQA-Diamond          | 专家级科学选择题         | 与多篇 OPD 工作可比；198 题规模可控                  | 低分接近四选一随机水平时解释力弱；难度与知识缺口混合[^gpqa]                               |
| HumanEval+ / MBPP+    | 函数级代码生成           | 164/378 道题，有加强测试；适合给小学生建立基础难度档 | 常见公开题有污染风险；先固定代码提取、运行环境与超时[^evalplus]                           |
| LiveCodeBench         | 竞赛编程                 | 适合较强学生与教师的代码迁移                         | 固定 release、题目日期、难度、去重和评测器；不能随 latest 漂移[^lcb]                      |
| IFEval                | 可程序验证的指令约束     | 541 prompts，便于观察格式、长度与语言约束保持        | 报 strict/loose、prompt/instruction；HF 的 split 名为 train 不等于项目可用于训练[^ifeval] |
| IFBench               | 新的精确指令约束         | 补 IFEval 的约束覆盖                                 | 独立报告，不能把两个集混为同一个 IF 指标[^ifbench]                                        |
| MMLU-Pro              | 多学科知识与推理         | 14 学科、超过 12K 题；可以分层抽样并单列非数学部分   | 抽样结果按自定义面板报告，完整 MMLU-Pro 分数另计；它也依赖推理[^mmlu-pro]                 |
| BBH                   | 多种文本推理任务         | 23 个任务中选定逻辑/符号任务，便于与 GKD 衔接        | 子集必须公开任务名、题目 ID 和 shot；旧公开题不能保证无污染[^bbh]                         |
| ReasoningGym          | 规则、关系、图与谜题     | 可控制 seed 和复杂度，适合受控外推                   | 新 seed 不能自动排除对任务规则的预训练；区分新实例与新技能[^reasoninggym]                 |
| MGSM / OlymMATH       | 多语言数学               | 分别提供基础难度和竞赛难度的语言比较                 | MGSM 保持题目配对；OlymMATH 按实际版本核验配对，避免地板效应[^mgsm][^olymmath]            |
| R-HORIZON             | 依赖子问题组成的长程推理 | 把解题跨度与生成长度分开                             | 与原始子问题比较，记录组合数、整题成功率和 token 预算[^rhorizon]                          |
| ToolAlpaca / ALFWorld | API 调用 / 交互任务      | 分别测试静态调用与环境决策                           | 静态调用准确率不等于多轮执行成功率；两类成本不同[^sdft][^guided]                          |
