## 1. DAPO-Math-17K 的来源与设计目标

DAPO 是 ByteDance Seed、清华 AIR 等团队发布的强化学习算法与系统。其配套数学题库的直接来源，论文 §3.5 写的是网页和竞赛官方网站，采集方式包括网页抓取与人工标注。作者进一步筛选、改写题目，使最终答案成为便于规则验证的整数。[^dapo]

例如，原问题要求一个形如 $(a+\sqrt b)/c$ 的表达式，改写后的问题要求输出 $a+b+c$。这种处理保留了主要数学求解过程，简化了答案解析和奖励判断。论文附录展示了改写流程，但没有给出每一道题到原竞赛网页的完整公开映射。因此能够确认“网页／竞赛题经过处理”，不能据此把整个 DAPO 命名为某个 AoPS 或 Numina 子集。

这决定了它的几个特征：

- 它首先服务于可验证奖励的数学 RL，OPD 后来复用了其中的题目。
- 整数答案对 RL 奖励器很方便；我们只优化 teacher/student KL 时，并不需要把所有新题也限制成整数答案。
- 竞赛数学是它的重要覆盖，但它不能独自代表全部数学题型、知识与语言表达。
- 原始题、整数化改写题、数字变体可能在不同题库中重现。跨数据集去污染应比较题干和题族，不能只比较最终答案。

本项目本地 `prepare_math_data.py` 先按原始 `extra_info.index` 保留首次出现，再移除 DAPO 指令外壳，得到 17,917 行；这一步不等于按题干去重。前一轮 CPU 探索再次规范化题干、排除现有 benchmark 与旧银行、筛去含汉字题目并处理数字变体，剩 13,419 道候选。Semi-OPD 报告的 14,116 道英语去重题采用其自己的清洗口径，两者不能直接互换。[^semi]

### 2.2 早期工作与复用的具体含义

GKD 既做 GSM8K 数学，也做 XSum 摘要、WMT 翻译和指令任务；证明 OPD 的输入来源并不限于竞赛数学。其任务、模型尺度和优化器差异较大，不把其中 T5／Adafactor 的学习率直接迁移到当前 decoder-only student。[^gkd]

MiniLLM 使用 Dolly 指令数据，先做 SFT 初始化，再用序列 RKL、策略梯度、教师混合采样及辅助语言建模项训练。它每次收集 256 条序列，以 mini64 做 4 个 inner epoch：每条序列访问 4 次、总计 16 次 minibatch 更新。它既不是“每条序列复用 16 次”，也不是“full batch256 连续更新 4 次”。[^minillm]

这批论文给出了 batch128 的直接依据，却没有为 full-vocab、全局 batch128、完整 reuse32 提供统一最优结论。reuse32 应被命名为我们主动选择的高复用拟合条件，并保留较低复用的诊断，而不是称作标准 OPD 默认值。

### 2.3 论文的验证题量

Distillation Dynamics 的自建域内留出为 Countdown426、Science507、MedReason471。它还在多个域外任务上抽 200 题，对 HumanEval164 与 EQ-Bench171 采用全集，对 MMLU-Pro 按 14 科各 200 题，总域外评估 3,935 题。这是明确的“按任务规模与覆盖分别选题”的先例。其数学补充在 MATH500 每 100 步评估一次，并同时报告轨迹与终点；正文最高点采用同一评估集选取，因此不能把最高点当作独立测试选出的无偏成绩。[^dynamics]

Every Coin 使用 GPQA-Diamond、IFEval 和按日期限定的 LiveCodeBench 等公开 benchmark；Semi-OPD 则主要报告 AIME／HMMT 等数学任务及跨域分析。它们并没有共同规定“任意 benchmark 抽 256 题即可”。能力评分的完整 benchmark 与固定状态 RKL 子集，应分别定义。[^coin][^semi]

### 3.1 推荐顺序按研究目的区分

| GSM8K train          | 7,473 题                                                    | 易题训练→难数学／跨域的受控对照                | 不适合作为唯一数学代表；去重后再确认是否容纳训练与留出              |

Big-Math 官方卡列出 Orca-Math、cn_k12、olympiads、MATH、AoPS、GSM8K、HARP、Omni-MATH 等来源，并加入 47,010 道由选择题改写的开放题。它提供按来源、学科和外部求解率分层的条件；Every Coin 也直接使用它。**对长期跨域研究，Big-Math 比继续扩大单一 DAPO 更有吸引力，理由是可分析的覆盖结构，而非已证实它使我们的 RKL 降得更快。**[^bigmath][^bigmath-card]

Big-Math 的清洗含外部模型可解性筛选，且保留部分来源例外；其难度字段也来自 Llama-3.1-8B。这些都是数据构造史的一部分。可用它做固定分层，不再用当前教师正确率筛掉问题。其原始去污染重点包括 MATH500 与 Omni-MATH，采用时仍要保护我们新增的全部 benchmark。[^bigmath-card]

NuminaMath-1.5 的来源从高中练习到竞赛，覆盖证明题、选择题和文字题。OPD 的教师监督来自冻结 teacher 对 student 前缀的分布，数据集已有答案／CoT 只用于质量检查或独立评分；若直接用数据集 CoT 优化，就是另一个监督条件。[^numina]

### 3.2 一个便于解释的数学比较

建议把 DAPO6,400 与 Big-Math6,400 作为两条独立条件，固定 student、teacher、rollout、reuse、学习率和读出点；不要立刻把它们混成未标来源的新池。若要检验训练难度，再增加固定题量的 DeepMath 难题子集或 GSM8K 易题子集。这样可区分“换数据覆盖”的效应与“换 teacher”的效应。

不同库不应被假定为互不相交：Big-Math 本来就吸收了多个常见数学来源。先合并保护清单、匹配原始 ID／规范化文本／题族，之后才抽取训练与留出。分别运行两个数学库时，训练题是否需要互斥取决于问题：研究相同题与来源重加权可保留交集并报告；研究未见来源泛化则应按来源整体隔离。

DeepMath、GSM8K 与 MATH 的结构分别见官方数据卡；其中 MATH 处理版可能少于标准题量，正式 split 以实际验收文件为准。[^deepmath][^gsm][^math]

## 4. 把训练领域反过来的数据方案

推荐先完成 Math、Code、Science、IF 四个单域条件。每条条件从相同 initial student 独立开始，对同一个固定 teacher 蒸馏，最后在同一组四领域评估题上读出。若同时把教师也换成各域专家，领域和教师会混在一起；应把这种专家对照另列。

| 训练领域 | 首选输入题池                                              | 备用／诊断选项                                              | 同来源留出                                           | 外部评测                              |
| -------- | --------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------- |
| Math     | Big-Math；DAPO 作为衔接对照                               | DeepMath 难度分层、MATH、GSM8K                              | 同来源先留 512 开发＋512 锁定，按题族划分            | MATH500；AIME／AMC 分集；跨域三个面板 |
| Code     | `agentica-org/DeepCoder-Preview-Dataset` 的 train configs | 本地 TACO；G-OPD 使用的 Eurus-RL-Code                       | 按问题来源／原始 contest ID／题族分组；先留 512＋512 | 时间隔离 LCB；HumanEval+164、MBPP+378 |
| Science  | `MegaScience/TextbookReasoning` 去 Math／CS               | SciKnowEval L3 受控子集；SCP-116K 去 Math                   | 优先按教材或章节分组；先留 512＋512                  | GPQA-Diamond198；独立 SciKnowEval L3  |
| IF       | `nvidia/Nemotron-Cascade-2-RL-data` 的 IF-RL              | Every Coin 使用的 Llama-Nemotron `RL/instruction_following` | 按基础请求及约束组合分组；先留 512＋512              | IFEval541、IFBench 独立报告           |

表中 6,400 训练＋1,024 同来源留出是拟议统一规模，不是这些论文的原始 split；新数据尚未完成逐行验收。对 Science，“教材分组”依赖实际字段是否保留书籍／章节 ID；若没有，采用可审计的相似题族划分并明确无法保证教材隔离。

DeepCoder 官方配置包含 TACO7,436、PrimeIntellect16,252、LCB train599，合计 24,287 行。LCB 训练日期截至 2024-07-31，官方 test279 题位于 2024-08-01 到 2025-02-01；单独的 Codeforces test408 题也应保留为测试。应检查其他合成／TACO 来源是否与 LCB 题族重合，而不只相信时间划分。此前本地 LCBv6 的 175 题不是这个官方 test 全集。[^deepcoder]

TextbookReasoning 来自约 12,000 本大学科学教材，约 650K 题，经历 OCR、问答抽取、答案核对和改写。Every Coin 的单教师科学训练明确去掉 Math／CS，适合我们研究 Science→Math／Code 迁移。其混合 MOPD 另用 SCP-116K，不能混写成同一个科学数据设置。[^textbook][^coin]

IF 首选 Cascade-2 的 45,879 条 IF-RL，是为了使用明确可核验的子集并与 Open-MOPD 对齐；Llama-Nemotron 旧 IF 子集则与 Every Coin 更接近。二者都比从 IFEval 测试题抽训练数据更适合独立泛化评估。IF 数据通常覆盖与 IFEval 相关的约束类型：新题泛化与新约束类型泛化要区分，后者可用 IFBench 或事先留出的约束类别。[^cascade][^llama-data]

逻辑训练可作为第五条：使用固定版本的 ReasoningGym，控制生成 seed、任务族和难度，另留同族新实例与更难实例。它具有扩量优势，但随机 seed 不同不保证题目不同，仍需规范化去重。知识训练暂不与科学混为一类；可以后续核验 Nemotron knowledge-mcqa 等专用来源，再定义不与 Science 重叠的学科边界。首轮保留 MMLU-Pro 非数学和 BBH 作为额外评估即可。[^gym]

## 5. 超参数怎样借鉴，哪些需要单独决定

### 5.1 Batch128 的实际变化

令外层批数为 $O$、每批题目数为 $B$、每题回答数为 $n$、完整全局批复用次数为 $r$。每次 inner update 覆盖该批全部回答，则：

$$
N_{\mathrm{prompt}}=OB,\qquad N_{\mathrm{response}}=OBn,\qquad U=Or,\qquad E=OBnr.
$$

$U$ 是 optimizer update 数，$E$ 是回答参与优化的累计次数。microbatch 梯度累积不增加 $U$；把一个 batch 拆成独立更新的 minibatch 会增加 $U$。

| 条件                | 新题   | 新回答 | Optimizer updates | 回答参与次数 |
| ------------------- | ------ | ------ | ----------------- | ------------ |
| 50×256，n1，reuse32 | 12,800 | 12,800 | 1,600             | 409,600      |
| 50×128，n1，reuse32 | 6,400  | 6,400  | 1,600             | 204,800      |
| 50×128，n1，reuse8  | 6,400  | 6,400  | 400               | 51,200       |
| 50×128，n4，reuse32 | 6,400  | 25,600 | 1,600             | 819,200      |

batch 从 256 减为 128，固定 50outer 与 reuse32 时更新数不变，但新题和每次梯度涉及的回答减少一半。它更适合快速扩大模型／训练域矩阵，也会改变梯度噪声，不能把差异都归因于更小 batch。每题 n4 增加状态覆盖，但不能把 6,400 道题称为 25,600 道独立题。

### 5.2 建议的参数讨论顺序

| 参数           | 论文范围或差异                                                | 对当前研究的建议                                                                         |
| -------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Full-vocab RKL | 有直接 KL 梯度、sampled PG、top-k、多目标等不同实现           | 主线继续保留直接 full-vocab RKL；改变估计器时另开对照                                    |
| LR             | 近邻方案 1e-6、1.5e-6、3e-6；另有 1e-5 及 5e-5 的不同任务实验 | 以 1e-6 起步；代表配对短程比较 3e-7／1e-6／3e-6，再统一，而不按每教师调到最优            |
| Reuse          | minibatch 划分、inner epoch 与完全固定轨迹三种机制并存        | 32 保留为候选；在代表配对比较 8／16／32 的收益和状态漂移                                 |
| Rollout        | Semi 固定 initial student；通常在线方法按新批刷新             | 每 outer 当前 student 生成；保留一个固定 initial student 对照；批内重算当前 student 分布 |
| Sampling       | 多篇采用 T1、top-p1；部分方法采用截断／不同 teacher 温度      | 拟合主线 T1、top-p1、不截断 top-k；行为采样温度与 KL 评分温度分开记录                    |
| Optimizer      | AdamW 常见；warmup 与 wd 不同                                 | 初始候选 betas0.9/0.999、wd0.01、clip1、constant LR；不因 batch 减半自动线性缩放 LR      |
| Response cap   | 4K、7K、16K 乃至更长均存在                                    | 训练 7,168 可作为统一上限；验证生成可到 16,384，并分别评分前 7,168 和更长部分            |
| Prompt cap     | 1,024／2,048 常见；代码／教材题可能更长                       | Math 先 2,048；跨域先统计截断率，必要时统一升到 4,096；不截断题干后当完整题训练          |
| 调度与选点     | 多篇按 epoch 训练或选最好验证点                               | 主比较固定 outer 终点；按 outer 而非 inner 定义公共读出，显示实际 update 和 token 预算   |
| Seeds          | 有单次曲线，也有 3seed 控制实验                               | 先 1seed 扩大覆盖，关键结论再 3seed；题目 bootstrap 不能代替训练 seed 重复               |

学习率与 reuse 要联合看：在旧前缀上 32 次更新后，student 已偏离生成该轨迹的策略。重算 student logits 保证条件分布与梯度是当前参数下的，但没有把前缀分布变回当前 on-policy。使用概率比也不能自动修正整条前缀访问分布。

### 5.3 跨领域必须明确损失归一化

沿用固定时域的目标时，令 $H$ 为共同 response cap，$L_i$ 为第 $i$ 条轨迹有效长度，$r_\theta(s_{it})$ 为该前缀的全词表 RKL：

$$
\mathcal L_H(\theta)=\frac{1}{BH}\sum_{i=1}^{B}\sum_{t=1}^{\min(L_i,H)}r_\theta(s_{it}).
$$

提前 EOS 之后用吸收状态贡献零。相同 $H$ 下，它与平均累计 KL 只差固定倍数。IF 回答往往较短，因而同样 128 题可能有更少的训练位置；相同题量和更新数不代表相同 token 预算或梯度尺度。

若改为逐回答 token 均值，再对题目取平均，就会改变长短回答的相对权重；这不只是显示单位转换。建议主线先明确沿用哪个目标，同时报告累计风险、固定 $H$ 归一化风险与有效 token 均值。跨域主要比较同一个评估领域内不同训练来源的变化，不用 Math 和 IF 的原始 KL 绝对大小直接判断哪个领域更容易。

## 6. 一个 benchmark 应该选多少题

### 6.1 先区分三个集合

1. **同来源开发留出**：判断训练题到同分布新题的泛化，供少量超参数决策。
2. **固定公共 benchmark**：检查更广的能力／分布迁移；小 benchmark 优先终点全集。
3. **锁定确认留出**：不参与选超参数；在预先规定初始与终点评估。

过程读出可以从开发留出中预抽 128 题形成固定评估子集。它始终是同一子集，避免曲线变化混入换题噪声。锁定确认集不用于按结果提前停止或选择最优 checkpoint。

### 6.2 RKL 应按题目做配对估计

对相同固定轨迹，第 $i$ 题在初始与终点的风险为 $R_{i,0},R_{i,k}$，定义改善 $d_i=R_{i,0}-R_{i,k}$。$d_i>0$ 表示下降。若独立抽样单位是题目，有限方差下均值的近似 95% 区间半宽为：

$$
\widehat\Delta=\frac1N\sum_i d_i,\qquad h\approx1.96\frac{s_d}{\sqrt N}.
$$

若存在同一题族／教材内相关性，抽样和 bootstrap 都应以相应组为单位。同一题内 token 不独立，不能把 $N$ 替换成 token 数。方法比较使用同题配对，保留模型前后、不同方法之间的对应关系。[^dror]

相对降幅报告为：

$$
g=1-\frac{\overline R_k}{\overline R_0}.
$$

对 $g$ 的区间，应配对重采样题目并重新计算两个均值及比值，不把每题百分比直接平均。初始风险很小时，相对量会不稳定，应主要看绝对风险差和残差。

为了规划样本量，暂把初始均值 $\mu_0$ 视为固定参考。若希望改善量的区间半宽不超过 $\epsilon\mu_0$，近似需要：

$$
N\gtrsim\left(\frac{1.96s_d}{\epsilon\mu_0}\right)^2.
$$

下表是假设方差下的预算计算，不是本项目已经测得的误差：

| $s_d/\mu_0$ | 半宽目标为初始风险的 5% | 半宽目标为初始风险的 2.5% |
| ----------- | ----------------------- | ------------------------- |
| 0.25        | 97 题                   | 385 题                    |
| 0.50        | 385 题                  | 1,537 题                  |
| 1.00        | 1,537 题                | 6,147 题                  |

所以 512 是一个可行的起点，不是统计上保证足够的常数。建议在代表配对的开发题上估计方差，预先允许 256→512→1,024 的扩量；扩量依据区间宽度及覆盖，不依据哪个教师更有利。确认阶段冻结样本量和题目，避免反复显著性判断造成选择偏差。

大量 token 只能减少给定轨迹上的数值估计问题，不能替代新题。多个 rollout 也有同题相关性：若 $Y_{ij}$ 为题 $i$ 的第 $j$ 条轨迹风险，在独立题、题内条件独立采样下，均值方差可分解为：

$$
\operatorname{Var}(\overline Y)=\frac{\operatorname{Var}_x[\mathbb E(Y\mid x)]}{N}+\frac{\mathbb E_x[\operatorname{Var}(Y\mid x)]}{NK}.
$$

增加每题 rollout 数 $K$ 只降低第二项；增加题目数 $N$ 同时降低两项。预算有限时先扩大不同题的覆盖，再为代表配对增加 rollout 重复，以估计轨迹噪声。

还要区别两个目标：在固定 initial student 银行上，给定权重的 full-vocab 评分基本是确定量，bootstrap 描述对题目总体的外推不确定性；对 fresh-current 或 teacher 生成银行，另有生成随机性。单次训练的题目区间也不包含优化 seed 差异。[^variance]

### 6.3 Accuracy 的题量不能直接套到 RKL

作为对照，独立题、单次二元评分、总体准确率约 50% 时，普通正态近似的 95% 半宽约为 $0.98/\sqrt N$：128 题±8.7 个百分点，256 题±6.1，512 题±4.3，1,024 题±3.1。判断前后差异应使用配对方法，不能简单套用两个独立区间。avg@4 减少同题生成噪声，但 256 题×4 回答不等于 1,024 道独立题。

若只描述固定 benchmark 全集上的确定评分，该全集均值本身没有题目抽样误差；上述区间涉及向更广题目分布外推。随机解码仍有生成误差。AIME 一届 30 题即使多次采样，也不会增加问题覆盖，不能单独承担“普遍可拟合”的证据。

### 8.2 Benchmark 的直接文献依据

Every Coin 的附录 B.4 明确 GPQA-Diamond 与 IFEval 使用 avg@4、LCB v5 使用 avg@10；MATH500 为 avg@1，AMC23 与 AIME25/26 为 avg@16。Open-MOPD 对数学 AIME24/25 用 mean@64，代码 LCB v5/v6用mean@10，IF的IFEval与IFBench用mean@1。G-OPD对HumanEval+、MBPP+和指定日期LCB v6 统一采用 avg@4。不同任务的原始采样数不一样；我们统一 avg@4 是既有项目决策，不称作逐项复现论文。[^coin][^openmopd][^gopd]

IFBench_test 官方卡有 300 题；它与 IFEval541 分别报告，避免新约束类型被一个 IF 平均值遮住。[^ifbench-cap] 推荐 LCB 采用 DeepCoder 配套的 v5 test279 题与已知日期边界，首轮不再叠加大幅重叠的其他 release。MATH 沿用既有 630 题分集结果；GPQA198 为科学能力主读出，TextbookReasoning 同来源留出负责较广科学题目分布上的风险。

任务得分和 KL 应并行解释：准确率衡量规则下的成功，KL 衡量指定状态上的分布接近。不能因为 IF 准确率容易计算就只测 IF 准确率，也不能把 GPQA 上的低 KL 当作科学答案正确。以四域来源留出作为风险主表，公共 benchmark 全集作为能力面板，再加较小的公共 benchmark 固定状态 KL 面板，可以区分来源泛化与外部任务分布变化。
