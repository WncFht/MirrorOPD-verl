### 1.1 PR 标题和说明可能落后于代码

Liger #1555 的说明仍称 chunked distillation 不在范围内，但所核对 head `740a415a55bdc6bc981f970e6494737fc0891126` 的 diff 已修改该路径，并增加 `_logit_gap`、近教师 `log1p/expm1` 以及自定义学生梯度。因此，不能只按旧 PR 说明判断它仅修 hard-label collapse，也不能据此宣称所有 Liger backend 都已覆盖。它仍未合入，CuTe/cutile/flydsl/Ascend 等路径需要分别核对。[^liger-collapse]

### 1.2 FlashAttention 的 CE 与 attention 是两个算子

所查 `flash_attn/ops/triton/cross_entropy.py` 先得到完整 LSE，再减去目标 logit；backward 先从 LSE 重建概率，再对目标概率减 1。FP32 提高了失效门槛，但仍会在高置信度处发生消减。这里的结论来自实际源码，关键词搜索未找到 PR 只是辅助证据。[^fa-ce]

FlashAttention #893 是另一类修复：2024-03-28 合入 `UNFUSE_FMA` 编译宏选项，避免 attention softmax 缩放与减最大值的 FMA 在特定输入上破坏数值行为。PR 和当前源码明确说明该宏在 FlashAttention 默认构建中未启用；当前 Hopper `softmax.h` 仍有乘缩放再减缩放后最大值的表达式。这不等于修复输出层 CE 的 collapse。[^fa-fma][^fa-softmax][^fa-hopper]

GProj 作者提供了独立 FA3 补丁仓库，针对 BF16 cast 之后 attention score gradient 的行和漂移，在 dQ/dK 收缩中加入质量修正。公开实现限定 BF16、head dimension 64、sm90a 等条件，不支持所有 attention 选项；它不是已确认合入 FlashAttention 主线的通用替换。论文所报训练成本约增加 4.7%，不能外推成我们的成本或收益。[^gproj]

## 2. 与本机修复逐项对照

以下统一用 p 表示学生分布，T 表示教师，q 表示冻结 anchor，m 表示融合目标，避免沿用论文中相反的 p/q 命名。

### 2.1 Selected-token CE：与作者方案直接对应

对目标类别 t，令非目标类的 log-sum-exp 为 a。稳定值和梯度可以写为

$$
\ell=\operatorname{softplus}(a-z_t),\qquad
g_t=-\sum_{j\ne t}p_j,\qquad g_j=p_j\quad(j\ne t).
$$

非目标质量必须在归约前排除目标项；从已舍入的总和中再减去 1 无法找回小量。本项目的 [stable_logprobs.py](../../../../../verl/utils/stable_logprobs.py) 和 [CUDA 实现](../../../../../verl/utils/stable_logprobs_triton.py) 使用这一结构；返回 log-probability 时符号与 CE 相反。上游常用 `expm1(logp_t)` 或非目标质量除以总质量来算 CE 目标梯度，我们用非目标梯度之和重建。数学目标一致，归约与舍入顺序不同。[^paper][^megatron][^unsloth-ce]

### 2.2 Soft-target CE 与 reverse-KL：梯度目标不同

冻结教师下，soft-target CE 与 forward-KL 对学生 logits 的梯度相同：

$$
\nabla_z\mathrm{KL}(T\Vert p)=p-T.
$$

论文通过原始 student/teacher logit 差、log1p/expm1 保留这一小差值，避免独立算两份概率再相减。[^paper]

我们的 Full-KL/MDPO 则使用 reverse-KL，其梯度为

$$
\nabla_{z_i}\frac1\eta\mathrm{KL}(p\Vert m)
=\frac{p_i}{\eta}\left(r_i-\mathbb E_p r\right),
\qquad r_i=\log p_i-\log m_i.
$$

BPO 的权重换成冻结 q：

$$
\nabla_{z_i}\frac1{2\eta}\operatorname{Var}_q[r]
=\frac{q_i}{\eta}\left(r_i-\mathbb E_q r\right).
$$

因此可复用“从 logit 差出发、保留小残差”的数值原则，但不能将 `p-T` 替换进 MDPO/BPO。Liger 当前 #1555 diff 和 Unsloth #2079 对 reverse-KL/JSD 的相对残差处理，更接近本项目的 [numerics.py](../../../../../verl/trainer/distillation/numerics.py)。[^liger-collapse][^unsloth-jsd]

### 2.3 融合 target 与近零 KL：仍需本项目自己的实现

| 本项目问题                        | 上游相关处理                                | 当前判断                                                           |
| --------------------------------- | ------------------------------------------- | ------------------------------------------------------------------ |
| 小 f 加到大 log q 后丢失          | CE/soft-target 修复保留 logit 差            | 一般 κ/η 融合 target 不在上述通用 CE API 内，继续保留 split target |
| BPO 的 q 总质量误差叠加大公共偏移 | 上游有残差中心化和零和主分量                | 继续显式归一化 q；事后投影不能恢复已丢失的残差                     |
| 极小 KL 与 log Z 标量失真         | log1p/expm1、稳定 normalizer                | 我们还保留二阶余项、融合目标 log Z、teacher 额外支持修正           |
| dZ 写回 BF16 后行和再次漂移       | GProj 针对 attention 的实际 BF16 操作数修正 | 我们在 cast 前重建主分量，不能据此宣称 cast 后仍严格零和           |
| 输出投影先落 BF16 再 `.float()`   | Liger #1433 直接 FP32 GEMM 输出             | 本项目 CUDA Full-KL 的 `project` 已避免这次中间舍入                |
| token-block dH/dW 累积误差        | CCE 的 Kahan/FP32 累积                      | 属于另一层误差；不能用它代替 loss/target 公式修复                  |

## 3. 本机最小核对

仅运行 CPU 小算例，没有安装或替换依赖，没有启动训练。环境为 PyTorch 2.11.0+cu128、Triton 3.6.0；已安装 FlashAttention 2.8.3、Liger 0.8.4，版本号不代表包含所查主分支补丁。

输入 FP32 logits `[9, -9, -9]`、目标 0，比较原生 CE、按论文 hard-label 恒等式直接组合的 Torch 表达式、项目 stable selected-log-prob 的负值：

| 实现                                       |     CE loss |     目标梯度 |      梯度行和 |
| ------------------------------------------ | ----------: | -----------: | ------------: |
| 本机 `F.cross_entropy`                     |           0 |            0 |   3.045996e-8 |
| 论文恒等式的 Torch 表达式                  | 3.045997e-8 | −3.045997e-8 | −1.421085e-14 |
| 本项目 `selected_logprobs`，Torch fallback | 3.045997e-8 | −3.045996e-8 |             0 |

这是一个输入上的直接核对，说明修复表达式保留了原生 CE 丢失的小梯度，不代表本项目在所有输入上逐位零和，也不是上游 CUDA PR 的运行验收。完整本机测试范围仍以[生产验收报告](../../infra/numerics/precision/2026-10-27-蒸馏数值修复与验收.md)为准。

## 4. 值得借鉴的后续工作

1. 跟踪 PyTorch #202049、verl #8377/#8378、Liger #1555 的合入与实际调用路径。满足本机测试、性能和 AMP 契约后再考虑减少自有代码；不能仅根据依赖版本号删补丁。
2. 把 Liger #1555 的补偿 FP32 差值算法与我们少量 FP64 寄存器减法做同输入比较。候选方案可能减少 FP64 成本，但必须覆盖独立公共平移、极近目标、尾部概率和 compiler FMA 行为后才能替换。
3. 参考 Megatron/Liger 将非目标质量装进已有 TP collective 的方式，扩展未来词表并行支持。本项目当前修复没有因此自动获得 TP CE 接口。
4. 保留 target 主分量、非目标分量、逐行相对误差、自目标、近目标、平移不变性和边界梯度测试。Unsloth #2123 展示了“loss 值正确但分支边界导数错误”的后续回归；本项目 selected-log-prob 使用手写 VJP，未采用它出问题的 clamp 分支。
5. GProj 和 attention FMA 修复作为独立诊断参照。它们不能证明我们 target KL 反弹的原因；只有在实际 attention 输入上复现对应误差、再做控制实验，才能判断收益。

这些是调研后的候选事项，本次没有改生产算法或精度配置，也没有运行上游 kernel benchmark。我们之前的验收仍是“已修复复现的输出算子错误，不能据此认定 BF16 target KL 反弹消失”。

## 6. 补偿 FP32 差值与本机算法的实际对照

复现脚本为 [compare_upstream_gap.py](../../../research/precision/compare_upstream_gap.py)，结果摘要为 [upstream-route-audit-20261027.json](../../experiments/teacher-transfer/optimizer-precision/mechanism/data/upstream-route-audit-20261027.json)。使用 Liger #1555 上述 head 的有限输入 `_logit_gap` 算法，分别写成 eager Torch 与 Triton 计算；Triton 显式关闭 FP fusion。候选只计算差值，不代表运行整个上游 JSD 补丁。

在同一个参考词元 a 下，目标为 `(x−x_a)−(y−y_a)`。本项目先在 FP64 中分别减参考值；候选先计算 `x−y` 和 `x_a−y_a`，保留两次减法的舍入余项，再合并高低部分。CPU/CUDA 分别测试 27 组随机输入、128 个保存的真实 logits 位置（分 16 块），以及独立小量反例。随机测试包含三个量级、三个公共偏移和三个扰动尺度。参考采用 FP64 的 difference-first 表达式，再转 FP32；这是固定测试集参考，不是任意输入的精确算术证明。

| CUDA 对照                    | 本项目最大绝对误差 | 候选最大绝对误差 | 判断                                         |
| ---------------------------- | -----------------: | ---------------: | -------------------------------------------- |
| 27 组随机输入，共 6912 行    |           3.64e−12 |          7.45e−9 | 候选不是逐位等价替代                         |
| 128 行真实 logits            |                  0 |          9.54e−7 | 当前表达在这组残差计算上更接近参考           |
| `x=[1,1e−20,0]`、`y=[1,0,0]` |           约 1e−20 |                0 | 候选保留小输入差异；当前先减参考值会把它舍掉 |

真实数据共有 19,447,808 个残差元素，候选与现有算法在 299,948 个元素上不同。该计数及绝对误差是残差层测量，不是 KL、参数梯度误差或训练收益。没有在共享 GPU 上做速度结论。

最后一行是新确认的边界：FP32 输入里的 `1e−20` 本来可表示，但 `1e−20−1` 即使在 FP64 中也会舍入成 −1，后续相减无法恢复。因此此前修复的验收范围不等于任意尺度残差都精确。该输入不是保存的真实训练位置，本次未证明它影响正式训练。

κ=0 的推广也有独立约束。取 q logits 为 `[0,0]`、T logits 为 `[0,1]`、学生 logits 为 `[0,float32(0.3)]`，η 为配置中的 0.3。生产路径保留约 `1.1920929e−8` 的残差；将两次补偿差值的输出直接在 FP32 中做 η 组合会得到 0。上游的双分布差值修复不能未经推导和验证就替换三分布融合表达。

决定：保留现有生产算法，将补偿算法作为候选及独立反例记录。后续可考虑同时保存差值高低部分并在 η 组合后舍入，但须一起验证 `_difference`、`_split_residual`、Torch autograd 和所有 κ/η 边界。本次没有把候选接入训练。

| FSDP `actor.use_torch_compile=True`                            | 所查实现用于 entropy 计算函数                                                   | 不会仅因这个开关就把整条 loss 编译成旧 CE；默认 full-vocab 不计算 entropy                     |
| FlashAttention attention、vLLM CUDA Graph                      | 分别影响 backbone attention、rollout 生成                                       | 不替换我们的 loss；它们自身的舍入与生成/训练差异仍独立存在                                    |
| standalone sampled 配合通用 fused PPO head                     | 可以走 `dense_common` 的 Torch/Triton/Liger 分支                                | 不在上述 shared_sync 保证范围；其中 Torch 分支还直接调用 FlashAttention CE，反向有 `onehot−p` |
| 显式 `logprobs_from_logits_naive`、NPU 原生 CE                 | 保留原实现                                                                      | 不在本轮修复覆盖范围，默认本机 CUDA shared_sync 不走它们                                      |

`use_liger` 和 `full_vocab.backend=liger` 是两种独立配置，不能混为一谈。共享教师由独立 `HFModelConfig` 构造，不会直接继承学生的 `use_liger` 配置，但这不保证实际模块隔离：已安装 Liger 0.8.4 的 Qwen2/Qwen3 patch 即使传入 model instance，也会修改 `modeling_qwen*` 的 RoPE 函数、RMSNorm 和 MLP 类符号。

独立 CPU 进程中的小 Qwen2 构造实验已确认：actor 打补丁前 norm 为 `Qwen2RMSNorm`；仅给 actor 应用 FSDP 使用的参数后，同进程新建 teacher 的 norm/MLP 分别成为 `LigerRMSNorm` / `LigerSwiGLUMLP`，RoPE 全局函数也改变。actor 顶层 forward 保持 `Qwen2ForCausalLM.forward`，说明 FLCE 确实没有开启，但 backbone patch 会跨实例传播。复现脚本的 `--liger-scope` 可重跑该检查。

共享训练恰好把 teacher 和 actor 注册到同一个 colocated worker 进程，并在 actor `init_model()` 后调用 teacher `reset()`。因此同架构师生可能受此全局修改影响，不能仅看 teacher 配置里的 False 判断实际算子。默认 `use_liger=False` 不触发它；本次没有运行开启该选项的完整 Ray 训练，也没有擅自修改第三方 monkey patch。

Rollout 的 vLLM log-probability 是生成行为分布的数据，并不经过本项目的 actor CE 修复。它与训练端 log-probability 有差异时，需要核对采样协议与计算路径；不能为了数值一致而把行为 IS 分母擅自换成当前 actor 概率。

### 7.1 在已安装依赖上实测第三方出口

GPU 0 上只运行小张量算例，限制 allocator 为整卡的 5%；未启动训练。FlashAttention 2.8.3 的 CE 在 `[9,−9,−9]` 上仍返回 loss=0、目标梯度=0，而项目 CUDA CE 返回约 `3.046e−8` 和 `−3.046e−8`。

另取 student logits `[0,−24,−26]`，teacher `[0,−23.97,−26.02]`，通过 identity head 调用实际 `full_reverse_kl_result`，分别测试学生公共偏移 0、32：

| 实际 backend       | 两种偏移的 KL 值 | 参考词元梯度 |
| ------------------ | ---------------: | -----------: |
| 自有 `precompute`  |       1.8175e−14 |   1.0304e−12 |
| 已安装 Liger 0.8.4 |      −1.0304e−12 |            0 |

因此 `FULL_KL_BACKEND=liger` 的旁路风险已由当前安装包复现，不只是对第三方的假设。它仍是显式可选的外部对照 backend，本次没有擅自删除或把它重定向成不同实现；要保持本项目输出修复，使用自有 backend。
