# 大规模预训练后期的数值精度证据

调研日期：2026-10-25。问题是 _A Fix for Softmax and Cross-Entropy_ 中的现象在大规模预训练中是否常见，以及后期训练是否存在可测量的精度瓶颈。检索使用 paper-search、arXiv、OpenReview、会议论文集和作者技术报告；关键结论核对论文正文、实验设置与附录，而不依据二手摘要。这里报告文献证据，没有重新运行预训练。

## 1. 结论

现有公开证据没有建立“标准大规模 BF16/FP32 混合精度预训练普遍被输出交叉熵的 Softmax Collapse 卡住”这一结论。普通 next-token 预训练使用硬标签，也没有软标签蒸馏中接近教师的前提，因此不能直接套用 Softmax Cancellation 的蒸馏实验。

但是，大规模长期预训练的数值精度问题有直接证据，尤其包括 BF16 权重更新丢失、attention 反向误差、长训练下的 FP8 异常值，以及学习率衰减阶段的 FP4 量化损失差距。7B/2T-token 和 12B/10T-token 工作提供了实际长训练与干预结果。这些问题与输出 CE 的 $p_t-1$ 消减不是同一个机制，修复位置也不同。

需要区分三个判断：少量 token 的算子失真、整场训练被数值误差显著影响、某种故障在业界配方中的发生频率。检测到第一项不能直接证明第二项，个别受控训练也不能给出第三项的普遍比例。

## 3. 与输出 CE 最接近的直接证据

### 3.1 原论文没有验证大规模预训练收益

Barron 等明确承认，其实验涉及的极端 margin 和极小师生差异在常规大规模训练中不常见。其结果证明了修复在所研究场景中的作用，没有证明修复能够提升 7B/70B 模型的长程预训练 loss 或下游能力。[^fix]

在硬标签预训练中，触发 collapse 的条件是个别位置的正确 token 概率接近一，而不是训练时间长本身。对近似 FP32 阈值，残余质量 $r=\sum_{j\ne t}\exp(z_j-z_t)$ 降到 $10^{-7}$ 附近，$\log(1+r)$ 的标准计算开始危险。具体阈值取决于归约、绝对 logit 偏移、实际精度和反向 kernel。

语言数据中仍有不确定的 next-token 位置，不会像完全记忆的模运算训练集那样整体趋向零损失。但平均 loss 不低，也不能排除容易预测的少数位置已经 collapse。平均 loss、零 loss token 比例和梯度误差质量必须分别测量。

### 3.2 110M GPT 的局部 collapse，不等于修复已带来训练收益

Liu 等使用 110M nanoGPT，在 FineWeb 上训练约 100000 步、13.1B tokens。其语言建模配方使用 BF16 训练、FP32 loss、零 weight decay，序列长 2048，每步 131072 tokens。作者报告每步约 4000 个 token 的 loss 为精确零，约占 3%；高频发生位置包括数据模板中的 `example.org`、姓名字段等高度可预测内容。[^glitch]

这项证据足以反驳“语言模型预训练里根本不会出现 collapse”，却不足以给出生产配方中的发生率。尤其需要保留其反向结果：将 loss 改成 FP64，并没有抑制该设置中的 logit 增长；100000 步时 mean logit 由 FP32 loss 下的 183 增至 FP64 loss 下的 498。作者讨论了词频不平衡及输出 embedding 的公共均值分量。这不是精度修复降低语言模型训练 loss 的证据。

该论文附录还讨论了为何标准训练中可见 Slingshot 较少：权重衰减限制参数增长，未 collapse 样本持续提供梯度，mini-batch 训练不容易进入完全静默的梯度阶段。这里可以支持定性解释，不能把它当作所有现代配方都不受影响的定理。

## 4. BF16 attention 的后期故障

Qiu 与 Yao 的 GPT-2 Small 实验将问题定位在 FlashAttention 中由保存的输出构造反向归约的路径；其复现实验使用零 weight decay 和固定失败数据顺序。Llama-3.1-8B 附录展示的是相似结构模式，不能据此称为 8B 训练失败和修复的因果实验。[^flash]

Chen 等的最新预印本报告 450M Full-AttnRes 模型在 50B-token 训练中，约 25B tokens 后梯度异常增长，最终 loss 比 FP32 attention 高约 0.2 nats，且没有 NaN。其固定前向、替换反向的干预提供了较直接的数值归因。该配方关闭 QK normalization/softcapping、使用零 weight decay；附录的 102M 普通 Transformer 对照还显示，即使出现训练失稳，也可能无法归因于 attention 数值误差。[^symmetry]

这两篇支持“无 NaN 不代表梯度正确”，同时也要求避免把输出 softmax、attention softmax 和优化动力学混成一种故障。前者处理词表概率，后者处理序列中的注意力权重；仅更换输出 CE 无法修复 attention backward。

## 5. 真正达到 B 参数、T tokens 的后期精度证据

### 5.1 7B / 2T：长期权重演化暴露 FP8 异常值问题

Fishman 等的 7B Llama2 架构训练在约 220B tokens 后出现标准 FP8 发散，而较短实验看不出问题。作者把失稳联系到 SwiGLU 两支权重逐渐对齐，以及大激活被放大为异常值。Smooth-SwiGLU 配合低精度训练策略使模型能够训练到 2T tokens，结果接近 BF16。[^fp8]

这里“后期”的含义是运行足够久后出现新的张量分布，不一定是学习率退火的最后阶段。即便当时普通 token 的 CE 远没有接近零，异常值仍然可以让量化和 GEMM 失真。把 CE 换成 `log1p` 无法替代这个修复。

### 5.2 12B / 10T：学习率衰减阶段的精度差距

NVIDIA 在 12B Mamba–Transformer 混合模型上比较 NVFP4 与 FP8，训练 10T tokens。WSD 学习率在前 80% 保持稳定，后 20% 衰减。稳定阶段的相对 validation-loss 差距低于 1%，衰减阶段扩大到略高于 1.5%；这不是训练崩溃，下游表现仍大体接近。[^nvfp4]

附录 D 提供了直接干预：从 8.2T tokens 起将相应计算升至 BF16，能够追平 FP8 基线的 loss；更晚切换也有帮助，但恢复不完全。仅提升前向精度就把相对差距从约 1.5% 降到约 0.5%，而只提升反向没有同样改善。该设置中的主要问题不能被概括成“反向小梯度被抹掉”。

这项证据最直接回答“预训练后期精度是否可能限制进一步降低 loss”。它支持肯定答案，同时限定在所测试的 FP4 混合精度配方与模型架构，不能外推为所有 BF16 训练都有相同差距。

### 5.3 Gopher：小更新落不进 BF16 参数

Gopher 报告，在 BF16 参数训练中，小学习率和小更新会使许多参数连续多步没有变化。其机制可以写成

$$
\operatorname{round}_{\mathrm{BF16}}(w+\Delta w)=w.
$$

这时梯度本身可以是正确的，问题发生在参数更新写回。作者使用 417M 对照分析，并推荐保存用于优化器更新的 FP32 参数副本。其所有精度对照都已经用 FP32 计算 attention softmax 和输出 softmax CE。[^gopher]

因此，“梯度为零”“梯度错误”“参数不变”需要分开诊断。现代混合精度配方常用 FP32 master weights 来避免这一问题；是否已采取保护比模型被笼统称为 BF16 更重要。

## 6. 稳定运行的反向证据

DeepSeek-V3 在 671B 总参数、14.8T-token 的训练中使用 FP8 GEMM，但对 embedding、输出头、attention、归一化等保留 BF16/FP32，并保留 FP32 master weights 和梯度累积。报告指出 H800 FP8 GEMM 的累积精度需要额外保护，并使用周期性高精度累积。作者报告没有不可恢复的 loss spike 或训练回滚。[^deepseek]

这支持“合理的精度分配可以支持大规模稳定训练”，并不证明所有小误差都不存在。成功的配方本身包含数值工程保护，所以不能用成功训练来证明这些保护没有必要。

## 8. 对当前 OPD 分析的修正与延伸

此前对 Full-KL 的判断仅覆盖 head/loss 的局部数值路径：它没有显示被输出 CE collapse 主导。这个判断不自动覆盖 backbone attention、BF16 参数更新、归约或低位宽量化。大规模预训练文献中的其他故障，在数学上可以独立于 Full-KL 的正确性存在。

如果需要验证实际训练后期，应该固定相同 checkpoint、相同 batch、相同前向激活，逐层改变一个数值环节，测量 logits/head/hidden/parameter 梯度的相对误差、方向和实际 optimizer 更新。只有保持输入与训练状态一致的高精度干预，才能把 precision 问题与数据、目标函数、学习率和一般优化困难区分开。
