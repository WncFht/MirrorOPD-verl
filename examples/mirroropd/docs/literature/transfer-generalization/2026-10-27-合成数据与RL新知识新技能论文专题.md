# 合成数据与 RL 新知识、新技能论文专题

核验日期：2026-10-27。本文从[原 32 篇调研](2026-10-27-LLM的RL与SFT迁移泛化论文调研.md)抽出合成任务研究，并补充 7 篇。原清单编号 A1–F5 保持不变。重点核对两篇候选论文及三篇新增近邻的正文；其他原清单论文复用已核对内容，对 Reusable Modules 进一步读取了合成任务设置。

## 1. 刘知远参与的两篇高匹配候选

最可能对应“合成数据检验 RL 能不能学到新能力”的，是 **From f(x) and g(x) to f(g(x)): LLMs Learn New Skills in RL by Composing Old Ones**，arXiv:2509.25123，2025-09-29 首发。作者包括 Lifan Yuan、Weize Chen、Yuchen Zhang、Ganqu Cui、Ning Ding、Zhiyuan Liu、Maosong Sun、Hao Peng 等。[^composition]

若记忆中的“新知识”特指学习一个新库或新 API，则 **SE-Bench: Benchmarking Self-Evolution with Knowledge Internalization** 更匹配，arXiv:2602.04811，2026-02-04 首发。v1 作者列表包含 Zhiyuan Liu 和 Maosong Sun；当前 v2 页面列出 Jiarui Yuan、Tailin Jin、Weize Chen、Zeyuan Liu 四位作者。这里记录版本差异，不推断变更原因。[^se-v1][^se-v2]

两篇都未进入上一轮 32 篇推荐，本专题补入。作者主页确认 Lifan Yuan 曾与刘知远在 THUNLP 合作；不据此把论文简化为单一机构或导师团队的成果。[^yuan]

## 2. 优先阅读：From f(x)…

### 2.1 合成与训练设置

论文构造 25 个确定性字符串变换，并使用无语义函数名。第一阶段先带函数定义生成正确轨迹，再移除定义做 rejection fine-tuning（RFT），让模型内化原子函数；第二阶段仍不提供定义，在函数组合题上比较 RFT 与 GRPO。作者代码公开了生成器及两阶段脚本，基于 verl。[^composition][^composition-code]

难度由嵌套深度控制；评估既包含未见组合，也包含更深组合。另一个实验只在字符串任务上做第二阶段 RL，测试是否迁移到 Countdown，并控制模型是否事先掌握 Countdown 的原子能力。

### 2.2 结论与边界

组合训练和 RL 同时存在时，受测模型在未见组合与更高难度上取得更好表现，并在目标原子能力已具备时出现跨任务迁移。作者还检查了大采样预算下的题目覆盖，避免仅用 pass@1 支持“新技能”。优先读第 3 节及第 4.1–4.4 节。[^composition]

这里的新能力是组合方式。函数定义已经通过第一阶段示范提供，不能解释成 RL 凭空获得未知函数语义。Countdown 实验的 Avg@32 是多次回答的平均正确率，不是“32 次中任一次成功”的 pass@32；合成结果也不能直接覆盖全部自然语言推理。

### 2.3 与当前研究的连接

若用它比较 SFT、RL 和 OPD，最有价值的是固定原子技能初始化，再分别改变监督目标与轨迹来源；独立控制组合深度、原子函数集合和训练组合支持集。仅在同题随机划分上提升，还不足以识别组合泛化。这是由论文设置导出的实验建议，尚未执行。

## 3. 直接研究知识内化：SE-Bench

### 3.1 合成方式与评估

SE-Bench 将 268 个 NumPy API 包装成随机命名的 ZWC 接口，并构造单函数与多函数编程题。训练覆盖单函数，测试撤掉 API 文档；通过执行与语法检查限制绕回 NumPy 的捷径。新信息主要是随机 API 映射，题目的数学功能仍来自熟悉的库。[^se-v2]

这比直接使用新近自然事实更容易隔离预训练先验：要分别测模型“看文档会做”和“撤掉文档仍会做”。它仍是伪新库，不能代表所有开放式知识获取。

### 3.2 核心对照

作者发现，带文档生成轨迹、去掉文档做 SFT 更新的 Closed-SFT 能学到部分映射；所测 Open／Closed-RL 配方表现很弱。消融将失败关联到 clipping 和组归一化优势中的负更新，但具体机制仍有待验证。[^se-v2]

阅读第 4.2 节时应记录一个实现条件：有文档 rollout 与无文档更新存在条件分布变化，论文没有采用理论上对应的完整跨条件重要性比率。因此，这是特定知识内化设置和优化配方的结果，不是所有 RL 都不能学习新知识的证明。

### 3.3 为什么适合补到 OPD 研究中

它提供了清晰的知识入口：teacher 能访问 API 文档，student 测试时不能。可以在固定生成样本与预算下比较 Closed-SFT、teacher soft targets 的蒸馏、仅结果奖励的 RL，以及先内化后 RL。知识保持、未见单函数题和多函数组合应分别报告。该方案是本专题提出的延伸，不是原论文已完成的 OPD 对照。

## 5. 其他新增近邻论文

### 5.1 Decomposing Elements of Problem Solving: What “Math” Does RL Teach?

Tian Qin 等，2025-05，arXiv:2505.22756。推荐放在两篇候选和 Atomic Skills 之后。[^decompose]

论文将解题拆成规划、执行与验证，并构造合成状态转移／解题树任务；可控制预训练中的伪相关、动作空间和 RL 数据量。受测 GRPO 的大部分收益来自执行更稳定，但在去除伪相关、简化探索或扩充数据等设置下，覆盖也可以改善。

它帮助分析“新能力”的收益来源，提供偏保守结果与可改变条件。合成部分使用受控训练的自回归 Transformer，应与自然数学 LLM 实验分别解释。

### 5.2 RL for Reasoning by Adaptively Revealing Rationales

Mohammad Hossein Amani 等，2025-06，arXiv:2506.18110。方法名 AdaBack。[^adaback]

构造 Chain-of-Parities：输出步骤必须满足递归 XOR 约束，早期错误会沿链传播；随机获得全正确结果的概率随长度指数下降。AdaBack 根据成功情况提供不同长度的正确前缀，再逐步撤掉辅助。

它直接研究稀疏奖励、学习信号和困难任务的可学性。结论依赖部分正确轨迹这一额外监督，适合研究 SFT/RL 中间机制，不能当作纯终局奖励 RL 自发获得技能的证据。

### 5.3 Learning from Synthetic Data Improves Multi-hop Reasoning

Anmol Kabra 等，ICLR 2026，arXiv:2603.02091。推荐用于连接可控合成实验与真实任务迁移。[^multihop]

训练使用 PhantomWiki、GSM-Infinite、ReasoningGym 的 Family-Relationships 与 Knights-Knaves。虚构人物、关系和规则题经过程序生成，可验证并控制跳数；评估包括 HotpotQA、2WikiMultihopQA、MuSiQue 等。

论文报告合成到真实任务的迁移，并做格式奖励消融。它支持知识组合过程可迁移，不意味着从虚构事实学到了测试域的新事实；目标任务已有知识及上下文提供的信息仍需区分。

### 5.4 Logic-RL: Unleashing LLM Reasoning with Rule-Based Reinforcement Learning

Tian Xie 等，2025-02，arXiv:2502.14768。[^logic]

用可控复杂度、可验证的合成逻辑题训练，报告向数学任务的迁移。适合验证简单逻辑环境是否提供跨任务收益。

与 From f(x)… 相比，它对原子技能是否预先具备的控制较弱。出现反思等输出行为本身也不证明对应技能首次形成；应结合成功率、题目覆盖和过程验证。

### 5.5 RLVE: Scaling Up Reinforcement Learning for Language Models with Adaptive Verifiable Environments

Zhiyuan Zeng 等，2025 首发／ICML 2026，arXiv:2511.07317。[^rlve]

RLVE-Gym 包含 400 个程序生成、算法验证的环境，按策略能力调整难度分布。它适合把单一玩具任务扩展成多环境训练和迁移评估，也与原清单的路线多样性研究衔接。

其主要证据是环境规模、课程和外部基准收益，不是严格隔离某一随机新事实的参数记忆。若研究新知识内化，应额外采用 SE-Bench 式的信息控制。

## 6. 教师生成的监督数据另作一类

“合成数据”也可能仅指由模型生成答案、CoT 或改写。它可以很好地研究监督迁移，但不会自动保证新知识未进入学生预训练。

| 原清单中的代表                                             | 合成对象                   | 与本专题受控任务的区别                               |
| ---------------------------------------------------------- | -------------------------- | ---------------------------------------------------- |
| A1 — Does Math Reasoning Improve General LLM Capabilities? | 教师数学 CoT               | 题目和技能可能已在预训练中；重点是跨域后训练效果。   |
| F2 — DeepSeek-R1                                           | 推理轨迹与蒸馏数据         | 外部教师可提供新的行为和信息，需区分蒸馏与纯 RL。    |
| E2 — ReLIFT                                                | 困难题的高质量示范         | 学生新增能力可能通过示范进入，不能只归因于后续 RL。  |
| E4 — Finetuning with Sampling                              | 调整得更匹配学生的专家轨迹 | 主要控制监督分布匹配，没有完全消除底模先验。         |
| C5 — ReasonXL                                              | 平行多语言推理数据         | 主要控制语言与能力保留。                             |
| F5 — STaR                                                  | 模型生成并筛选的推理过程   | 属于自训练／推理监督路线，不是随机新知识的专门诊断。 |

这些条目的来源和完整分析见[总调研](2026-10-27-LLM的RL与SFT迁移泛化论文调研.md)。

## 7. 建议的阅读顺序与实验选择

| 优先级 | 论文                                                                     | 放在这里的原因                                             |

|      1 | From f(x)…                                                               | 最匹配用户的团队与合成技能线索；组合、外推和迁移控制清晰。 |
|      2 | SE-Bench                                                                 | 与第一篇并列区分“新组合”和“新知识映射内化”。               |

|      7 | Learning from Synthetic Data Improves Multi-hop Reasoning                | 连接可控合成与真实领域迁移。                               |

|      9 | Debunk the Myth of SFT Generalization                                    | 防止固定提示和示范质量导致不公平的 SFT 对照。              |

如果优先搭一个与本仓库相关、计算量可控的实验，建议使用两套互补任务：字符串组合检验“技能已知时能否形成新策略”；随机 API 映射检验“外部信息能否进入参数”。不把二者合成单一总分。

应固定或分别记录：新信息首次出现的位置、原子技能掌握程度、teacher/student 可见上下文、采样与更新所用条件、轨迹来源、训练和推理预算、未见划分，以及 pass@1／pass@k／Avg@k 的区别。上述实验建议未执行，也不把有限预算下的零成功率解释成数学上的零概率。
