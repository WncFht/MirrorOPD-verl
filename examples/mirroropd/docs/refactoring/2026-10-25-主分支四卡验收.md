# 主分支四卡验收

2026-10-25，在本机 GPU 0–3（四张 H800 80GB）上完成四组分布式集成测试和两条真实 1.5B 短训练，全部通过。验收代码为主分支 `5f1a0cee82dfabeaee855fc307c5208d9a9ec858`；运行前仅将 full-vocab 测试中写死的两卡计数改为根据 `world_size` 计算，训练实现没有变化。

本次直接验证合并后的主分支，补充[此前实施验收](2026-10-25-架构重构实施与验收.md)。此前的 CPU 回归和基点数值对照没有在本次重复运行。

## 1. 环境和隔离

所有 GPU 进程设置 `CUDA_VISIBLE_DEVICES=0,1,2,3`；各组测试顺序运行。真实训练使用独立本地 Ray session，明确申请 4 GPU。GPU 4–7 的既有任务未停止、未参与测试。

使用既有原生环境 `/root/.local/share/mirroropd/venvs/profile-cu128/bin/python`：Python 3.12.11、PyTorch 2.11.0+cu128、Transformers 5.12.1、vLLM 0.25.1+cu129、Ray 2.56.1。没有安装依赖或升级驱动。结束后 GPU 0–3 均恢复到 1 MiB、0% 利用率，见[环境及退出后状态](data/2026-10-25-main-four-gpu/README.md)。

## 2. 四卡分布式集成测试

| 测试 | 配置与检查 | 结果 |
| --- | --- | --- |
| Full-KL native | 合成小型 Qwen2，`precompute`，教师比学生多 4 个词表行 | 通过 |
| Full-KL fused | 合成小型 Qwen3，`precompute_fused`，师生均 tied head；学生 hidden 32、教师 hidden 64；教师多 4 个词表行 | 通过 |
| Sampled/current-IS | `token_is/current`，每批复用 4 次，tied embedding | 通过，恢复后累计 14 次更新 |
| Sampled/frozen-PPO | `token_ppo/rollout`，每批复用 2 次 | 通过，恢复后累计 8 次更新 |

两组 Full-KL 测试均验证了以下行为：

1. 第一次更新的 loss 与独立 dense 参考计算相符，误差小于 `5e-4`；head 和 transformer 参数实际发生更新。
2. 三批数据的全局有效 token 数分别为 16、12、16。第二批 rank 0 的 mask 全空，仍能正常完成四卡归约和更新；位置分桶计数符合预期。
3. 保存并恢复参数、完整 Adam 状态和 scheduler 状态；恢复后对相同数据再更新一次，与未中断分支逐 rank 精确一致，比较容差为 `atol=0, rtol=0`。

这两组使用不同模型配置，不能用它们的 loss 差值判断 native 与 fused 的数值差异。完整结果分别见 [Qwen2 native](data/2026-10-25-main-four-gpu/full-qwen2.json) 和 [Qwen3 fused](data/2026-10-25-main-four-gpu/full-qwen3-fused.json)。

## 3. 真实模型短训练设置

| 项目 | 本次配置 |
| --- | --- |
| Student | `DeepSeek-R1-Distill-Qwen-1.5B` |
| Teacher | `JustRL-DeepSeek-1.5B` |
| 执行方式 | `shared_sync`，四卡 FSDP2；师生轮流使用同组 GPU |
| 训练数据 | 本机 DAPO；数据集加载上限 64 条，本次执行 2 个 batch |
| Batch / reuse | batch 8，`ppo_epochs=2`，共 4 次 optimizer update |
| 学习率 | `1e-6`，constant scheduler；Adam betas `(0.9, 0.999)`，weight decay `0.01` |
| 长度 | prompt cap 1024；训练及验证 response cap 512 |
| 训练采样 | 每题 1 条，temperature 1.0，top-p 1.0，top-k 不截断 |
| Sampled 目标 | `k1`，`use_policy_gradient=True`，`advantage_source=current`，`policy_loss_mode=vanilla`；不混合任务奖励 |
| Full-vocab 目标 | `full_reverse_kl`，`precompute`，token chunk 512、vocab chunk 8192，异步写入与预取均开启；不混合任务奖励 |
| 验证 | MATH-500、AMC23、AIME25 各取原始文件第一题；每题 1 条，temperature 0.7、top-p 0.9 |
| 日志及 checkpoint | console + file，W&B disabled；两批结束后验证；真实短训练不保存 checkpoint |

小模型集成测试中的 current-IS/frozen-PPO 配置与真实 sampled 短训练的 vanilla 配置是不同覆盖项。真实短训练的完整参数以[解析后的配置和实际命令](data/2026-10-25-main-four-gpu/README.md)为准。

### 更新和位置统计

| Optimizer update | Outer step | Sampled loss | Full-vocab loss |
| --- | --- | --- | --- |
| 1 | 1 | 0.11394158 | 0.11198634 |
| 2 | 1 | 0.11319268 | 0.11147654 |
| 3 | 2 | 0.10830109 | 0.10089839 |
| 4 | 2 | 0.10762525 | 0.10094048 |

两条运行的四次更新均有 `update_applied=1`、`update_skipped=0`，loss 和梯度范数均有限。`step/update` 与 `step/optimizer` 都为 1、2、3、4，`step/outer` 为 1、1、2、2；`lr_next` 只在更新 2、4 出现，符合每轮复用结束时推进 scheduler 的既有语义。

Full-vocab 每次更新均产生 10 个相对位置区间的 `sum`、`token_count` 和 `mean`。每次的计数之和为 4096；区间内部的 `sum / token_count` 与对应 `mean` 相符。用所有区间重建整体 KL：

\[
\mathrm{KL}_{\mathrm{reconstructed}}
=\frac{\sum_{b=1}^{10}\mathrm{sum}_b}
       {\sum_{b=1}^{10}\mathrm{token\_count}_b}.
\]

四次更新中，与 `distill/full_kl` 的最大绝对误差为 **2.59325 × 10⁻⁹**。前三个区间的前缀均值也应按相同的加总后相除方式重建。

三个验证集均成功输出指标。两条运行各自的三项单题 accuracy 都是 0；此处只据此确认验证链路完成，不作模型能力结论。完整检查结果见 [summary.json](data/2026-10-25-main-four-gpu/summary.json)。

## 4. 结论的适用范围

本次覆盖四卡通信、师生切换、真实生成与评分、重复更新、更新日志、位置统计及验证链路；checkpoint 的精确恢复由四卡小模型集成测试覆盖。

本次没有运行长回答、长时间训练、完整验证集或真实 1.5B checkpoint 恢复，也没有执行真实 1.5B fused 短训练。Full-vocab 第四次 loss 比第三次略高，因此这四个更新不能证明单调下降或长期收敛，更不能作为论文 failure 复现或 full-vocab 改善效果的证据。

本次代码差异只有测试计数适配；其余新增内容为本验收文档及证据。没有推送或部署。原始完整运行目录为仓库下 `outputs/main-four-gpu-20261025-0f02312b/`。
