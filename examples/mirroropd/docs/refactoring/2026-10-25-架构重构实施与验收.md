## 1. 已裁决的归一化与时钟契约

真实TQ存储及FSDP批归一化检查确认：拒绝采样更新 `response_mask` 后，`loss_mask` 保留原始有效token总体。两个回答原有6个token、筛选后保留3个时，单位token损失的全局均值和参数梯度都是0.5；微批切成1个或2个回答不改变结果。

本轮明确保留这个行为：拒绝的token作为原总体中的零贡献，不对保留token重新归一化。它与按保留样本条件平均是不同目标；若未来实验需要后者，须作为独立算法变更，不混入重构。

| 对象 | 冻结的含义 |
| --- | --- |
| `loss_mask` | 原始训练资格与全局token归一化总体 |
| `response_mask` | 当前目标实际应用位置，可因拒绝采样而减少 |
| `metrics_response_mask` | 筛选前诊断总体，按既有使用点保留 |
| 明确传入的sequence分母 | 保留配置的全局batch数，包括零贡献的空sequence |
| 全部token被拒绝但原始总体非空 | 允许零loss／零梯度，不自动改变optimizer执行政策 |
| 原始全局 `loss_mask` 为零 | 训练入口拒绝，不用零分母继续计算 |

测试使用真实独立Ray／TQ与Gloo进程组，执行原FSDP批归一化和backward；只有模型forward与微批划分替换为受控CPU实现。没有连接或停止已有Ray集群。

Scheduler保留每次 `train_mini_batch` 末轮推进一次的规则。现有pipeline测试仍验证4次尝试、3次实际执行、scheduler推进1次；完整scheduler checkpoint恢复将在后续集成阶段补充。
