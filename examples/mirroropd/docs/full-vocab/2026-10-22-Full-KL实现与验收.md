# Full-KL 实现与验收

## 1. 实现范围

单 teacher 的 full-vocab reverse KL 已接入 FSDP2 shared-sync 训练。流程是 student rollout → teacher 输出有效预测位置的 hidden → teacher backbone offload → student 当前有梯度 forward → head-loss 算子 → backward/optimizer。该路径跳过 old-log-prob、PG advantage/return 与 sampled-action IS；reward 分数仍可供任务指标使用。

本轮只实现直接 reverse-KL loss。Full baseline、多 teacher、SP>1、词表 TP、LoRA/tied head 仍不在当前支持范围。Teacher/student 均要求已适配的 untied Qwen2，使用相同 token ID 语义、temperature=1、全局 token-mean。Math/code/IF 共用实现，不按领域复制 loss。

数学定义和资源公式分别复用[计算图说明](../opd-objective/2026-10-21-Reverse-KL实验排序与Top-k支持集.md#2-full-vocab-kl一个真值不同计算图)与[共用预算](2026-10-22-词表蒸馏的计算与显存预算.md)。[原实现计划](2026-10-22-Full-baseline与Full-KL实现计划.md)保留阶段背景，本页是已实现接口和验收状态的入口。

## 2. 代码职责

| 位置 | 职责 |
| --- | --- |
| `verl/models/transformers/full_vocab.py` | 按模型实例安装 Qwen2 adapter；经过正常 root 和 `lm_head` forward，保留两层 FSDP hooks |
| `verl/trainer/distillation/full_vocab.py` | 纯张量 KL 总和及一阶 VJP；teacher 无梯度，student hidden/head 均求导 |
| `verl/trainer/distillation/hidden.py` | 预测位置映射、只加载 safetensors teacher head、独立 CPU/GPU 生命周期 |
| `verl/trainer/distillation/hidden_io.py` | micro-batch 读写、一个 pending write 的背压、一个后续 batch 的预取 |
| `verl/utils/transferqueue_utils.py` | 将 KV 或索引式 BatchMeta 中的样本 key 保留为随样本重排的字段 |
| `verl/workers/engine/fsdp/transformer_impl.py` | 复用现有 micro-batch/同步循环，在 head 前消费 compact hidden，输出总和与有效 token 数 |
| `verl/trainer/distillation/losses.py` | 一处完成全局 token 归一化，记录真实 KL，不构造 sampled advantage |
| `verl/trainer/ppo/v1/trainer_base.py` | Teacher/actor 调度，跳过不需要的评分和优势，按 micro-batch 读取大 payload |

Teacher head 不注册到 student module，也不进入 student optimizer、checkpoint 或 rollout 权重导出。重计算 backend 在 backward 完成前保留所需 hidden/head；actor 更新结束后释放 GPU 上的冻结 teacher head。Teacher 输出每个 micro-batch 后将 hidden 搬到 CPU，避免在 GPU 上累积整批结果。

位置以每条样本的预测行表示；首个 response token 使用最后一个 prompt 位置的 hidden。Teacher 和 student 使用同一位置函数，并在更新时比较位置记录。工具结果、padding 和其他 mask=0 的位置不传输；完整上下文仍用于 backbone 前向。读取的 sample key 跟随 TensorDict 的 shuffle 和动态 micro-batch 重排。

## 3. 启动与配置

入口是 [run_full_reverse_kl.sh](../../run_full_reverse_kl.sh)。它复用已有公共配方并设置 `loss_mode=full_reverse_kl`、`use_policy_gradient=False`、禁用额外 task reward/entropy 与 rollout sampled log-prob。数学目标只有一个配置入口，不另加 `objective` 或 `use_full_vocab`。

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 STUDENT_GPUS=4 DOMAIN=math \
FULL_KL_BACKEND=precompute FULL_KL_ASYNC_WRITE=True FULL_KL_PREFETCH=True \
bash examples/mirroropd/run_full_reverse_kl.sh
```

默认路径沿用仓库 `.venv-native/bin/python`、同级 `model/` 和 `data/`。本机实验显式覆盖 `PYTHON_BIN=/root/.local/share/mirroropd/venvs/profile-cu128/bin/python`、`MODEL_ROOT=../models`、`DATA_ROOT=../MD-OPD/data`。CUDA 可见卡数与 `STUDENT_GPUS` 必须匹配分配的资源；小实验另显式指定 Ray `num_gpus`。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `DOMAIN` | `math` | 也可选择 `code`、`if`，沿用对应数据/teacher/判分设置 |
| `FULL_KL_BACKEND` | `recompute` | 明确选择下表算子；不按可用显存静默切换 |
| `FULL_KL_TOKEN_CHUNK` | 512 | 预测位置分块大小 |
| `FULL_KL_VOCAB_CHUNK` | 8192 | cached/streaming 的词表分块大小 |
| `FULL_KL_ASYNC_WRITE` | False | Teacher 的 CPU hidden 写 TQ 与下一 micro-batch 计算重叠 |
| `FULL_KL_PREFETCH` | False | Actor 预取下一 micro-batch 的 CPU hidden |

直接 Hydra 配置位于 `distillation.distillation_loss.full_vocab`，字段为 `backend`、`token_chunk_size`、`vocab_chunk_size`、`async_write`、`prefetch`。两种 I/O 选项默认关闭，便于独立消融。预取当前只覆盖 TQ→CPU，不宣称完成 CUDA copy-stream 的 H2D 重叠。

不支持的组合提前报错，包括 standalone teacher pool、SP>1、静态 packed padding、非 Qwen2、tied head、LoRA、额外 KL reward/critic、非 token-mean、非单位温度和 sampled-policy diagnostics。旧 sampled-token 启动入口保持原默认值。

## 4. 算子选择与实际优化

| Backend | 前向与反向组织 | 适用目的 |
| --- | --- | --- |
| `dense` | 全 logits 与普通 KL autograd | 小规模数值参照，长 micro-batch 可能 OOM |
| `recompute` | Token 分块，反向重新投影完整词表块 | 可读的初始训练实现 |
| `cached` | Token/vocab 二维投影，复用当前 token 块完整 logits 缓存，再逐词表块归约；反向重投影 | 对照 reference 的缓存与重计算策略 |
| `streaming` | 在线词表归约，只保存每位置统计；反向重投影小块 | 低显存候选 |
| `precompute` | 当前 token 块内计算并累计 hidden/head 梯度，及时释放 logits | 避免 backward 再投影，性能候选 |
| `liger` | `LigerFusedLinearJSD(jsd_beta=1, accum_dtype=float32)`，将 local mean 转为 token sum | 现成融合算子对照，要求安装版支持该接口 |

所有训练 backend 返回未归一化 KL 总和，外层乘 DP size/全局有效 token 数，避免 micro-batch mean 等权累加。全零局部 mask 仍返回连接 student hidden 和 head 的零 loss，保持 FSDP 参与；全局有效 token 数为零则报错。

CUDA BF16 GEMM 输入直接产生 FP32 logits；归一化和梯度累积使用 FP32。当前 PyTorch 的 `mm(out_dtype=float32)` 缺少自动求导，因此 dense 参照的线性部分使用标准 VJP 包装。自定义算子只保证一阶导数。CPU FP64 使用独立 dense autograd 校验。

已完成的内存优化包括：FP32 accumulator 上直接 `addmm`，避免每块额外分配完整 head 梯度；原地复用 log-gap/gradient buffer；明确释放 token/vocab 块的临时量；cached backend 复用固定 cache，不跨 token 块重新累积缓存。上述 PyTorch/cuBLAS 实现不声称逐 kernel 复刻参考文章未公开的 Chunked cuBLAS。

生产算子基准脚本为 [benchmark_full_kl.py](scripts/benchmark_full_kl.py)。初始实现与 buffer/累积优化后的原始结果分别为 [kernel-before.json](data/implementation-20261022/kernel-before.json)和 [kernel-after.json](data/implementation-20261022/kernel-after.json)。实测是 H800 单卡、synthetic hidden、V=151936、hidden=1536，包含 head-loss 前反向，排除 backbone、FSDP、TQ 和 optimizer。报告 allocated 峰值，不是 NVML 整卡峰值。

最终实现的 [kernel-final.json](data/implementation-20261022/kernel-final.json) 包含 cached 和显式释放块临时量后的完整对照。4096 位置、token chunk=512 的测量如下：

| Backend | 前反向中位数 | allocated 峰值 |
| --- | ---: | ---: |
| dense | 37.40 ms | 12.55 GiB |
| recompute | 61.87 ms | 3.30 GiB |
| cached | 71.59 ms | 2.30 GiB |
| streaming | 70.93 ms | 2.30 GiB |
| precompute | 37.40 ms | 3.15 GiB |
| liger | 130.58 ms | 2.47 GiB |

该形状下 precompute 与 dense 耗时接近，allocated 峰值低约 75%；这不证明所有长度或设备上最优。Cached 与 streaming 的整体峰值接近，是因为梯度 accumulator/返回缓冲等公共部分限制了峰值，不能仅按前向 logits 缓存大小推断整个算子的峰值。

另对默认 micro-token 预算 32768 做了 [head-loss 容量实验](data/implementation-20261022/capacity-32k.json)。这里使用 streaming 作为跨 backend 参照，避免 dense 工作区 OOM；数学正确性仍由小规模 dense/FP64 检查支持。

| Backend | 32768 位置前反向 | allocated 峰值 |
| --- | ---: | ---: |
| cached | 567.36 ms | 2.71 GiB |
| streaming | 562.79 ms | 2.71 GiB |
| precompute | 288.00 ms | 3.48 GiB |

容量实验只覆盖输出头与 loss，不包括 32768-token backbone 激活或完整训练，也不将此显存直接称为整卡训练峰值。

## 5. 验收证据

| 范围 | 已有证据 |
| --- | --- |
| CPU 回归 | 259 项通过，含原 sampled loss、TQ bridge、shared teacher、指标和 launcher；后续专项测试覆盖新增模式，计数相互重叠 |
| 数值/VJP | FP64 独立 dense 对照，空局部位置、不同 hidden size、不整除 tile、teacher 无梯度、非单位上游梯度 |
| I/O | 同步/异步 key 顺序、预取与当前消费重叠、读写错误传播、线程结束、索引式 TQ metadata 恢复 key |
| 两卡 FSDP2 | 五个初始 backend 三次真实更新；不等长 packed 输入、工具位置 mask、一个 rank 全零 mask，head/backbone 都更新 |
| 四卡 cached | 三次真实更新、全零局部 mask、与 dense 前向对齐；checkpoint 扰动后逐元素恢复 |
| Checkpoint | Streaming 两卡保存 model/optimizer/RNG/scheduler，扰动参数后加载；参数逐元素恢复 |
| 真实 teacher 重建 | 三个实际 teacher，各三段输入，BF16 hidden/head 重建 logits 与原模型逐元素一致 |

原始证据位于 [implementation-20261022](data/implementation-20261022/verification.json)。真实 teacher 审计使用 SDPA 单模型前向，不替代多轮 IF 的数据与验证协议测试；三领域 launcher 已做配置检查，不能据此声称三领域训练准确率已验证。

## 6. 实验复现与运行环境

```bash
CHECK_PYTHON=/root/.local/share/mirroropd/venvs/profile-cu128/bin/python
CUDA_VISIBLE_DEVICES='' "$CHECK_PYTHON" -m pytest \
  tests/trainer/distillation/test_full_vocab_on_cpu.py \
  tests/trainer/distillation/test_hidden_io_on_cpu.py -q

CUDA_VISIBLE_DEVICES=0,1 "$CHECK_PYTHON" -m torch.distributed.run \
  --standalone --nproc-per-node=2 tests/special_distributed/test_full_vocab_fsdp2.py \
  --backend streaming --checkpoint --output /tmp/full-kl-fsdp-checkpoint.json

CUDA_VISIBLE_DEVICES=0 "$CHECK_PYTHON" \
  examples/mirroropd/docs/full-vocab/scripts/verify_teacher_hidden.py \
  --model-root ../models --output /tmp/teacher-reconstruction.json

CUDA_VISIBLE_DEVICES=0 "$CHECK_PYTHON" \
  examples/mirroropd/docs/full-vocab/scripts/benchmark_full_kl.py \
  --output /tmp/full-kl-kernels.json
```

这些 GPU 命令需要调用者事先分配空闲卡。本机使用的 driver 为 550.163.01；短上下文 vLLM smoke 曾在 FA3 初始化遇到非法显存访问，显式 FA2 又遇到预编译 PTX 工具链不兼容。独立 `TRITON_ATTN` 生成通过，完整 smoke 使用该 rollout override；训练侧 FSDP/FlashAttention 和 KL backend 不因此改变。不修改宿主机驱动或覆盖环境中的依赖包。

### 完整训练 smoke

四卡 H800 的真实 math smoke 已退出码 0 完成两步，backend=precompute、async_write=True、prefetch=True；batch=8、prompt≤256、response≤128、micro-token=384，使用原 JustRL→R1-Distill-1.5B 权重。原始[指标](data/implementation-20261022/smoke4.json)、[解析配置](data/implementation-20261022/smoke4-resolved_config.yaml)和[实际命令](data/implementation-20261022/smoke4-command.sh)已保存。

| Step | KL loss | Optimizer 累计更新 | Teacher forward | Actor update |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.0771442 | 1 | 0.599 s | 5.555 s |
| 2 | 0.0643552 | 2 | 0.303 s | 3.447 s |

两步的前缀不同，loss 下降不能作为收敛结论。没有运行验证或长程准确率实验，128-token smoke 也不能代表默认 7168-token 配方的显存/吞吐。初步测试确认连续 teacher/actor 切换、TQ hidden 传递、head/backbone 更新和 optimizer 计数可用；old-log-prob 与 advantage 阶段均未执行。
