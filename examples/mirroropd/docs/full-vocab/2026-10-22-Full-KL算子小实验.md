# Full-KL 算子小实验

## 1. 实验范围

2026-10-22 在本机空闲的 GPU 0（H800 80GB）运行独立算子实验，使用 `CUDA_VISIBLE_DEVICES=0`，不占用 GPU 4–7。输入是随机 hidden 与 head，不加载真实模型，没有 backbone、FSDP、TQ、optimizer、rollout 或验证任务。本实验用于选择实现路径，不提供训练准确率和端到端加速结论。

脚本是 [probe_full_kl.py](scripts/probe_full_kl.py)，原始结果为 [CPU 审计](data/probe-20261022/cpu.json)和 [H800 数值/性能](data/probe-20261022/h800.json)。理论与容量不在本页重复，见[共用预算](2026-10-22-词表蒸馏的计算与显存预算.md)；接入步骤见[实现计划](2026-10-22-Full-baseline与Full-KL实现计划.md)。

## 2. 实验条件与口径

| 项目 | 取值 |
| --- | --- |
| PyTorch / CUDA | 2.11.0+cu128 / 12.8 |
| Liger 包版本 | 0.8.4；记录实际安装路径，版本号不保证等同上游发行源码 |
| Liger 入口 | `liger_kernel.transformers.fused_linear_jsd.LigerFusedLinearJSD`，`jsd_beta=1.0` |
| Student/teacher hidden size | 1536 / 1536 |
| 词表大小 | 151936，与当前三个领域模型配置一致 |
| 位置数 | 512、4096；每个位置都参与 loss |
| 输入与权重 | BF16；随机种子 42，head 按 hidden size 平方根缩放 |
| Projection / reduction | BF16 GEMM 输入，FP32 GEMM 输出与统计；关闭 TF32 |
| Student head | 全参数可训练；teacher 无梯度 |
| 自有原型 tile | token=512，vocab=8192；token-only 模式不切词表 |
| 计时 | 每个方法预热 2 次、测量 5 次，报告中位数；同步后的 wall time，包含 Python 调度和 backward |
| 显存 | PyTorch allocator 的 allocated 峰值；另记录 reserved 和相对调用前常驻输入的增量 |

每次计时清理上一轮 student gradients。预热后释放 allocator 空闲缓存，再重置峰值；首次测量可能包含重新申请显存，因此原始 JSON 保留全部样本，不能将中位数当作置信区间。常驻输入和 head 约 0.94–0.96 GiB，峰值已包含它们，增量列将其扣除。没有采集 NVML 整卡峰值，不能将 allocator 峰值称为完整模型训练峰值。

Dense 的 KL 部分使用普通 autograd。当前 PyTorch 的 `torch.mm(..., out_dtype=torch.float32)` 实测没有自动求导实现，因此 GPU dense projection 用独立的标准线性 VJP 包装：对上游梯度转回 BF16 后进行 hidden/head GEMM；CPU FP64 dense 参照使用原生自动求导。所有 GPU 方法都采用相同 FP32 projection 输出口径，减少“先 BF16 舍入再转 FP32”造成的目标差异。

Token/streaming 原型以 FP32 累积 head 梯度，最后转回参数 dtype。Liger 默认版本以参数 dtype 累积；FP32 变体单独列出，使精度与容量代价可见。这里的 Liger 入口不能代表库内所有蒸馏入口，token 原型不是参考文章的 Chunked cuBLAS，streaming 原型也不是 Nitrobrew 的复现。

## 3. 数值与梯度

CPU FP64 共 24 组组合：三个随机种子，非均匀带符号上游权重/全零权重两种情况，四种 token/vocab 分块；student/teacher hidden size 分别为 5/8，词表 19，包含不能整除的尾块。最大 KL/hidden/head 梯度误差为 `5.44e-15`。Teacher 梯度均为 None；另检验 self-teacher 和 current baseline 中心化 logit-gap 身份。

| CPU 附加检查 | 最大绝对误差 |
| --- | ---: |
| Self-teacher KL | `4.44e-16` |
| Self-teacher hidden/head 梯度 | 0 |
| `log T(a) - log p(a) + K` 与中心化 logit gap | `8.88e-16` |

已有 `opd-objective/scripts/verify_reward_estimators.py` 的 64 个有限分布案例也通过，最大恒等式误差约 `4.44e-16`。它同时提醒 full KL baseline 不保证在所有分布上降低 score-gradient 方差；实验不预设一定提高准确率。

GPU 的值误差最大约 `2.38e-7`。4096 位置时：

| 实现 | Hidden 梯度相对 L2 误差 | Head 梯度相对 L2 误差 |
| --- | ---: | ---: |
| Token 分块重计算 | 8.240e-04 | 2.449e-04 |
| 在线词表分块重计算 | 9.225e-04 | 2.539e-04 |
| Liger 默认累积 | 9.034e-04 | 9.297e-03 |
| Liger FP32 累积 | 9.034e-04 | 2.407e-04 |

Liger 改为 FP32 head 梯度累积后，head 误差从约 0.93% 降到约 0.024%；差异主要与累积精度有关，hidden 梯度不随该开关变化。两种自有原型的 head 误差也约为 0.025%。这些是相对同一 BF16 线性 VJP 参照的误差，不能称为 FP64 精确梯度。

脚本的 GPU 检查阈值是值绝对误差 `1e-4`、梯度相对 L2 `2%`，只用来拦截原型的明显错误；它不是正式训练验收阈值。真实 teacher/student 接近、长序列、非均匀 logits、真实 mask 和分布式累积需在 P1–P3 中进一步验收。CPU JSON 与 GPU JSON 内嵌的 CPU 审计均包含 self-teacher 梯度和 baseline 检查。

## 4. Full loss：完整前反向

| 位置数 | 实现 | 时间中位数（ms） | allocated 峰值（GiB） | 增量峰值（GiB） |
| ---: | --- | ---: | ---: | ---: |
| 512 | Dense 参照 | 4.94 | 2.386 | 1.449 |
| 512 | Token 分块重计算 | 9.56 | 3.837 | 2.901 |
| 512 | 在线词表分块重计算 | 10.99 | 2.276 | 1.339 |
| 512 | Liger 默认累积 | 80.97 | 1.414 | 0.478 |
| 512 | Liger FP32 累积 | 110.38 | 2.268 | 1.332 |
| 4096 | Dense 参照 | 37.46 | 12.549 | 11.592 |
| 4096 | Token 分块重计算 | 70.21 | 3.878 | 2.921 |
| 4096 | 在线词表分块重计算 | 81.80 | 2.327 | 1.370 |
| 4096 | Liger 默认累积 | 101.15 | 1.730 | 0.773 |
| 4096 | Liger FP32 累积 | 130.60 | 2.475 | 1.518 |

4096 位置时，token 分块将 allocated 峰值从 12.55 GiB 降到 3.88 GiB，耗时从 37.46 ms 增至 70.21 ms；在线词表分块进一步降到 2.33 GiB，耗时约 81.80 ms。小到 512 位置时，token 重计算反而比 dense 更占显存，因为 FP32 head 梯度累积和多个工作 buffer 的固定成本超过节省的 logits。不能把“分块必然更省”推广到所有形状。

Liger 默认路径在 4096 位置下峰值约 1.73 GiB，耗时约 101.15 ms；FP32 累积为 2.47 GiB、130.60 ms。本机源码对 H800 自动选择的 token chunk 在这两个形状下分别为 8 和 64，而自有原型使用 512。较多的小块及反复 head 梯度累加是值得 profile 的开销来源；这里没有 kernel 分项计时，不能将全部时间差归因于 chunk 大小。

该结果与参考文章的“Liger 比 Chunked cuBLAS 快”不同，原因尚未隔离：模型维度、具体 Liger 入口、实现版本、精度和分块参数都可能不同。实现计划将 PyTorch token 重计算作为可读基线，保留 streaming 作为低显存候选；当前不把 Liger 自动设为默认最快 backend。

## 5. Full baseline：仅计算数值

| 位置数 | 实现 | 时间中位数（ms） | allocated 峰值（GiB） | 增量峰值（GiB） |
| ---: | --- | ---: | ---: | ---: |
| 512 | Token 分块数值 | 3.96 | 2.965 | 2.029 |
| 512 | 在线词表分块数值 | 4.42 | 1.047 | 0.110 |
| 4096 | Token 分块数值 | 31.35 | 2.986 | 2.029 |
| 4096 | 在线词表分块数值 | 34.83 | 1.067 | 0.109 |

4096 位置时，在线数值路径的增量峰值约 0.109 GiB，而 token-only 数值路径约 2.029 GiB；耗时分别约 34.83 ms 和 31.35 ms。对 baseline，在线归约以约 11% 的算子时间增加换取约 94.6% 的增量峰值下降，是优先接入的候选。

这里只测双方 head projection 与 KL 数值，没有计入 sampled student backward。不能拿这两行直接与 full loss 的前反向时间比较后声称 baseline 训练快多少。当前原型还返回 log-normalizer 和 mean-gap，后续 value-only 接口可以进一步减少不需要的输出。

## 6. 可复现实验命令

从仓库根目录执行。本机使用已存在的 profile 环境，不安装或升级依赖；迁移到开发机时先验证 PyTorch 版本、Liger API 与 FP32 projection 路径，不能假定安装 0.8.4 就具有本机所有补丁。

```bash
PROBE_PYTHON=/root/.local/share/mirroropd/venvs/profile-cu128/bin/python
CUDA_VISIBLE_DEVICES='' "$PROBE_PYTHON" \
  examples/mirroropd/docs/full-vocab/scripts/probe_full_kl.py \
  --device cpu \
  --output examples/mirroropd/docs/full-vocab/data/probe-20261022/cpu.json
```

确认 GPU 0 空闲后运行：

```bash
CUDA_VISIBLE_DEVICES=0 "$PROBE_PYTHON" \
  examples/mirroropd/docs/full-vocab/scripts/probe_full_kl.py \
  --device cuda --tokens 512 4096 --token-chunk 512 --vocab-chunk 8192 \
  --warmup 2 --repeats 5 \
  --output examples/mirroropd/docs/full-vocab/data/probe-20261022/h800.json
```

复用已有估计器期望梯度检查：

```bash
CUDA_VISIBLE_DEVICES='' "$PROBE_PYTHON" \
  examples/mirroropd/docs/opd-objective/scripts/verify_reward_estimators.py
```

这些命令不修改训练配置。尚未完成真实模型重建、FSDP 多卡、TQ、异步 I/O、端到端训练或准确率测试；对应验收安排见实现计划。
